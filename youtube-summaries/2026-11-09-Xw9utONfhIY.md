# What Your Coding Agent Can't See in the Code - Tom Moor, Linear

🔗 https://youtu.be/Xw9utONfhIY · 📅 2026-11-09 · 🎙 AI Engineer

## 한 줄 요약
AI 코딩 에이전트의 한계를 극복하기 위해, 코드 자체를 넘어 제품 개발 수명 주기 전반에 걸쳐 의도, 히스토리, 컨벤션 등 풍부한 컨텍스트를 제공하고 관리하는 시스템을 구축하는 것이 중요하다는 주장.

## 발표자·소속
Tom Moor, Linear

## 핵심 주장
-   **AI 코딩의 급속한 발전:** GitHub Copilot, ChatGPT, 코딩 에이전트 등 AI 도구의 발전 속도가 매우 빨라, 몇 년 만에 소프트웨어 엔지니어링 방식이 근본적으로 변화하고 있다.
-   **컨텍스트 문제의 부상:** 과거에는 코드 작성이나 구현이 병목 현상이었으나, 이제는 AI가 코드를 빠르게 생성하면서 제품의 일관성을 유지하고 올바른 문제를 해결하는 '컨텍스트'가 새로운 병목이 되었다.
-   **에이전트가 놓치는 컨텍스트:** 코딩 에이전트는 코드 자체는 읽을 수 있지만, 기능의 의도, 제품 히스토리, 디자인 컨벤션, 다른 팀의 작업, 소유권, 잠재적 위험 등 중요한 비코드 컨텍스트를 놓친다.
-   **전체 개발 수명 주기 컨텍스트 관리:** 아이디어 구상부터 구현, 검토, 지식 증류에 이르는 제품 개발의 모든 단계에서 컨텍스트를 지속적으로 수집, 강화, 전달하는 시스템이 필요하다.
-   **인간의 판단 역할 강조:** 코드가 저렴해질수록 인간의 판단이 더욱 중요해지며, 에이전트가 제공하는 풍부한 컨텍스트를 바탕으로 인간이 더 나은 의사결정을 내리고 제품의 일관성을 유지해야 한다.

## 세부 내용
발표자는 2019년에 설립된 Linear라는 회사에 대해 소개하며, Linear는 팀과 에이전트를 위한 제품 개발 시스템으로, 기존 이슈 트래커의 불편함에서 시작되었다고 설명합니다.

그는 AI 기술의 발전 속도를 보여주는 타임라인을 제시했습니다. 2021년 GitHub Copilot(탭 완성), 2022년 ChatGPT(대화형 디버깅), 2024년 코딩 에이전트(초기), 2025년 Claude Code(성숙), 2026년 소프트웨어 팩토리(오케스트레이션이 핵심)로 이어지는 변화를 언급하며, 이 모든 것이 불과 몇 년 사이에 일어났다고 강조했습니다. 또한, 인텔리전스 비용이 3년 만에 100달러에서 5센트로 급감하는 그래프를 보여주며, AI가 더 저렴하고 풍부해질 것이며, 작업 범위(task horizon)도 기하급수적으로 확장될 것이라고 예측했습니다.

이러한 변화 속에서 코딩 에이전트가 몇 시간, 며칠 동안 작업을 수행하게 되면, 코딩 자체보다 '일관성 유지'가 더 큰 문제가 된다고 지적했습니다. 수천 개의 개별적으로는 올바른 변경 사항들이 모여 일관성 없는 제품을 만들 수 있다는 것입니다. 발표자는 에이전트가 놓치는 중요한 컨텍스트로 의도(왜 중요한지), 히스토리(왜 이렇게 작동하는지), 컨벤션(어떻게 맞춰야 하는지), 다른 작업(무엇이 변하고 있는지), 소유권(누가 트레이드오프를 결정하는지), 위험(무엇이 망가질 수 있는지) 등을 꼽았습니다.

이러한 문제를 해결하기 위해 Linear는 제품 개발 프로세스를 '인테이크(Intake) → 구현(Implement) → 검토(Review) → 증류(Distill)'의 네 단계로 나누고, 각 단계에서 컨텍스트를 다음 단계로 전달하는 시스템을 구축했다고 설명했습니다.

1.  **인테이크 (Intake):** Zendesk, Slack, Teams, Gong 등 다양한 채널에서 들어오는 아이디어와 버그를 수집합니다. '트리아지 에이전트(Triage agent)'가 이를 분류하고, 고객 정보, 관련 이슈, 예상 담당자, 프로젝트 등 추가 컨텍스트를 풍부하게 합니다. 예를 들어, 비디오 캡션이 자동으로 켜지는 버그의 경우, 에이전트가 버그를 재현하고 자동 브라우저 액션이 사용자 의도로 오인되었음을 발견했습니다. 또한, 팀 계층 데이터 지원 요청의 경우, 에이전트가 기존 코드베이스를 분석하여 관련 작업과 고객 가치를 파악했습니다.
2.  **구현 (Implement):** 트리아지 에이전트가 제공한 풍부한 컨텍스트를 바탕으로 코딩 에이전트가 코드를 구현합니다. Linear는 조직 컨텍스트에 대한 접근 권한을 가진 MCP(영상에서 불명)와 검증 스킬, CI(지속적 통합) 실패 피드백을 활용합니다. 발표자는 이 단계는 이미 "해결된 문제"에 가깝다고 언급했습니다.
3.  **검토 (Review):** 코드 변경 사항, 저장소 히스토리, PR(Pull Request) 설명 외에, 원본 이슈, 제품 히스토리, 관련 이슈, 스택 내 다른 PR, 전체 에이전트 세션 히스토리, 소유권 등 더 많은 컨텍스트를 제공하여 인간 리뷰어가 코드의 논리적 정확성뿐만 아니라 제품 전체에 대한 적합성을 판단하도록 돕습니다. 예를 들어, 느린 첨부파일 다운로드로 인한 이슈 생성 블록킹 문제에서 에이전트는 6~7개월 전의 관련 변경 사항과 인시던트 위험을 식별했습니다. 또한, UI 요소가 "너무 복잡하다"는 이유로 과거에 제거되었던 히스토리를 에이전트가 찾아내어, 비슷한 UI를 다시 추가하려는 PR을 막았습니다. Linear는 이러한 결정을 표면화하는 UI를 구축하여 인간 리뷰어를 돕습니다.
4.  **증류 (Distill):** 검토 과정에서 발생한 피드백(거부된 접근 방식, 결정, 근거 등)을 다시 코딩 에이전트에게 학습시킵니다. Linear는 병합된 PR 리뷰에서 학습하는 자동화 루프를 운영하여, 코드베이스에 학습된 교훈(예: `agents.md` 파일 또는 관련 문서)을 지속적으로 주입합니다. 이는 에이전트가 동일한 실수를 반복하지 않도록 하고, 조직의 지식을 지속적으로 축적하는 데 기여합니다.

이러한 컨텍스트 중심의 접근 방식은 잘못된 문제를 해결하는 변경 사항을 줄이고, 놓친 결정으로 인한 재작업을 줄이며, 제품에 더 잘 맞는 변경 사항을 늘려, 궁극적으로 더 빠른 반복과 더 높은 품질을 달성한다고 발표자는 결론지었습니다. "코드가 저렴해질수록 우리의 판단이 더 중요해진다"는 메시지를 강조하며 발표를 마쳤습니다.

## 실무 적용 포인트
-   **컨텍스트 중심의 개발 프로세스 구축:** 코드 변경 사항뿐만 아니라, 그 변경의 배경이 되는 의도, 제품 히스토리, 사용자 피드백, 관련 작업 등 비코드 컨텍스트를 체계적으로 수집하고 관리하는 시스템을 도입합니다.
-   **AI 에이전트의 역할 확장:** 단순한 코드 생성이나 디버깅을 넘어, 이슈 트리아지, 과거 결정 분석, 잠재적 위험 식별 등 개발 수명 주기 전반에 걸쳐 컨텍스트를 풍부하게 하는 데 AI 에이전트를 활용합니다.
-   **학습 루프 설계:** 코드 리뷰 코멘트, PR 히스토리, 버그 리포트 등에서 얻은 교훈을 에이전트에게 다시 학습시켜, 에이전트의 지식 기반을 지속적으로 개선하고 동일한 실수를 반복하지 않도록 합니다.
-   **인간-AI 협업 강화:** AI가 제공하는 풍부한 컨텍스트를 바탕으로 인간 개발자가 더 복잡하고 전략적인 의사결정에 집중하고, 제품의 일관성과 품질을 최종적으로 책임지는 역할을 수행하도록 합니다.
