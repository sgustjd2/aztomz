# From Your Laptop to the Pipeline: Scaling Custom Agents with GitHub Copilot

🔗 https://youtu.be/b9UhZkKjX_A · 📅 2026-10-10 · 🎙 AI Engineer

## 한 줄 요약
GitHub Copilot을 활용하여 로컬 에이전트, 공유 에이전트, 파이프라인 에이전트를 구축하고 확장하는 방법을 소개하며, 에이전트 기반 개발(Agentic Development)을 통해 코드 품질 향상, 자동화된 워크플로우, 비용 최적화를 달성할 수 있음을 강조합니다.

## 발표자·소속
Jose Palafox, GitHub

## 핵심 주장
- **다양한 인터페이스를 통한 에이전트 상호작용:** GitHub Copilot은 IDE, CLI, 모바일, 웹 등 다양한 인터페이스를 통해 접근 가능하며, 모든 상호작용은 Copilot API(하네스)를 거쳐 모델 제공자에게 전달됩니다.
- **로컬 및 공유 에이전트의 손쉬운 생성 및 배포:** CLI의 `agent` 명령어를 통해 사용자 또는 프로젝트 수준의 커스텀 에이전트를 쉽게 생성할 수 있으며, `.github/private/agents` 디렉토리나 마켓플레이스를 통해 조직 내외로 에이전트를 공유하고 관리할 수 있습니다.
- **에이전트 기반 워크플로우를 통한 파이프라인 자동화 및 확장:** `orchestrate` 명령어를 사용하여 여러 리포지토리에 걸쳐 에이전트가 자율적으로 작업을 수행하도록 설정할 수 있으며, 이는 반복적인 유지보수 작업 자동화, 코드 품질 향상, 비용 최적화에 기여합니다.

## 세부 내용

발표자는 GitHub에서 6년 반 동안 보안 비즈니스를 성장시키고 최근 1년간 AI에 집중해온 Jose Palafox입니다. 그는 GitHub Copilot 플랫폼에서 에이전트를 활용하는 방법을 소개했습니다.

**GitHub Copilot 데이터 흐름 및 인터페이스:**
Copilot은 VS Code, JetBrains와 같은 IDE 확장 프로그램, GitHub CLI, GitHub Mobile, GitHub.com 웹 인터페이스, Slack, Teams, Linear, Replit과 같은 코딩 에이전트 통합 등 다양한 클라이언트 인터페이스를 제공합니다. 모든 클라이언트 요청은 Copilot API(하네스)를 통해 처리됩니다. 이 하네스는 입력 분석, 응답 평가, GitHub 코드 참조 인덱스 관리, 인증 서비스 연동, 책임감 있는 AI 콘텐츠 필터링 등의 엔지니어링 작업을 수행합니다. 이후 요청은 Azure OpenAI Service, OpenAI Service, AWS Service, Anthropic IP Service, Google Cloud Service 등 다양한 모델 제공자에게 전달되고, 응답은 필터링되어 클라이언트에 다시 표시됩니다.

**로컬 에이전트 생성 및 구성:**
CLI에서 `/agents` 명령어를 입력하면 `explore`, `task`, `general-purpose`, `rubber-duck`, `code-review`, `research`, `security-review`와 같은 내장 에이전트 목록이 나타납니다. 각 에이전트는 `claude-haiku-4.5` 또는 `claude-sonnet-4.0`와 같은 기본 모델을 사용하도록 구성되어 있습니다. 발표자는 `agent --name` 명령어를 사용하여 커스텀 에이전트를 생성하는 과정을 시연했습니다. 에이전트는 프로젝트 수준(`project/.github/agents`) 또는 사용자 수준(`~/.copilot/agents`)에서 생성할 수 있으며, Copilot이 에이전트의 설명, 임무, 방법론, 출력 형식 등을 자동으로 스캐폴딩해줍니다. 예를 들어, `copilot-changelog-summarizer` 에이전트는 GitHub 변경 로그를 요약하는 역할을 합니다.

**에이전트 공유 및 재사용:**
생성된 에이전트는 Copilot 하네스 내에서 작동합니다. 에이전트를 다른 팀원이나 조직과 공유하려면 "마켓플레이스"를 생성할 수 있습니다. 마켓플레이스는 특정 JSON 메타데이터를 포함하는 리포지토리로, 에이전트의 버전 관리, 업데이트, 보안 취약점 알림 등의 기능을 제공합니다. 또한, 리포지토리 내의 `.github/private/agents` 디렉토리를 사용하여 조직 내부에서 에이전트를 공유할 수 있습니다. 이 디렉토리에 있는 에이전트들은 GitHub UI의 드롭다운 메뉴를 통해 직접 호출될 수 있어, 팀 전체의 표준화된 작업 수행과 에이전트 재사용을 촉진합니다.

**에이전트 기반 워크플로우 및 파이프라인 통합:**
Copilot 앱의 `orchestrate` 명령어를 사용하면 여러 리포지토리에 걸쳐 에이전트를 수평적으로 확장하고 관리할 수 있습니다. 이는 GitHub 이슈를 에이전트의 목표로 설정하고, 해당 목표를 달성하기 위해 하위 에이전트들을 실행하는 방식입니다. 에이전트는 개발자의 로컬 머신이 아닌 플랫폼에서 자율적으로 실행되므로, 개발자의 작업 흐름에 영향을 주지 않고 리포지토리의 예산을 사용하여 작업을 수행합니다.

발표자는 "Research - Plan - Assign"이라는 에이전트 기반 워크플로우를 예시로 들었습니다.
1.  **Research:** "Deep Research" 에이전트가 리포지토리에서 연구를 수행하고 아티팩트를 생성합니다.
2.  **Plan:** 개발자가 연구 결과를 바탕으로 계획을 세우고, "Issue Monster" 에이전트가 이를 바탕으로 작업을 할당합니다.
3.  **Assign:** "Copilot" 에이전트가 할당된 작업을 수행하고 풀 리퀘스트를 생성합니다.
4.  **Review & Merge:** 개발자가 생성된 코드를 검토하고 병합합니다.
이러한 워크플로우는 인간 개입 지점(Human-in-the-loop triggers)을 포함하여, 개발자가 중요한 결정 단계에서 에이전트의 작업을 검토하고 승인할 수 있도록 합니다.

GitHub Next 조직의 "Agentics" 프로젝트는 이러한 에이전트 기반 개발의 실제 사례를 보여줍니다. 이 프로젝트는 수백 개의 파이프라인 에이전트로 구성되어 있으며, 코드 중복 제거, 성능 최적화, 문서화 업데이트 등 다양한 유지보수 및 개선 작업을 자동화합니다. 에이전트들은 OpenTelemetry(OTel)로 계측되어 있어, 에이전트의 실행 비용, 토큰 사용량, 성공/실패 여부 등을 모니터링하고 최적화할 수 있습니다. 이를 통해 개발자는 에이전트의 성능을 분석하고, 더 효율적인 모델을 선택하거나 프롬프트를 개선하여 비용을 절감할 수 있습니다.

## 실무 적용 포인트
- **커스텀 에이전트 활용:** 반복적인 코드 분석, 문서화, 특정 도구 실행 등 개발자의 일상 업무를 자동화하기 위해 GitHub CLI의 `agent` 명령어를 사용하여 커스텀 에이전트를 생성하고 활용할 수 있습니다.
- **조직 내 에이전트 공유:** `.github/private/agents` 디렉토리를 활용하여 팀 또는 조직 내에서 표준화된 에이전트를 공유하고 배포함으로써, 개발자들이 동일한 모범 사례를 따르고 불필요한 중복 작업을 줄일 수 있습니다.
- **에이전트 기반 파이프라인 구축:** GitHub Actions와 같은 CI/CD 시스템에 에이전트를 통합하여 자율적인 워크플로우를 구축할 수 있습니다. 이를 통해 코드 품질 검사, 성능 최적화, 보안 감사 등 반복적인 작업을 자동화하고 개발자의 개입을 최소화할 수 있습니다.
- **비용 및 성능 최적화:** 에이전트의 실행 메트릭(예: 토큰 사용량, 실행 시간)을 모니터링하고 분석하여, 에이전트의 프롬프트, 모델 선택, 실행 빈도 등을 최적화함으로써 AI 사용 비용을 절감하고 효율성을 높일 수 있습니다.
