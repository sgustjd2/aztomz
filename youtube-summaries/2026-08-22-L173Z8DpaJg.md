# The Agent Behind the Curtain: Building the Oz Cloud Agent Platform — Safia Abdalla, Warp

## 한 줄 요약

## 핵심 주장
- **개발자 도구는 개발자와 함께 성장해야 합니다:** 훌륭한 개발자 도구는 개발자가 있는 곳에서 만나고 그들의 변화하는 워크플로우와 복잡성에 적응하며 함께 성장해야 합니다. 이는 개발자의 생산성을 극대화하고 소프트웨어 개발에 대한 긍정적인 경험을 제공합니다.
- **플랫폼은 사용자에게 도달하기 전에 복잡성을 흡수해야 합니다:** 클라우드 환경에서 AI 에이전트를 실행하는 것은 많은 인프라 복잡성을 수반하므로, 플랫폼은 이러한 복잡성을 추상화하여 사용자가 핵심 작업에 집중할 수 있도록 해야 합니다.
- **다중 에이전트 오케스트레이션과 API 노출이 중요합니다:** 실제 엔지니어링 작업은 단일 프롬프트로 해결되지 않으므로, 여러 AI 에이전트(기획자, 구현자, 검증자)를 오케스트레이션하고, 플랫폼의 모든 핵심 구성 요소를 API로 노출하여 유연성과 확장성을 제공해야 합니다.
- **AI 에이전트는 개발 프로세스를 의미 있게 개선할 수 있습니다:** AI 에이전트는 코드 작성뿐만 아니라 이슈 분류, 컨텍스트 제공, 초기 사양 초안 작성, 구현 및 검토 게이트 역할까지 수행하여 개발 워크플로우의 고된 작업을 줄이고 인간이 더 창의적인 작업에 집중할 수 있도록 돕습니다.

## 세부 내용
발표는 AI Engineer World's Fair에서 "The Agent Behind the Curtain: Building the Oz Cloud Agent Platform at Warp"라는 제목으로 진행되었습니다.

발표자인 Safia Abdalla는 8년 이상 개발자 도구를 구축해왔으며, 오픈소스(Python, 데이터 과학, Jupyter Notebook, Interact 프로젝트)와 Microsoft(웹 개발자를 위한 API 및 SDK)에서 일한 경험을 공유했습니다. 현재는 Warp에서 클라우드 기반 AI 에이전트를 구축하고 있습니다.

그녀는 훌륭한 개발자 도구의 두 가지 핵심 철학을 제시했습니다. 첫째, "훌륭한 개발자 도구는 개발자가 있는 곳에서 만나고 그들과 함께 성장합니다." 도구는 개발자의 워크플로우에 맞춰야 하며, 작업의 복잡성과 성격이 변함에 따라 적응할 수 있어야 합니다. 둘째, "훌륭한 개발자 도구는 세상에 복합적인 영향을 미칩니다." 개발자가 더 나은 소프트웨어를 만들도록 돕는 도구는 세상에 존재하는 훌륭한 소프트웨어의 양을 증폭시킵니다.

Warp의 AI 툴링 발전 과정은 세 단계로 설명됩니다.
1.  **Warp Terminal (AI 이전):** 개발자들이 익숙한 명령줄 워크플로우를 지원했습니다.
2.  **Warp Agent (AI 도입):** AI 코딩 패턴이 터미널, IDE, 에디터 등 로컬 머신에 도입되었습니다.
3.  **Oz (클라우드 에이전트 플랫폼):** 로컬 머신의 한계를 넘어 장기 실행되고 다양한 제약 조건에 적응하는 에이전트가 필요해지면서 클라우드 기반 플랫폼이 등장했습니다.

클라우드로 이동하면서 복잡성이 증가하는데, Safia는 "플랫폼은 사용자에게 도달하기 전에 복잡성을 흡수해야 한다"고 강조했습니다. 클라우드에서 에이전트를 실행하려면 샌드박스가 필요합니다. 처음에는 자체 호스팅 샌드박스를 제공했지만, 실제로는 개발자들이 자체 인프라를 관리해야 하는 경우가 많아 관리형 호스팅과 자체 호스팅 모두를 지원하게 되었습니다. 이는 사용자로부터 복잡성을 추상화하는 중요한 단계입니다.

또한, 개발자들은 자신이 사용하는 도구에 열정적이므로, 다양한 하네스(예: Claude Code, Codex, 커스텀 하네스)를 지원하여 유연성을 제공해야 합니다. 플랫폼은 대화 상태 저장 및 복원, 에이전트가 생성하는 아티팩트(PR, 이슈, 새 파일)와의 상호 작용 등 일관된 경험을 위한 구조와 가이드라인을 제공해야 합니다.

실제 엔지니어링 작업은 단일 프롬프트로 해결되지 않기 때문에, 여러 에이전트의 오케스트레이션이 필요합니다. 예를 들어, 문제를 조사하고 해결책을 계획하는 에이전트, 이를 구현하는 에이전트, 그리고 결과를 검증하는 에이전트가 있을 수 있습니다. 각 에이전트는 다른 하네스와 모델을 사용하여 견고한 접근 방식을 취할 수 있습니다. Warp는 `/orchestrate` 명령어를 통해 여러 서브 에이전트에게 작업을 위임하는 프롬프트 기반 오케스트레이션을 지원합니다.

이러한 에이전트 및 서브 에이전트와의 상호 작용은 API를 통해 이루어집니다. Safia는 "원시 요소(primitives)가 제품이다"라고 말하며, 에이전트 스핀업, 환경 및 컴퓨팅 관리, 아티팩트 작업 등 모든 핵심 구성 요소를 API로 노출하여 사용자가 그 위에 새로운 도구를 구축할 수 있도록 한다고 설명했습니다. 이러한 구성 가능성은 매우 강력합니다.

Warp는 약 3개월 전 오픈소스화되었으며, 이는 큰 성공을 거두었습니다. GitHub 스타는 2만 개에서 6만 개 이상으로 급증했고, 수천 개의 PR과 수백 명의 기여자가 참여했습니다. 특히 비엔지니어링 팀원들도 SDK와 API를 활용하여 소셜 멘션 관리, 감성 분석, 응답 제안 등을 위한 커스텀 Slack 봇을 구축했습니다.

Warp는 에이전트가 개발 프로세스에 의미 있게 참여하도록 설계했습니다. 에이전트는 단순히 코드를 작성하는 것을 넘어, 버그 보고서나 기능 요청이 접수되면 자동으로 이슈를 분류하고, 코드베이스를 조사하여 컨텍스트를 제공하며, 필요한 경우 질문을 던져 정보를 얻고, 초기 사양을 초안 작성하고, 구현하며, 심지어 PR에 대한 검토 게이트 역할까지 수행합니다. 에이전트가 PR을 승인한 후에야 인간 검토자에게 알림이 갑니다. 이는 팀의 워크로드를 크게 줄여줍니다.

Safia는 이러한 접근 방식을 "소프트웨어 팩토리 워크숍"이라는 용어로 설명했습니다. 이는 도예가의 작업실 비유를 통해, 도예가가 완벽한 머그잔을 만들기 위해 손잡이의 곡선, 유약 처리 등 세부 사항에 깊이 몰두하고, 점토 준비, 검증 등 체계적인 프로세스를 통해 수십 명의 견습생과 함께 하루에 수백 개의 머그잔을 수공예로 생산하는 것과 같다고 비유했습니다.

소프트웨어 팩토리 워크숍의 핵심 요소는 다음과 같습니다.
-   **자동화:** 실제 이벤트에 반응하는 자동화 구현.
-   **관찰 가능성(Observability):** 시스템을 검사하고 들여다볼 수 있도록 함.
-   **자기 개선(Self-improvement):** 시스템이 스스로 변화에 반응하고 목표에 맞춰 수정되도록 함.
-   **비용 효율성(Cost-effectiveness):** 버그가 있는 소프트웨어의 양을 줄이고 토큰 사용을 최적화.

궁극적인 목표는 "고된 작업과 단조로움을 제거하여 모든 사람이 창의적으로 만들 수 있는 시스템을 구축하는 것"입니다. 이는 비기술 직군을 포함한 더 많은 빌더들이 아이디어를 코드로 전환할 수 있는 진지한 시스템을 제공하는 것을 의미합니다.

## 실무 적용 포인트
- **복잡성 추상화에 집중:** 클라우드 기반 AI 에이전트 플랫폼을 구축할 때, 사용자가 인프라 세부 사항에 신경 쓰지 않도록 샌드박스 관리, 환경 구성 등의 복잡성을 플랫폼 수준에서 처리하는 데 우선순위를 둡니다.
- **API 중심 설계:** 에이전트 스핀업, 관리, 아티팩트 처리 등 플랫폼의 모든 핵심 기능을 API로 노출하여 개발자들이 그 위에 커스텀 도구를 쉽게 구축하고 확장할 수 있도록 합니다.
- **다중 에이전트 오케스트레이션 도입:** 복잡한 엔지니어링 작업을 단일 에이전트가 아닌 여러 전문 에이전트(기획, 구현, 검증 등)가 협력하도록 오케스트레이션하는 시스템을 고려하여, 더 견고하고 신뢰할 수 있는 솔루션을 만듭니다.
- **개발 라이프사이클에 에이전트 통합:** AI 에이전트를 이슈 분류, 사양 초안 작성, 코드 검토 게이트 등의 개발 워크플로우에 통합하여 반복적인 작업을 자동화하고 인간 개발자가 더 가치 있는 창의적 작업에 집중할 수 있도록 지원합니다.
