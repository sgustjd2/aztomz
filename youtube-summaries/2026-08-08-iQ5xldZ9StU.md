# Realtime multiplayer, automation, and you! — Idan Gazit, GitHub

🔗 https://youtu.be/iQ5xldZ9StU · 📅 2026-08-08 · 🎙 AI Engineer

## 한 줄 요약
GitHub Next의 이단 가짓은 AI 시대에 소프트웨어 개발의 미래가 개인의 생산성을 넘어 팀의 협업과 자동화를 강화하는 '에이전틱 워크플로우'와 '실시간 멀티플레이어 개발'에 있다고 주장하며, 이를 위한 두 가지 프로토타입을 소개합니다.

## 발표자·소속
이단 가짓 (Idan Gazit), GitHub Next 리더

## 핵심 주장
-   **미래 지향적 프로토타이핑:** GitHub Next는 당장 내일이 아닌 1~2년 후의 소프트웨어 개발 도구를 탐색하고 프로토타이핑하며, AI 시대에는 모든 팀이 이러한 '랩스 팀'처럼 미래를 탐색해야 합니다.
-   **'나'가 아닌 '우리'의 증폭:** AI는 개인의 생산성을 높이는 데 기여했지만, 진정한 가치는 여러 에이전트가 개인을 돕는 것을 넘어 팀 전체의 협업 능력을 증폭시키는 데 있습니다.
-   **자동화와 협업의 두 축:** AI 시대의 소프트웨어 개발은 '자동화'를 통해 수동 작업을 줄여 시간을 확보하고, '협업'을 통해 팀원 간의 이해와 조율을 실시간으로 개선하는 두 가지 렌즈로 접근해야 합니다.
-   **보안 중심의 에이전틱 워크플로우:** 에이전틱 워크플로우는 마크다운 문서로 정의되며, 명시적인 권한, 도구, 네트워크 및 출력 제어를 통해 에이전트의 행동을 엄격하게 제한하여 보안을 기본으로 합니다.
-   **실시간 멀티플레이어 에이전틱 개발:** Ace는 Slack과 유사한 인터페이스에서 클라우드 기반 마이크로 VM을 통해 팀원들이 실시간으로 코드와 문서를 협업하고, AI 에이전트가 대화의 맥락을 이해하여 작업을 실행합니다.
-   **인간은 이제 '도구 호출':** AI 모델이 발전함에 따라 에이전트가 코드베이스를 이해하고 작업을 수행하며, 필요한 경우 인간에게 명확화를 요청하거나 직접 개입을 요청하는 방식으로 역할이 변화합니다.

## 세부 내용
발표자는 GitHub의 랩스 팀인 GitHub Next를 이끌고 있으며, 이 팀은 GitHub Copilot을 개발하고 스펙 기반 프로그래밍, 자연어-앱 전환 등 다양한 분야를 개척했습니다. GitHub Next의 목표는 1~2년 후의 GitHub, 즉 미래의 소프트웨어 개발 도구를 탐색하는 것입니다. 발표자는 이를 "Research? Prototyping."이라고 표현하며, 미래를 예측하는 유일한 방법은 직접 만들어보는 것이라고 강조합니다.

AI 시대에는 코드 한 줄의 한계 비용이 0에 가까워지고 AI가 생각하고 만드는 것을 돕기 때문에, 무엇을 만들고 무엇이 중요한지 선택하는 것이 중요해졌습니다. 발표자는 AI가 개인의 생산성을 높이는 데 기여했지만, 진정한 가치는 '나'를 증폭시키는 것이 아니라 '우리'를 증폭시키는 데 있다고 말합니다. 이를 위해 '자동화'와 '협업'이라는 두 가지 렌즈를 통해 접근합니다.

**자동화 (Agentic Workflows):**
소프트웨어 산업은 아직 '산업화 이전' 단계에 있으며, 기존의 자동화는 세미콜론 추가와 같은 휴리스틱에 불과했습니다. 하지만 AI는 기본적인 판단을 요구하는 작업을 자동화할 수 있게 합니다. 발표자는 자신의 개인 웹사이트(Astro 프레임워크 기반) 업그레이드 과정을 예시로 들며 에이전틱 워크플로우를 시연합니다.

1.  **워크플로우 생성:** Copilot을 사용하여 "Astro의 모든 종속성에 대한 새 릴리스가 있는지 매일 확인하고, 변경 로그와 업그레이드 문서를 검토하여 업그레이드 계획을 세우고, 필요한 변경 사항을 포함하여 PR을 생성하라"는 지시를 내립니다.
2.  **워크플로우 정의:** 생성된 워크플로우는 마크다운 문서 형태로 나타나며, YAML 프론트 매터에는 `permissions: read-all`, `tools: web-fetch`, `safe-outputs: create-pull-request: max: 1`, `networks: allowed: defaults, node, github, docs.astro.build`와 같은 가드레일(guardrails)이 명시되어 있습니다. 이는 에이전트가 수행할 수 있는 작업, 접근 가능한 도구, 네트워크 요청, 생성할 수 있는 PR의 수 등을 제한하여 보안을 강화합니다.
3.  **PR 생성 및 검증:** 에이전트는 Astro의 마이너 버전 업그레이드 PR을 생성하고, 변경 로그 요약, 주요 변경 사항, 빌드 검증(npm install, astro check, astro build 실행) 결과 등을 자동으로 포함합니다. 심지어 Cloudflare Pages를 통한 프리뷰 배포 링크까지 제공하여 변경 사항을 시각적으로 확인할 수 있게 합니다.
4.  **메이저 버전 업그레이드:** Astro v5에서 v7로의 메이저 버전 업그레이드 시연에서는 에이전트가 변경 사항 요약, Astro v7 및 v6(건너뛴 버전)의 주요 변경 사항, 그리고 코드베이스에 필요한 브레이킹 변경 사항(Content Layer API 마이그레이션)까지 파악하여 제시합니다.
5.  **보안 원칙:** 에이전틱 워크플로우는 '심층 방어(Defense in depth)', '에이전트를 비밀(secrets)로 신뢰하지 말 것', '모든 쓰기 작업을 스테이징하고 검증할 것(Stage and vet all writes)', '모든 것을 기록할 것(Log everything)'이라는 네 가지 보안 원칙을 따릅니다. 에이전트는 비밀에 직접 접근하지 않고, 워든(Warden)을 통해 요청해야 합니다.
6.  **Home Assistant 사례:** Home Assistant 프로젝트는 에이전틱 워크플로우를 사용하여 제출된 이슈를 분석하고, 파이썬 스택 트레이스를 추적하여 버그의 원인이 퍼스트 파티 코드인지 서드 파티 코드인지 식별하며, 관련 없는 이슈는 자동으로 닫는 워크플로우를 구축했습니다. 이는 기존에는 불가능했던 자동화입니다.
7.  **공개 프리뷰:** 에이전틱 워크플로우는 현재 공개 프리뷰 상태이며, `gh.io/aw-public-preview`에서 사용해 볼 수 있습니다.

**협업 (Ace):**
전통적인 소프트웨어 개발은 '계획-구축-검토'의 선형적인 과정을 따랐고, '구축' 단계는 주로 개별 개발자가 혼자 진행했습니다. 하지만 AI 시대에는 계획과 검토뿐만 아니라 구축 과정에서도 실시간 협업이 필요합니다.

1.  **Ace 인터페이스:** Ace는 Slack과 유사한 실시간 멀티플레이어 개발 환경입니다. 각 세션은 클라우드에서 실행되는 마이크로 VM으로, 레포지토리의 브랜치를 체크아웃하여 사용합니다.
2.  **실시간 대화 및 실행:** 팀원들은 Ace 내에서 대화하며 코드를 수정하고 터미널 명령을 실행할 수 있습니다. AI 에이전트는 대화의 전체 맥락을 이해하고, 팀원들의 지시에 따라 코드를 변경하거나 작업을 수행합니다. 예를 들어, 팀원 간의 색상 테마 변경 논의를 AI가 이해하고 실제 코드에 반영합니다.
3.  **공동 문서 편집:** Ace는 공유 문서 편집 기능을 제공하여 팀원들이 함께 계획을 세우고 수정할 수 있습니다. AI는 이 문서를 기반으로 실제 작업을 실행합니다.
4.  **팀 현황 파악 (Team Pulse):** Ace는 팀원들이 진행 중인 작업, PR 상태, 해결된 이슈 등 팀의 활동을 요약하여 보여주는 'Team Pulse' 대시보드를 제공하여 팀원들이 서로의 진행 상황을 쉽게 파악할 수 있도록 돕습니다.
5.  **인간의 역할 변화:** AI가 코드 작성의 5%를 넘어 시스템 이해(Comprehension, 50%), 탐색(Navigation, 24%) 등 나머지 95%의 개발자 시간을 돕게 되면서, 인간은 이제 에이전트에게 '도구 호출(tool calls)'을 하는 역할을 하게 됩니다. 에이전트는 모든 것을 듣고 이해하며, 필요한 경우 인간에게 질문을 던져 명확화를 요청합니다.

## 실무 적용 포인트
-   **에이전틱 워크플로우 도입 검토:** 반복적이고 판단이 필요한 작업(예: 종속성 업그레이드, 이슈 분류, CI/CD 오류 분석)에 GitHub Agentic Workflows를 활용하여 개발 시간을 절약하고 오류를 줄일 수 있습니다.
-   **보안 가드레일 설정:** 에이전틱 워크플로우를 사용할 때는 에이전트의 권한, 접근 가능한 도구, 네트워크 요청 범위 등을 명확히 정의하여 보안 위험을 최소화해야 합니다.
-   **실시간 협업 환경 탐색:** Ace와 같은 실시간 멀티플레이어 개발 환경을 도입하여 팀원 간의 소통과 코드/문서 협업을 강화하고, AI 에이전트가 팀 대화의 맥락을 이해하여 작업을 자동화하도록 할 수 있습니다.
-   **문서 중심 개발 전환:** AI 에이전트가 마크다운 문서 기반의 계획을 실행하고 업데이트하는 능력을 활용하여, 코드뿐만 아니라 문서도 개발 과정의 핵심 산출물로 관리하는 문서 중심 개발(Documentation-driven development) 방식을 고려할 수 있습니다.
