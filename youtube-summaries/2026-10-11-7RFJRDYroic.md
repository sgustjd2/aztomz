## 세부 내용

발표는 AI 엔지니어링 컨퍼런스인 AI Engineer World's Fair의 워크숍 세션으로 진행되었습니다. 발표자들은 Weco AI 소속이며, Microsoft가 주요 스폰서로 참여했습니다.

발표는 오토리서치의 개념 소개로 시작되었습니다. 2026년 3월 7일 Andrej Karpathy가 오토리서치를 공개하며 21,000개 이상의 GitHub 스타를 얻은 "Karpathy Moment"를 언급했습니다. 오토리서치는 언어 모델에 코드와 재현 가능한 평가 스크립트를 제공하여, 모델이 아이디어를 시도하고, 테스트하며, 개선 사항을 유지하고 나머지는 폐기하는 시행착오 루프입니다. 정확도, 속도, 비용 등이 예시 측정 지표로 제시되었습니다. 오토리서치는 훈련을 넘어 백엔드 엔지니어링(53% 더 빠르고 61% 적은 할당), 프롬프트 엔지니어링(0.73에서 0.97로 향상), 모델 추론 속도 향상(30% 더 빠름) 등 다양한 분야로 확산되었습니다.

Weco AI의 자율 AI 엔지니어 에이전트인 'Aiden'은 OpenAI의 "파라미터 골프" 채용 챌린지에서 우승했습니다. 이 챌린지는 16MB의 총 아티팩트(모델 가중치 + 훈련 코드)와 10분의 훈련 예산 내에서 최고의 언어 모델을 훈련하는 것이 목표였습니다. Aiden은 Claude 및 GPT 모델을 기반으로 하는 자체 개선 멀티 에이전트 시스템으로, 공개된 논문, GitHub 저장소, 자체 실험 로그를 읽고 새로운 아이디어를 제안하며, 로컬에서 실험하고, 적법성을 감사한 후, 품질 기준을 통과하면 PR을 생성하여 제출하는 루프를 자동화했습니다. Aiden은 1,016명의 참가자 중 7개의 리더보드 기록을 세우며 1위를 차지했고, 이는 다음 인간 기여자의 두 배에 달하는 기록입니다. 또한, 전체 커뮤니티 GPU 컴퓨팅의 4%만 사용하여 15%의 총 병합 기록을 달성하여 3.7배 더 비용 효율적이었습니다.

발표자들은 참가자들이 오토리서치를 직접 경험할 수 있도록 "미니 파라미터 골프"를 소개했습니다. 이는 실제 챌린지와 동일한 연구 형태(제한된 아티팩트, 고정된 평가자, 단일 스칼라 지표)를 가지지만, 더 작은 데이터셋을 사용하고 실행 시간이 몇 초에 불과하여 빠르고 저렴하게 실제 단계를 라이브로 볼 수 있도록 축소된 버전입니다. 참가자들은 Weco AI 대시보드와 Modal 컴퓨팅 플랫폼에 가입하고, GitHub 저장소를 클론한 후 코딩 에이전트를 실행하여 미니 파라미터 골프를 시작하도록 안내받았습니다.

오토리서치 실행의 해부학적 구조도 제시되었습니다.
1.  **소스 파일**: 에이전트가 수정할 수 있는 코드(예: `solution.py`).
2.  **평가**: 에이전트가 생성한 각 솔루션을 평가하는 스크립트. 빠르고, 저렴하며, 노이즈가 적고, 에이전트의 속임수에 강해야 합니다.
3.  **측정 지표 및 목표**: 개선하고자 하는 스칼라 지표(예: `val_bpb`)와 목표(예: 최소화).
4.  **단계**: 에이전트가 아이디어를 시도할 횟수(예: 20단계).
5.  **평가 시간 초과**: 각 평가 실행에 허용되는 최대 시간(예: 210초)을 설정하여 무한 루프나 하드웨어 오류를 방지합니다.
6.  **지침**: 에이전트에게 초기 방향을 제시하거나 하드 제약을 설정하는 인간의 지식(예: `weco_instructions.md`).

Weco AI의 오토리서치 시스템은 **구조화(Structured)**, **관찰 가능성(Observability)**, **조종 가능성(Steerability)**을 강조합니다. 트리 기반 검색을 통해 에이전트의 모든 시도를 시각화하고, 각 노드를 클릭하여 코드 변경 사항과 그 이유를 정확히 확인할 수 있습니다. 또한, 자연어 프롬프트를 통해 에이전트의 탐색 방향을 조종하여 인간의 직관과 지식을 시스템에 통합할 수 있습니다. 실제 파라미터 골프 챌린지에서 에이전트가 5일간 정체되었을 때, 커뮤니티의 인간 기여자가 새로운 토크나이저를 제안했고, 에이전트가 이를 통합하여 몇 주 만에 가장 큰 성능 향상을 달성한 사례가 조종 가능성의 중요성을 보여주었습니다.

발표는 "Flappy Weco Cup"이라는 라이브 경쟁으로 마무리되었습니다. 참가자들은 Flappy Bird 컨트롤러를 최적화해야 하며, 이 컨트롤러는 일반, 움직이는 틈새, 바람, 변수 등 네 가지 다른 게임 세계에서 평균 점수를 기준으로 평가됩니다. 점수는 숨겨진 검증 세트에서 다시 채점되어 공개 시드에 과적합되는 것을 방지합니다. 참가자들은 `ai_controller.py` 파일만 수정하고, 외부 라이브러리나 병렬 컴퓨팅 없이 Claude-opus-4-8 모델을 사용하여 50단계 내에서 최적화해야 합니다. 최고 점수를 얻은 참가자에게는 닌텐도 스위치가 상품으로 제공됩니다.

## 인상적인 대목
- "오토리서치는 기본적으로 시행착오의 루프입니다." (Autoresearch is basically a loop of trial and errors.)
- "에이전트가 스스로 루프를 실행합니다. 프롬프트와 설정에 훨씬 더 큰 승수입니다." (The agent is running in a loop on its own. So it's a much bigger multiplier on your prompt and your setup.)
- "에이전트가 정체되었을 때, 인간의 아이디어가 돌파구를 열었습니다." (When it stalled, a human idea broke it open.)
- "오토리서치를 이렇게 어려운 문제에 적용하는 것은 '설정하고 잊어버리는' 방식이 아니라 협업입니다." (Running autoresearch on something this hard is less of a set it and forget it, it's a collaboration.)

## 실무 적용 포인트
- **평가 스크립트의 중요성**: 오토리서치 시스템의 핵심은 빠르고, 저렴하며, 노이즈가 적고, 견고한 평가 스크립트를 설계하는 것입니다. 이는 에이전트가 더 많은 아이디어를 효율적으로 탐색하고, 약한 평가를 악용하는 것을 방지하는 데 필수적입니다.
- **인간-AI 협업의 활용**: 에이전트가 정체될 때 인간의 도메인 지식과 직관을 자연어 지침 형태로 제공하여 에이전트의 탐색 방향을 조종하는 것이 중요합니다. 이는 복잡한 문제 해결에서 AI의 한계를 보완하고 새로운 돌파구를 찾는 데 도움이 됩니다.
- **구조화된 탐색 및 관찰 가능성**: 트리 기반 검색을 통해 에이전트의 모든 시도와 코드 변경 사항을 추적하고 시각화하는 것은 디버깅 및 학습에 매우 유용합니다. 이를 통해 에이전트가 왜 특정 결정을 내렸는지 이해하고, 성공적인 아이디어를 기반으로 빌드할 수 있습니다.
- **작고 집중된 변경 사항 시도**: 오토리서치 에이전트에게 한 번에 많은 것을 바꾸기보다 안전 마진, 속도 임계값, 버퍼 조정 등 작고 집중된 코드 변경을 시도하도록 지시하는 것이 효과적일 수 있습니다.
