# Your AI Agent Is Hiding Its Mistakes From You - Ben Holmes, Warp

🔗 https://youtu.be/pz74r-4dGfQ · 📅 2026-11-06 · 🎙 AI Engineer

## 한 줄 요약
Warp의 Ben Holmes는 AI 에이전트가 과거의 작업을 검토하고, LLM 기반의 평가 시스템을 통해 스스로 개선 사항을 제안하여 소프트웨어 개발 공장을 최적화하는 '자기 개선 에이전트'의 개념과 구현 방안을 제시합니다.

## 발표자·소속
Ben Holmes, DevEx Engineering Lead at Warp

## 핵심 주장
*   **AI 에이전트의 자기 개선:** 에이전트는 자신의 과거 작업(대화, 도구 호출, 출력)을 검토하고, 정의된 루브릭에 따라 품질을 평가하며, 실패 원인을 분석하여 스스로 개선 사항을 제안함으로써 지속적으로 성능을 향상시킬 수 있습니다.
*   **중앙 집중식 데이터 저장:** 에이전트의 모든 대화 기록과 메타데이터를 한 곳에 저장하는 것이 중요합니다. 이를 통해 에이전트가 자신의 모든 작업을 추론하고 분석할 수 있는 기반을 마련합니다.
*   **LLM 기반의 품질 평가:** 효율성, 코드 품질, 테스트 커버리지, 장황함 등 다양한 기준에 대한 루브릭을 정의하고, LLM을 '심판'으로 활용하여 에이전트의 작업 품질을 자동으로 평가할 수 있습니다.
*   **자동화된 피드백 루프:** 에이전트의 작업 평가에서 발견된 실패 사례들을 취합하여, 다른 에이전트(자기 개선 에이전트)가 이 실패들을 분석하고 에이전트의 스킬이나 설정에 대한 구체적인 개선 제안(예: PR)을 생성하는 자동화된 피드백 루프를 구축합니다.
*   **성능 대시보드:** 에이전트의 성능 지표(예: 효율성 점수)를 지속적으로 추적하고 시각화하는 대시보드를 통해 개선 사항 적용 전후의 효과를 명확히 확인하고 최적화 노력을 검증할 수 있습니다.

## 세부 내용
발표자는 먼저 소프트웨어 개발 라이프사이클을 자동화하는 '소프트웨어 공장(Software Factory)'의 개념을 소개합니다. 이는 '새로운 작업 할당'부터 '트리아지', '사양 작성', '구현', '검증', '코드 검토', '배포', '사용량 모니터링'까지 이어지는 순환 고리(Inner Loop)로, 각 단계를 AI 에이전트가 수행합니다.

핵심은 이 '이너 루프'를 개선하는 '아우터 루프(Outer Loop)'입니다. 이는 에이전트가 자신의 작업을 '메타 엔지니어링'하여 공장 자체를 개선하는 과정입니다. 아우터 루프는 다음과 같은 단계로 진행됩니다.

1.  **에이전트 대화 검토:** 에이전트가 수행한 모든 대화 기록을 수집하고 저장합니다. 이는 로컬 파일 시스템(예: Claude, Codex)이나 중앙 집중식 저장소(예: Warp의 대화 저장소)에 저장될 수 있습니다. 각 대화 기록에는 트랜스크립트(대화 내용), 도구 호출(에이전트가 수행한 작업), 출력(생성된 코드 등)이 포함됩니다.
2.  **품질 점수 매기기:** LLM을 '심판'으로 활용하여 에이전트 대화의 품질을 평가합니다. 발표자는 세 가지 주요 평가 기준을 제시합니다.
    *   **중복 테스트(Redundant tests):** 에이전트가 불필요하게 많은 테스트를 작성하는지 평가합니다.
    *   **장황함(Verbosity):** 에이전트가 너무 길거나 불필요한 설명을 하는지, 코드 주석이 과도한지 평가합니다. 이는 코드 검토 시간을 늘릴 수 있습니다.
    *   **효율성(Efficiency):** 에이전트가 목표 달성을 위해 불필요한 단계를 거치거나 비효율적인 도구 호출을 하는지 평가합니다. 에이전트는 실패한 도구 호출을 보고하지 않고 스스로 해결하려는 경향이 있어, 이를 추적하는 것이 중요합니다.
    발표자는 `efficiency.md`와 같은 마크다운 형식의 루브릭 파일을 통해 각 기준에 대한 정의, 성공/실패 라벨(점수 포함), 평가 항목(예: 실수로 인한 재작업, 인간에게 드는 비용, 정보 수집, 반복적인 오버헤드, 배치 처리, 실패, 검증 시간)을 상세히 기술하는 방법을 시연합니다.
3.  **실패 격리:** 에이전트의 대화 기록을 평가한 후, 정의된 루브릭 기준에 미달하는 '실패' 사례들을 식별합니다.
4.  **개선 제안:** 매 24시간마다 크론 잡(cron job)을 통해 자기 개선 에이전트가 최근 실패한 대화 기록들을 검토하고 공통점을 찾아 에이전트의 스킬이나 설정 파일에 대한 개선 사항을 제안합니다. 예를 들어, 중복 테스트가 많다면 테스트 작성 스킬에 '커버리지 피라미드' 원칙을 추가하도록 제안할 수 있습니다.

발표자는 Skill Doctor라는 도구를 시연하며, 이 도구가 Codex 세션을 검토하여 에이전트가 잘못된 브랜치에 푸시하거나, `writing-tests` 스킬을 로드하지 못하거나, UI 버그를 놓치는 등의 문제를 발견하는 과정을 보여줍니다. Skill Doctor는 이러한 문제들을 바탕으로 에이전트의 `test-desktop-app/SKILL.md` 파일에 포트 번호 처리 개선 지침을 추가하고, `changelog/SKILL.md` 파일에 변경 로그 작성 언어를 더 명확하게 정의하는 등의 변경 사항을 제안합니다.

마지막으로, 발표자는 이러한 자기 개선 루프를 지속적으로 실행하여 에이전트의 성능 변화를 추적하는 대시보드를 소개합니다. 이 대시보드는 효율성, 코드 품질, 절차 준수, 장황함, 스킬 커버리지 등의 지표를 그래프로 보여주며, 특정 스킬 변경이 에이전트 성능에 미친 영향을 시각적으로 확인할 수 있게 합니다. Warp Factories의 'Self-improvement' 인박스에서는 에이전트가 직접 생성한 PR 목록을 볼 수 있으며, 이는 에이전트가 스스로 문제를 발견하고 해결책을 제안하는 실제 사례들을 보여줍니다.

## 실무 적용 포인트
*   **에이전트 작업 기록 중앙화:** 에이전트가 수행하는 모든 대화, 도구 호출, 파일 시스템 변경, 코드 출력 등을 구조화된 형식(예: JSONL)으로 중앙 저장소에 기록하여 에이전트의 행동을 분석할 수 있는 기반을 마련합니다.
*   **LLM 기반 루브릭 개발:** 에이전트의 성능을 평가할 핵심 지표(예: 효율성, 코드 품질, 장황함, 테스트 중복성)를 식별하고, 각 지표에 대한 구체적인 성공/실패 기준을 담은 마크다운 형식의 루브릭을 작성합니다. 이를 LLM에 프롬프트로 제공하여 에이전트의 작업을 평가하도록 합니다.
*   **자동화된 자기 개선 피드백 루프 구축:** 에이전트의 작업이 완료되거나 PR이 병합될 때마다 자동으로 품질 평가를 수행하고, 실패한 평가 보고서를 자기 개선 에이전트에게 전달하여 에이전트 스킬이나 설정 파일에 대한 개선 PR을 생성하도록 자동화합니다.
*   **성능 대시보드 활용:** 에이전트의 주요 성능 지표를 시계열 그래프로 시각화하는 대시보드를 구축하여, 스킬 변경이나 설정 업데이트가 에이전트의 효율성 및 품질에 미치는 영향을 지속적으로 모니터링하고 검증합니다.
*   **Warp Skill Doctor 활용:** Warp Skill Doctor와 같은 도구를 사용하여 기존 에이전트의 대화 기록을 분석하고 개선 기회를 식별하는 일회성 또는 주기적인 평가를 수행하여, 에이전트 성능 최적화를 위한 '로우 행잉 프루트'를 찾아냅니다.
