## 한 줄 요약
Skill Engineering은 대규모 언어 모델(LLM)의 한계를 극복하고 신뢰할 수 있는 AI 애플리케이션을 구축하기 위해 외부 도구, 지식, 논리를 LLM과 결합하는 체계적인 엔지니어링 접근 방식입니다.

## 핵심 주장
*   **LLM은 강력하지만 신뢰성 부족:** 대규모 언어 모델(LLM)은 뛰어난 능력을 가졌지만, 환각, 상태 및 맥락 부족, 복잡한 추론의 어려움, 도구 사용의 한계 등으로 인해 신뢰할 수 있는 애플리케이션 구축에 어려움이 있습니다.
*   **Skill Engineering은 LLM의 신뢰성 확보를 위한 핵심:** Skill Engineering은 LLM을 외부 도구, 지식, 논리와 결합하여 AI가 특정 작업을 안정적으로 수행하도록 만드는 엔지니어링 분야입니다. 이는 단순한 프롬프트 엔지니어링을 넘어선 체계적인 접근 방식입니다.
*   **"스킬"은 재사용 가능하고 신뢰할 수 있는 단위:** 스킬은 단순한 함수가 아니라, 명확한 입력, 출력, 오류 처리를 가지며 LLM이 호출하도록 설계된 신뢰할 수 있고 재사용 가능하며 조합 가능한 기능 단위입니다. 이를 통해 LLM은 외부 세계와 상호작용할 수 있습니다.
*   **구조화된 출력과 오류 처리가 중요:** LLM이 도구를 호출할 때 JSON과 같은 구조화된 형식으로 출력을 강제하고, 도구 호출 및 LLM 응답에서 발생할 수 있는 오류에 대한 강력한 처리 및 재시도 로직을 구현하는 것이 신뢰성 있는 시스템 구축에 필수적입니다.
*   **고급 기법으로 복잡한 문제 해결:** 자기 수정(Self-Correction), 다단계 추론(Chaining), 병렬 도구 호출(Parallel Tool Calls), 인간 개입(Human-in-the-Loop) 등과 같은 고급 기법들을 활용하여 LLM의 한계를 극복하고 더욱 복잡하고 견고한 AI 시스템을 구축할 수 있습니다.

## 세부 내용
발표는 대규모 언어 모델(LLM)의 강력한 능력에도 불구하고, 환각(hallucinations), 상태 및 맥락 부족, 복잡한 추론의 어려움, 외부 도구 사용의 한계 등으로 인해 신뢰할 수 있는 AI 애플리케이션을 구축하기 어렵다는 문제 제기로 시작합니다. 발표자는 이러한 문제를 해결하기 위한 "Skill Engineering"이라는 개념을 소개합니다.

**Skill Engineering의 정의:**
Skill Engineering은 LLM을 외부 도구, 지식, 논리와 결합하여 AI가 원하는 바를 안정적으로 수행하도록 만드는 엔지니어링 분야입니다. 이는 단순한 프롬프트 엔지니어링을 넘어, LLM을 "뇌"로 보고 외부 "몸"과 "감각"을 제공하여 실제 세계와 상호작용하게 하는 접근 방식입니다. 여기서 "스킬(Skill)"은 명확한 입력, 출력, 오류 처리를 가지며 LLM에 의해 호출되도록 설계된 신뢰할 수 있고 재사용 가능하며 조합 가능한 기능 단위를 의미합니다.

**LLM의 주요 한계:**
*   **환각(Hallucinations):** 사실이 아닌 정보를 생성합니다.
*   **상태 및 맥락 부족(Lack of State/Context):** 이전 대화나 외부 정보를 기억하지 못합니다.
*   **추론의 어려움(Lack of Reasoning):** 복잡한 논리나 계산에 취약합니다.
*   **도구 사용의 한계(Lack of Tool Use):** 외부 도구를 직접 사용하거나 결과를 해석하는 데 어려움이 있습니다.

**Skill Engineering의 핵심 원칙:**
1.  **명확한 스킬 정의:** 각 스킬은 단일 목적을 가지며, 명확한 입력과 출력을 정의합니다.
2.  **구조화된 출력:** LLM이 도구를 호출할 때 JSON, XML과 같은 특정 형식으로 출력을 강제하여 파싱 및 실행을 용이하게 합니다. Pydantic과 같은 라이브러리를 활용하여 스키마 유효성 검사를 수행할 수 있습니다.
3.  **오류 처리 및 재시도:** LLM의 응답이나 도구 실행에서 발생할 수 있는 오류를 예측하고, 재시도, 대체 로직 등을 구현하여 시스템의 견고성을 높입니다.
4.  **관찰 가능성(Observability):** LLM의 결정 과정, 스킬 호출, 결과 등을 상세히 로깅하여 문제 발생 시 원인을 파악하고 디버깅할 수 있도록 합니다.
5.  **인간 개입(Human-in-the-Loop):** 중요한 결정이나 모호한 상황에서는 인간의 검토나 승인을 거치도록 설계합니다.
6.  **테스팅:** 스킬 단위 테스트 및 오케스트레이터와 스킬 간의 통합 테스트를 통해 시스템의 정확성을 보장합니다.
7.  **버전 관리:** 스킬을 일반 코드처럼 버전 관리하여 변경 사항을 추적하고 협업을 용이하게 합니다.

**예시: 여행 계획 AI**
발표자는 "여행 계획 AI"를 예시로 들어 Skill Engineering의 작동 방식을 설명합니다.
*   **필요한 스킬:** `search_flights(origin, destination, date)`, `search_hotels(location, check_in, check_out, guests)`, `book_flight(...)`, `book_hotel(...)`, `get_weather(location, date)` 등.
*   **오케스트레이션:** 사용자가 "다음 달 파리로 여행 계획을 세워줘"라고 요청하면, LLM(오케스트레이터)은 이 요청을 분석하여 `search_flights`와 `search_hotels` 스킬을 호출하도록 결정합니다. 스킬 실행 결과를 바탕으로 LLM은 사용자에게 정보를 제공하고, 사용자의 확인을 받아 `book_flight` 및 `book_hotel` 스킬을 호출합니다.

**고급 기법 ("Dark Arts"):**
*   **자기 수정(Self-Correction/Reflection):** LLM이 자신의 출력이나 도구 호출 결과를 검토하고, 오류가 발견되면 이를 수정하여 다시 시도하도록 하는 기법입니다. 예를 들어, 잘못된 날짜 형식으로 항공편 검색 스킬을 호출했을 때, 오류 메시지를 받아 다시 올바른 형식으로 호출하는 방식입니다.
*   **다단계 추론(Chaining):** 복잡한 작업을 여러 개의 작은 스킬 호출 단계로 나누어 순차적으로 실행함으로써 복잡한 논리를 처리합니다.
*   **병렬 도구 호출(Parallel Tool Calls):** 독립적으로 실행될 수 있는 여러 스킬을 동시에 호출하여 처리 속도를 높입니다.
*   **인간 피드백 루프(Human Feedback Loops):** AI의 결정에 대한 인간의 피드백을 시스템에 통합하여 지속적으로 개선합니다.
*   **동적 도구 발견(Dynamic Tool Discovery):** LLM이 사용자 질의에 따라 적절한 스킬을 동적으로 찾아 사용하도록 합니다.
*   **맥락 관리(Context Management):** LLM의 제한된 컨텍스트 윈도우를 효율적으로 관리하기 위해 요약, 검색 증강 생성(RAG) 등의 기법을 사용합니다.
*   **가드레일(Guardrails):** 원치 않거나 유해한 AI의 행동을 방지하기 위한 입력 유효성 검사 및 출력 필터링 메커니즘을 구현합니다.

발표는 Skill Engineering이 신뢰할 수 있고 견고하며 제어 가능한 AI 애플리케이션을 구축하기 위한 필수적인 엔지니어링 분야임을 강조하며 마무리됩니다.

## 실무 적용 포인트
*   **스킬 기반 아키텍처 설계:** AI 애플리케이션을 개발할 때, LLM이 직접 모든 것을 처리하게 하기보다, 명확한 입력/출력을 가진 재사용 가능한 '스킬' 단위로 기능을 분리하고 정의하여 시스템의 모듈성과 신뢰성을 높입니다.
*   **구조화된 도구 호출 구현:** LLM이 외부 도구를 호출할 때, JSON 스키마와 같은 구조화된 형식으로 출력을 강제하고, Pydantic 같은 라이브러리를 사용하여 스키마 유효성 검사를 수행함으로써 도구 호출의 안정성을 확보합니다.
*   **강력한 오류 처리 및 재시도 로직:** LLM의 응답이나 외부 스킬 실행에서 발생할 수 있는 오류를 예측하고, 적절한 재시도 메커니즘, 대체 스킬, 또는 사용자에게 피드백을 요청하는 로직을 구현하여 시스템의 견고성을 강화합니다.
*   **관찰 가능성(Observability) 확보:** LLM의 추론 과정, 스킬 호출 시점, 입력/출력, 오류 발생 여부 등을 상세히 로깅하여 시스템의 동작을 이해하고 문제 발생 시 신속하게 원인을 파악하고 디버깅할 수 있도록 준비합니다.
