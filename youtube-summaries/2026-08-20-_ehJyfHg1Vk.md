## 핵심 주장
- **단일 모델의 한계와 복합 시스템의 필요성**: 단일 대규모 언어 모델(LLM)은 강력하지만, 특정 도메인 지식 부족, 환각 현상, 최신 정보 반영의 어려움 등 고유한 한계를 가집니다. 복합 엔지니어링은 이러한 한계를 극복하기 위해 LLM을 코어로 삼아 검색 증강 생성(RAG), 전문 모델, 외부 API 등 다양한 컴포넌트를 결합하는 접근 방식이 필수적임을 주장합니다.
- **복합 엔지니어링의 정의 및 구성 요소**: 복합 엔지니어링은 단순히 여러 모델을 사용하는 것을 넘어, 각 컴포넌트가 특정 작업을 수행하도록 설계하고, 이들을 지능적으로 오케스트레이션하여 더 크고 복잡한 문제를 해결하는 시스템을 구축하는 것입니다. 이는 LLM, 벡터 데이터베이스, 검색 엔진, 전문 모델, 외부 API, 그리고 이들을 연결하는 에이전트 프레임워크 등으로 구성됩니다.
- **에이전트 기반 시스템의 중요성**: 발표자는 복합 시스템의 핵심으로 '에이전트'를 강조했습니다. 에이전트는 주어진 목표를 달성하기 위해 스스로 계획을 세우고, 적절한 도구를 선택하여 실행하며, 결과를 평가하고 반복하는 능력을 가집니다. 이는 시스템이 동적으로 변화하는 환경에 적응하고, 복잡한 다단계 작업을 수행할 수 있게 합니다.
- **평가 및 모니터링의 복잡성 및 중요성**: 단일 모델과 달리 복합 시스템은 여러 컴포넌트의 상호작용으로 인해 디버깅과 성능 평가가 훨씬 복잡합니다. 발표자는 각 컴포넌트의 성능뿐만 아니라 전체 시스템의 엔드투엔드 성능, 견고성, 비용 효율성 등을 종합적으로 평가하고 지속적으로 모니터링하는 것이 성공적인 복합 시스템 구축에 매우 중요하다고 역설했습니다.

## 세부 내용
발표는 단일 대규모 언어 모델(LLM)의 등장으로 AI의 가능성이 크게 확장되었지만, 실제 비즈니스 문제 해결에는 여전히 한계가 있음을 지적하며 시작되었습니다. 발표자는 LLM이 일반적인 추론 능력은 뛰어나지만, 특정 사실에 대한 정확성, 최신 정보 반영, 복잡한 계산 수행, 외부 시스템과의 상호작용 등에서 부족함을 보인다고 설명했습니다.

이러한 한계를 극복하기 위해 '복합 엔지니어링(Compound Engineering)'이라는 새로운 패러다임을 제시했습니다. 복합 엔지니어링은 LLM을 '두뇌'로 활용하되, 그 주변에 다양한 '도구'와 '전문가'를 배치하여 하나의 강력한 시스템을 구축하는 접근 방식입니다. 발표자는 이를 마치 오케스트라의 지휘자와 각 악기 연주자에 비유하며, LLM이 전체 흐름을 지휘하고 각 도구가 특정 전문 기능을 수행한다고 설명했습니다.

세부 아키텍처로는 다음과 같은 구성 요소를 제시했습니다.
1.  **대규모 언어 모델(LLM)**: 시스템의 핵심 추론 엔진이자 의사 결정자. 사용자 질의를 이해하고 다음 행동을 계획합니다.
2.  **검색 증강 생성(RAG) 시스템**: 외부 지식 베이스(예: 벡터 데이터베이스)에서 관련 정보를 검색하여 LLM의 답변을 보강합니다. 이를 통해 LLM의 환각을 줄이고 최신 정보를 반영할 수 있습니다.
3.  **전문 모델(Specialized Models)**: 특정 작업을 위해 훈련된 소형 모델(예: 감성 분석 모델, 이미지 인식 모델, 번역 모델). LLM이 직접 수행하기 비효율적이거나 성능이 떨어지는 작업을 담당합니다.
4.  **외부 API 및 도구**: 데이터베이스 조회, 웹 검색, 계산기, 예약 시스템, CRM 등 외부 시스템과 상호작용하여 실제 세계의 작업을 수행합니다.
5.  **에이전트 프레임워크**: LLM이 이러한 다양한 도구와 상호작용하고, 다단계 작업을 계획하고 실행하며, 결과를 평가하고 수정하는 과정을 관리하는 소프트웨어 계층입니다. 발표자는 LangChain이나 LlamaIndex와 같은 프레임워크가 이러한 에이전트 구축에 유용하다고 언급했습니다.

발표자는 가상의 고객 서비스 챗봇 데모를 통해 복합 엔지니어링의 작동 방식을 시연했습니다. 사용자가 "내 주문 상태를 알려줘"라고 질문하면, 에이전트 LLM은 이를 '주문 조회' 의도로 파악하고, '주문 조회 API' 도구를 호출합니다. API로부터 받은 정보를 다시 LLM이 사용자 친화적인 언어로 가공하여 답변합니다. 만약 "최근 AI 기술 동향은?"과 같은 질문이 오면, 에이전트는 '웹 검색 도구'나 'RAG 시스템'을 활용하여 최신 정보를 찾아 답변하는 식입니다. 이 과정에서 에이전트는 도구 호출 실패 시 재시도하거나 다른 도구를 시도하는 등 유연하게 대응하는 모습을 보였습니다.

또한, 발표자는 복합 시스템의 개발 및 운영에 있어 '평가(Evaluation)'와 '모니터링(Monitoring)'의 중요성을 강조했습니다. 단일 모델의 평가와 달리, 복합 시스템은 각 컴포넌트의 성능뿐만 아니라 컴포넌트 간의 상호작용, 전체 워크플로우의 성공률, 지연 시간, 비용 등을 종합적으로 고려해야 한다고 설명했습니다. 이를 위해 A/B 테스트, 골든 데이터셋 구축, 자동화된 평가 파이프라인 구축 등이 필요하다고 덧붙였습니다.

마지막으로, 복합 엔지니어링은 AI 시스템을 더욱 강력하고 유연하며 신뢰할 수 있게 만들 미래 AI 개발의 핵심 패러다임이 될 것이라고 전망하며 발표를 마쳤습니다.

## 실무 적용 포인트
-   **모듈화된 AI 시스템 설계**: 처음부터 단일 모델에 모든 기능을 넣으려 하기보다, LLM을 핵심 추론 엔진으로 두고 특정 기능(검색, 계산, 외부 API 연동 등)은 별도의 모듈이나 도구로 분리하여 설계하는 접근 방식을 채택해야 합니다.
-   **에이전트 프레임워크 적극 활용**: LangChain, LlamaIndex 등 에이전트 기반 프레임워크를 사용하여 LLM이 여러 도구를 유연하게 호출하고 복잡한 워크플로우를 자동화하는 시스템을 구축하는 연습을 시작해야 합니다.
-   **RAG(검색 증강 생성) 시스템 도입**: LLM의 환각을 줄이고 최신 정보를 반영하기 위해 사내 문서, 데이터베이스, 웹 등에서 정보를 검색하여 LLM에 제공하는 RAG 시스템을 구축하는 것을 우선적으로 고려해야 합니다.
-   **복합 시스템 평가 및 모니터링 전략 수립**: 단일 지표가 아닌, 각 컴포넌트의 성능, 엔드투엔드 성공률, 지연 시간, 비용 등 다각적인 관점에서 시스템을 평가하고 지속적으로 모니터링할 수 있는 체계를 미리 계획하고 구축해야 합니다.
