## 세부 내용
발표자는 "The Research Desk"라는 UI에서 Google과 Microsoft에 대한 분석을 요청하는 데모를 시작합니다. 메인 에이전트는 먼저 기존 메모리에 두 회사에 대한 정보가 있는지 확인합니다. 정보가 없으면, `dispatch_analytic('tickers', ["GOOGL", "MSFT"])`라는 커스텀 툴을 호출하여 Google과 Microsoft 각각에 대해 개별 세션을 시작합니다. 이 과정은 여러 에이전트가 협력하여 작업을 수행하는 "멀티 세션 하네스"를 보여줍니다. 각 세션 내에서도 여러 에이전트가 협업하며, 자체 감독 메커니즘과 메모리 저장소를 통해 서로 학습합니다.

이어서 발표자는 반복적인 작업을 위한 "배포(Deployments)" 기능을 소개합니다. 배포는 에이전트 정의, 환경, 메모리 저장소, 실행 스케줄(예: 매월 첫째 날 오전 1시 UTC) 및 초기 메시지를 포함합니다. 사용자는 Claude Console에서 배포를 수동으로 실행하거나, API를 통해 커스텀 워크플로우를 구축할 수 있습니다.

다음으로 "Dreams"라는 프리뷰 기능이 시연됩니다. Dreams는 에이전트가 최근 트랜스크립트를 분석하여 기존 메모리를 정리하고 새로운 학습을 도출하는 자기 개선 메커니즘입니다. 데모에서는 특정 메모리 저장소와 Claude 3.0 모델을 선택하고, 지난 30일간의 세션 기록을 Dreams 기능으로 분석합니다. Dreams는 에이전트의 스킬(skill)에 존재하는 격차를 발견하고, 메모리 저장소를 업데이트하여 에이전트가 해당 지식을 확장하도록 지시합니다. 이는 에이전트가 스스로 문제를 인식하고 개선하는 과정을 보여줍니다.

Q&A 세션에서는 여러 질문이 오갔습니다.
*   **텔레메트리/관찰 가능성**: 발표자는 Claude Console이 에이전트 세션 내의 모든 이벤트를 상세히 기록하며, API를 통해 모든 이벤트에 접근할 수 있다고 설명합니다. 이를 통해 모델 호출 시작/종료 시간 등 상세한 성능 지표를 확인할 수 있습니다.
*   **에이전트 실행 기간**: 에이전트는 무기한으로 실행될 수 있으며, 플랫폼이 메모리 압축(compaction)을 자동으로 처리하여 장기 실행을 지원합니다.
*   **오케스트레이션**: 현재는 서브 에이전트를 통해 오케스트레이션을 구현하며, Claude가 최적의 토폴로지를 스스로 결정하도록 하는 것이 더 나은 성능을 보인다고 언급합니다.
*   **신뢰성 및 평가(Evals)**: 에이전트의 성능을 평가하기 위해 Evals를 실행하고, "outcomes"를 정의하여 에이전트가 특정 목표를 달성하도록 유도하는 것이 권장됩니다. Dreams 기능은 Evals를 통해 에이전트의 성능 개선에 기여합니다.
*   **온프레미스/멀티테넌시**: 멀티테넌시(Multi-tenancy)는 워크스페이스(Workspaces)를 통해 관리되며, 세분화된 접근 제어(RBAC) 기능은 로드맵에 있습니다.
*   **모델 제한**: 현재는 Anthropic의 Claude 모델만 지원됩니다.
*   **Cloud Code vs. Managed Agents**: Cloud Code는 터미널 기반의 도구인 반면, Managed Agents는 API 기반의 제품으로, 인프라 관리 및 확장성에 중점을 둡니다.
