# AI That Hunts Logic Bugs Before Attackers Do - Taylor Luttrell-Williams, Sonar

🔗 https://youtu.be/UW8Qkk7MG8A · 📅 2026-10-28 · 🎙 AI Engineer

## 한 줄 요약
SonarQube Hunter Agent는 AI 기반 보안 에이전트로, 기존 SAST 도구가 놓치는 의도 기반의 비즈니스 로직 취약점을 탐지하고, OpenAI의 첨단 사이버 보안 모델을 통합하여 개발자들이 공격자보다 먼저 취약점을 해결할 수 있도록 돕는다.

## 발표자·소속
테일러 루트렐-윌리엄스(Taylor Luttrell-Williams), Sonar (Makers of SonarQube)

## 핵심 주장
- **AI 생성 코드의 취약점 증가:** AI 에이전트가 코드를 기계 속도로 대량 생성하면서, 전례 없는 수의 취약점이 프로덕션 환경에 도달하고 있어 기업들이 위협에 노출되고 있다.
- **기존 SAST의 한계 극복:** 전통적인 패턴 기반 SAST(Static Application Security Testing) 도구는 코드의 버그를 찾는 데는 효과적이지만, 의도 기반의 비즈니스 로직 취약점(예: 권한 상승, 비즈니스 로직 오용, 접근 제어 오류)은 탐지하지 못한다.
- **SonarQube Hunter Agent의 역할:** Hunter Agent는 코드베이스를 전역적으로 매핑하고, 보안 연구원처럼 관계를 분석하여 이러한 의도 기반의 논리적 결함을 찾아낸다. 탐지된 모든 잠재적 취약점은 표면화되기 전에 검증 과정을 거친다.
- **OpenAI Daybreak 프로그램 통합:** Sonar는 OpenAI Daybreak 사이버 파트너 프로그램에 참여하여, Hunter Agent에 고급 사이버 보안 프론티어 모델을 통합함으로써 공격자보다 빠르게 움직이는 보안 위협에 대응할 수 있는 최첨단 인텔리전스를 제공한다.
- **통합된 보안 플랫폼:** Hunter Agent의 발견 사항은 기존 SonarQube 이슈와 함께 표시되어, 개발자들이 익숙한 환경에서 취약점의 심각도, 영향, 정확한 위치를 파악하고, 필요시 자동화된 방식으로 해결할 수 있도록 지원한다.

## 세부 내용

발표는 AI 생성 코드의 증가로 인한 보안 취약점의 급증 문제로 시작한다. AI 에이전트가 코드를 기계 속도로 대량 생산하면서, 기존의 패턴 기반 SAST 도구로는 탐지하기 어려운 새로운 유형의 취약점들이 발생하고 있다. 발표자는 이러한 취약점들이 코드 자체의 버그라기보다는 비즈니스 로직의 의도와 관련된 문제라고 설명한다. 예를 들어, `InvoiceController.java` 파일에서 `findbyId(id)` 메서드가 테넌트(tenant) 체크 없이 인보이스를 반환할 경우, 테넌트 A 사용자가 테넌트 B의 인보이스를 읽을 수 있게 되는 '누락된 권한 부여(missing authorization)'와 같은 취약점이다. 이러한 취약점은 코드가 문법적으로 유효하더라도 비즈니스 로직의 의도가 잘못된 경우에 발생한다.

기존의 SAST 도구는 주입(Injection), 하드코딩된 비밀(Hard-coded secret), 알려진 CVE(Common Vulnerabilities and Exposures)와 같은 패턴 기반의 취약점은 잘 탐지하지만, 의도 기반의 취약점은 놓친다. 또한, 많은 기업에서 침투 테스트(Pentest)는 1년에 두 번 정도 진행되는데, 그 사이 AI가 생성하는 코드는 지속적으로 배포되어 '미확인 상태로 배포(shipped unchecked)'되는 기간이 길어지면서 공격에 취약해진다.

이러한 격차를 해소하기 위해 SonarQube Hunter Agent가 소개된다. Hunter Agent는 보안 연구원처럼 취약점을 탐지한다.
1.  **탐지(Hunt):** 먼저 코드 저장소를 전역적으로 매핑하여 모든 구성 요소 간의 관계를 파악한다. 이 글로벌 맵을 기반으로 세 가지 특수 에이전트(각각 특정 유형의 취약점 클래스에 특화)를 실행하여 잠재적인 취약점 '리드(lead)'를 찾는다.
2.  **확인(Confirm):** 탐지된 모든 리드는 표면화되기 전에 검증 과정을 거친다. 이는 '적대적 검증(adversarial validation)'을 통해 실제 취약점인지 확인하고, '노이즈 게이트(noise gates)'를 통해 의도적인 설계로 인한 낮은 유효성 이슈나 오탐(false positive)을 걸러낸다.
3.  **설명(Explain):** 검증된 취약점에 대해 심각도(Severity), 영향(Impact), 정확한 위치(Exact location)를 제공한다. 예를 들어, '사용자 제어 키를 통한 권한 우회(Authorization bypass through user-controlled key)'와 같은 취약점은 '높음(High)' 심각도로 분류되며, 해당 코드 라인과 함께 "어떤 사용자가 다른 테넌트의 인보이스를 읽을 수 있다"는 설명이 제공된다.

Hunter Agent의 발견 사항은 기존 SonarQube 이슈 목록에 통합된다. 개발자는 새로운 대시보드로 이동할 필요 없이 익숙한 SonarQube UI에서 Hunter Agent가 탐지한 취약점을 확인할 수 있다. 각 이슈는 'Hunter Agent' 태그와 함께 해당 취약점 클래스(예: Broken Access Control)로 분류된다.

발표자는 공격자들이 점점 더 빠르게 움직이고 있으며, 취약점이 발견되어 악용되기까지의 시간이 줄어들고 있음을 강조한다. 이러한 '프론티어 AI(Frontier AI)' 시대에 대응하기 위해 Sonar는 OpenAI Daybreak 사이버 파트너 프로그램에 참여하여, SonarQube Hunter Agent에 고급 사이버 보안 프론티어 모델을 통합했다. 이 협력을 통해 Hunter Agent는 코드베이스 전반에 걸쳐 정밀하고, 반복 가능하며, 감사 가능한 '프론티어 추론(Frontier reasoning)'을 제공한다.

데모에서는 SonarQube Cloud 대시보드에서 Hunter Agent 기능을 보여준다.
*   Hunter Agent 메뉴에서 프로젝트의 '최신 스캔 결과'를 확인할 수 있다.
*   '스캔 시작(Scan now)' 버튼을 클릭하여 온디맨드 스캔을 실행할 수 있으며, 스캔에는 프로젝트의 크기와 복잡성에 따라 약 1시간이 소요될 수 있다.
*   스캔 과정은 코드 복제(Cloning), 분석(Analyzing), 스캔(Scanning), 통합(Consolidating), 보고(Reporting)의 단계로 진행된다.
*   데모 프로젝트에서는 'Broken Access Control' 14개, 'Business Logic' 5개, 'Authentication & Session' 27개의 총 46개 취약점이 발견되었다.
*   'Broken Access Control' 이슈 중 하나를 클릭하면, 해당 코드 라인과 함께 "어떤 로그인된 사용자도 관리자 접근 권한을 통과할 수 있다. 왜냐하면 그들은 그들 자신의 역할 필드를 쓸 수 있기 때문이다."라는 설명이 제공된다. 또한, "이것이 왜 문제인가?", "어떻게 고칠 수 있는가?"에 대한 상세한 설명과 수정 가이드라인이 제시된다.
*   이슈는 기본적으로 '열림(Open)' 상태이며, 개발자는 이를 '수락(Accept)'하거나 '오탐(False Positive)'으로 표시할 수 있다.
*   Hunter Agent는 일별, 주별, 월별로 스캔 일정을 구성할 수 있으며, 특정 브랜치만 스캔하도록 설정할 수도 있다.
*   SonarQube Remediate Agent를 통해 이러한 취약점을 자동으로 수정할 수 있는 기능도 제공될 예정이다.

결론적으로 SonarQube Hunter Agent는 SAST 및 SCA(Software Composition Analysis)와 함께 단일 플랫폼에서 다계층 검증을 제공하여, 200개 이상의 0-day 취약점을 90%의 정밀도로 반복적으로 탐지할 수 있는 '설계에 의한 계층형 보안(Layered security by design)'을 구현한다.

## 인상적인 대목
- "Not all vulnerabilities are bugs in your code. The code is valid. The intent is not." (모든 취약점이 코드의 버그는 아니다. 코드는 유효하다. 의도가 그렇지 않다.)
- "Hunt before you're hunted." (사냥당하기 전에 사냥하라.)
- "Attackers are moving faster. The window keeps closing." (공격자들은 더 빠르게 움직인다. 창은 계속 닫히고 있다.)

## 실무 적용 포인트
- **AI 생성 코드 보안 강화:** AI가 생성하는 코드의 양과 속도를 고려하여, 기존 SAST 도구가 놓치는 비즈니스 로직 및 의도 기반 취약점 탐지 솔루션 도입을 고려해야 한다.
- **다계층 보안 전략:** 패턴 기반 SAST와 더불어 Hunter Agent와 같은 의도 기반 분석 도구를 함께 사용하여, 코드의 모든 측면에서 취약점을 포괄적으로 탐지하는 다계층 보안 전략을 구축한다.
- **자동화된 취약점 관리:** Hunter Agent가 제공하는 심각도, 영향, 정확한 위치 정보를 활용하여 개발팀이 취약점을 효율적으로 분류하고 해결할 수 있도록 워크플로우를 자동화한다.
- **지속적인 보안 검증:** 온디맨드 및 정기 스캔 기능을 활용하여 코드 배포 주기와 관계없이 지속적으로 취약점을 모니터링하고, 공격자가 악용하기 전에 선제적으로 대응한다.
