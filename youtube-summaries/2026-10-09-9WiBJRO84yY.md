# Building on the Codex Harness — Dominik Kundel, OpenAI

🔗 https://youtu.be/9WiBJRO84yY · 📅 2026-10-09 · 🎙 AI Engineer

## 한 줄 요약

## 발표자·소속
Dominik Kundel, OpenAI (Developer Experience)

## 핵심 주장
- **Codex 앱 서버는 Codex 하네스를 감싸는 오픈 소스 JSON-RPC 프로토콜입니다.** 이 프로토콜은 Codex 데스크톱 앱, TUI/CLI, SSH 연결과 같은 OpenAI의 자체 제품뿐만 아니라 JetBrains IDE, VS Code, Xcode 등 타사 통합에도 활용됩니다.
- **개발자는 앱 서버를 통해 에이전트의 동작을 깊이 있게 제어하고 커스터마이징할 수 있습니다.** 120가지 이상의 클라이언트 요청 유형을 노출하며, `developerInstructions`를 사용하여 시스템 프롬프트를 확장하고, `dynamicTools`를 지연 로딩하여 컨텍스트 창을 오염시키지 않으면서 에이전트에 새로운 기능을 추가할 수 있습니다.
- **앱 서버는 유연한 배포 및 통합 옵션을 제공합니다.** Codex CLI의 일부로 제공되어 로컬에서 실행하거나, Python SDK를 통해 쉽게 통합할 수 있으며, 심지어 Codex 자체에 지시하여 앱 서버를 기반으로 애플리케이션을 구축할 수도 있습니다.
- **자체 Codex 하네스 버전을 배포하고 `developerInstructions`를 사용하는 것이 권장됩니다.** 이는 사용자 시스템의 CLI 버전 의존성 문제를 해결하고, OpenAI가 최적화한 기본 프롬프트를 활용하면서도 특정 클라이언트 요구사항에 맞게 에이전트를 맞춤 설정할 수 있도록 합니다.

## 세부 내용
발표는 AI 엔지니어링 컨퍼런스에 대한 소개와 함께 시작되었습니다. 도미닉 쿤델은 청중에게 에이전트 하네스를 직접 구축해본 경험이나 구축에 대한 부담감을 느끼는지 물으며 강연의 주제를 제시했습니다.

그는 Codex 앱 서버가 Codex 하네스를 감싸는 프로토콜이라고 설명했습니다. 이는 에이전트 클라이언트 프로토콜(ACP)과 유사한 개념으로, 클라이언트 애플리케이션이 Codex 하네스와 직접 통신할 수 있도록 합니다. Codex 하네스와 앱 서버 모두 Apache 2 라이선스 하에 오픈 소스로 제공되며, GitHub 저장소를 통해 접근할 수 있습니다. 이를 통해 개발자는 LM Studio나 Ollama와 같은 다른 모델 제공업체와도 연결할 수 있습니다.

앱 서버 아키텍처는 JSON-RPC 스타일의 프로토콜을 사용합니다. OpenAI의 Codex 데스크톱 앱, TUI/CLI, SSH 연결과 같은 자체 제품은 물론, JetBrains IDE, VS Code, Xcode와 같은 타사 통합도 이 앱 서버를 통해 Codex 하네스와 통신합니다. 도미닉은 Theos T3 Code나 Remotex와 같은 오픈 소스 프로젝트도 이 앱 서버를 활용한다고 덧붙였습니다.

JSON-RPC 프로토콜의 작동 방식을 설명하기 위해, 그는 Codex 앱과 앱 서버 간의 실시간 이벤트 흐름을 보여주는 "Inspector"라는 도구를 시연했습니다. 이 도구는 `config/load`, `app/list`, `thread/started`, `item/agentMessage`, `item/completed` 등 다양한 요청 및 이벤트와 그에 따른 JSON 페이로드를 표시했습니다. 그는 앱 서버가 앱의 핵심 기능(스트리밍, 파일 검색 등)을 깊이 있게 노출하여 개발자가 에이전트의 목표, 메모리, 플러그인, 샌드박스 제어 등 120가지 이상의 클라이언트 요청 유형을 제어할 수 있다고 강조했습니다. 또한, ChatGPT 로그인 지원을 통해 사용자가 자신의 구독을 가져오거나 API 인증을 사용할 수 있다고 언급했습니다.

에이전트 커스터마이징에 대한 섹션에서는 `developerInstructions`와 `baseInstructions`를 사용하여 프롬프트를 재정의하는 방법을 설명했습니다. `developerInstructions`는 기존 시스템 프롬프트에 지침을 추가하는 반면, `baseInstructions`는 전체 지침을 재정의합니다. 그는 OpenAI가 모델에 맞게 프롬프트를 조정하는 데 들인 노력을 활용하기 위해 `developerInstructions`를 사용하는 것을 권장했습니다. 또한, `dynamicTools`를 사용하여 클라이언트를 위한 동적 도구를 정의하고, 이를 지연 로딩하여 컨텍스트 창을 불필요하게 오염시키지 않으면서 에이전트가 필요할 때 도구를 검색하도록 할 수 있다고 설명했습니다. 모델 제공업체 변경, 샌드박스 동작(네트워크 연결, 파일 시스템 접근) 제어 등 다양한 구성을 스레드별로 제어할 수 있습니다.

앱 서버 사용법에 대해, 그는 앱 서버가 Codex CLI의 일부로 제공된다고 설명하며 `codex app-server --version` 명령을 통해 확인할 수 있음을 보여주었습니다. `codex app-server --help` 명령은 `daemon`, `proxy`, `generate-ts`, `generate-json-schema` 등 다양한 명령어를 보여주며, 특히 TypeScript 바인딩과 JSON 스키마를 생성하는 기능은 프로토콜이 버전 간에 자주 변경될 수 있으므로 유용하다고 강조했습니다. 앱 서버는 표준 입출력(STDIO) 또는 웹소켓을 통해 실행될 수 있습니다.

통합 옵션으로는 Python SDK와 Codex에 직접 요청하는 두 가지 방법을 제시했습니다. Python SDK는 앱 서버의 라이프사이클 관리를 추상화하고, ChatGPT 로그인과 같은 편리한 인증 흐름을 제공합니다. 두 번째 옵션은 Codex 자체에 지시하여 애플리케이션을 구축하는 것으로, 그는 "Build macOS Apps" 플러그인을 사용하여 iMessage 스타일의 메뉴바 채팅 앱을 만들도록 Codex에 요청하는 시나리오를 보여주었습니다.

가장 인상적인 대목으로, 그는 "Be creative!"라는 슬라이드와 함께 Codex를 *둠(Doom)* 게임 내에서 실행하는 라이브 데모를 선보였습니다. 일렉트론 앱이 클라우드플레어의 둠 WASM 렌더러를 사용하여 둠 게임을 실행하고, 게임 내 터미널에서 Codex 앱 서버와 상호작용하는 모습을 보여주었습니다. "hello" 메시지에 Codex가 응답하고, "give me max health and armor" 명령에 따라 게임 내 체력과 방어구가 증가하며, "what's the dir" 명령에 현재 작업 디렉토리를 출력하는 등 게임 내에서 Codex가 동적으로 도구를 호출하고 명령을 실행하는 것을 시연했습니다. 이는 앱 서버가 단순한 채팅 인터페이스를 넘어 다양한 창의적인 방식으로 통합될 수 있음을 보여주었습니다.

마지막으로, 그는 앱 서버 사용 팁을 요약했습니다. `codex exec` 명령은 비대화형 스크립팅(예: CI/CD 파이프라인에서 PR 자동 수정)에 적합하지만, 더 포괄적인 클라이언트를 구축하거나 여러 Codex 스레드를 병렬화할 때는 앱 서버가 더 효과적이라고 설명했습니다.

## 실무 적용 포인트
- **자체 Codex 하네스 복사본 배포:** 사용자 시스템의 CLI 버전에 의존하지 않고, 애플리케이션과 함께 Codex 하네스 바이너리를 번들로 제공하여 버전 불일치 및 호환성 문제를 방지합니다.
- **동적 도구는 지연 로딩(deferred)으로 주입:** 에이전트에 새로운 기능을 추가할 때, 모든 도구를 시스템 프롬프트에 직접 주입하는 대신 지연 로딩으로 설정하여 컨텍스트 창을 효율적으로 관리하고 에이전트의 성능을 최적화합니다.
- **`developerInstructions`를 통한 프롬프트 커스터마이징:** OpenAI가 최적화한 기본 시스템 프롬프트를 `baseInstructions`로 완전히 덮어쓰기보다는, `developerInstructions`를 사용하여 특정 클라이언트 요구사항에 맞는 추가 지침을 덧붙여 에이전트의 동작을 미세 조정합니다.
- **JSON 스키마 및 TypeScript 바인딩 활용:** `codex app-server generate-json-schema` 및 `generate-ts` 명령을 사용하여 앱 서버 프로토콜의 최신 정의를 얻고, 이를 통해 클라이언트 애플리케이션 개발 시 타입 안전성과 개발 편의성을 높입니다.
