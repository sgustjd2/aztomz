# Give the Agent a Budget, Not a Token — Sachin Malhotra, Anthropic

🔗 https://youtu.be/rbjWzZK2LU0 · 📅 2026-08-22 · 🎙 AI Engineer

## 한 줄 요약
Anthropic의 Sachin Malhotra는 LLM 기반 에이전트의 신뢰성, 비용 효율성, 안전성을 높이기 위해 단순한 토큰 제한 대신 비용, 시간, 단계 등을 포괄하는 '예산(Budget)' 개념을 도입해야 한다고 주장한다.

## 발표자·소속
Sachin Malhotra, Anthropic (AI Engineer)

## 핵심 주장
- **단순 토큰 제한의 한계 극복**: 기존 LLM 에이전트의 토큰 제한은 에이전트가 작업을 완료하기 전에 강제로 중단시켜 불완전하거나 비효율적인 결과를 초래할 수 있습니다. 이는 에이전트가 자원을 전략적으로 활용할 기회를 박탈하며, 에이전트의 환각(hallucinations) 및 예측 불가능한 비용 발생 문제와도 연결됩니다.
- **예산 기반 접근 방식 도입**: 에이전트에게 토큰 수 대신 비용, 시간, 또는 작업 단계 수와 같은 '예산'을 부여함으로써, 에이전트가 이 예산 내에서 자원을 어떻게 사용할지 스스로 결정하게 합니다. 이는 에이전트에게 단순한 제약이 아니라 자원 사용에 대한 '신호'로 작용하여 자율성과 효율성을 높입니다.
- **에이전트의 신뢰성 및 안전성 향상**: 예산은 에이전트가 작업을 수행하면서 자원을 현명하게 배분하고, 필요시 스스로 중단하거나 요약하는 등 자가 수정 능력을 갖게 합니다. 이는 예상치 못한 고비용 발생이나 무한 루프와 같은 문제를 방지하여 에이전트의 신뢰성과 안전성을 강화합니다.
- **비용 효율적인 에이전트 개발**: 예산은 에이전트가 주어진 자원 내에서 최적의 결과를 도출하도록 유도하며, 개발자는 에이전트의 행동을 더 효과적으로 제어하고 예측할 수 있게 됩니다. 이는 장기적으로 LLM 기반 시스템의 운영 비용을 절감하고, 에이전트가 '비용 인식(cost-aware)' 및 '지연 시간 인식(latency-aware)' 능력을 갖추도록 돕습니다.

## 세부 내용
발표는 LLM 기반 에이전트 시스템이 직면한 주요 문제점, 특히 '환각(hallucinations)', '비용', '신뢰성' 문제를 지적하며 시작됩니다. Sachin Malhotra는 이러한 문제의 근본 원인 중 하나로 에이전트에게 단순히 '토큰 제한(token limit)'을 부여하는 현재의 접근 방식을 꼽습니다. 토큰 제한은 에이전트가 작업을 완료하기 전에 강제로 중단시켜 불완전하거나 비효율적인 결과를 초래할 수 있으며, 에이전트가 자원을 전략적으로 활용할 기회를 박탈합니다. 그는 "토큰은 에이전트에게 너무 낮은 수준의 추상화"라고 강조합니다.

이에 대한 대안으로 '예산(Budget)' 개념을 제안합니다. 예산은 단순히 토큰 수를 제한하는 것을 넘어, 에이전트에게 주어진 작업에 사용할 수 있는 총 '비용', '시간', 또는 '작업 단계 수'와 같은 보다 포괄적인 자원 한도를 의미합니다. 이 예산은 에이전트에게 단순한 제약이 아니라, 자원을 어떻게 사용할지 결정하는 '신호(signal)'로 작용하며, 에이전트가 자율적으로 자원을 관리하고 의사결정을 내리도록 돕습니다.

발표자는 예산 기반 에이전트의 작동 방식을 설명하기 위해 몇 가지 시나리오를 제시합니다.
1.  **요약 작업**: 토큰 제한이 있는 경우, 에이전트는 중요한 정보가 남아있음에도 불구하고 제한에 도달하면 요약을 중단할 수 있습니다. 반면, 예산이 있는 에이전트는 주어진 예산 내에서 가장 효과적인 요약을 생성하기 위해 더 많은 토큰을 사용하거나, 요약이 충분하다고 판단될 때 스스로 중단할 수 있습니다.
2.  **연구 에이전트**: 복잡한 질문에 답하기 위해 여러 단계를 거쳐 정보를 수집해야 하는 연구 에이전트의 경우, 토큰 제한은 불충분한 연구로 이어질 수 있습니다. 예산이 있는 에이전트는 예산 내에서 필요한 만큼의 연구를 수행하고, 예산이 소진될 경우 현재까지의 진행 상황을 요약하거나 추가 예산을 요청하는 등 전략적으로 대응할 수 있습니다.

이러한 예산 기반 접근 방식은 에이전트가 '비용 인식(cost-aware)', '지연 시간 인식(latency-aware)' 능력을 갖추도록 돕습니다. 에이전트는 예산을 통해 자신의 행동이 초래할 비용이나 시간을 인지하고, 이를 바탕으로 더 효율적인 의사결정을 내릴 수 있습니다.

발표에서는 '예산 관리 에이전트 아키텍처(Budgeted Agent Architecture)'의 개념도 제시됩니다. 이 아키텍처는 다음과 같은 구성 요소를 포함합니다:
*   **Budget Manager**: 에이전트의 자원 사용량을 모니터링하고, 남은 예산을 에이전트에게 피드백합니다.
*   **Agent**: LLM을 활용하여 작업을 수행하며, Budget Manager로부터 받은 예산 정보를 바탕으로 의사결정을 내립니다.
*   **Tools**: 에이전트가 외부 정보 검색이나 특정 작업을 수행하는 데 사용하는 도구들입니다.
*   **LLM**: 에이전트의 핵심 추론 엔진입니다.

이 아키텍처에서 예산은 에이전트의 시스템 프롬프트(system prompt)에 포함될 수 있으며, 예를 들어 "당신에게는 X달러의 예산이 있습니다. 현명하게 사용하세요."와 같이 명시적으로 전달될 수 있습니다. 예산이 소진될 경우, 에이전트는 단순히 중단되는 것이 아니라, "예산이 소진되었습니다. 현재까지의 진행 상황을 요약하고 추가 예산을 요청합니다."와 같이 사전에 정의된 방식으로 대응할 수 있습니다.

결론적으로, 예산은 에이전트에게 자율성을 부여하고, 자가 수정 능력을 강화하며, 예측 가능한 비용으로 신뢰성 높은 결과를 도출할 수 있도록 돕는 강력한 원시(primitive) 도구로 소개됩니다.

## 실무 적용 포인트
- **예산 기반 프롬프트 엔지니어링**: 에이전트의 시스템 프롬프트에 명시적으로 비용, 시간 또는 단계 수와 같은 예산을 포함하여 에이전트가 자원 사용에 대한 인식을 갖도록 유도합니다. 예를 들어, "당신에게는 5달러의 예산이 있습니다. 이 예산 내에서 가장 정확하고 간결한 답변을 제공하세요."와 같이 지시할 수 있습니다.
- **예산 관리 모듈 구현**: 에이전트 시스템에 자원 사용량(LLM 호출 비용, API 호출 횟수, 실행 시간 등)을 모니터링하고 남은 예산을 에이전트에게 피드백하는 'Budget Manager'와 같은 모듈을 구축하여 에이전트의 자율적인 자원 관리를 지원합니다.
- **예산 소진 시 대응 전략 정의**: 예산이 소진될 경우 에이전트가 단순히 중단되는 것이 아니라, 현재까지의 작업 요약, 추가 예산 요청, 또는 특정 폴백(fallback) 동작 수행 등 사전에 정의된 대응 로직을 구현하여 시스템의 견고성을 높입니다.
- **비용/시간 최적화 에이전트 개발**: 특정 작업에 대해 비용이나 시간을 최소화하도록 에이전트를 설계할 때, 예산을 핵심 제약 조건으로 활용하여 에이전트가 더 효율적인 도구 사용이나 추론 경로를 선택하도록 유도합니다. 예를 들어, 고비용 LLM 호출 대신 저비용 LLM 호출을 먼저 시도하도록 지시할 수 있습니다.
