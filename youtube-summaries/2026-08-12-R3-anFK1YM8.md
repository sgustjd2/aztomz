# Memory Harnesses for Long-Running Research Agents — Stefania Druga, Sakana.ai

🔗 https://youtu.be/R3-anFK1YM8 · 📅 2026-08-12 · 🎙 AI Engineer

## 한 줄 요약
발표자는 장기 실행 AI 에이전트의 컨텍스트 문제를 해결하기 위한 메모리 하네스 디자인과 그 효과를 설명하며, 특히 로컬 모델에서 메모리 정책을 측정하는 것의 중요성을 강조합니다.

## 발표자·소속
Stefania Druga, Sakana.ai - RSI Lab

## 핵심 주장
- 장기 실행 AI 에이전트의 컨텍스트 문제는 모델이 자체 모순되거나, 작업을 반복하거나, 질문에서 벗어나는 등의 문제로 이어지며, 이는 모델 릴리스 감소 및 장기 작업 증가 추세로 인해 더욱 중요해지고 있습니다.
- 로컬 모델은 에이전트 및 도구 사용에 유용해지고 있지만, RAM 제약이 여전히 존재하며, 비용 효율적인 AI 사용을 위해 더 나은 라우팅, 캐싱, 컨텍스트 관리 등의 실천이 필요합니다.
- 메모리 하네스는 모델 주변의 "쓰기-관리-읽기" 루프를 통해 작동하며, 에이전트에게 항상 코어(인-컨텍스트 작업 세트)를 보여주고, 리콜 블록에서 다양한 메모리 모드(벡터 랙, 의사결정 원장 등)를 테스트하며, 아카이브 블록에서 세션 간 정보를 추적합니다.
- 컨텍스트가 메모리 창에 맞는 단기 작업의 경우, 메모리 하네스는 정확도에 큰 영향을 미치지 않지만 토큰 비용을 증가시킵니다. 그러나 컨텍스트가 메모리 창을 벗어나는 장기 작업에서는 잘 설계된 메모리 하네스가 성능을 크게 향상시키고 비용을 절감할 수 있습니다.
- 메모리 정책을 일등 시민 측정 지표로 간주하고, 데이터, 모델, 컴퓨팅, 평가, 권한 및 책임 측면에서 제어 가능한 로컬 모델과 관리되는 하네스를 통해 "측정된 역량"으로서의 주권적 AI 역량을 구축하는 것이 중요합니다.

## 세부 내용
발표자는 AI 에이전트가 장기 실행 작업을 수행할 때 발생하는 컨텍스트 블로트(Context Bloat) 문제를 지적합니다. 이는 모델이 이전 결정을 뒤집거나, 완료된 작업을 반복하거나, 질문에서 벗어나는 형태로 나타납니다. 최근 모델 릴리스가 줄어들고 장기 작업의 필요성이 증가함에 따라 이 문제는 더욱 심화되고 있습니다. 코인베이스(Coinbase)의 사례는 로컬 모델과 더 나은 라우팅, 캐싱, 컨텍스트 관리 등을 통해 AI 비용을 절감하면서 사용량을 늘릴 수 있음을 보여줍니다.

발표자는 GLM(Generative Language Model) 및 DeepSeek-V4-Flash와 같은 로컬 모델들이 M3 Ultra 칩셋(28코어 CPU, 96GB 통합 메모리)에서 실행 가능해지면서 에이전트-도구 사용에 유용해지고 있다고 언급합니다. 이러한 로컬 모델을 활용하기 위해 발표자는 "메모리 하네스"를 설계했습니다. 이 하네스는 모델 자체가 아닌 모델 주변의 "쓰기-관리-읽기" 루프입니다.

하네스 디자인은 다음과 같은 구성 요소를 포함합니다:
-   **Research agent**: 영구 메모리가 없는 작은 에이전트입니다.
-   **CORE - In-context working set**: 에이전트에게 항상 보이는 추적 정보입니다.
-   **RECALL - session ledger**: 다양한 메모리 모드를 테스트하는 블록입니다.
    -   `off`: 메모리 사용 안 함 (기준선)
    -   `vector_rag`: 유사성에 따라 정보를 가져옴.
    -   `decision_json`: 각 턴에서 내려진 결정을 추적하고 우선순위를 지정.
    -   `oracle_recall`: 정답(ground truth)을 제공하여 메모리 검색의 정확도를 측정.
-   **ARCHIVAL - cross-session store**: 다른 세션의 정보를 추적합니다.
-   **CONTROL**: 에이전트와 메모리 저장소 사이의 흐름을 관리합니다.

실험은 두 가지 유형의 작업으로 진행되었습니다.
1.  **컨텍스트가 메모리 창에 맞는 경우 (단기 작업)**: 문헌 검토 작업에서 모든 관련 정보가 컨텍스트에 포함될 때, 메모리 하네스를 사용하는 것은 정확도에 차이를 만들지 않지만, 더 많은 토큰을 사용하여 비용만 증가시킵니다. 즉, "메모리는 공짜가 아닙니다."
2.  **컨텍스트가 메모리 창에서 벗어나는 경우 (장기 작업)**: XBench 벤치마크의 장기 QA 작업에서 정답이 초기 단계(124단계)에 주어졌지만, 질문은 컨텍스트 창을 훨씬 벗어난 후(500단계)에 주어졌습니다.
    -   `rank_only` 정책을 사용한 리콜이 가장 좋은 성능을 보였습니다. 이는 단순히 메모리를 사용할지 말지 결정하는 것보다, 관련성을 기준으로 메모리를 순위화하는 것이 더 효과적임을 시사합니다.
    -   `oracle_recall`은 모델에 올바른 메모리를 제공하지만, 모델이 이를 사용하도록 강제하지 않기 때문에 여전히 잘못된 정보를 검색하거나 혼란스러워할 수 있습니다.
    -   "나쁜 메모리"는 더 많은 토큰을 소비하고 에이전트를 잘못된 방향으로 이끌 수 있으므로 비용이 많이 듭니다. 좋은 리콜 정책은 토큰과 예산을 절약할 수 있습니다.

발표자는 메모리 정책을 일등 시민 측정 지표로 간주하고, 시스템에서 메모리를 어떻게 사용할지 고민해야 한다고 제안합니다. 메모리 기술의 스펙트럼은 단순한 파일 시스템 검색부터 메모리 모델 훈련에 이르기까지 매우 넓습니다.

결론적으로, 발표자는 로컬 모델과 관리되는 하네스를 결합한 "주권적 역량(Sovereign capability)"을 강조합니다. 이는 데이터를 로컬에 유지하고, 컴퓨팅 및 평가를 제어하며, 메모리 거버넌스를 감사할 수 있는 투명한 시스템을 의미합니다. Sakana.ai는 이러한 주권적 AI를 구축하는 데 중점을 두고 있으며, 일본에서 관련 인재를 채용 중이라고 덧붙입니다.

## 인상적인 대목
- "메모리는 공짜가 아닙니다." (Memory is not a free win.)
- "나쁜 메모리는 두 배로 비쌉니다. 토큰을 소비하고 에이전트를 잘못된 방향으로 보냅니다." (Bad memory is expensive twice - it spends tokens and sends the agent the wrong way.)
- "주권적 역량은 측정된 역량입니다." (Sovereign capability is measured capability.)

## 실무 적용 포인트
- **메모리 정책 설계**: 장기 실행 에이전트를 개발할 때 단순히 메모리를 추가하는 것을 넘어, 어떤 메모리를 저장하고, 어떻게 순위를 매기며, 언제 검색할지에 대한 명확한 정책(예: `rank_only`와 같은 리콜 정책)을 설계해야 합니다.
-   **로컬 모델 활용 고려**: M3 Ultra와 같은 엣지 디바이스에서 GLM, DeepSeek-V4-Flash와 같은 로컬 모델을 활용하여 데이터 주권과 비용 효율성을 확보할 수 있습니다.
-   **비용 및 성능 측정**: 메모리 하네스 도입 시 정확도뿐만 아니라 토큰 사용량과 같은 비용 지표도 함께 측정하여 최적의 균형점을 찾아야 합니다. 컨텍스트 창에 모든 정보가 들어가는 경우, 메모리 사용이 오히려 비효율적일 수 있습니다.
-   **투명성 및 제어**: 에이전트의 메모리 파이프라인의 모든 단계를 제어하고 감사할 수 있는 시스템을 구축하여 예측 가능성과 신뢰성을 높여야 합니다.
