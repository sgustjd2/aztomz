# Why AI Agents Should Have Their Own Sandbox — Philipp Schmid, Google DeepMind

🔗 https://youtu.be/oWTEiYpxl80 · 📅 2026-10-07 · 🎙 AI Engineer

## 한 줄 요약
Google DeepMind의 Philipp Schmid는 AI 에이전트가 자체 샌드박스를 가져야 하는 이유를 설명하며, 개발자가 복잡한 인프라 관리 없이도 강력한 에이전트를 구축하고 배포할 수 있도록 Interactions API와 관리형 샌드박스 환경을 소개했습니다.

## 발표자·소속
Philipp Schmid, Google DeepMind

## 핵심 주장
- AI 모델 개발 속도가 매우 빨라지고 있으며, Gemini 및 Gemma 모델과 같은 프론티어 및 오픈 모델이 끊임없이 출시되고 있습니다. 특히 Nano Banana Light(이미지 생성)와 Omni Flash(비디오 생성/편집)는 빠른 속도와 저렴한 비용으로 미디어 생성에 혁신을 가져오고 있습니다.
- LLM과의 상호작용 방식은 단순한 텍스트 완성에서 지시 따르기, 함수 호출을 거쳐 이제는 목표 지향적인 에이전트(Goals + Thinking + Functions)로 발전하고 있습니다. 이는 모델이 직접 사고하고 행동을 계획하며 목표를 달성하는 방식으로, 개발자가 더 복잡한 작업을 위임할 수 있게 합니다.
- Interactions API는 모델과 에이전트 추론을 지원하는 통합 API로, 복잡한 컨텍스트 관리, 장기 실행 백그라운드 작업, 선택적 서버 측 상태 관리, 쉬운 해석 가능성 및 구성 가능성, 그리고 Google 검색 및 사용자 정의 함수와 같은 도구 사용을 결합하여 에이전트 개발을 간소화합니다.
- 관리형 샌드박스 환경에서 실행되는 Antigravity 에이전트는 개발자가 인프라 관리에 대한 걱정 없이 에이전트를 구축하고 배포할 수 있게 합니다. 이 샌드박스는 안전하고 격리되어 있으며, 파일 시스템, 웹 검색, URL 컨텍스트, 에이전트 스킬 등 풍부한 도구 세트를 제공합니다.

## 세부 내용

발표는 AI 모델의 빠른 발전 속도를 보여주는 타임라인으로 시작되었습니다. Gemini 및 Gemma 모델이 끊임없이 출시되고 있으며, 최근에는 이미지 생성 모델인 Nano Banana Light와 비디오 생성 및 편집을 위한 Omni Flash가 Interactions API를 통해 출시되어 개발자들이 미디어 애플리케이션을 구축할 수 있게 되었습니다.

LLM과의 상호작용 역사는 텍스트 완성(BERT, GPT)에서 시작하여, 질문에 답하는 지시 따르기(ChatGPT)를 거쳐, 이제는 모델이 외부 도구를 호출하여 행동을 취하는 함수 호출 단계에 이르렀습니다. 궁극적으로는 모델에 목표를 부여하고, 모델이 스스로 생각하고 도구를 사용하여 목표를 달성하는 에이전트(Goals + Thinking + Functions) 패러다임으로 발전하고 있습니다.

Google AI Studio(ai.studio 또는 ai.dev)는 이러한 모델과 에이전트를 쉽게 시작할 수 있는 플랫폼입니다. API 키 발급, 설정, 무료 티어 사용, 비용 관리 등 모든 과정이 AI Studio 내에서 이루어지며, 개발자 친화적인 환경을 제공합니다.

새롭게 소개된 Interactions API는 모델과 에이전트의 추론을 위한 통합 API입니다. 이 API는 복잡한 컨텍스트 관리, 장기 실행 백그라운드 작업, 선택적 서버 측 상태 관리, 쉬운 해석 가능성 및 구성 가능성, 그리고 Google 검색 및 사용자 정의 함수와 같은 도구 사용을 지원합니다. 특히 서버 측 상태 관리 기능을 통해 개발자는 클라이언트에서 상태를 관리할 필요 없이 이전 상호작용 ID를 전달하여 대화를 이어갈 수 있습니다.

Interactions API는 텍스트뿐만 아니라 오디오 및 이미지 생성과 같은 다양한 모달리티를 지원합니다. 오디오 생성 시에는 `response_modalities=['audio']`를 지정하여 텍스트 대신 오디오를, 이미지 생성 시에는 `response_modalities=['image']`를 지정하여 이미지를 반환받을 수 있습니다. 도구 사용의 경우, 모델이 Google 검색이나 사용자 정의 함수를 호출할지 스스로 결정하며, 함수 호출 결과는 사용자 입력이 아닌 환경으로부터 오는 것으로 간주되어 더 자연스러운 에이전트 흐름을 만듭니다.

"The Steps Data Model"은 모델이 수행한 모든 작업을 타임라인 형태로 기록하는 새로운 데이터 모델입니다. 이는 기존의 "사용자/모델 턴" 개념을 대체하며, `model_output`, `thought`, `function_call`, `google_search_call`과 같은 명확한 유형을 통해 에이전트의 내부 작동 방식을 더 쉽게 이해하고 확장할 수 있도록 합니다.

Antigravity 에이전트는 Gemini API 내에서 제공되는 일반 목적의 자율 에이전트로, Google이 관리하는 Linux 샌드박스에서 실행됩니다. 이 샌드박스는 코드 실행, 파일 시스템, 웹 검색, URL 컨텍스트, 에이전트 스킬 등 풍부한 도구 세트를 제공하며, 보안과 격리를 보장합니다. 개발자는 `environment='remote'` 옵션을 통해 이 관리형 샌드박스를 활용할 수 있으며, 인프라 관리에 대한 부담 없이 에이전트를 실행할 수 있습니다.

"Persistent Environments" 기능을 통해 에이전트는 여러 상호작용에 걸쳐 상태를 유지할 수 있으며, GCS 버킷, GitHub 리포지토리, 인라인 파일 등 다양한 소스를 환경에 포함시킬 수 있습니다. 이는 에이전트 간의 컨텍스트 공유를 가능하게 하고, 미리 구성된 환경을 재사용하여 개발 효율성을 높입니다.

개발자는 이러한 기능을 활용하여 자신만의 관리형 에이전트를 구축할 수 있습니다. 소스 코드, 스킬, 환경을 묶어 명명된 에이전트를 생성하거나, 기존 환경에서 스냅샷을 포크하여 새로운 에이전트를 만들 수 있습니다. 이 과정에서 Terraform, Kubernetes 등 복잡한 인프라 설정 없이도 에이전트를 배포하고 공유할 수 있습니다.

마지막으로, Gemini API CLI는 명령줄에서 Gemini API와 상호작용할 수 있는 도구를 제공합니다. 이를 통해 개발자는 프롬프트를 실행하고, 에이전트를 스캐폴딩, 테스트, 배포할 수 있어 개발 워크플로우를 더욱 간소화합니다.

데모에서는 AI Studio의 "AI Talk Radio" 앱을 시연했습니다. "파인애플이 피자에 속하는지 여부에 대한 토크쇼 라디오"를 생성하는 프롬프트를 입력하자, 에이전트가 환경을 프로비저닝하고, 프롬프트 제약을 분석하며, 필요한 Python 종속성을 설치하고, 스킬을 읽어들이는 과정을 보여주었습니다. 미리 생성된 "The Great Breakfast Bowl Debate" 오디오를 재생하여 에이전트가 생성한 라디오 쇼의 품질을 선보였습니다. 또한, AI Studio 내에서 앱의 코드를 확인하고, Antigravity Agent Preview에서 에이전트가 실행되는 샌드박스 환경의 세부 정보(OS, CPU, 메모리, 설치된 도구 등)를 탐색하는 과정을 보여주며, 개발자가 에이전트의 작동 방식을 투명하게 이해하고 제어할 수 있음을 강조했습니다.

## 실무 적용 포인트
- **Google AI Studio 활용**: `ai.studio`를 방문하여 Gemini API 및 관리형 에이전트 기능을 무료 티어에서 직접 실험해 볼 수 있습니다. 복잡한 설정 없이 빠르게 프로토타입을 만들고 아이디어를 테스트하기에 적합합니다.
- **Interactions API로 에이전트 개발**: 복잡한 컨텍스트 관리, 장기 실행 작업, 서버 측 상태 관리, 그리고 Google 검색 및 사용자 정의 함수와 같은 다양한 도구 사용이 필요한 에이전트를 개발할 때 Interactions API를 활용하여 개발 복잡성을 줄일 수 있습니다.
- **관리형 샌드박스 환경 활용**: Antigravity 에이전트와 같은 관리형 샌드박스 환경을 사용하여 에이전트를 배포하면, 개발자가 직접 가상 머신, 컨테이너, 파일 시스템 등을 관리할 필요 없이 안전하고 격리된 환경에서 코드를 실행하고 파일을 조작할 수 있습니다.
- **재사용 가능한 에이전트 및 환경 구축**: Persistent Environments 기능을 통해 GCS 버킷이나 GitHub 리포지토리의 코드를 소스로 포함시켜 에이전트 환경을 구성하고, 이를 다른 에이전트나 팀원들과 공유하여 개발 효율성을 높일 수 있습니다.
