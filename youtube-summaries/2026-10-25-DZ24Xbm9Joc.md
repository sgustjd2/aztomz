# How to Build Financial Agents That Work Across the Web - Jay Sahnan & Arik Bird, Browserbase

🔗 https://youtu.be/DZ24Xbm9Joc · 📅 2026-10-25 · 🎙 AI Engineer

## 한 줄 요약
브라우저베이스(Browserbase)는 포크된 크로미움(Chromium)과 스테이지핸드(Stagehand) SDK를 활용하여 웹 전반에서 금융 에이전트가 수천 개의 브라우저를 동시에 제어하고, 복잡한 웹사이트에서 데이터를 추출하며, 안티봇(anti-bot) 시스템을 우회하여 신뢰성 있는 자동화를 가능하게 하는 방법을 제시합니다.

## 발표자·소속
- Jay Sahnan: Growth Engineer, Browserbase
- Arik Bird: Account Executive, Browserbase

## 핵심 주장
- **브라우저 에이전트의 필요성:** API가 제공되지 않는 웹사이트에서 로그인, 양식 작성, 영수증 다운로드 등 사람이 하는 작업을 AI 에이전트가 수행하려면 브라우저가 필수적입니다. 이는 금융 정보와 같이 접근하기 어려운 데이터를 다루는 데 특히 중요합니다.
- **크로미움 포크를 통한 확장성 확보:** 일반적인 크로미움 바이너리를 데이터센터에서 실행할 경우, 브라우저 지문, 세션 상태, 데이터센터 IP 등으로 인해 안티봇 시스템에 의해 차단될 위험이 높습니다. 브라우저베이스는 자동화 플래그 제거, 브라우저 ID 일치, 프로세스 유지 등의 패치를 적용한 포크된 크로미움을 통해 이러한 문제를 해결하고 수천 개의 브라우저를 안정적으로 동시 실행할 수 있게 합니다.
- **스테이지핸드(Stagehand) SDK를 통한 제어 및 데이터 추출:** 스테이지핸드는 에이전트가 자연어 프롬프트를 사용하여 브라우저를 제어하고, 웹 페이지의 복잡한 DOM 구조를 간소화하여 관련 정보만 LLM에 전달하며, 비정형 데이터를 Zod 스키마를 통해 구조화된 데이터로 변환할 수 있도록 돕습니다.
- **네트워크 트래픽 최적화:** 스테이지핸드를 브라우저와 함께 호스팅함으로써, 에이전트의 명령과 브라우저의 응답 간 네트워크 왕복 횟수를 줄여 작업 처리량을 1.59배 향상시킵니다.

## 세부 내용
발표는 웹 전반에서 작동하는 금융 에이전트를 구축하는 방법에 초점을 맞춥니다. 발표자들은 브라우저 에이전트의 정의와 필요성을 설명하며, API가 없는 웹사이트에서 사람이 수행하는 다양한 작업을 자동화하는 데 브라우저가 필수적이라고 강조합니다.

**1. 램프(Ramp) 사례: 누락된 영수증**
램프는 기업 지출 관리 플랫폼으로, 사용자의 영수증을 자동으로 수집해야 합니다. 초기에는 사람이 직접 포털에 로그인하여 영수증을 다운로드했지만, 이는 확장성이 떨어지는 방식입니다. 브라우저 에이전트를 도입하여 델타 항공 웹사이트에 로그인하고, 항공권 영수증을 찾아 다운로드한 후 해당 거래와 매칭하는 과정을 자동화했습니다. 이를 통해 램프는 3만 시간 이상의 수동 작업을 절약하고 5배의 확장성을 달성했습니다.

**2. 크로미움의 작동 방식과 확장 문제**
발표자들은 크로미움 브라우저가 사용자 노트북에서 어떻게 작동하는지 설명합니다. 브라우저는 브라우저 버전, OS, 글꼴, 화면 크기, 시간대 등 일관된 "지문"을 가지고 있으며, 쿠키, 로그인 상태, 이전 방문 기록을 통해 "익숙한 방문자"로 인식됩니다. 또한 네트워크 평판, 요청 타이밍, 탐색 패턴 등 "익숙한 패턴"을 통해 사용자가 인간임을 식별합니다.

하지만 이 크로미움 바이너리를 데이터센터 서버에서 실행하면 문제가 발생합니다. 데이터센터 IP를 사용하고, 매번 새로운 브라우저 지문과 로그인 상태를 가지며, 프록시를 사용하면 웹사이트는 이를 봇으로 인식하고 차단합니다.

**3. 브라우저베이스의 해결책: 포크된 크로미움과 스테이지핸드**
브라우저베이스는 이러한 문제를 해결하기 위해 크로미움을 포크하여 "검증된 브라우저"를 만들었습니다. 주요 변경 사항은 다음과 같습니다.
1.  **자동화 플래그 제거:** `navigator.webdriver` 값을 `true`에서 `false`로 변경하여 자동화된 브라우저임을 숨깁니다.
2.  **브라우저 ID 일치:** "HeadlessChrome" 대신 "Chrome"으로 브라우저 ID를 일치시킵니다.
3.  **프로세스 유지:** 브라우저 작업을 마칠 때마다 크로미움 프로세스 전체를 종료하는 대신, 창만 닫고 프로세스는 유지하여 세션 상태를 보존합니다.

**라이브 데모:**
-   **단일 브라우저 실행:** `ramp.com`에 접속하는 단일 브라우저를 라이브로 실행하여 보여줍니다.
-   **100개 브라우저 동시 실행:** 다양한 웹사이트에 접속하는 100개의 브라우저를 동시에 실행하는 모습을 보여줍니다. 발표자는 관객들에게 QR 코드를 스캔하여 휴대폰으로 무작위 브라우저 중 하나와 직접 상호작용할 수 있도록 합니다. 이는 브라우저가 클라우드에서 실제로 작동하고 있음을 증명합니다.

**4. 빌(Bill) 사례: 다양한 포털의 벤더 인보이스 처리**
빌은 수많은 벤더의 인보이스를 처리해야 하는데, 각 벤더 포털마다 결제 흐름과 UI가 다릅니다. 전통적인 자동화 도구(예: Playwright)는 하드코딩된 셀렉터를 사용하므로 페이지 변경 시 스크립트가 쉽게 깨집니다.

**스테이지핸드(Stagehand) SDK:**
브라우저베이스는 에이전트가 브라우저를 제어할 수 있도록 오픈소스 SDK인 스테이지핸드를 개발했습니다.
-   **자연어 기반 제어:** 스테이지핸드는 페이지의 DOM 구조와 접근성 트리를 분석하여 LLM(Large Language Model)에 간소화된 정보를 제공합니다. 에이전트는 "학습 더하기 버튼을 찾아라"와 같은 자연어 프롬프트를 통해 특정 요소를 식별하고, "로그인 버튼을 클릭하라"와 같은 명령으로 작업을 실행할 수 있습니다.
-   **데이터 추출:** `extract` 기능을 통해 웹 페이지의 비정형 콘텐츠를 Zod 스키마를 사용하여 구조화된 데이터로 변환할 수 있습니다. 이는 엔지니어가 웹에서 데이터를 쉽게 추출하고 활용할 수 있게 합니다.
-   **네트워크 트래픽 최적화:** 스테이지핸드는 크롬 확장 프로그램 형태로 호스팅된 브라우저 옆에서 실행됩니다. 이는 에이전트와 브라우저 간의 네트워크 왕복 횟수를 줄여 작업 처리량을 1.59배 향상시킵니다.

**5. 스트라이프(Stripe) 사례: 동시 다중 소스 조사**
스트라이프는 수만 명의 판매자를 온보딩하면서 KYC(Know Your Customer) 검증을 위해 판매자 웹사이트, 정책 페이지, 리뷰 사이트 등 다양한 소스를 조사해야 합니다. 이는 발견된 정보에 따라 다음 단계가 달라지는 복잡한 작업입니다.

**라이브 데모:**
-   **단일 회사 웹사이트 추출:** 치폴레(Chipotle) 웹사이트에서 회사명과 판매 품목을 추출하는 데모를 보여줍니다.
-   **4개 소스 동시 조사:** 치폴레의 웹사이트, 투자자 페이지, SEC 공시, NYSE 상장 정보를 4개의 브라우저를 사용하여 동시에 조사하고 데이터를 추출하는 데모를 보여줍니다.
-   **20개 회사, 각 3개 소스 (60개 브라우저) 동시 조사:** JP모건 체이스, 골드만삭스, 모건 스탠리, 비자, 마스터카드, 페이팔, 블록 등 20개 금융 회사의 웹사이트, 투자자 관계, SEC 공시 데이터를 동시에 추출하는 데모를 보여줍니다. 이는 브라우저베이스의 확장성과 스테이지핸드의 유연성을 잘 보여줍니다.

발표는 SEC 템플릿을 포함한 다양한 리소스에 대한 QR 코드를 제공하며 마무리됩니다.

## 인상적인 대목
- "Anything that you need to do on the web, your agent should have the tool called the browser." (웹에서 해야 할 일이라면 무엇이든, 에이전트는 브라우저라는 도구를 가지고 있어야 합니다.)
- "You're just going to be bottlenecked by the limitation of scale." (확장의 한계에 병목 현상이 발생할 것입니다.)
- "Hard-coded selectors can break when the page changes." (페이지가 변경되면 하드코딩된 셀렉터는 깨질 수 있습니다.)
- 122,456 토큰의 원시 HTML을 4,117 토큰의 접근성 트리로 줄여 LLM에 전달하는 스테이지핸드의 효율성.
- 30개 액션 크롤링에서 Playwright 22.0초 대비 Stagehand가 14.3초로 1.59배 처리량 향상을 보여준 수치.
- 수십, 수백 개의 브라우저를 동시에 실행하고 라이브로 보여주는 데모.

## 실무 적용 포인트
-   **API 없는 웹사이트 자동화:** 금융 기관, 이커머스, 여행 등 API를 제공하지 않거나 불완전한 웹사이트에서 데이터 수집, 양식 작성, 거래 처리 등의 작업을 자동화하는 데 브라우저 에이전트를 활용할 수 있습니다.
-   **안티봇 우회 및 신뢰성 확보:** 브라우저베이스의 포크된 크로미움과 같은 "검증된 브라우저"를 사용하여 데이터센터 환경에서도 봇으로 감지되지 않고 웹사이트에 안정적으로 접근할 수 있습니다.
-   **유지보수 용이한 자동화 스크립트:** 스테이지핸드의 자연어 기반 제어 및 데이터 추출 기능을 활용하여 페이지 UI 변경에 덜 민감한 자동화 스크립트를 작성하고 유지보수 비용을 절감할 수 있습니다.
-   **대규모 동시 웹 리서치:** 여러 웹사이트에서 동시에 정보를 수집해야 하는 시장 조사, 경쟁사 분석, 규제 준수(SEC 공시 등)와 같은 작업에 수십, 수백 개의 브라우저 에이전트를 병렬로 배포하여 효율성을 극대화할 수 있습니다.
