# Lessons from Generating 12 Trillion Synthetic Tokens — Bogdan Gaza, DatologyAI

🔗 https://youtu.be/FQwTqUmcbRg · 📅 2026-10-02 · 🎙 AI Engineer

## 한 줄 요약
DatologyAI는 LLM 사전 학습을 위한 합성 데이터 생성 시 발생하는 수조 토큰 규모의 엔지니어링 병목 현상, GPU 인프라 불안정성, 교차 인프라 오케스트레이션, 추론 최적화 문제를 해결한 경험과 교훈을 공유합니다.

## 발표자·소속
Bogdan Gaza, Co-Founder & CTO DatologyAI

## 핵심 주장
- **데이터 부족 문제 해결:** 대규모 언어 모델(LLM) 사전 학습에 필요한 고품질 데이터가 웹에서 제한적이므로, 합성 데이터 생성이 필수적입니다. DatologyAI는 문서 재구성을 통해 다양하고 정보 밀도가 높은 합성 데이터를 생성합니다.
- **수조 토큰 규모의 엔지니어링 과제:** 수조 토큰 규모의 데이터셋을 처리할 때 수백만 개의 데이터 파티션, S3 요청 스로틀링, Ray 헤드 메타데이터 병목 현상 등으로 인해 GPU 유휴 시간이 길어지는 문제가 발생합니다.
- **GPU 인프라 안정성 확보:** 장기 실행 추론 작업 중 GPU 노드 실패로 인한 진행 상황 손실, 컴퓨팅 낭비, 지연된 전달 문제를 해결하기 위해 Ray 작업 체크포인트 및 저장소에 대한 멱등성(idempotency)을 구현하여 복구 가능한 재시도를 가능하게 했습니다.
- **교차 인프라 오케스트레이션의 중요성:** 여러 클라우드 및 GPU 제공업체에 걸쳐 이기종 작업을 효율적으로 스케줄링하고 GPU 용량 한계를 극복하기 위해 인하우스 스케줄러와 중앙 집중식 메타데이터 및 계보 추적 시스템을 구축했습니다.
- **추론 최적화를 통한 성능 향상:** vLLM(및 SG Lang)의 배치 크기, 투기적 디코딩(speculative decoding) 등 핵심 매개변수를 최적화하여 40%의 처리량(throughput) 향상을 달성했습니다.

## 세부 내용

발표는 LLM 사전 학습을 위한 합성 데이터의 필요성으로 시작됩니다. 스케일링 법칙에 따르면, LLM 성능 향상을 위해서는 모델 크기뿐만 아니라 데이터 양도 기하급수적으로 늘려야 하지만, 웹상의 고품질 데이터는 한계에 도달하는 '데이터 벽(Data Wall)'에 부딪힙니다. DatologyAI는 이러한 문제를 해결하기 위해 합성 데이터 생성에 집중합니다.

DatologyAI의 합성 데이터 생성 프레임워크인 'BeyondWeb'은 기존 문서를 재구성(rephrasing)하여 다양하고 정보 밀도가 높은 데이터를 만듭니다. 발표자는 BeyondWeb을 통해 생성된 합성 데이터로 학습한 모델이 기존 데이터셋으로 학습한 모델과 비교하여 더 작은 모델 크기(3B 파라미터)로 더 높은 평균 정확도(8B 파라미터 모델과 유사)를 달성하고, 동일한 정확도를 얻는 데 필요한 토큰 수를 2.7배에서 7.2배까지 줄여 학습 속도를 크게 향상시켰음을 보여주는 그래프를 제시합니다.

합성 데이터 생성을 위한 엔지니어링 과정은 크게 '타겟 데이터셋'을 'GPU'를 통해 '합성 데이터셋'으로 변환하는 과정으로 구성됩니다. 타겟 데이터셋은 텍스트 또는 이미지-텍스트 형태이며, 합성 데이터셋은 재구성된 텍스트 또는 재캡션된 이미지입니다.

초기에는 합성 데이터 생성이 핵심 제품에 통합되지 않고, Slurm 클러스터에서 연구 목적으로 별도로 진행되었습니다. 이로 인해 데이터 큐레이션과 합성 레시피가 이중으로 관리되고, GPU 자원 제약, 느리고 오류 발생 가능성이 높은 반복 작업, 제한된 실험 속도 등의 문제가 있었습니다.

현재 DatologyAI는 합성 데이터 파이프라인을 코어 제품에 통합했습니다. 워크플로우 오케스트레이터와 잡 스케줄러를 통해 모든 작업을 Kubernetes(K8s) 클러스터에서 관리합니다. Spark 작업은 온디맨드 CPU를 사용하고, Ray 작업은 온디맨드 GPU를 사용하며, H100 GPU가 필요한 작업은 별도의 H100 컴퓨팅 클러스터(AWS, GCP, Prime Intellect 등)에서 실행됩니다. 모든 데이터는 S3와 호환되는 스토리지 계층에 저장됩니다. 이러한 통합을 통해 실험이 자동 추적 및 오케스트레이션되며, 더 빠르고 안정적인 반복이 가능해졌습니다.

발표자는 수조 토큰 규모의 합성 데이터 생성 과정에서 얻은 네 가지 주요 엔지니어링 교훈을 공유합니다.

1.  **수조 토큰 규모의 병목 현상:**
    *   **과제:** FineWeb, DCLM, Nemotron과 같은 텍스트 데이터셋은 30조 토큰 이상, DataComp-XL과 같은 이미지-텍스트 쌍은 약 128억 개에 달하며, 데이터셋 용량은 600TB 이상, 스토리지 PB+에 이릅니다. 이 규모에서는 수백만 개의 데이터 파티션, S3 요청 스로틀링, Ray 헤드 메타데이터 병목 현상으로 인해 GPU 유휴 시간이 길어집니다. 메타데이터를 가져오는 데만 9~11일이 소요될 수 있었습니다.
    *   **해결책:** S3 서버에 배치 요청을 보내고, 메타데이터(파일 이름, 크기, 스키마)를 GCS(Google Cloud Storage)에 10ms/요청으로 기록합니다. Ray 헤드는 S3에서 메타데이터를 일괄적으로 가져와(1k 요청당 100-400ms) Ray GPU 워커에 스트림 배치로 전달합니다. 이를 통해 메타데이터 가져오는 시간을 11일에서 2시간으로 단축했습니다.
    *   **결과:** GPU 유휴 시간을 99% 단축했습니다.

2.  **GPU 인프라 불안정성:**
    *   **과제:** 며칠에 걸쳐 실행되는 장기 추론 작업 중 GPU 노드가 실패하거나 GPU 제공업체에 의해 교체될 수 있습니다. 이는 진행 상황 손실, 컴퓨팅 낭비, 부분적인 출력, 전달 지연으로 이어집니다.
    *   **해결책:** 1:1 입력-출력 파티션 매핑을 통해 데이터 흐름 전반에 걸쳐 추적 가능성을 확보했습니다. Ray 워커는 작업 완료 후 진행 상황을 체크포인트로 저장하여 재개 가능한 실행을 지원합니다. 저장소에 대한 멱등성을 보장하여 안전한 재시도, 중복 또는 부분 쓰기 방지, 원활한 복구를 가능하게 했습니다. 실패한 작업은 마지막 체크포인트부터 어떤 GPU 노드에서든 재개됩니다.
    *   **결과:** 며칠이 걸리던 작업 실패가 복구 가능한 재시도로 전환되었습니다.

3.  **교차 인프라 오케스트레이션:**
    *   **과제:** 수조 토큰 규모의 워크로드는 GPU 용량 한계를 초과합니다. 여러 GPU 제공업체와 클라우드에 걸쳐 워크로드를 조정해야 하며, 이기종 작업 스케줄링은 단편화와 GPU 유휴를 초래합니다. 예를 들어, CPU 작업이 모든 GPU 작업을 차단하여 나중에 GPU 작업이 적합하더라도 실행되지 못하는 경우가 발생할 수 있습니다.
    *   **해결책:** 인하우스 스케줄러를 개발하여 하나의 설정으로 모든 곳에서 작업을 스케줄링할 수 있도록 했습니다. 클러스터, 클라우드, 제공업체 간에 이식 가능한 작업을 지원합니다. 중앙 집중식 메타데이터와 계보 추적을 통해 추적 가능성을 보장합니다. 스케줄 구성은 작업 큐, 스케줄링 정책, 물리적 노드 풀을 정의하여 CPU와 GPU 자원을 효율적으로 배분합니다.
    *   **결과:** GPU 자원 제약을 완화하고 효율적인 자원 활용을 가능하게 했습니다.

4.  **추론 최적화:**
    *   **과제:** vLLM(및 SG Lang)의 최적 매개변수를 빠르게 찾는 방법입니다.
    *   **핵심 교훈:** 빠른 스윕을 위한 주요 레버는 배치 크기(max-num-seqs, max-num-batched-tokens)와 투기적 디코딩(num_speculative_tokens, prompt_lookup_max)입니다.
    *   **결과:** Olmo 및 L40 GPU에서 vLLM의 기본 설정 대비 40%의 처리량 향상을 달성했습니다.

**성과 및 영향:**
-   **데이터 전달 규모:** 2024년 12월 300억 토큰에서 2025년 5월 7조 토큰, 2025년 6월 12조 토큰으로 급격히 증가했습니다.
-   **학습 결과:** BeyondWeb은 Nemotron-Synth, Cosmopedia, QA WRAP, RedPajama와 같은 데이터셋 대비 평균 정확도에서 우위를 보이거나 동등한 성능을 더 적은 토큰으로 달성했습니다.
-   **도메인 커버리지:** 웹, 법률, 다국어, 수학 코드, 멀티모달 등 다양한 도메인에서 합성 데이터를 생성하고 있습니다.

발표자는 DatologyAI가 데이터 인프라, 클라우드 인프라, 일반 인프라, 제품 관리 등 전 분야에서 채용 중임을 알리며 발표를 마무리합니다.

## 인상적인 대목

- "GPU 유휴 시간을 99% 단축했습니다." (Reduce GPU idle time by 99%.)

## 실무 적용 포인트
- **대규모 데이터셋 메타데이터 관리:** 수백만 개의 파티션을 가진 S3와 같은 객체 스토리지에서 메타데이터를 효율적으로 가져오기 위해 배치 요청(List batch request)을 사용하고, 메타데이터를 별도의 빠른 저장소(예: GCS)에 캐싱하는 전략을 고려해야 합니다.
- **장기 실행 GPU 작업의 복원력 강화:** 며칠이 걸리는 추론 또는 합성 데이터 생성 작업의 경우, GPU 노드 실패에 대비하여 Ray 작업의 체크포인트 기능을 활용하고, 저장소에 대한 멱등성을 구현하여 작업 재시작 시 데이터 중복이나 손실을 방지해야 합니다.
- **이기종 컴퓨팅 자원 스케줄링 최적화:** CPU와 GPU 자원이 혼합된 워크로드를 여러 클러스터 및 클라우드 제공업체에 걸쳐 효율적으로 스케줄링하기 위해, CPU 전용 풀과 GPU 전용 풀을 분리하고, 작업 스케줄러가 각 작업의 자원 요구사항(CPU, GPU)을 고려하여 최적의 위치에 배정하도록 설계해야 합니다.
- **LLM 추론 엔진 매개변수 튜닝:** vLLM과 같은 LLM 추론 엔진을 사용할 때는 기본 설정에만 의존하지 않고, 배치 크기(max-num-seqs, max-num-batched-tokens) 및 투기적 디코딩(num_speculative_tokens, prompt_lookup_max)과 같은 핵심 매개변수에 대한 그리드 서치(grid search)나 베이지안 최적화(Bayesian optimization)를 통해 처리량을 크게 향상시킬 수 있습니다.
