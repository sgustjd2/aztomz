# How VS Code Went from Monthly to Weekly Releases with AI — Harald Kirschner

🔗 https://youtu.be/I2LL_wd89-A · 📅 2026-10-03 · 🎙 AI Engineer

## 한 줄 요약
VS Code 팀은 AI를 활용하여 월별 릴리스에서 주간 릴리스로 전환하며 개발 속도를 크게 높였고, 이 과정에서 코드 품질 유지, 버그 진단 및 수정, 개발 프로세스 전반을 개선하기 위해 에이전트 기반 시스템을 구축하고 발전시켰습니다.

## 발표자·소속
Harald Kirschner, VS Code 팀 (Microsoft 소속)

## 핵심 주장
-   **AI를 활용한 개발 속도 향상:** VS Code 팀은 AI 에이전트를 활용하여 개발자가 작성한 코드의 커밋률(코드 생존율)을 55%에서 86%로 높였으며, 이를 통해 월별 릴리스에서 주간 릴리스로 전환하는 등 개발 속도를 획기적으로 개선했습니다.
-   **품질 유지 및 문제 해결:** AI 도입으로 인해 증가한 이슈와 풀 리퀘스트(PR)를 관리하고 코드 품질을 유지하기 위해, GitHub Actions에 계층화된 AI 파이프라인을 구축하여 이슈 필터링, 보강, 할당을 자동화하고, UI 변경에 대한 시각적 피드백 루프를 마련했습니다.
-   **개발 프로세스 전반의 진화:** AI를 단순히 도구로 사용하는 것을 넘어, 에이전트가 제품 자체를 구축하는 데 기여하도록 개발 시스템과 프로세스 전체를 재설계했습니다. 이는 코드 리뷰, 에러 진단 및 수정, 프로토타이핑, 평가(eval) 인프라 등 모든 단계에 걸쳐 이루어졌습니다.
-   **지속적인 학습과 개선의 중요성:** AI 에이전트의 성공은 새로운 병목 현상을 야기하므로, 자동화된 시스템을 지속적으로 모니터링하고 조정하며, 가장 긴 피드백 루프를 찾아 개선하는 '루프 엔지니어링' 접근 방식이 중요하다고 강조했습니다.

## 세부 내용

발표는 AI Engineer World's Fair의 스폰서 소개로 시작하여, 발표자인 Harald Kirschner가 VS Code 팀의 AI 활용 사례를 소개했습니다.

**AI를 통한 개발 속도 향상:**
VS Code 팀은 AI를 제품에 통합하는 것을 넘어, AI 에이전트가 제품 자체를 구축하는 데 기여하는 방식을 탐구했습니다. 60명 규모의 VS Code 팀은 AI 덕분에 월별 릴리스 주기에서 주간 릴리스 주기로 전환할 수 있었습니다. 이는 지난 10년간 유지해온 월별 릴리스 정책을 변경한 것입니다.

AI 에이전트가 작성한 코드의 커밋률(코드 생존율)은 1년 전 GPT-4.1 사용 시 55%였으나, 현재 Claude Opus 4.6을 사용하면서 86%로 31%p 증가했습니다. 이는 더 나은 모델과 개선된 하네스(harness) 덕분이며, 개발자들의 AI 코드에 대한 신뢰가 높아졌음을 보여줍니다.

**성공이 가져온 새로운 문제와 해결:**
AI 도입으로 인한 개발 속도 증가는 새로운 문제를 야기했습니다. 2026년 1월 이후로 오픈 이슈가 3.4K개, 오픈 PR이 850개 증가했습니다. 이는 AI가 이슈를 더 잘 찾아내고, 개발자들이 더 많은 코드를 생성하기 때문입니다. 이러한 출력 증가에 맞춰 릴리스 주기를 월간에서 주간으로 변경해야 했습니다.

발표자는 "팀에게 더 많은 AI를 사용하라고 말하는 것은 쉬운 부분이다. 작업은 모든 엔지니어링 시스템과 그 주변의 모든 프로세스를 진화시키는 것이다. AI를 채택하는 것은 쉬웠지만, 속도를 유지하는 것이 일이다"라고 핵심 주장을 밝혔습니다.

**루프 엔지니어링(Loop Engineering):**
발표자는 에이전트 기반 SDLC(소프트웨어 개발 생명주기)를 세 가지 루프의 집합으로 설명했습니다.
1.  **더 빠르게 배포 (Ship Faster):** 누가 코드를 작성하는가?
    *   **에이전트 준비성(Agent-readiness):** `AGENTS.md` 파일과 문서를 통해 에이전트가 인간뿐만 아니라 코드베이스의 컨텍스트를 이해하도록 합니다.
    *   **전문가 지식 인코딩:** 특정 영역의 전문가 지식을 스킬(skill) 형태로 에이전트에 인코딩하여, 한 명의 전문가가 모든 에이전트의 실행을 담당하는 대신 지식이 시스템 전체에 확산되도록 합니다.
    *   **리트머스 테스트:** 비엔지니어가 에이전트로부터 합리적인 PR을 받을 수 있다면 코드베이스 품질이 실제적이라는 것을 의미합니다.
    *   **개발자 불편함(Dev Annoyance)은 에이전트의 벽:** 8분 빌드는 개발자에게 큰 문제가 아니었지만, 에이전트가 20번 빌드를 실행하면 160분 블로커가 됩니다. VS Code 팀은 TypeScript Go로 전환하여 빌드 시간을 10배 단축했습니다.
    *   **PM이 빌더로 참여:** PM도 에이전트를 활용하여 PR을 생성하고, 팀은 이를 다듬어 몇 주 만에 완벽하게 다듬어진 디자인 경험을 만들 수 있었습니다.

2.  **품질 유지 (Hold Quality):** 어떻게 안전하게 배포하는가?
    *   **피드백 루프 에이전트:** 에이전트가 UI를 변경할 때 추측하는 문제를 해결하기 위해 피드백 루프를 구축했습니다.
    *   **컴포넌트 브라우저:** 전체 빌드 없이 컴포넌트를 렌더링하고, VS Code가 변경 사항 없이 실행되며, 변경 전후 스크린샷을 PR에 게시하여 시각적으로 확인하고 기능 및 사이드 이펙트 회귀를 포착합니다.
    *   **자체 수정 루프:** "버튼을 녹색으로 만들어라"와 같은 지시를 내리면, 에이전트가 변경 전 스크린샷을 찍고, 해당 요소를 찾아 반복적으로 수정하며, 시각적으로 올바른지 확인합니다. 이는 오픈소스 커뮤니티 PR에도 유용합니다.
    *   **코드 리뷰를 품질 게이트로:** 6개월 전 AI 리뷰는 너무 시끄러워 엔지니어들이 무시했지만, 신호 대 잡음비가 임계값을 넘어서자 이제 모든 PR에 필수적으로 적용됩니다. 71%의 피드백이 실행 가능하며, GitHub에서 5개 중 1개 이상의 코드 리뷰가 AI에 의해 이루어지고, 12,000개 이상의 조직이 AI를 사용합니다.
    *   **계층화된 AI 파이프라인 (GitHub Actions):** 하루에 수백 개의 이슈가 20개 이상의 저장소에서 발생합니다.
        *   **필터:** 스팸, 중복, 메타 이슈, 프롬프트 거부 등을 걸러냅니다.
        *   **강화:** 이슈를 번역하고, 재현 단계를 요청하며, 의미론적 중복을 제거합니다.
        *   **할당:** Git 기록과 선언된 소유권을 기반으로 담당자를 할당합니다.
        *   인바운드 이슈가 계속 증가하여 인간이 수동으로 처리하기 어려워졌습니다.
    *   **GitHub 이슈 트리아지 확장:** 에이전트가 실수를 할 수 있으므로, 인간의 피드백 루프가 필요합니다. Chrome 확장 프로그램을 통해 중복 이슈를 수정하고, 알 수 없는 이슈를 분류하며, 엔지니어링 워크플로우와 통합하여 이슈를 처리합니다.
    *   **자체 치유 오류 (Self-Healing Errors):** 40명의 팀이 수천만 명의 사용자에게 서비스를 제공하므로, 모든 롱테일 버그를 수동으로 수정할 수 없습니다. 에이전트가 스택 트레이스에서부터 제안된 수정 사항까지 첫 번째 패스를 수행하도록 구축했습니다.
    *   `errors.visualstudio.com`은 하루에도 여러 번 실행되며, 프로덕션 노이즈에서부터 수정 제안까지의 과정을 거칩니다. 50-80억 개의 원시 텔레메트리 이벤트에서 3-7백만 개의 오류를 필터링하고, 10-4천 개의 오류를 강화하며, 300개 이상의 임계값을 넘는 오류를 찾아내고, 최종적으로 10개 미만의 이슈를 특정 담당자에게 할당하여 PR을 자동 생성합니다.
    *   **자동화의 진정한 비용:** 과거에는 100% 롤아웃(YOLO)을 했지만, 이제는 단계별 롤아웃(8%에서 동결)을 통해 위험을 줄입니다. 자동화는 `자동화 -> 모니터링 -> 조정`의 과정을 거쳐야 하며, `잊지 않는 것`이 중요합니다. 가드레일 없이는 처음 2주 동안은 좋지만, 이후 회귀가 누적됩니다.

3.  **더 빠르게 학습 (Learn Faster):** 코드를 배포하는 것이 저렴하고 안전할 때, 희소한 자원은 판단력입니다.
    *   **평가(Eval)를 일류 인프라로:** 공개 벤치마크만으로는 충분하지 않아, 매일 자체 평가를 실행합니다.
    *   **VSC-Bench:** VS Code 에이전트 하네스를 위한 오프라인 평가 스택으로, 5줄짜리 스모크 테스트부터 전체 벤치마크 스위트까지 매일 수많은 작업 변형을 실행합니다.
    *   **모든 하네스 변경 측정:** 토큰 비용이 감소하는 동안 작업 성공률이 유지되는지 측정합니다. 회귀는 변경 실패를 의미하며, 하네스는 데이터에 맞춰 조정됩니다.
    *   **오프라인 + 온라인 시스템:** 오프라인 평가는 결함이 있을 수 있으므로, 프로덕션 환경에서 A/B 프롬프트 실험을 통해 놓치는 부분을 포착합니다.
    *   **5글자 파일 실험:** 50,974번의 5줄 평가 실행, 20개 모델, 6개월 동안 동일한 5글자 파일에 대해 가장 비싼 모델이 최대 70배 더 많은 토큰을 사용했습니다. 이는 모델 크기가 예측하지 못하는 '노력 보정(effort calibration)'의 격차를 보여줍니다.
    *   **프로토타입 기반 논의:** 프로토타입이 곧 사양입니다. 아이디어를 프로토타입으로 만들고, 팀의 반응을 얻어 반복하며, 2~3개월 걸리던 디자인 과정을 2주로 단축했습니다.

**결론:**
세 가지 핵심 사항을 강조하며 발표를 마무리했습니다.
1.  **병목 현상은 계속 이동하며, 기존의 문제는 사라지지 않는다.** 코드를 작성하고, 안전하게 릴리스하며, 올바른 것을 배포하고 있다는 것을 아는 것은 복합적으로 작용합니다.
2.  **하네스만 튜닝하지 말고, 루프를 닫아라.** 더 나은 하네스는 한 단계를 날카롭게 만들지만, 모든 승리는 엔드투엔드 루프(평가, 가드레일, 관찰 가능성)에서 나옵니다. 모델 교체만으로는 안 됩니다.
3.  **성공이 시험대다.** 성공했을 때 무엇이 일어나는지 질문하세요. 가장 긴 피드백 루프를 찾으세요. 그것이 가장 높은 레버리지 에이전트입니다.

## 실무 적용 포인트
-   **AI 에이전트의 컨텍스트 제공:** 에이전트가 코드베이스를 더 잘 이해하도록 `AGENTS.md`와 같은 문서를 작성하고, 전문가 지식을 스킬 형태로 인코딩하여 에이전트의 효율성을 높일 수 있습니다.
-   **CI/CD 파이프라인 최적화:** 에이전트가 반복적으로 빌드를 실행할 때 발생하는 병목 현상을 식별하고, TypeScript Go와 같은 기술을 활용하여 빌드 시간을 단축하는 등 CI/CD 파이프라인을 최적화해야 합니다.
-   **자동화된 품질 게이트 구축:** AI를 활용하여 이슈 필터링, 중복 제거, 담당자 할당을 자동화하고, UI 변경에 대한 시각적 회귀 테스트(컴포넌트 브라우저, 스크린샷 비교)를 도입하여 코드 리뷰의 효율성과 품질을 향상시킬 수 있습니다.
-   **자체 평가(Eval) 인프라 구축:** 공개 벤치마크에만 의존하지 않고, 자체적으로 에이전트의 성능을 평가하고 개선할 수 있는 오프라인 및 온라인 평가 스택을 구축하여, 모델과 하네스의 상호작용을 이해하고 제품 개선에 활용할 수 있습니다.
