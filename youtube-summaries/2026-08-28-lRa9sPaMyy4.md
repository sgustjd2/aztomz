# Your Code Has Bugs. Lean4 Has Proofs: Formal Verification for Engineers — Varun Pant, AWS

🔗 https://youtu.be/lRa9sPaMyy4 · 📅 2026-08-28 · 🎙 AI Engineer

## 한 줄 요약
AI 에이전트가 생성하는 코드의 정확성을 보장하기 위해 형식 검증(Formal Verification)을 활용하여, 확률적 정확성을 넘어 수학적으로 증명 가능한 소프트웨어 시스템을 구축하는 방법을 제시합니다.

## 발표자·소속
Varun Pant, AWS Builder Center

## 핵심 주장
- **AI 생성 코드의 정확성 검증 필요성:** AI 코딩 에이전트가 방대한 양의 코드를 생성하고 있지만, 기존의 LLM 기반 판단, 테스트, 수동 코드 리뷰 방식으로는 모든 입력에 대한 코드의 정확성을 보장할 수 없습니다.
- **형식 검증의 역할:** 형식 검증은 모든 가능한 입력에 대해 코드가 올바르다는 수학적 증명을 제공하여, 소프트웨어의 신뢰성을 극대화하는 유일한 방법입니다.
- **Lean 언어의 활용:** Lean은 정의와 증명을 동일한 언어로 작성할 수 있는 프로그래밍 언어이자 증명 보조 도구로, 작은 신뢰 커널을 통해 증명을 독립적으로 검증할 수 있어 형식 검증에 이상적입니다.
- **명세 주도 개발(Spec-driven development) 방법론:** 먼저 '올바름'의 의미를 명세(specification)로 작성하고 이를 검증한 후, AI 코딩 에이전트가 해당 명세를 기반으로 코드를 구현하고, 형식 검증 도구가 구현이 명세와 일치함을 증명하는 방식으로 개발을 진행합니다.
- **다양한 언어에 대한 형식 검증 확장:** Rust와 같은 다른 프로그래밍 언어로 작성된 코드도 Lean을 활용한 기능적 명세나 SMT 솔버를 통해 검증할 수 있으며, AWS는 Strata라는 오픈소스 툴을 통해 모든 프로그래밍 언어에 대한 형식 검증을 지원하는 것을 목표로 하고 있습니다.

## 세부 내용
발표자는 코딩 에이전트가 전례 없는 양의 코드를 생성하고 있지만, 이 코드의 정확성을 어떻게 보장할 것인지에 대한 문제를 제기하며 발표를 시작했습니다. LLM 기반 판단은 확률적이고, 테스트는 일부 입력만 확인하며, 인간의 코드 리뷰는 에이전트의 속도를 따라갈 수 없다는 한계를 지적했습니다. 이러한 방법들로는 "모든 입력에 대해 코드가 올바르다"고 말할 수 없으며, 오직 형식 검증만이 이를 가능하게 한다고 강조했습니다.

형식 검증은 모든 입력에 대해 코드가 올바르다는 수학적 증명을 제공합니다. 이 과정은 '올바름'의 의미(명세)를 작성하는 것에서 시작하며, 이는 형식적으로 작성되거나 AI가 자연어 설명을 자동 형식화할 수 있습니다. 중요한 것은 이 명세가 인간의 검토와 테스트를 통해 유효성이 검증되어야 한다는 점입니다. 명세가 확정되면, AI 코딩 에이전트가 이 명세에 따라 코드를 구현하고, 형식 검증 도구가 구현이 명세와 일치함을 증명합니다. 발표자는 "인간은 명세를 소유하고, 기계는 코드와 증명을 소유한다"고 설명했습니다.

Lean은 프로그래밍 언어이자 증명 보조 도구로, 정의와 증명을 동일한 언어로 작성할 수 있어 번역 계층이 필요 없습니다. Lean 자체도 Lean으로 구현되어 확장성이 뛰어나며, 특히 작은 신뢰 커널(trusted kernel)을 가지고 있어 증명을 내보내 독립적으로 확인할 수 있습니다. 발표자는 Lean의 작동 방식을 체스에 비유하며, LLM이 전술(tactics)을 제안하고 커널이 이를 확인하는 과정을 설명했습니다. 잘못된 증명은 즉시 거부되며, C++, Rust 등 다양한 언어로 구현된 독립적인 커널을 사용할 수 있습니다.

실제 적용 사례로, AI가 C 압축 라이브러리인 Zlib을 Lean으로 변환한 예시를 들었습니다. 자연어 명세("압축 해제 결과가 모든 입력과 모든 압축 수준에서 원본 데이터를 반환한다")를 AI가 형식 명세로 변환하고, AI가 생성한 헬퍼 렘마(sub-goal)들을 통해 최종 정리를 증명했습니다. 이 과정에서 AI는 문제를 렘마로 분해하고, 각 렘마를 전술을 사용하여 증명한 후, 최종 정리를 구성하고 커널이 이를 확인했습니다. 이 특정 예시에는 약 32,000줄의 증명 코드가 포함되어 있었습니다.

두 번째 예시로 Rust로 작성된 코드와 Lean으로 작성된 기능적 명세를 함께 사용하는 Cedar 사례를 소개했습니다. Cedar는 AWS Verified Permissions 및 AWS Verified Access에서 사용되는 오픈소스 권한 부여 정책 언어입니다. Cedar의 명세는 Lean으로 작성되었고, 실제 프로덕션 코드는 Rust로 실행됩니다. 이 시스템은 매일 밤 1억 건의 차등 무작위 테스트를 통해 Lean 모델과 Rust 구현이 동일한 결과를 내는지 확인하며, 모델, 증명, 차등 테스트가 모두 최신 상태가 아니면 새 버전이 출시되지 않는 "릴리스 게이트"를 운영합니다.

세 번째 예시에서는 Rust 코드를 Lean 또는 솔버(solver)로 검증하는 방법을 설명했습니다. Verus라는 오픈소스 도구는 Rust 프로그래머가 `requires`(사전 조건) 및 `ensures`(사후 조건) 키워드를 사용하여 명세를 추가할 수 있도록 합니다. 이 명세는 정적 검사로 검증자에 의해 강제되며 런타임에는 제거됩니다. 또한, Rust의 중간 표현(IR)을 Lean으로 기능적으로 번역하여 증명하는 Aeneas 프로젝트도 소개했습니다.

마지막으로, AWS는 Strata라는 오픈소스 툴(현재 개발 중)을 통해 어떤 프로그래밍 언어든 검증할 수 있는 비전을 제시했습니다. Strata는 Python, Java, Rust 등 다양한 언어의 프론트엔드를 Strata Dialect를 거쳐 Lean으로 작성된 Core로 변환하고, 이를 SMT 솔버, 모델 체커, Lean 증명과 같은 다양한 분석 엔진으로 디스패치하는 구조입니다.

발표자는 청중에게 `https://live.lean-lang.org/`에서 Lean을 시작해 볼 것을 권하며, 가장 중요한 코드를 선택하고, '올바름'의 의미를 명세로 작성한 다음, 코딩 에이전트가 이를 구현하고 형식 검증 도구가 증명하도록 하는 3단계 접근법을 제시했습니다. 결론적으로, "이 용감한 신세계에서 우리는 아마도 올바른(probably correct) 소프트웨어와 시스템이 아니라, 증명 가능한(provably correct) 소프트웨어와 시스템을 갖게 될 것"이라고 역설하며 발표를 마쳤습니다.

## 인상적인 대목
- "None can say: 'For ALL inputs, this is correct.' Formal verification can." (어떤 것도 '모든 입력에 대해 이것이 올바르다'고 말할 수 없습니다. 형식 검증은 가능합니다.)
- "Humans own the spec. Machines own the code and proof." (인간은 명세를 소유하고, 기계는 코드와 증명을 소유합니다.)
- "AI did the work. Kernel kept it honest." (AI가 작업을 수행했습니다. 커널이 정직하게 유지했습니다.)
- "Hopefully in this brave new world, we have software and systems that are not probably correct, but provably correct." (이 용감한 신세계에서 우리는 아마도 올바른 소프트웨어와 시스템이 아니라, 증명 가능한 소프트웨어와 시스템을 갖게 될 것입니다.)

## 실무 적용 포인트
- **핵심 코드베이스에 형식 검증 도입 고려:** 보안, 안정성, 신뢰성이 매우 중요한 시스템의 핵심 코드에 대해 형식 검증을 적용하여 잠재적 버그를 제거하고 견고성을 확보할 수 있습니다.
- **명세 주도 개발(Spec-driven development) 채택:** 개발 초기 단계부터 '무엇이 올바른지'에 대한 명확하고 형식적인 명세를 작성하고 이를 검증하는 과정을 통해, 개발 과정에서 발생할 수 있는 오류를 줄이고 코드의 품질을 향상시킬 수 있습니다.
- **Lean 언어 및 관련 도구 학습:** Lean은 증명 보조 도구로서 코드와 증명을 통합하는 강력한 기능을 제공합니다. `https://live.lean-lang.org/`에서 직접 Lean을 체험하며 형식 검증의 기본 원리를 이해하고 활용법을 익힐 수 있습니다.
- **다국어 형식 검증 프레임워크 활용:** Strata와 같은 오픈소스 프로젝트를 통해 Rust, Python, Java 등 다양한 프로그래밍 언어로 작성된 코드에 대한 형식 검증 가능성을 탐색하고, 장기적으로는 기존 시스템의 검증 프로세스에 통합하는 방안을 모색할 수 있습니다.
