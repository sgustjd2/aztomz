# Skill issue: stop deploying vision language models, use them with Skills — Merve Noyan, Hugging Face

🔗 https://youtu.be/dKcTBQzR7jI · 📅 2026-09-23 · 🎙 AI Engineer

## 한 줄 요약
발표자는 Hugging Face의 VibeVision 툴킷을 소개하며, 개발자들이 비전 언어 모델(VLM)을 직접 사용하는 대신 에이전트를 활용하여 효율적이고 비용 효율적으로 비전 애플리케이션을 구축하도록 돕는 방법을 제시합니다.

## 발표자·소속
Merve Noyan, Hugging Face

## 핵심 주장
- **VLM의 비효율성:** 비전 언어 모델은 범용성이 높지만, 특정 비전 작업에 직접 사용하기에는 너무 크고 비용이 많이 들며 실시간 처리 및 견고성 측면에서 비효율적입니다.
- **에이전트 기반 비전 개발의 필요성:** 개발자들이 VLM을 직접 사용하는 대신, 에이전트가 특정 작업에 최적화된 소형 모델을 선택하고 훈련하는 파이프라인을 활용하여 비전 애플리케이션을 구축해야 합니다.
- **라이선스 문제의 중요성:** 많은 개발자가 YOLO와 같은 인기 모델의 상업적 사용 제한 라이선스를 인지하지 못하고 배포하는 실수를 저지르므로, Apache 2.0과 같은 상업적으로 허용되는 라이선스 모델로 전환해야 합니다.
- **VibeVision 툴킷의 역할:** VibeVision은 VLM을 라벨러 및 심사관으로 활용하여 데이터셋을 자동으로 라벨링하고, 이를 기반으로 RF-DETR과 같은 작고 효율적인 모델을 훈련하는 에이전트 친화적인 워크플로우를 제공합니다.

## 세부 내용
발표자는 컴퓨터 비전 및 멀티모달 분야에서 3년간 일했으며, 최근에는 온디바이스 및 에이전트 기술에 집중하고 있다고 소개했습니다. 비전 언어 모델(VLM)에 대한 애정으로 책까지 썼지만, 개발자들이 VLM을 단순 작업에 직접 사용하는 것을 지양하고 에이전트를 통해 비전 앱을 구축하기를 바란다고 강조했습니다.

발표자가 관찰한 개발자들의 일반적인 행동은 다음과 같습니다.
- 자연어 사용이 쉽다는 이유로 모든 작업에 VLM을 사용하려 하지만, 대부분의 경우 VLM은 너무 크고 비싸며 실시간, 저비용, 저지연 처리가 불가능합니다. 특정 작업에 훈련된 모델보다 견고하지도 않습니다.
- 개발자들이 YOLO와 같은 모델의 비상업적 라이선스(AGPL 3.0)를 확인하지 않고 상업적으로 배포하는 경우가 많습니다. 발표자는 Apache 2.0 라이선스 모델로의 전환을 권장했습니다.

이러한 문제 해결을 위해 발표자는 "VibeVision"이라는 에이전트 기반 컴퓨터 비전 툴킷을 구축했습니다. 이 툴킷은 Maziyar Panahi의 Gemma-4가 SAM 3.1을 도구로 사용하여 주차장의 차량을 세그먼트하는 사례에서 영감을 받았습니다. VibeVision은 라벨링, 성능, '바이브'를 기준으로 모델을 선택하며, 상업적 사용이 가능한 라이선스를 최우선으로 고려합니다.

VibeVision의 핵심은 VLM을 활용한 라벨링 및 훈련 파이프라인입니다.
1.  **라벨링:** Qwen3.5-9B와 같은 VLM을 사용하여 이미지 데이터셋을 라벨링합니다.
2.  **심사(Judging):** 라벨링된 데이터셋을 Gemma-4-E4B-it (8B 파라미터)와 LFM2.5-VL-1.6B (1.6B 파라미터) 두 개의 VLM 심사관에게 전달합니다. 심사관에게는 바운딩 박스가 오버레이된 이미지와 라벨 설명이 프롬프트로 제공됩니다. 라벨 설명은 코딩 에이전트가 생성합니다.
3.  **병합(Merging):** 두 심사관의 판단을 병합합니다. LFM2.5-VL-1.6B가 Gemma-4-E4B-it에 비해 '부정확한' 판단(거부)이 많았기 때문에, 최소 1개의 심사관이 동의하면 해당 라벨을 채택하는 '최소 동의' 방식을 사용했습니다. 이는 데이터셋의 예시 수를 보존하여 모델 성능 저하를 막기 위함입니다.
4.  **훈련(Training):** 병합된 라벨을 사용하여 RF-DETR-medium (33.7M 파라미터)과 같은 작고 효율적인 실시간 객체 탐지 모델을 훈련합니다.

이 파이프라인은 Hugging Face의 서버리스 인프라(Inference Providers)와 배치 처리 잡스(Jobs)를 활용하여 실행되며, 1.4k 이미지 전체 파이프라인 실행에 약 3~4달러의 비용이 든다고 언급했습니다. 라벨링은 DeepInfra를 통해 1.4k 이미지당 0.16달러, 심사 및 훈련은 Hugging Face Jobs를 통해 L4 GPU에서 시간당 0.47~1.8달러로 저렴하게 수행됩니다.

VibeVision은 두 가지 문제에 대해 테스트되었습니다.
1.  **도로 표지판 감지:** Qwen이 생성한 의사 라벨(pseudo-labels)로 훈련한 모델의 mAP50은 0.9693이었고, 인간 GT(Ground Truth) 라벨로 비교한 mAP50은 0.8028이었습니다. ROC-AUC는 0.987로 높은 성능을 보였습니다.
2.  **문서 파싱:** DocVQA 데이터셋에서 텍스트가 아닌 미디어(서명, 이미지 등)를 추출하는 작업에서, 훈련된 모델은 Qwen3.5가 놓친 서명을 감지하는 등 뛰어난 일반화 능력을 보여주었습니다.

발표자는 이 파이프라인이 하이퍼파라미터 튜닝 없이도 좋은 베이스라인을 제공하지만, 자연어로 설명하기 어려운 산업용 사용 사례에서는 한계가 있을 수 있다고 인정했습니다. 이러한 경우 이미지 가이드드 탐지(Image-guided detection)가 도움이 될 수 있다고 제안했습니다.

향후 계획으로는 비용과 시간을 줄이기 위한 더 작은 모델 사용, IoU(Intersection over Union) 기반 심사 병합(실험 중), RF-DETR-Seg를 활용한 세그멘테이션 지원 등이 있습니다.

## 인상적인 대목
- "Just because a model is open-source doesn't mean you can use it!" (모델이 오픈소스라고 해서 무조건 사용할 수 있는 것은 아닙니다!)
- "your coding agent, despite no matter how good it is... it's clueless as a computer vision engineer as well as it misses common sense." (아무리 훌륭한 코딩 에이전트라도... 컴퓨터 비전 엔지니어로서 무지하며 상식도 부족합니다.)

## 실무 적용 포인트
- **라이선스 확인 필수:** 모델을 상업적으로 사용하기 전에 반드시 라이선스 조건을 확인하여 AGPL 3.0과 같이 상업적 사용에 제한이 있는 모델을 피하고, Apache 2.0과 같은 허용적인 라이선스 모델을 선택해야 합니다.
- **VLM의 전략적 활용:** VLM을 최종 배포 모델로 직접 사용하기보다는, 데이터 라벨링 및 라벨 심사와 같은 전처리 단계에서 활용하여 비용과 시간을 절약하고, 실제 배포에는 RF-DETR과 같은 작고 효율적인 태스크별 모델을 훈련하여 사용하는 것이 효과적입니다.
- **에이전트 기반 파이프라인 도입:** Hugging Face의 VibeVision과 같은 툴킷을 활용하여 라벨링, 심사, 훈련 과정을 자동화하고, 코딩 에이전트가 이 파이프라인을 관리하도록 하여 개발 효율성을 높일 수 있습니다.
- **데이터 증강(Augmentation)의 신중한 적용:** 코딩 에이전트가 데이터 증강을 자동으로 적용할 때, 도로 표지판의 좌우 반전처럼 의미를 왜곡하거나 트래픽 라이트에 색상 지터(color jitter)를 적용하여 데이터를 손상시키는 경우가 있으므로, 특정 작업에 대한 증강 기법은 인간의 검토와 승인을 거쳐야 합니다.
