# I Made a Fruit Fly Review My Code - Nick Nisi, WorkOS

🔗 https://youtu.be/geMAe-PLJF4 · 📅 2026-11-01 · 🎙 AI Engineer

## 한 줄 요약
AI가 작성한 코드의 리뷰 과정에서 인간이 병목 현상이 되고 있음을 지적하며, 초파리 뇌의 연결체(connectome)를 활용한 AI 모델로 코드 리뷰를 자동화하고 인간은 더 복잡한 '왜'라는 질문에 집중해야 한다고 주장한다.

## 발표자·소속
닉 니시(Nick Nisi), WorkOS 엔지니어링 매니저, 개발자 및 에이전트 경험 팀 리더

## 핵심 주장
-   **코드 리뷰는 소프트웨어 개발의 병목 현상이다:** AI가 코드를 빠르게 작성하고 CI/린팅/코드 에이전트가 버그를 찾아내지만, 여전히 인간의 코드 리뷰가 필요하여 출시 속도를 늦추는 주된 원인이 되고 있다.
-   **인간은 더 이상 코드 작성에 전적으로 투자하지 않는다:** AI 코드 생성 도구의 발전으로 코드를 직접 작성하는 것보다 생성된 코드를 관리하는 역할로 전환되고 있으며, 이는 코드 리뷰의 본질적인 변화를 요구한다.
-   **코드의 기능성이 외형보다 중요하다:** CI, Greptile, CodeRabbit과 같은 도구들이 이미 코드의 버그를 찾아내고 테스트를 통과시키므로, 코드의 외형이나 스타일보다는 실제 기능이 제대로 작동하는지가 더 중요해졌다.
-   **코드 리뷰의 목적은 '무엇이' 아닌 '왜'에 집중해야 한다:** 미래의 코드 리뷰는 단순히 코드 변경 사항을 승인하는 것을 넘어, 변경이 발생한 이유와 그 변경이 시스템에 미치는 영향에 대한 맥락을 인간에게 제공하는 방향으로 진화해야 한다.
-   **초파리 뇌 모델을 활용한 코드 리뷰 자동화:** 초파리 뇌의 실제 신경망(connectome)을 기반으로 한 AI 모델이 코드 변경 사항을 '냄새'로 인지하고, 과거 학습된 '좋은 코드'와 '나쁜 코드'의 기억을 바탕으로 변경 승인 여부를 결정할 수 있다.

## 세부 내용

발표자는 소프트웨어 개발에서 코드 리뷰가 가장 큰 병목 현상이라고 지적하며 강연을 시작한다. AI가 코드를 빠르게 작성하고 CI/CD 파이프라인이 린팅, 테스트, 코드 에이전트(Greptile, CodeRabbit 등)를 통해 많은 문제를 자동으로 감지하지만, 여전히 인간의 승인이 필요한 단계에서 지연이 발생한다는 것이다. 발표자 본인도 이러한 병목 현상의 원인이 되고 있다고 인정하며, 코드를 직접 작성하는 것보다 관리하는 역할로 전환되고 있다고 설명한다.

발표자는 코드 리뷰의 초점이 '무엇이 변경되었는지'에서 '왜 변경되었는지'로 바뀌어야 한다고 강조한다. 이를 설명하기 위해 '버그(bug)'라는 용어의 유래(1947년 컴퓨터 릴레이에 끼인 나방)를 언급하며, 2026년에는 '버그'가 '버그'를 찾는 시대가 될 것이라고 말한다.

발표자는 초파리 뇌의 연결체(connectome)를 활용한 AI 모델을 소개한다. 이 모델은 176,422개의 뉴런, 630만 개의 연결, 1억 2,500만 개의 시냅스로 구성된 실제 초파리 뇌의 와이어링 다이어그램이다. 발표자는 이 뇌 모델에 코드 리뷰 기능을 학습시켰다.

**초파리 뇌 기반 코드 리뷰 시스템의 작동 방식:**
1.  **냄새(The noise) - 특징 추출(Feature Extraction):** AI 모델(Jev, System 1 모델)이 코드 변경 사항에 대해 30가지 비편향적인 질문을 던지고, 그 답변을 '냄새'로 변환한다.
2.  **기억(The memory) - 해킹(Hacking):** 이 '냄새'는 6,384개의 기억 세포 중 약 5%를 활성화시킨다. 모델은 코드베이스의 '좋은 코드'와 '나쁜 코드'를 학습하여 기억하고 있다. '좋은 코드'는 설탕 냄새, '나쁜 코드'는 쓴 냄새로 인지한다.
3.  **교사(The teacher) - 훈련(Training - The Mute):** 테스트 결과가 '맛'이 된다. 버그가 재현되면 '쓴맛'으로 인지하여 처벌 도파민(punishment dopamine)을 분비하고, '접근(approach)' 관련 뉴런 연결을 약화시킨다. 테스트가 통과되면 '설탕'으로 인지하여 보상 도파민(reward dopamine)을 분비하고, '회피(avoid)' 관련 뉴런 연결을 약화시킨다.
4.  **투표(The vote) - 추론(Inference - The Read):** 최종적으로 초파리는 '혀를 내밀면(tongue out)' 승인(Smells Good To Me), '뒤로 물러나면(backs away)' 변경 요청(Changes Requested)을 의미한다.

발표자는 청중과 함께 "당신은 초파리보다 똑똑한가요?"라는 게임을 진행한다. 세 가지 실제 코드 변경 사항을 보여주고 청중과 초파리 AI가 각각 승인/변경 요청을 결정한다.
-   **라운드 1 (src/punycode.ts):** 청중은 변경 요청, 초파리는 승인. 실제 결과는 버그. (초파리 틀림)
-   **라운드 2 (src/pkce.ts):** 청중은 승인, 초파리도 승인. 실제 결과는 무해한 변경. (초파리 맞음)
-   **라운드 3 (src/create-client.ts):** 청중은 변경 요청, 초파리도 변경 요청. 실제 결과는 버그. (초파리 맞음)
게임 결과, 청중은 3/3, 초파리는 2/3으로 청중이 더 나은 성능을 보였다. 발표자의 테스트에서는 초파리가 약 88%의 정확도를 보였다고 언급한다.

발표자는 초파리 AI가 코드 변경 사항의 '무엇'이 바뀌었는지는 알지만, '왜' 바뀌었는지는 모른다는 점을 지적하며, 이것이 여전히 인간의 역할이라고 강조한다.

**제안하는 시스템(Proposed System):**
인간을 모든 코드 리뷰에서 제외하고, 필요한 경우에만 에스컬레이션하는 시스템을 제안한다.
1.  **팀 리뷰 스킬(Team review skill):** 코드 소유자(code owners)가 팀의 리뷰 방식을 유지한다. (예: DX 팀은 DX 엔지니어가 코드 리뷰에서 중요하게 보는 최소한의 기준을 AI에 학습시킨다.)
2.  **분류기(Classifier):** Jev 또는 다른 모델이 변경 사항의 복잡성을 평가한다.
3.  **자동 리뷰(Automated review):** 테스트, 목(mock), CI/CD 검사 등을 수행한다.
4.  **병합 또는 에스컬레이션(Merge, or escalate):** 모든 자동화된 검사를 통과하면 자동으로 병합하고, 실패하거나 너무 복잡하면 인간에게 에스컬레이션한다.
5.  **인간에게 요약 제공(A human, summarized):** 에스컬레이션된 경우, 인간에게 비즈니스 로직, 변경 이유, 다른 대안이 왜 기각되었는지 등을 요약하여 제공한다.

이 시스템은 에이전트가 스크린샷, 비디오, 테스트 결과, 커맨드 출력, 스모크 테스트 등 변경 사항을 재현할 수 있는 쉬운 방법을 제공하여 인간이 검증할 수 있도록 돕는다. 최종적으로, AI가 생성한 리뷰는 '인간이 봐야 할 것'과 'AI가 이미 검증한 것'으로 나뉘어 표시될 수 있다.

발표자는 fruitfly.review 웹사이트에서 직접 자신의 풀 리퀘스트를 실행해 볼 수 있다고 안내하며 강연을 마무리한다.

## 실무 적용 포인트
-   **AI 기반 코드 리뷰 도구 적극 활용:** Greptile, CodeRabbit 등 AI 기반 코드 에이전트를 CI/CD 파이프라인에 통합하여 기본적인 버그 감지, 린팅, 테스트 통과 여부 등을 자동화한다.
-   **팀별 코드 리뷰 스킬 정의 및 자동화:** 각 개발 팀이 중요하게 생각하는 코드 품질 기준, 아키텍처 원칙 등을 명확히 정의하고, 이를 AI 모델에 학습시켜 팀별 맞춤형 자동 리뷰 시스템을 구축한다.
-   **인간 리뷰어의 역할 재정의:** 단순하고 반복적인 코드 변경 리뷰는 AI에 맡기고, 인간 개발자는 변경의 비즈니스 로직, 아키텍처 영향, 장기적인 유지보수성 등 '왜'라는 질문에 대한 깊이 있는 분석과 의사 결정에 집중한다.
-   **AI 리뷰 결과의 투명성 확보:** AI가 코드 변경을 승인하거나 변경을 요청할 때, 스크린샷, 비디오, 테스트 결과, 커맨드 출력 등 변경 사항을 재현하고 검증할 수 있는 증거를 함께 제공하도록 시스템을 설계하여 인간의 신뢰를 높인다.
