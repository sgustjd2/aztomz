# What It Actually Takes to Build a Software Factory — Tereza Tížková, Factory

🔗 https://youtu.be/vGCJ7diEtrw · 📅 2026-09-27 · 🎙 AI Engineer

## 한 줄 요약
발표자는 소프트웨어 팩토리를 자율적으로 소프트웨어를 개발하는 전체 라이프사이클로 정의하며, 이를 구축하기 위해 시스템이 '불가지론적(Agnostic)', '자율적(Autonomous)', '지속적으로 개선(Always Improving)'되어야 한다고 강조합니다.

## 핵심 주장
- **소프트웨어 팩토리는 자율적인 개발의 전체 사이클입니다.** 단순히 코드 생성 에이전트를 넘어, 신호 수집, 우선순위 지정, 실행, 검증, 그리고 지속적인 개선을 포함하는 완전한 루프를 의미합니다.
- **AI 기술 발전으로 소프트웨어 팩토리 구축이 가능해졌습니다.** 과거에는 환각 현상, 컨텍스트 길이 제한, 추론 품질 문제 등으로 어려웠지만, 최근 LLM의 발전과 영구적인 환경 구축 기술 덕분에 현실화되고 있습니다.
- **AI 도입은 '무엇을 만들지'에 집중하는 인간의 역할을 강화합니다.** AI가 '어떻게 만들지'를 담당하면서 인간은 더 높은 수준의 창의적이고 전략적인 의사 결정에 집중할 수 있게 됩니다.
- **성공적인 AI 도입을 위해서는 'AI 위에 구축'해야 합니다.** 단순히 기존 시스템에 AI를 '도입'하는 것을 넘어, 조직과 코드베이스를 AI에 맞춰 근본적으로 재구성하는 것이 중요하며, 그렇지 않으면 오히려 코드 품질 저하 등의 역효과를 낳을 수 있습니다.

## 세부 내용

발표자는 소프트웨어 팩토리에 대한 논의가 활발하지만, 실제로 구축하는 사람은 적고 그 의미를 아는 사람도 드물다고 지적하며 강연을 시작합니다. 발표자는 소프트웨어 팩토리를 "자율적으로 소프트웨어를 개발하는 전체 라이프사이클"로 정의합니다. 이는 신호 수집, 분류, 계획, 실행, 검증, 그리고 이 모든 과정의 반복을 포함합니다.

소프트웨어 팩토리가 가능해진 것은 최근 2년간의 AI 기술 발전 덕분입니다. 2021년 코파일럿(Copilot)의 자동 완성 기능부터 챗GPT(ChatGPT), GPT-4, 커서(Cursor)를 통한 코드 생성, 그리고 데빈(Devin)과 같은 첫 번째 에이전트의 등장까지, 컨텍스트 창의 확장, 추론 능력 향상, 영구적인 환경(persistent environments)의 발전이 핵심적인 역할을 했습니다. 과거에는 LLM의 환각 현상, 컨텍스트 길이 제한, 추론 품질 문제 등으로 완전한 소프트웨어 팩토리 구축이 어려웠습니다.

발표자는 AI를 '도입'하는 것과 'AI 위에 구축'하는 것의 차이를 강조합니다. 소프트웨어 팩토리는 단순한 코딩 에이전트나 컨설팅 전략이 아니며, 조직을 근본적으로 재구성해야 한다고 주장합니다.

소프트웨어 팩토리를 구축하는 세 가지 중요한 원칙은 다음과 같습니다:

1.  **불가지론적(Agnostic):**
    *   **인터페이스 독립성:** 슬랙(Slack), CLI, 데스크톱, 휴대폰 등 다양한 환경에서 작동해야 합니다.
    *   **구독 독립성:** 사용자가 자신의 모델 키와 머신을 가져와 사용할 수 있어야 합니다.
    *   **토큰 최적화:** 단순히 비용 절감을 넘어 토큰 사용을 최적화해야 합니다. 코인베이스(Coinbase) 사례에서 보듯이, 기본 모델을 개선하고 캐싱(caching)을 활용하며, 지능형 라우팅(routing)을 통해 토큰 사용량을 줄이면서도 효과를 높일 수 있습니다.
    *   **자동 라우팅:** 팩토리(Factory)의 자동 모델 라우팅은 LLM 간의 스마트한 라우팅을 통해 비용을 25% 이상 절감하고, 신뢰성(제공업체 장애 시 자동 전환)과 속도(오픈소스 모델 활용)를 향상시킵니다. 라우팅의 핵심은 분류기(classifier)에 있으며, 프롬프트 구조, 코드베이스, 도구 사용, 난이도 등을 분석하여 최적의 모델을 선택합니다.
    *   **캐싱:** 첫 번째 프롬프트는 전체 비용이 청구되지만, 캐싱을 통해 두 번째 메시지부터는 10배 이상 저렴해질 수 있습니다. 오픈 모델도 전용 컴퓨팅에서 호스팅하여 캐싱 효율성을 높일 수 있습니다.

2.  **자율적(Autonomous):**
    *   **루프의 진화:** 루프(Loops) 개념은 수학적 귀납법, 1950년대 코드 루프, 2010년대 학습 루프, 2023년 도구 루프를 거쳐 2025년 소프트웨어 팩토리 루프까지 발전했습니다. 중요한 것은 '완료'의 기준을 명확히 정의하는 것입니다.
    *   **검증 가능한 루프:** 에이전트가 자율적으로 장시간 실행될 수 있지만, 여전히 50% 정도의 신뢰성만 보장됩니다. '치팅', '루프 깨짐', '불명확한 조건' 등의 문제가 발생할 수 있으므로, 루프는 검증 가능해야 합니다.
    *   **팩토리 미션(Factory Missions):** 팩토리의 미션은 장기 실행 자율 세션으로, 오케스트레이터(Orchestrator)가 검증 계약(validation contract)을 작성하고, 워커(Workers) 에이전트가 기능을 구현하며, 검증자(Validators) 에이전트가 결과물을 검토하는 방식으로 작동합니다. 검증자는 코드를 직접 작성하지 않고, 코드 검토(scrutiny validator)와 사용자 테스트(user-testing validator)를 통해 품질을 확인합니다.

3.  **지속적으로 개선(Always Improving):**
    *   **컨텍스트 문제:** 에이전트가 수백 개의 도구를 사용하는 기업 환경에서는 컨텍스트 블로트(context bloat) 문제가 발생할 수 있습니다. 이는 잘못된 도구 선택, 주의력 분산, 증거 손실 등으로 이어집니다.
    *   **점진적 공개(Progressive Disclosure):** 팩토리의 '지연 컨텍스트 엔진(Deferred Context Engine)'은 도구를 점진적으로 공개하여 컨텍스트를 관리합니다. 처음에는 도구의 간략한 설명만 제공하고, 필요할 때 전체 스키마를 로드하여 캐싱합니다. 이를 통해 토큰 사용량을 50% 이상 절감할 수 있습니다.
    *   **AI 도입의 양면성:** AI 도입은 생산성 격차를 12배까지 벌릴 수 있으며, 구조화되지 않은 코드베이스에 AI를 적용하면 오히려 코드 품질이 3~16배 저하될 수 있습니다. 중요한 것은 '모델'이 아니라 '구조'입니다.
    *   **에이전트 준비도(Agent Readiness):** 코드 스타일 및 검증, 빌드 시스템, 테스트, 문서화, 개발 환경, 관찰 가능성, 보안, 작업 발견 등 8가지 지표를 통해 에이전트 준비도를 측정하고 개선할 수 있습니다.
    *   **반복 작업 중단:** 플러그인(재사용 가능한 스킬 패키지), 오토위키(자동 생성 문서), 컨텍스트 엔진(지연 컨텍스트, 범위 지정 도구, 구조화된 사용자 선호도)을 통해 에이전트에게 반복적으로 지시하는 것을 줄일 수 있습니다.

발표자는 AI가 인간의 일자리를 빼앗는 것이 아니라, 인간이 '무엇을 만들지'에 집중하고 에이전트가 '어떻게 만들지'를 담당하는 방향으로 진화할 것이라고 긍정적인 전망을 제시합니다. 기업이 내부 정렬(internal alignment)에 50% 이상의 시간을 소비하는 현실에서, 이러한 작업들을 에이전트에게 위임하여 인간은 더 가치 있는 일에 집중할 수 있다고 말하며 발표를 마칩니다.

## 실무 적용 포인트
- **자동 모델 라우팅 도입 고려:** LLM 사용 시 비용, 신뢰성, 속도를 최적화하기 위해 여러 모델 간에 자동으로 요청을 라우팅하는 시스템을 구축하거나 활용합니다. 특히 분류기를 통해 프롬프트의 특성을 분석하여 적절한 모델을 선택하는 방식이 효과적입니다.
- **컨텍스트 관리 전략 수립:** 에이전트가 많은 도구를 다루는 환경에서 컨텍스트 블로트를 방지하기 위해 '점진적 공개' 방식을 적용합니다. 도구의 간략한 설명만 제공하고, 필요할 때만 전체 스키마를 로드하는 방식으로 토큰 사용량과 에이전트의 효율성을 높일 수 있습니다.
- **코드베이스 '에이전트 준비도' 평가 및 개선:** 코드 스타일, 빌드 시스템, 테스트, 문서화, 개발 환경, 관찰 가능성, 보안, 작업 발견 등 8가지 요소를 기준으로 코드베이스의 '에이전트 준비도'를 측정하고, AI가 더 효과적으로 작동할 수 있도록 개선합니다.
- **반복적인 지시를 줄이는 시스템 구축:** 플러그인(재사용 가능한 스킬 패키지), 오토위키(자동 업데이트 문서), 컨텍스트 엔진(사용자 선호도 반영) 등을 활용하여 에이전트에게 반복적으로 지시하는 수고를 줄이고, 에이전트가 스스로 학습하고 개선할 수 있는 환경을 조성합니다.
