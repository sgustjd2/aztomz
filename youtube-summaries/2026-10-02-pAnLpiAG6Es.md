# MCP Doesn't Suck. Your Agent Does. — Jan Čurn, Apify

🔗 https://youtu.be/pAnLpiAG6Es · 📅 2026-10-02 · 🎙 AI Engineer

## 한 줄 요약
MCP(Model Context Protocol)는 에이전트가 도구에 접근하는 표준 프로토콜이지만, 기존 에이전트 구현 방식의 비효율성을 개선하기 위해 `mcpc`라는 범용 CLI 클라이언트를 통해 MCP와 CLI의 장점을 결합하여 효율적이고 안전한 에이전트-도구 상호작용을 제안합니다.

## 발표자·소속
Jan Čurn, Apify의 창립자 겸 CEO

## 핵심 주장
-   **MCP는 그 자체로 문제가 아니라 에이전트의 구현 방식이 문제**: MCP 프로토콜 자체는 에이전트가 도구와 리소스에 안전하게 접근하는 표준이지만, 대부분의 에이전트가 모든 도구와 결과를 컨텍스트에 한꺼번에 로드하는 비효효율적인 방식으로 구현되어 있습니다.
-   **컨텍스트 관리 개선을 위한 세 가지 해결책**: 컨텍스트 오염 및 비용 문제를 해결하기 위해 서브 에이전트 분할, 점진적 도구 발견, 도구를 코드로 처리하는 코드 모드(Code Mode)와 같은 방법들이 제시되었습니다.
-   **CLI는 에이전트에게 자연스러운 인터페이스**: 에이전트는 CLI 도구를 코드처럼 실행하고, 필요할 때만 문서를 로드하며, 셸 명령어를 능숙하게 다루는 데 최적화되어 있습니다.
-   **MCP와 CLI의 결합이 최적의 솔루션**: 원격 접근에는 MCP의 표준화된 이점을 활용하고, 로컬 에이전트 인터페이스에는 CLI의 효율성과 유연성을 사용하여 두 가지 접근 방식의 장점을 모두 취하는 것이 가장 효과적입니다.
-   **`mcpc`는 MCP를 위한 범용 CLI 클라이언트**: `mcpc`는 MCP 프로토콜의 모든 기능을 지원하며, 경량이고, 에이전트와 사람 모두에게 사용하기 쉬우며, `--json` 옵션을 통해 코드 모드를 완벽하게 지원하여 효율적인 에이전트 개발을 돕습니다.

## 세부 내용

발표자는 AI 엔지니어링 컨퍼런스에서 "MCP Doesn't Suck. Your Agent Does."라는 제목으로 강연을 시작했습니다. Apify의 창립자 겸 CEO인 Jan Čurn은 MCP(Model Context Protocol)가 에이전트가 도구와 리소스에 안전하게 접근하기 위한 표준 프로토콜이라고 설명했습니다. Anthropic이 약 2년 전 도입한 이 프로토콜은 지난 해 AI 세계에서 큰 주목을 받았으며, 많은 서버와 클라이언트가 이를 채택하여 사실상의 표준이 되었습니다.

하지만 발표자는 MCP에 대한 많은 비판과 "MCP는 실수였다", "MCP는 쓸모없다"는 등의 부정적인 의견을 담은 유튜브 영상과 트윗들을 제시하며, 이러한 비판의 근본적인 원인을 분석했습니다.

**문제점**: 대부분의 에이전트가 모든 MCP 도구와 그 결과를 컨텍스트에 한꺼번에 로드하는 방식이 비효율적이라는 점을 지적했습니다. 에이전트가 질문을 하기도 전에 컨텍스트의 상당 부분이 도구 정의와 이전 결과로 채워져 토큰 비용이 증가하고 정확도가 떨어지는 문제가 발생합니다. 발표자는 이는 MCP 프로토콜 자체의 문제가 아니라, 에이전트 구현의 "하네스(harness)" 문제라고 강조했습니다. MCP 사양은 하네스 설계에 대해 아무것도 명시하지 않으므로, 에이전트 개발자가 MCP를 효과적으로 사용하도록 구현해야 합니다.

**해결책 1: 컨텍스트를 서브 에이전트로 분할**: 첫 번째 해결책으로 메인 에이전트가 서브 에이전트를 생성하여 특정 작업을 위임하고, 각 서브 에이전트가 자체 컨텍스트를 갖도록 하는 방식을 제시했습니다. 이는 메인 컨텍스트의 오염을 줄이지만, 여전히 토큰 비용은 발생하며, 민감한 정보가 컨텍스트에 남아 악용될 수 있는 보안 문제가 해결되지 않습니다.

**해결책 2: 점진적 도구 발견**: 지난 해 Anthropic과 Cursor가 도입한 이 방법은 "도구 검색 도구(Tool search tool)"를 사용하여 필요한 도구만 컨텍스트에 로드하는 방식입니다. 발표자는 이 방법이 기존 방식 대비 컨텍스트 사용량을 크게 줄여(예: 200k 토큰 중 61.4% 자유 공간에서 95.65% 자유 공간으로 증가) 효율성과 비용 절감 효과를 가져온다고 설명했습니다.

**해결책 3: 도구를 코드로 처리 (코드 모드)**: 지난 해 Cloudflare가 도입한 코드 모드는 MCP 도구를 함수 호출이 아닌 코드로 취급하는 방식입니다. LLM은 코드 작성 및 분석에 능숙하므로, `grep` 같은 도구를 사용하여 코드 내에서 도구 정의를 찾고 탐색할 수 있습니다. 이는 도구 호출이 인공적인 구성 요소라는 점을 고려할 때 더 자연스러운 접근 방식입니다. 그러나 Cloudflare의 구현은 특정 플랫폼에 종속적이고 사용하기 어렵다는 한계가 있습니다.

**CLI와의 비교**: 발표자는 CLI(Command Line Interface)가 에이전트에게 어떻게 다른지 설명하며, 에이전트가 CLI 도구와 문서를 한꺼번에 로드하지 않고 점진적으로 처리한다고 말했습니다. 에이전트는 필요한 경우에만 CLI 도구를 호출하며, 기본적인 Linux 명령어는 이미 학습되어 있거나 `--help` 옵션을 통해 사용법을 학습할 수 있습니다. CLI는 본질적으로 코드 모드와 유사하게 작동하며, 셸은 1969년부터 존재해 온 고도로 최적화된 인터페이스입니다. 에이전트는 셸을 통해 무한한 양의 훈련 데이터를 생성할 수 있습니다.

**MCP와 CLI의 결합**: 발표자는 CLI가 로컬 에이전트 인터페이스에 적합하고, MCP는 표준 원격 접근에 더 적합하다고 주장하며, 이 둘을 결합하는 것이 최선이라고 강조했습니다. 이를 위해 `mcpc`라는 범용 CLI 클라이언트를 소개했습니다. `mcpc`는 에이전트가 단일 `Bash()` 도구 호출을 통해 MCP 서버와 상호작용할 수 있도록 MCP의 모든 복잡성을 숨깁니다. 세션, 인증, OAuth 등에 대해 걱정할 필요 없이 모든 MCP 프로토콜 기능을 활용할 수 있습니다.

**`mcpc`의 디자인 목표**:
-   **완벽한 MCP 지원 및 호환성**: 태스크, 리소스, 프롬프트 등 MCP 프로토콜의 모든 기능을 지원합니다.
-   **경량성**: LLM 없이 MCP 프로토콜 위에 구축된 CLI 래퍼로, 최소한의 의존성을 가집니다.
-   **에이전트와 사람 모두에게 쉬운 사용성**: 직관적인 인터페이스를 제공합니다.
-   **`--json`을 통한 코드 모드**: 모든 명령어가 순수 JSON 형식으로 결과를 반환하여 `jq`와 같은 도구와 쉽게 연동하여 복잡한 셸 스크립트를 작성할 수 있습니다.

**데모**: 발표자는 `mcpc --help`를 통해 최적화된 도움말 인터페이스를 보여주고, 로컬 파일 시스템 서버와 원격 Apify MCP 서버에 연결하는 과정을 시연했습니다. OAuth 인증을 통해 자격 증명을 로컬 OS 키체인에 안전하게 저장하고, `mcpc`가 활성 세션과 인증 프로필을 관리하는 것을 보여주었습니다. 또한 `mcpc grep "find"` 명령어를 통해 여러 서버에서 특정 키워드를 포함하는 도구를 검색하고, `apify-rag-web-browser` 도구를 비동기 태스크로 실행하여 백그라운드에서 작업이 진행되고 나중에 결과를 확인할 수 있는 기능을 시연했습니다. 마지막으로 `mcpc x402 init` 명령어를 통해 에이전트 결제를 위한 로컬 지갑을 생성하는 기능도 소개했습니다.

**성능 평가**: 발표자는 `connector-evals`라는 프레임워크를 구축하여 MCP, `mcpc`, CLI의 성능을 비교한 초기 결과를 공유했습니다. 그래프는 `mcpc`와 CLI가 유사한 성능(시간 및 토큰 비용)을 보이며, "raw MCP"는 더 빠르지만 토큰 비용이 더 높다는 것을 보여주었습니다. 이는 `mcpc`가 CLI의 효율성을 유지하면서 MCP의 표준화된 원격 접근 이점을 제공함을 시사합니다.

**결론**: 발표자는 "CLI가 MCP보다 낫다고 말하는 것을 멈춰라. MCP+CLI가 최고다."라는 문구와 함께 강연을 마무리하며, 두 기술의 시너지를 강조했습니다.

## 실무 적용 포인트
-   **에이전트 컨텍스트 관리 최적화**: LLM 기반 에이전트 개발 시, 모든 도구 정의와 이전 대화 기록을 컨텍스트에 한꺼번에 로드하는 대신, 점진적 도구 발견(Progressive Tool Discovery) 방식을 도입하여 토큰 사용량을 줄이고 비용을 절감하며 정확도를 높일 수 있습니다.
-   **도구 인터페이스 설계에 코드 모드 고려**: 에이전트가 외부 도구와 상호작용할 때, 단순히 함수 호출 방식이 아닌 코드를 직접 생성하고 실행하는 "코드 모드"를 지원하도록 도구 인터페이스를 설계하여 LLM의 코드 생성 및 분석 능력을 최대한 활용할 수 있습니다.
-   **`mcpc` 활용을 통한 MCP 통합 간소화**: MCP 서버를 구축하거나 MCP 기반 에이전트를 개발할 때, `mcpc`와 같은 범용 CLI 클라이언트를 사용하여 MCP 프로토콜의 복잡성을 추상화하고, `Bash()` 호출을 통해 세션, 인증, 자원 관리 등을 간편하게 처리할 수 있습니다.
-   **보안 및 상태 관리 강화**: `mcpc`가 OAuth 인증을 통해 자격 증명을 로컬 OS 키체인에 안전하게 저장하고 세션을 유지하는 기능을 활용하여, 에이전트가 민감한 정보에 접근하고 장기적인 작업을 수행할 때 보안과 상태 관리의 편의성을 높일 수 있습니다.
