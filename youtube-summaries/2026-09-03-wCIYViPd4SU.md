# Tethered: Our Agents Are Us — Shu Fang, Two Sigma

🔗 https://youtu.be/wCIYViPd4SU · 📅 2026-09-03 · 🎙 AI Engineer

## 한 줄 요약
Two Sigma는 AI 에이전트가 사용자의 ID로 클라우드에서 원격으로 실행되도록 허용하면서 발생하는 내부 및 외부 위험을 관리하기 위해 엔드투엔드 추적 및 웹 그라운딩과 같은 가드레일을 구축하여 에이전트를 '테더링'하는 방법을 제시합니다.

## 발표자·소속
Shu Fang, Two Sigma

## 핵심 주장
-   **에이전트의 사용자 ID 실행:** Two Sigma는 모든 직원이 자신의 ID로 클라우드 에이전트를 실행할 수 있는 환경을 구축했으며, 이는 규제가 엄격한 금융 산업에서 중요한 과제였습니다.
-   **분리된 에이전트 ID의 문제점:** 기존의 사용자-에이전트 분리 ID 모델은 권한 불일치, 소프트웨어 라이선스 비용 증가, 시스템 호환성 문제, 공용 인터넷 접근 제한 등의 문제로 인해 비효율적입니다.
-   **위험 관리 및 가치 유지:** 에이전트를 사용자 ID로 실행하면 높은 가치와 함께 높은 위험이 따르므로, Two Sigma는 에이전트의 행동을 추적하고 웹 접근을 제한하는 기술적 가드레일을 통해 위험을 줄이면서 가치를 유지하는 데 집중했습니다.
-   **엔터프라이즈의 역할:** 개인은 위험을 피하는 경향이 있지만, 기업은 엔터프라이즈 리소스를 활용하여 위험 요소를 엔지니어링으로 낮추고 AI 에이전트의 잠재력을 최대한 활용할 수 있습니다.

## 세부 내용
발표는 Two Sigma가 퀀트 펀드로서 "많은 약한 신호(many weak signals)"를 합산하여 "하나의 증폭된 예측(one amplified forecast)"을 도출하는 방식으로 운영된다는 설명으로 시작합니다. 발표자는 회사가 25년 된 규제 산업에 속해 있음에도 불구하고, 모든 직원이 클라우드 에이전트를 자신의 ID로 실행하는 시스템을 구축했다고 강조합니다.

이러한 시스템을 구축하게 된 배경에는 2025년 6월 Claude Code 출시 이후 에이전트가 로컬 터미널을 넘어 클라우드로 확장되면서, 모바일, Slack, 브라우저 등 다양한 인터페이스를 통해 에이전트를 원격으로 실행할 필요성이 대두되었기 때문입니다.

기존의 "사용자(shu)"와 "에이전트(shu-agent)"를 분리하는 방식은 여러 문제점을 야기했습니다.
-   **권한 불일치:** 사용자 권한과 에이전트 권한이 동기화되지 않아 관리의 어려움이 있었습니다.
-   **이중 비용:** 두 개의 소프트웨어 라이선스(사용자용, 에이전트용)가 필요하여 비용이 증가했습니다.
-   **ID 미지원:** 일부 시스템은 여러 ID 간의 상호작용을 지원하지 않았습니다.
-   **시스템 차단:** 에이전트가 기본적으로 시스템 접근이 차단되는 경우가 많았습니다.
-   **공개 접근 제한:** 에이전트가 내부 데이터가 아닌 공용 데이터에만 접근할 수 있는 제약이 있었습니다.

Two Sigma는 이러한 문제들을 해결하기 위해 에이전트를 사용자와 동일한 ID로 원격 실행하는 방식을 채택했습니다. 이를 통해 이메일, 캘린더, Jira, 코드 저장소, 워크스페이스 등 모든 시스템에 사용자와 동일한 권한으로 접근할 수 있게 되었습니다.

이러한 아키텍처는 기존의 Kubernetes 클러스터를 활용하여 구현되었습니다. 각 사용자(예: shu, alice, bob)는 자신만의 네임스페이스를 가지며, 이 네임스페이스 내에서 자동화된 작업, 코드 컨테이너, 연구 노트북 등이 사용자의 ID로 실행됩니다. Pod가 사용자 ID로 스핀업되는 과정은 다음과 같습니다. 트리거가 Pod를 스핀업하면, Pod 내의 'identity sidecar'가 플랫폼 ID 서비스로부터 사용자 ID를 가져와 마운트하고, 워크로드는 해당 사용자 ID로 실행됩니다.

하지만 에이전트를 사용자 ID로 실행하는 것은 두 가지 주요 위험을 수반합니다.
1.  **내부 위험 (Internal Danger): 누가 행동했는가?**
    *   사용자와 에이전트가 동일한 ID로 실행되므로, 데이터베이스 삭제와 같은 중요한 작업이 발생했을 때 누가(사용자인지, 에이전트인지) 해당 작업을 수행했는지 구분하기 어렵습니다.
    *   이를 해결하기 위해 Two Sigma는 모든 액션에 엔드투엔드 태그를 추가했습니다. `X-TS-LLM-Agent`라는 HTTP 헤더를 사용하여 에이전트의 종류와 버전을 기록하고, 이 태그는 에이전트 간의 호출 체인을 따라 전파됩니다. 이를 통해 특정 작업이 인간에 의해 시작되었는지, 아니면 에이전트의 어떤 단계에서 발생했는지 전체 체인을 재현하고 추적할 수 있습니다.
2.  **외부 위험 (External Danger): 웹 접근의 위협**
    *   에이전트가 외부 인터넷에 접근할 경우, 데이터 유출(exfiltration), 프롬프트 인젝션, 라이선스 콘텐츠 노출, 악성코드 및 취약점 감염 등의 위험이 있습니다.
    *   이를 해결하기 위해 "Web Grounding for Enterprise"라는 솔루션을 도입했습니다. 에이전트 Pod는 외부 인터넷으로의 직접적인 이그레스(egress)가 차단됩니다. 대신, 에이전트가 웹 검색이나 웹 페치(WebFetch)와 같은 기능을 사용해야 할 경우, Gemini Enterprise Agent Platform의 그라운딩 서비스를 통해 캐시된 Google 인덱스에 접근합니다. 이 인덱스는 금융, 건강, 공공 데이터 등 큐레이션된 서브셋으로 구성되며, 6시간 또는 24시간마다 새로고침됩니다. 이 방식은 트래픽이 Google의 경계를 벗어나지 않도록 보장하여 공용 인터넷에 직접 접근하는 위험을 제거합니다.
    *   에이전트가 웹 그라운딩을 사용하도록 강제하기 위해, 내장된 웹 도구(WebSearch, WebFetch)는 비활성화되고, 웹 접근 요청은 MCP, CLI, 코드(skills)를 통해 그라운딩된 캐시 인덱스로 리디렉션됩니다.

결론적으로 Two Sigma는 이러한 가드레일(사용자 ID 실행, 이그레스 없음, 웹 그라운딩, 추적 가능)을 통해 에이전트를 '테더링'하여 위험을 크게 줄이면서도 에이전트의 가치를 유지할 수 있었다고 주장합니다. 개인은 위험을 피할 수 있지만, 기업은 엔지니어링을 통해 위험을 낮추고 AI 에이전트의 잠재력을 활용해야 한다는 것이 핵심 메시지입니다.

## 인상적인 대목
-   "An individual can only avoid the risk. An enterprise can engineer it down." (개인은 위험을 피할 수 있을 뿐이지만, 기업은 위험을 엔지니어링으로 낮출 수 있습니다.)
-   "So we keep ours tethered. Our agents are us." (그래서 우리는 에이전트를 테더링합니다. 우리의 에이전트는 우리 자신입니다.)

## 실무 적용 포인트
-   **Kubernetes 네임스페이스 활용:** 각 사용자에게 전용 Kubernetes 네임스페이스를 할당하여 에이전트가 사용자 ID로 실행될 수 있는 격리된 환경을 제공합니다.
-   **엔드투엔드 액션 태깅:** HTTP 헤더(`X-TS-LLM-Agent`)를 사용하여 에이전트의 모든 액션에 대한 상세한 추적 정보를 기록하고 전파함으로써, 누가(인간 또는 에이전트) 어떤 작업을 수행했는지 명확하게 식별하고 감사할 수 있도록 합니다.
-   **안전한 웹 접근을 위한 웹 그라운딩:** 에이전트의 외부 인터넷 직접 접근을 차단하고, 대신 큐레이션되고 캐시된 내부 인덱스(예: Google의 엔터프라이즈 웹 그라운딩 서비스)를 통해 웹 정보를 검색하도록 강제하여 데이터 유출 및 악성코드 감염 위험을 제거합니다.
-   **기존 도구의 리디렉션:** 에이전트 내부에 내장된 웹 검색/페치 도구를 비활성화하고, 지원되는 내부 경로(MCP, CLI, 커스텀 스킬 등)를 통해 웹 그라운딩 서비스로 요청을 리디렉션하여 안전한 웹 접근 정책을 강제합니다.
