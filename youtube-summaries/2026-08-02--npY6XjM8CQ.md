# When Will The Benchmaxxing Plague End? — Nick Heiner, Surge AI

🔗 https://youtu.be/-npY6XjM8CQ · 📅 2026-08-02 · 🎙 AI Engineer

## 한 줄 요약
AI 모델 벤치마킹의 문제점인 '벤치맥싱'은 인센티브, 부실한 방법론, 낮은 야망, 주관적인 취향, 운영 능력 부족 등 여러 요인으로 인해 발생하며, 이를 해결하기 위해서는 인간 전문가의 참여와 고품질 데이터, 그리고 엄격한 검증 절차가 필수적입니다.

## 발표자·소속
닉 하이너(Nick Heiner), Surge AI의 RL 환경 리더

## 핵심 주장
-   **벤치마킹의 문제점 인식**: AI 모델 출시 시 벤치마크 점수가 실제 성능과 괴리되는 '벤치맥싱(benchmaxxing)' 현상이 만연하며, 이는 모델의 실제 가치보다 마케팅과 인센티브에 의해 좌우되는 경향이 있습니다.
-   **벤치마크의 신뢰성 저하 원인**: 높은 비용, 데이터 오염, 낮은 벤치마크 설계 야망, 인간의 취향 반영 부족, 운영 능력 미흡 등이 벤치마크가 실제 가치를 제대로 반영하지 못하는 주요 원인입니다.
-   **인간 중심의 평가 필요성**: 기계적인 벤치마크나 LLM을 평가자로 사용하는 것은 한계가 있으며, 실제 세계의 복잡성과 인간의 선호를 정확히 반영하기 위해서는 해당 분야의 인간 전문가가 직접 참여하는 평가가 중요합니다.
-   **올바른 벤치마크 설계 원칙**: 벤치마크는 인간 전문가의 지식, AI 사용 방식에 대한 제품 감각, 고품질 입력 데이터, 제대로 작동하는 도구, 프롬프트와 완벽하게 일치하는 검증기, 철저한 품질 관리, 그리고 비공개 홀드아웃 세트를 통해 설계되어야 합니다.

## 세부 내용
발표는 "언제 벤치맥싱이라는 역병이 끝날 것인가?"라는 질문으로 시작됩니다. 발표자는 기술 산업, 특히 AI 분야에서 '하이프 사이클(hype cycle)'을 좋아하며, 새로운 모델이 출시되면 대대적인 발표와 벤치마크 점수가 공개되지만, 실제 사용 시 기대에 미치지 못하면 '벤치맥싱'이라는 비난이 제기된다고 설명합니다. '벤치맥싱'은 연구실이 벤치마크에 지나치게 집중하여 실제 사용자가 중요하게 생각하는 가치에서 벗어나는 방식으로 모델을 훈련하는 것을 의미합니다.

발표자는 벤치맥싱이 발생하는 이유, 전통적인 벤치마크가 신뢰할 수 없는 이유, 벤치마킹 자체의 문제인지, 그리고 어떤 모델이 최고인지 알 수 있을지에 대한 질문을 던지고, 각각 인센티브, 부실한 방법론, 아니오, 예라고 답합니다.

LM 아레나(LMArena)와 같은 인기 있는 벤치마크가 쉽게 조작될 수 있다는 업계 리더들의 발언을 인용하며, 벤치마크 점수가 현실과 동떨어져 있음을 지적합니다. 특히, Andrej Karpathy의 사례를 들어, 개인적으로 우수하다고 생각한 모델이 LM 아레나에서는 낮은 순위를 기록하고, LM 아레나에서 높은 점수를 받은 모델들이 "중첩된 목록, 글머리 기호 및 이모티콘"과 같은 특정 형식에 최적화되어 있을 수 있다고 비판합니다. 이는 모델들이 전반적으로 더 나은 모델이 아니라 "더 나은 LM 아레나 모델"을 만들고 있다는 의미입니다.

발표자는 벤치마크가 실제 가치를 반영하지 못하는 다섯 가지 주요 '안티 패턴(anti-patterns)'을 제시합니다.

1.  **가격(Price)**: 에이전트 코딩 벤치마크를 예로 들며, 1,000개의 태스크에 각각 60시간이 소요되고 소프트웨어 엔지니어 연봉이 50만 달러라고 가정하면, 초기 비용만 1,500만 달러, 매년 500만 달러의 유지보수 비용이 발생한다고 추산합니다. 이러한 높은 비용 때문에 연구실은 공개 데이터 사용(오염), AI 지원 활용(순환적 노력), 작은 샘플 크기(노이즈), 저렴한 노동력 사용(낮은 품질, 전문성 부족)과 같은 편법을 사용하게 됩니다.
2.  **오염(Contamination)**: 모델이 테스트 데이터에 명시적으로 훈련되는 것을 넘어, 공개된 질문-답변 데이터가 인터넷에 존재하면 모델이 이를 암기할 수밖에 없다고 설명합니다. SWE-Bench Verified 벤치마크에서 Opus 4.8 모델이 프롬프트의 일부를 주면 나머지를 그대로 암기하여 출력하는 사례를 보여주며, 이는 문제 설명과 정답 패치 모두에서 통계적으로 유의미한 오염이 있음을 보여줍니다.
3.  **야망(Ambition)**: AutomationBench 벤치마크를 예로 들며, 에이전트가 Salesforce에서 전화번호를 업데이트하는 태스크에서, 벤치마크의 검증기가 하드코딩된 문자열 일치 방식을 사용하여 다양한 유효한 전화번호 형식 중 하나만 정답으로 인정하는 문제를 지적합니다. 이는 모델이 실제로는 올바른 답을 생성했음에도 불구하고 낮은 점수를 받게 만들며, "산업 전체를 재편하는" AI의 능력을 하드코딩된 문자열 일치로 측정할 수 없다고 강조합니다.
4.  **취향(Taste)**: 벤치마크가 단순히 건조한 학술적 질문-답변 세트가 아니라, AI가 어떻게 행동하기를 원하는지에 대한 가치를 표현하는 '열망적인 아티팩트'가 되어야 한다고 주장합니다. IFEval 벤치마크를 예로 들며, "500단어 이상, 17문장 미만", "특정 키워드 포함", "쉼표 사용 금지", "모두 소문자 또는 대문자", "특정 글자 사용 빈도 제한"과 같은 인위적인 프롬프트는 실제 사용자의 요구와 동떨어져 있으며, 심지어 모순되거나 불가능한 지시를 포함하는 경우도 있다고 비판합니다.
5.  **운영 능력(Operational Ability)**: 대규모 벤치마크를 만드는 데는 많은 품질 관리(QC) 작업이 필요하지만, 많은 조직이 이러한 투자를 하지 않는다고 말합니다. Apex라는 RAG 벤치마크의 사례를 들어, 골든 응답, 실제 정답, 채점 기준(rubric) 간에 날짜가 일치하지 않거나, 데이터에 명백한 플레이스홀더 값, 존재하지 않는 날짜나 장소가 포함되어 있어 모델이 "평가 인식(eval awareness)"을 개발하게 만들고 실제 데이터 분포에서 벗어나게 한다고 지적합니다.

발표자는 '벤치맥싱'을 끝내기 위한 해결책으로 "올바르게 수행된 벤치마크"의 7가지 원칙을 제시합니다.
1.  관련 분야의 **인간 전문가**로 시작합니다.
2.  사람들이 AI를 사용하는 방식에 대한 전문 지식 / **제품 감각**과 결합합니다.
3.  **고품질 입력 데이터**를 제공합니다.
4.  **실제로 작동하는 도구**를 제공합니다.
5.  프롬프트와 완벽하게 일치하는 **검증기**를 만듭니다.
6.  **철저한 품질 관리(QC)**를 수행합니다.
7.  **비공개 홀드아웃 세트**를 유지합니다.

Surge AI는 이러한 원칙에 따라 글쓰기 능력을 측정하는 '헤밍웨이 벤치(Hemingway-bench)'를 개발했다고 소개합니다. 이 벤치마크는 수천 명의 전문 작가(기술 작가, 시인, 언론인, 편집자 등)로 구성된 인력을 활용하여 블라인드 모델 비교를 수행합니다. 이는 비용이 많이 들지만, Surge AI의 목표는 비용 최소화가 아닌 품질 극대화라고 강조하며 발표를 마무리합니다.

## 인상적인 대목
-   "AI는 모두를 위한 것이고, 모두가 어떤 모델이 최고인지 알아낼 도구가 필요하며, 벤치마크가 바로 그것입니다. 하지만 벤치마크가 좋은지 평가할 능력이 없다면, 무엇이 인기 있는지 평가하게 됩니다."
-   "벤치맥싱은 벤치마크가 인간의 선호도와 어긋나는 것을 악용하는 행위이지만, 우리는 더 잘할 수 있습니다."
-   "모델들은 전반적으로 더 나은 모델이 아니라 더 나은 LM 아레나 모델을 만들고 있습니다." (Andrej Karpathy 인용)
-   "당신은 '전체 산업을 재편하는' 것을 하드코딩된 문자열 일치로 측정할 수 없습니다."

## 실무 적용 포인트
-   **벤치마크 선택 시 신중함**: 단순히 높은 벤치마크 점수만 보고 모델을 선택하기보다, 벤치마크의 설계 방식, 데이터 소스, 검증 방법 등을 면밀히 검토하여 실제 사용 시나리오와의 관련성을 평가해야 합니다.
-   **인간 전문가의 역할 강화**: AI 모델의 실제 성능과 가치를 평가하기 위해 해당 도메인의 인간 전문가를 평가 과정에 적극적으로 참여시켜, 기계적 평가의 한계를 보완하고 인간의 미묘한 선호를 반영해야 합니다.
-   **고품질 데이터 및 도구 사용**: 벤치마크를 구축하거나 활용할 때, 실제 세계에서 수집된 고품질의 입력 데이터를 사용하고, 버그 없이 신뢰할 수 있는 도구를 활용하여 평가의 정확성과 공정성을 높여야 합니다.
-   **투명성과 재현성 확보**: 벤치마크 결과 발표 시 데이터 오염 여부, 평가 조건, 사용된 도구 및 검증기의 세부 사항 등을 투명하게 공개하여 커뮤니티가 벤치마크의 유효성을 독립적으로 평가하고 재현할 수 있도록 해야 합니다.
