# Stop Giving Your Agent Tools. Give It a Sandbox - Mikyo King, Arize AI

🔗 https://youtu.be/dAoOYFx7ZYw · 📅 2026-10-27 · 🎙 AI Engineer

## 한 줄 요약
AI 에이전트에 코드 모드를 도입하여 도구 호출의 비효율성을 해결하고, 에이전트가 동적으로 코드를 생성하고 실행하여 더 복잡하고 효율적인 작업을 수행할 수 있도록 하며, 이를 통해 비용 절감과 성능 향상을 달성할 수 있습니다.

## 발표자·소속
Mikyo King, Arize AI 오픈소스 그룹 총괄

## 핵심 주장
-   **기존 도구 호출 방식의 한계 극복:** 전통적인 LLM(대규모 언어 모델) 기반 에이전트의 도구 호출 방식은 컨텍스트 창이 빠르게 채워지고, 여러 번의 턴이 필요하며, 비용이 증가하는 "너무 많은 도구 문제"를 야기합니다.
-   **코드 모드의 효율성:** 코드 모드는 LLM이 샌드박스 환경에서 직접 코드를 생성하고 실행하여 필요한 도구를 동적으로 탐색하고 조합하며, 결과 중 필요한 부분만 컨텍스트에 다시 넣어 토큰 효율성을 극대화합니다.
-   **향상된 기능과 유연성:** 코드 모드는 점진적 공개(Progressive disclosure), 구성 가능성(Composability), 토큰 효율성(Token efficiency), 그리고 에이전트가 자체 도구를 구축하는 "예측 불가능한 행동(Emergent behavior)"을 가능하게 하여 에이전트의 능력과 복잡한 작업 처리 능력을 크게 향상시킵니다.
-   **실제 적용 및 이점:** Arize AI는 자사의 오픈소스 플랫폼인 Phoenix에 코드 모드를 적용하여 Bash, Python 샌드박스, SQL 실행 등 다양한 기능을 구현했으며, 이를 통해 토큰 사용량 43% 감소, 비용 31% 감소, 보상 유지, 지연 시간 0.6% 증가라는 긍정적인 결과를 얻었습니다.

## 세부 내용

발표는 AI 에이전트 개발의 현재 상황과 "코드 모드"라는 새로운 접근 방식의 이점을 설명합니다.

**1. 기존 LLM + 도구 방식의 문제점 (Too many tools problem)**
발표자는 지난 30년간의 소프트웨어 개발을 엔지니어용 소프트웨어와 비엔지니어용 소프트웨어로 나눌 수 있다고 설명합니다. 엔지니어는 스크립트를 작성하여 동적으로 작업을 자동화할 수 있지만, 비엔지니어는 소프트웨어 인터페이스에 의해 제한됩니다. LLM 에이전트가 도구를 사용하는 방식은 이와 유사하게 제한적입니다.

기존 LLM 에이전트는 사용자 질문에 답하기 위해 도구 정의를 컨텍스트 창에 로드하고, 질문이 들어오면 도구를 호출하며, 도구의 결과가 다시 컨텍스트에 추가되는 방식으로 작동합니다. 이 과정이 반복되면 컨텍스트 창이 빠르게 가득 차게 되고(context bloat), 이는 여러 번의 턴을 유발하며(multi-turn), 결국 비용 증가와 성능 저하로 이어집니다. 또한, 컨텍스트에 불필요한 정보가 쌓이는 "컨텍스트 부패(context rot)" 문제도 발생합니다.

**2. 코드 모드 소개 (Code mode)**
코드 모드는 이러한 문제를 해결하기 위한 대안적인 아키텍처입니다. LLM은 미리 정의된 도구 목록을 받는 대신, 샌드박스 환경에서 직접 코드를 생성하고 실행합니다. 이 코드는 필요한 도구를 검색하고, 여러 도구를 조합하여 복잡한 작업을 수행하며, 그 결과 중 모델이 추론하는 데 필요한 핵심 정보만 컨텍스트에 다시 전달합니다.

예를 들어, "오늘 Acme 미팅의 통화 내용을 CRM의 Acme 딜에 첨부해줘"라는 사용자 요청이 있을 때, 모델은 `find_meeting`, `get_transcript`, `find_deal`, `attach`와 같은 도구를 호출하는 파이썬 코드를 샌드박스에 생성하고 실행합니다. 샌드박스는 이 코드를 실행하고 최종적으로 "attached"라는 간결한 결과만 모델에게 반환합니다.

**3. 코드 모드의 작동 원리 및 이점**
-   **점진적 공개 (Progressive disclosure):** 에이전트는 모든 도구 정의를 한 번에 알 필요 없이, 필요할 때마다 도구를 검색하고 이해합니다. 이는 컨텍스트 창의 효율성을 높입니다.
-   **구성 가능성 (Composability):** 에이전트는 도구를 순차적으로, 병렬로, 또는 복잡한 체인 형태로 조합하여 실행할 수 있습니다. 이는 훨씬 더 복잡하고 효율적인 작업 흐름을 가능하게 합니다. (예: Claude의 동적 워크플로우)
-   **토큰 효율성 (Token efficiency):** 샌드박스 내에서 코드를 실행하고, 모델은 도구의 모든 출력을 컨텍스트에 넣는 대신, 필요한 정보만 선별하여 컨텍스트에 다시 주입합니다. 이는 토큰 사용량을 크게 줄입니다.
-   **예측 불가능한 행동 (Emergent behavior):** 에이전트가 필요에 따라 자체 도구를 생성하고 활용할 수 있는 능력을 갖게 됩니다. 예를 들어, 개인 식별 정보를 제거하는 도구가 없을 때, 에이전트가 직접 해당 기능을 수행하는 코드를 작성하여 실행할 수 있습니다.

**4. 실제 적용 사례 (Code mode in practice)**
Arize AI는 자사의 오픈소스 플랫폼인 Phoenix X-ray Inspector (PXI)에 코드 모드를 구현했습니다.
-   **Bash 샌드박스:** Bash 쉘을 통해 리눅스 기본 명령어와 자체 CLI 도구를 조합하여 사용하고, 결과를 파일로 저장하는 기능을 제공합니다.
-   **Python 샌드박스:** 모든 REST CRUD(생성, 읽기, 업데이트, 삭제) 엔드포인트를 Python 샌드박스에 통합하여, 에이전트가 데이터셋 조작이나 트레이스 검색과 같은 복잡한 작업을 프로그래밍 방식으로 수행할 수 있도록 합니다.
-   **SQL 실행:** 텍스트-투-SQL 기능을 통해 에이전트가 데이터베이스에 직접 SQL 쿼리를 작성하고 실행하여 특정 조건(예: P95 지연 시간이 특정 값 이상인 LLM 스팬)에 맞는 데이터를 정확히 찾아낼 수 있습니다.
-   **브라우저 내 코드 모드:** UI에 바인딩된 프로그래밍 패러다임을 웹 워커에서 실행하여, 에이전트가 시간 범위를 변경하거나 데이터 스토어에서 데이터를 읽는 등 복잡한 UI 상호작용을 수행할 수 있게 합니다.

**5. 코드 모드의 트레이드오프 및 오픈 문제**
코드 모드는 많은 이점을 제공하지만, LLM이 생성한 코드를 다루기 때문에 몇 가지 과제도 있습니다.
-   **자원 제한:** 샌드박스 환경의 CPU, 메모리, 실행 시간 제한을 관리해야 합니다.
-   **네트워크 유출:** 샌드박스가 외부 네트워크에 접근할 경우, 악성 웹사이트에 접속할 위험이 있어 네트워크 이그레스(egress)에 대한 신중한 관리가 필요합니다.
-   **샌드박스 내 비밀 정보:** API 키나 관리자 토큰과 같은 비밀 정보가 샌드박스에 노출되지 않도록 안전한 볼팅(vaulting) 전략이 중요합니다.
-   **과도한 권한:** 에이전트에게 너무 넓은 권한을 부여하면 의도치 않은 작업을 수행할 수 있으므로, 세밀한 권한 제어가 필요합니다.
-   **운영 복잡성:** 샌드박스 시작 비용, 디버깅의 어려움(코드 디버깅), 도구 발견의 복잡성, 그리고 샌드박스 중첩(duplicating the harness)으로 인한 직렬화/파싱 오버헤드 등이 있습니다.
-   **오픈 문제:** 코드 실행의 내구성(Durability, 중간에 실패 시 재개 불가), 결정론(Determinism, 수학적 정확성을 위한 언어 선택), 이미지 및 바이너리 데이터 처리(샌드박스 외부로 안전하게 전달), 그리고 소형 모델에서의 성능 유지 등이 여전히 해결해야 할 과제입니다.

**6. 코드 모드 평가**
Arize AI는 자사의 Harbor 프레임워크를 사용하여 에이전트의 코드 모드 성능을 평가합니다. 에이전트를 샌드박스 환경에 넣고, 네트워크 접근을 차단한 상태에서 명확한 지침에 따라 여러 번 실행합니다. Harbor 검증자(verifiers)를 통해 에이전트가 올바르게 작동하는지 확인하고, RL(강화 학습) 프레임워크 기반으로 1 또는 0의 보상을 부여하여 태스크 성공 여부를 측정합니다. 이를 통해 플래키(flakey)한 동작을 줄이고 다양한 시나리오에서 에이전트의 성능을 추적합니다.

평가 결과, 코드 모드를 통해 토큰 사용량은 43% 감소, 비용은 31% 감소했으며, 보상은 동일하게 유지되고 지연 시간은 0.6% 증가하는 데 그쳤습니다. 이 데이터는 에이전트의 회귀를 파악하고, 트레이스를 분석하며, 도구와 지침을 조정하여 에이전트를 개선하는 데 활용됩니다.

## 인상적인 대목
-   "LLM + tools"가 "LLM + code mode"로 진화하며, 에이전트가 동적으로 소프트웨어를 구축하는 능력을 갖게 되는 비전이 인상적입니다.
-   "Sandbox it. Trace it. Improve it."라는 문장은 코드 모드 에이전트 개발 및 개선의 핵심 과정을 간결하게 요약합니다.

## 실무 적용 포인트
-   **샌드박스 환경 활용:** 에이전트가 복잡한 작업을 수행해야 하거나, 동적으로 도구를 조합해야 할 경우, 샌드박스 환경에서 코드를 생성하고 실행하는 코드 모드 아키텍처를 고려하세요.
-   **컨텍스트 효율성 최적화:** 에이전트가 도구의 모든 출력을 컨텍스트에 넣는 대신, 필요한 정보만 선별하여 반환하도록 설계하여 토큰 사용량과 비용을 절감하고 지연 시간을 줄이세요.
-   **보안 및 자원 관리:** LLM 생성 코드의 자원 사용량(CPU, 메모리, 시간), 네트워크 접근, 비밀 정보 노출, 권한 문제에 대한 명확한 가드레일과 관리 전략을 수립해야 합니다.
-   **체계적인 평가 프레임워크 구축:** Harbor와 같은 평가 프레임워크를 사용하여 에이전트의 동작을 다양한 시나리오에서 여러 번 실행하고, 트레이스 및 평가 지표를 분석하여 에이전트의 성능을 지속적으로 개선하고 회귀를 방지하세요.
