# We Mapped 115 Microservices for Our Coding Agents — Kamalakannan Nandagopal, Postman

🔗 https://youtu.be/k2ClBT4aqAg · 📅 2026-10-08 · 🎙 AI Engineer

## 한 줄 요약
Postman의 스태프 엔지니어 카말라카난 난다고팔은 코딩 에이전트의 성능을 향상시키기 위해 115개 이상의 마이크로서비스와 수천 개의 API 엔드포인트를 매핑하여 API 컨텍스트 그래프를 구축하고, 이를 통해 에이전트의 코드 생성 및 시스템 분석 능력을 개선하는 방법을 제시합니다.

## 발표자·소속
카말라카난 난다고팔 (Kamalakannan Nandagopal), Postman 스태프 엔지니어

## 핵심 주장
*   **API 컨텍스트 그래프는 코딩 에이전트의 핵심 컨텍스트 레이어입니다.** 복잡한 분산 시스템에서 API는 도메인과 모델로 분해된 엔지니어링 아키텍처의 핵심이며, 각 시스템의 책임과 상호작용을 정의합니다. API 컨텍스트 그래프는 이러한 API 정보를 구조화하여 에이전트가 시스템을 더 잘 이해하도록 돕습니다.
*   **기존 코딩 에이전트의 한계를 극복하기 위해 API 컨텍스트 그래프가 필요합니다.** 문서화는 유지보수가 어렵고, 스킬 및 MCP는 제공된 컨텍스트만큼만 유용하며, 에이전트 메모리는 개별 사용자에게 제한적입니다. API 컨텍스트 그래프는 이러한 한계를 넘어 시스템 전반의 지식을 에이전트에 제공합니다.
*   **API 컨텍스트 그래프는 코드와 프로덕션 텔레메트리에 기반한 '하드 트루스'로 구축됩니다.** 모든 마이크로서비스를 카탈로그화하고, 각 엔드포인트의 구현 위치와 상호 호출 관계를 파악하며, 데이터 흐름(캐시, 데이터베이스 포함) 및 프론트엔드/CLI 애플리케이션의 백엔드 상호작용을 매핑합니다. 이 모든 데이터는 LLM에 의해 인덱싱되지만, 실제 코드나 프로덕션 텔레메트리를 통해 검증됩니다.
*   **API 컨텍스트 그래프는 에이전트의 API 검색, 설계/재설계, 영향 평가 성능을 크게 향상시킵니다.** API 컨텍스트 그래프를 활용한 Postman 에이전트는 순수 코드 검색이나 일반 코딩 에이전트(Claude Code)보다 훨씬 높은 정확도와 효율성으로 올바른 API를 식별하고, API 입력 형태를 분석하며, 변경 사항의 영향을 평가하는 데 도움을 줍니다.

## 세부 내용
발표자는 먼저 AI 엔지니어 월드 페어에 참석한 것을 환영하며, 코딩 에이전트가 코드 생성을 넘어 어떻게 발전할 수 있는지, 그리고 API 컨텍스트가 그 해답이 될 수 있음을 설명합니다. 발표자는 Postman의 스태프 엔지니어이며, Postman은 API 플랫폼으로서 115개 이상의 마이크로서비스와 수천 개의 REST API 엔드포인트를 가진 광범위한 마이크로서비스 아키텍처를 가지고 있다고 소개합니다.

코딩 에이전트의 도입은 라인/함수 자동 완성에서 시작하여 전체 코드베이스 리팩토링, 일회성 수정/구현을 거쳐 자율 코딩 에이전트 및 PR 검토 에이전트로 발전하고 있습니다. 코딩 에이전트는 그린필드 프로젝트나 단일 프로젝트 내의 수정 및 개선 작업에서 뛰어난 성능을 보입니다.

그러나 프로덕션 시스템은 복잡합니다. 여러 연결된 마이크로서비스로 구성된 분산 시스템이며, 여러 환경에 배포되고, 웹, 데스크톱, CLI, API 등 다양한 애플리케이션을 포함하며, 수백 개의 리포지토리에 걸쳐 코드가 분산되어 있습니다.

코딩 에이전트 성능 향상을 위한 접근 방식으로는 문서화, 스킬 및 MCP(Multi-Agent Communication Protocol), 에이전트 메모리가 있습니다. 문서화는 시작하기 좋지만, 개발자들이 작성하고 유지보수하기를 꺼리며, LLM이 전적으로 작성한 문서는 시간이 지남에 따라 품질이 저하될 수 있습니다. 스킬 및 MCP는 제공된 컨텍스트만큼만 유용합니다. 에이전트 메모리는 개별 사용자에게 제한적이며, 팀 전체에 공유하는 표준 패턴이 아직 없습니다.

발표자는 비즈니스 에이전트에서 얻은 교훈을 언급합니다. 비즈니스 에이전트는 다양한 데이터 소스의 고객 데이터를 벡터 검색을 위해 인덱싱하고 임베딩하며, RAG(Retrieval Augmented Generation)와 그래프 RAG를 활용하여 비즈니스 데이터에 대한 목적 지향적인 에이전트를 구축합니다. 이는 비정형 데이터를 구조화된 컨텍스트 레이어로 조직하여 효율적인 에이전트 검색을 가능하게 합니다.

이러한 교훈을 바탕으로, 발표자는 "API가 컨텍스트"라는 아이디어를 제시합니다. 복잡한 엔지니어링 아키텍처는 도메인과 모델로 분해되며, 각 시스템은 책임을 가지고 API는 그 책임을 정의합니다. 시스템 간의 API 호출은 워크플로우와 사용자 여정을 나타냅니다.

Postman은 API 컨텍스트 그래프를 구축하기 위한 여정을 시작했습니다.
1.  프로덕션의 모든 마이크로서비스를 카탈로그화합니다.
2.  각 마이크로서비스가 노출하는 모든 엔드포인트와 구현 위치를 식별합니다.
3.  모든 엔드포인트가 다른 엔드포인트를 호출하는 방식을 캡처합니다.
4.  서비스 간의 의존성을 매핑합니다.
5.  데이터가 어디로 가는지(캐시, 데이터베이스 포함) 캡처합니다.
6.  프론트엔드 및 CLI와 같은 애플리케이션이 백엔드를 소비하고 상호작용하는 방식을 식별합니다.

이 모든 데이터는 LLM에 의해 인덱싱되지만, 모든 데이터 포인트는 "코드 또는 프로덕션 텔레메트리"라는 확실한 진실에 기반을 둡니다. 현재 Postman의 API 컨텍스트 그래프는 90개 이상의 마이크로서비스와 4200개 이상의 엔드포인트를 포함하며, 중앙 클러스터의 핵심 서비스와 외부의 부풀려진 서비스와 같은 일반적인 패턴을 보여줍니다.

API 컨텍스트 그래프의 평가를 위해 실제 PR(Pull Request)을 분석하고, 설계 논의에서 핵심 요점을 식별하며, 이를 실제 변경 사항과 매핑하여 그라운드 트루스로 사용했습니다. Postman 에이전트를 API 컨텍스트 그래프와 함께 사용하여 검증하고, 일반적인 Claude Code(GitHub 코드 검색만 사용) 및 Claude Code에 API 컨텍스트 그래프 스킬을 추가한 경우와 비교했습니다.

평가 결과는 0-5점 척도와 사용된 토큰 수로 시각화되었습니다.
*   **API Discovery (API 검색):** "사용자 프로필 이름을 얻기 위한 올바른 API는 무엇인가?"와 같은 순수 검색 시나리오에서, 컨텍스트 그래프를 사용한 에이전트(Postman, Claude + CG)는 순수 코드 검색(Claude)보다 훨씬 높은 점수를 받았습니다. Postman 에이전트는 Claude + CG와 비슷한 성능을 보였지만, 약간의 편차가 있었습니다.
*   **API Design/Redesign (API 설계/재설계):** 개발자가 새로운 API를 설계하고 스키마를 정의한 후, 나중에 추가 속성을 전달해야 하는 상황에서, 컨텍스트 그래프는 API의 모든 입력 형태와 사용 이유를 분석하는 데 도움을 줍니다. 이 시나리오는 모든 소비자를 추적하기 어렵고, 정확한 입력 형태를 파악하기 어려우며, 프로덕션 로그에서 필요한 정보가 부족하고, 형태가 식별되더라도 왜 그렇게 전달되었는지 추론하기 어렵기 때문에 복잡합니다. 이 시나리오에서 Postman 에이전트는 Claude Code보다 훨씬 높은 점수를 받았고, Claude + CG도 순수 Claude보다 나은 성능을 보였습니다. Postman 에이전트는 더 적은 토큰으로 더 높은 품질의 결과를 제공했습니다.
*   **Impact Assessment (영향 평가):** "v3/collections API를 도입할 계획입니다. v2/collections의 모든 소비자와 사용 방식을 보여주세요."와 같은 변경 영향 평가 시나리오에서, 초기에는 Postman 에이전트가 실패하는 모습을 보였습니다 (그래프가 반전됨). 실패 원인은 시나리오 식별과 검증 사이에 새로운 소비자가 프로덕션에 추가되었기 때문입니다. 이는 컨텍스트 그래프를 최신 상태로 유지하는 것이 중요하며, 지연은 잘못된 데이터로 이어져 신뢰를 깨뜨린다는 것을 보여줍니다. 또한 새로운 API 및 의존성을 식별하는 것만큼 API 호출의 제거를 감지하는 것도 중요합니다.

발표자는 상위 10개 리포지토리의 PR 중 75% 이상이 API에 영향을 미치거나 API를 통합한다는 통계를 제시하며, 이러한 사용 사례가 매우 흔하다는 것을 강조합니다.

API 컨텍스트 그래프를 통해 더 나은 결정을 내릴 수 있습니다. 이는 종속성 주기, 위험한 장기 마이그레이션, 단일 실패 지점, 텔레메트리의 사각지대 등 엔지니어링 아키텍처에 대한 통찰력을 제공하며, CEO, CTO, 스태프 엔지니어를 위한 명확한 실행 항목을 도출합니다.

**학습 내용:**
*   API 컨텍스트 그래프는 코딩 에이전트의 컨텍스트 레이어 역할을 합니다.
*   엔지니어링 아키텍처에 대한 높은 수준의 시야를 제공합니다.
*   통합 문제를 해결하는 올바른 방법을 찾는 시간을 단축합니다.
*   효율성은 개발 프로세스에서 더 자주, 더 일찍 실행할 수 있음을 의미합니다.
*   변경 사항이 배포되기 전에 영향을 평가하여 신뢰를 구축합니다.

발표자는 Postman 플랫폼 내에서 이러한 기능들을 얼리 액세스로 사용할 수 있으며, 질문이 있다면 발표 후 부스 S32에서 만날 수 있다고 말하며 발표를 마칩니다.

## 실무 적용 포인트
1.  **API 컨텍스트 그래프 구축:** 분산 시스템의 복잡성을 관리하기 위해 모든 마이크로서비스, 엔드포인트, 데이터 흐름, 애플리케이션 상호작용을 매핑하는 API 컨텍스트 그래프를 구축하는 것을 고려해야 합니다. 이는 에이전트가 시스템을 전체적으로 이해하는 데 필수적입니다.
2.  **코드 및 텔레메트리 기반의 '하드 트루스' 활용:** 에이전트에 제공되는 정보의 신뢰성을 높이기 위해, 문서화에만 의존하지 않고 실제 코드와 프로덕션 텔레메트리 데이터를 기반으로 컨텍스트 그래프를 구축하고 검증해야 합니다.
3.  **컨텍스트 그래프의 지속적인 업데이트:** 시스템 변경 사항(새로운 API, 의존성 추가/제거)을 실시간으로 반영하여 컨텍스트 그래프를 최신 상태로 유지하는 것이 중요합니다. 지연된 업데이트는 에이전트의 잘못된 판단으로 이어져 신뢰를 잃게 할 수 있습니다.
4.  **개발 초기 단계에서의 에이전트 활용:** API 컨텍스트 그래프를 통해 에이전트가 더 효율적으로 작동하므로, API 검색, 설계/재설계, 변경 영향 평가와 같은 작업을 개발 라이프사이클 초기에 더 자주 수행하여 잠재적인 문제를 조기에 발견하고 해결할 수 있습니다.
