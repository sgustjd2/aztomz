# Your Agent Evolved. Your Evals Didn't. — Ameya Bhatawdekar, Braintrust

🔗 https://youtu.be/nxokqOq1imY · 📅 2026-08-20 · 🎙 AI Engineer

## 한 줄 요약
빠르게 진화하는 LLM 에이전트의 복잡한 행동을 평가하기 위해, 정적이고 수동적인 방식에서 벗어나 전체 실행 트레이스를 기반으로 한 연속적인 평가 시스템을 구축하고, 합성 데이터 생성 및 인간 피드백을 통합하여 개발 라이프사이클 전반에 걸쳐 적용해야 합니다.

## 발표자·소속
Ameya Bhatawdekar, Braintrust

## 핵심 주장
-   **기존 평가 방식의 한계**: 정적 테스트셋과 수동 평가는 빠르게 진화하는 LLM 에이전트의 복잡한 행동과 비결정성을 포착하기 어렵고, 확장성이 부족하여 개발 속도를 저해합니다. 에이전트는 여러 단계를 거치며 도구를 사용하기 때문에 최종 출력뿐 아니라 전체 실행 과정을 평가해야 합니다.
-   **연속적인 트레이스 기반 평가의 필요성**: 에이전트의 전체 실행 트레이스(trace)를 기록하고 평가하는 것이 중요합니다. 이는 에이전트의 내부 작동 방식, 중간 단계, 도구 사용 등을 상세히 파악하여 문제의 근본 원인을 진단하고 개선하는 데 필수적입니다.
-   **합성 데이터 생성의 활용**: LLM을 활용하여 다양하고 새로운 테스트 케이스, 엣지 케이스, 심지어 적대적(adversarial) 예시까지 자동으로 생성함으로써, 정적 데이터셋의 한계를 극복하고 테스트 커버리지를 획기적으로 확장할 수 있습니다.
-   **인간 개입(Human-in-the-Loop)과 자동화된 평가의 결합**: LLM 기반 평가(LLM-as-a-judge), 정규 표현식, 사용자 정의 함수 등 자동화된 평가 방식과 함께, 주관적인 판단이 필요한 부분에는 인간의 피드백을 통합하여 평가의 정확성과 신뢰도를 높여야 합니다.
-   **평가 시스템의 개발 라이프사이클 통합**: 에이전트 평가를 개발, CI/CD, 프로덕션 모니터링 과정에 지속적으로 통합하여, 코드 변경이 성능에 미치는 영향을 즉시 파악하고 회귀(regression)를 방지하며, 프로덕션 환경의 문제를 신속하게 감지하고 개선하는 선순환 구조를 구축해야 합니다.

## 세부 내용
발표는 "당신의 에이전트는 진화했지만, 당신의 평가는 그렇지 못했다"는 제목으로, LLM 에이전트의 빠른 발전 속도에 비해 평가 방식이 뒤처져 있다는 문제 제기로 시작합니다. 발표자는 기존의 정적 테스트셋과 수동 평가는 에이전트의 다단계적, 비결정적 특성을 반영하지 못하며, 새로운 기능 추가 시 회귀를 방지하기 어렵다고 지적합니다. 특히 에이전트가 여러 도구를 사용하고 복잡한 추론 과정을 거치기 때문에, 최종 출력뿐만 아니라 전체 실행 과정을 평가하는 것이 중요하다고 강조합니다.

발표자는 Braintrust 플랫폼을 통해 이러한 문제를 해결하는 방법을 시연했습니다. 핵심은 **연속적인 트레이스 기반 평가(Continuous Trace-based Evaluation)**입니다.

1.  **문제점 진단 및 트레이스 분석**: 에이전트의 복잡한 동작(예: 검색 도구 사용, 계산기 호출, 중간 추론 과정)을 평가하려면 최종 출력뿐 아니라 전체 실행 트레이스를 분석해야 합니다. Braintrust는 각 에이전트 실행의 프롬프트, 응답, 도구 호출, 중간 생각 과정(`thought`) 등을 상세히 기록하고 시각화하여 개발자가 에이전트의 "생각"을 이해하고 디버깅할 수 있도록 돕습니다. 데모에서는 특정 에이전트 실행의 상세 트레이스 뷰를 통해 프롬프트, 응답, 도구 호출(예: `search`, `calculator`), 중간 추론 과정을 시각적으로 보여주며, 이를 통해 에이전트가 왜 특정 결정을 내렸는지, 어디서 오류가 발생했는지 쉽게 파악할 수 있음을 강조합니다.

2.  **평가 방법론**:
    *   **LLM-as-a-judge**: LLM을 사용하여 에이전트의 응답을 평가합니다. 예를 들어, 특정 질문에 대한 답변의 정확성, 유용성, 안전성 등을 평가하는 프롬프트를 정의할 수 있습니다.
    *   **정규 표현식/키워드 매칭**: 간단한 규칙 기반의 평가에 사용됩니다.
    *   **사용자 정의 함수**: 특정 비즈니스 로직이나 복잡한 조건을 평가하는 데 활용됩니다.
    *   **인간 피드백**: 주관적인 판단이 필요한 경우, 개발자나 사용자가 직접 평가하고 피드백을 제공합니다.

3.  **합성 데이터 생성(Synthetic Data Generation)**:
    *   정적 테스트셋의 한계를 극복하기 위해, LLM을 "생성기(generator)"로 활용하여 새로운 입력 데이터를 만듭니다. 예를 들어, 특정 주제(예: "집 짓는 방법")에 대한 다양한 질문을 생성하도록 프롬프트를 정의하여 테스트 커버리지를 확장합니다. 이는 엣지 케이스나 적대적 예시를 발견하는 데 특히 유용합니다.

4.  **데모 시연**:
    *   Braintrust 대시보드에서 프로젝트, 실험, 데이터셋, 평가 결과를 한눈에 볼 수 있음을 보여줍니다.
    *   두 가지 에이전트 버전(`agent-v1`, `agent-v2`)을 비교하는 실험 화면을 통해 `정확성(correctness)`, `지연 시간(latency)`, `비용(cost)` 등의 지표를 비교합니다.
    *   평가 결과를 바탕으로 에이전트의 성능을 개선하고, 새로운 버전을 배포하기 전에 회귀 테스트를 수행하는 과정을 설명합니다.

5.  **개발 워크플로우 통합**:
    *   Braintrust Python SDK를 사용하여 에이전트의 트레이스를 쉽게 로깅하고 평가를 실행할 수 있습니다.
    *   CI/CD 파이프라인에 평가를 통합하여 코드 변경 시 자동으로 성능 저하를 감지하고 배포를 차단할 수 있습니다.
    *   프로덕션 환경에서 에이전트의 성능을 지속적으로 모니터링하고, 문제가 발생하면 이를 평가 데이터셋에 추가하여 에이전트를 개선하는 피드백 루프를 구축합니다.

발표는 에이전트 개발의 미래는 단순히 더 똑똑한 모델을 만드는 것이 아니라, 지속적으로 학습하고 개선할 수 있는 더 똑똑한 시스템을 구축하는 데 있다는 메시지로 마무리됩니다.

## 실무 적용 포인트
1.  **에이전트 실행 트레이스 로깅 및 분석 시스템 구축**: 에이전트 개발 시, 단순히 최종 응답뿐만 아니라 프롬프트, 중간 추론, 도구 호출 등 전체 실행 과정을 상세히 기록하고 시각화하는 시스템을 구축하여 디버깅 및 성능 분석에 활용해야 합니다.
2.  **LLM 기반 평가(LLM-as-a-judge) 도입**: 수동 평가의 한계를 극복하기 위해, LLM을 활용하여 에이전트 응답의 정확성, 유용성, 안전성 등을 평가하는 자동화된 평가 프롬프트를 설계하고 적용하여 평가 효율성을 높일 수 있습니다.
3.  **합성 데이터 생성으로 테스트 커버리지 확장**: LLM을 사용하여 다양한 시나리오, 엣지 케이스, 적대적 예시를 포함하는 합성 테스트 데이터를 자동으로 생성함으로써, 에이전트의 견고성을 높이고 예상치 못한 오류를 사전에 발견할 수 있습니다.
4.  **CI/CD 파이프라인에 평가 통합**: 에이전트 코드 변경 시마다 자동화된 평가를 실행하도록 CI/CD 파이프라인을 구성하여, 새로운 기능 추가나 코드 수정으로 인한 성능 회귀를 즉시 감지하고 방지하는 안전망을 구축해야 합니다.
