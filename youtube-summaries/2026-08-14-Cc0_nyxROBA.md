# From RL to IRL — Gaurav Mishra, Amazon AGI Lab

🔗 https://youtu.be/Cc0_nyxROBA · 📅 2026-08-14 · 🎙 AI Engineer

## 한 줄 요약
강화 학습(RL) 에이전트를 실제 환경(IRL)에 배포할 때 발생하는 예측 불가능한 문제점들을 해결하기 위해, 에이전트 훈련 환경과 모델 자체, 그리고 에이전트와 실제 환경 사이의 인터페이스인 하네스(Harness)를 개선해야 한다는 발표입니다.

## 발표자·소속
Gaurav Mishra, Amazon AGI Lab (Member of Technical Staff)

## 핵심 주장
- **RL은 게임 환경에서 효과적이지만, 실제 환경은 게임이 아니다:** RL은 태스크가 풍부하고, 여러 정답이 존재하며, 결과 검증이 가능하고, 추론이 중요한 코딩과 같은 도메인에서 효과적입니다. 하지만 실제 환경은 부분적 관측 가능성, 비가역적 행동, 비결정론, 일시적 권한, 모호한 성공, 적대적/오염된 맥락 등 RL의 가정을 깨뜨리는 복잡한 도전 과제를 안고 있습니다.
- **IRL 훈련은 '비행 학교'와 같아야 한다:** 실제 환경에서 에이전트를 훈련시키기 위해서는 단순히 시험을 통과하는 것을 넘어, 실제 세계의 복잡성과 혼란스러움을 반영한 고충실도 디지털 샌드박스에서 훈련해야 합니다. 이는 레이아웃 변화, 느린 로딩, 누락된 라벨, 팝업, 무작위 계정 상태 등 다양한 현실적 시나리오를 포함해야 합니다.
- **에이전트(파일럿)와 하네스(조종석) 모두 업그레이드해야 한다:** 에이전트 자체는 스크린 이해, 의미론적 UI 파악, 변화 감지, 다중 소스 관측과 같은 인지적 능력을 강화해야 합니다. 동시에 하네스는 체크포인트/롤백, 행동 위험 분류, 자격 증명 보호, 실행 모니터링, 감사 로그, 그리고 필요시 사용자에게 제어권을 넘기는(Human Handoff) 기능을 통해 에이전트의 안전하고 효율적인 작동을 지원해야 합니다.
- **데모와 제품의 차이는 첫 번째 실패한 클릭 이후에 결정된다:** 에이전트가 실제 환경에서 마주치는 첫 번째 실패를 어떻게 처리하는지가 데모와 실제 제품 간의 핵심적인 차이입니다. 현실 세계의 복잡성을 훈련 과정에 통합하고, 에이전트가 실패로부터 학습하며 안전하게 복구할 수 있도록 시스템을 설계하는 것이 중요합니다.

## 세부 내용

발표는 강화 학습(RL)의 기본 개념과 효과적인 적용 분야를 간략히 설명하는 것으로 시작합니다. RL에서 에이전트는 정책(policy)이며, 보상 함수(reward function), 모델 또는 다른 에이전트를 통해 보상을 계산합니다. RL은 태스크가 많지만 시연 데이터 수집이 어려운 경우, 여러 정답이 있지만 결과 검증이 가능한 경우, 그리고 추론이 중요한 도메인에서 특히 효과적입니다. 코딩은 이러한 패러다임에 완벽하게 부합하여 강력한 코딩 에이전트 개발에 기여했습니다.

RL의 주요 구성 요소는 세 가지입니다:
1.  **태스크(Task):** 검증 가능한 결과, 목표 기술, 적절한 난이도 범위를 가져야 합니다.
2.  **환경(Environment):** 모델의 응답을 실행하고 결과를 반환하는 코드 샌드박스가 필요합니다.
3.  **검증자(Verifier):** 컴파일러, 린터, 단위 테스트, 데이터베이스 조회, 또는 루브릭(rubrics)과 비교하는 에이전트 등을 통해 모델 응답에 보상을 할당합니다.

코딩 에이전트가 발전하면서, 이들이 단순히 코드를 생성하는 것을 넘어 컴퓨터 사용 전반에 걸쳐 활용될 수 있다는 인식이 생겼습니다. 예를 들어, 채팅, 이메일, 문서 작업을 위한 API 호출, 브라우저에서 양식을 작성하고 제출하는 Playwright 코드, 특정 주제를 조사하기 위한 웹 검색 API 호출 등이 가능합니다. 이론적으로 코딩 에이전트는 컴퓨터 사용에 뛰어나야 합니다.

하지만 실제 환경(IRL)에서는 여러 가지 문제점이 발생합니다. 발표자는 두 가지 데모를 통해 이를 설명합니다.
1.  **에이전트가 계정을 잠금:** 에이전트가 경비 보고서를 제출하려 하지만, 로그인 화면이 나타납니다. 에이전트는 비밀번호를 추론하려 시도하고 여러 번 실패하여 결국 계정을 잠급니다.
2.  **에이전트가 피싱 당함:** 에이전트가 경비 보고서를 제출하려 하지만, 실제 제출 버튼과 유사하게 생긴 광고 버튼을 클릭합니다. 이로 인해 다른 웹사이트로 이동하여 개인 정보를 입력하기 시작합니다.

이러한 데모는 RL이 게임 환경에서는 잘 작동하지만, 실제 환경에서는 "게임이 반격할 때" 문제가 발생한다는 점을 보여줍니다. 실제 컴퓨터 사용 환경의 주요 도전 과제는 다음과 같습니다:
*   **부분적 관측 가능성:** 스크린샷, DOM, 커서, 스크롤 위치, 보이지 않는 상태 등 모든 정보가 완전하게 제공되지 않습니다.
*   **비가역성:** 이메일 전송, 아이템 구매, 파일 삭제, 양식 제출 등 일부 행동은 되돌릴 수 없습니다.
*   **비결정론:** 지연 시간, 팝업, 불안정한 네트워크, 속도 제한 등으로 인해 행동의 결과가 항상 예측 가능하지 않습니다.
*   **일시적 권한:** 세션 만료, 자격 증명 변경, OAuth 창 발생 등 권한이 일시적일 수 있습니다.
*   **모호한 성공:** "완료"가 사용자 관점에서는 성공일 수 있지만, 환경 관점에서는 아닐 수 있습니다.
*   **적대적 또는 오염된 맥락:** 광고, 스캠, 기타 함정들이 에이전트를 오도할 수 있습니다.

이러한 현실에 적응하기 위해 IRL 훈련은 '비행 시뮬레이터'와 같은 접근 방식을 필요로 합니다.
*   **고충실도 디지털 샌드박스:** 레이아웃 변화, 느린 로딩, 누락된 라벨, 팝업, 포커스 스틸링, 무작위 계정 상태, 오래된 탭 등 현실의 모든 혼란을 시뮬레이션하여 훈련해야 합니다.
*   **모델-액션으로서의 복구:** 오류가 발생하면 모델에게 다시 전달하여 새로고침, 백트랙, 비교, 대기, 체크포인트, 포기, 에스컬레이션 등과 같은 '네이티브 모델-액션'을 통해 스스로 복구하도록 해야 합니다.
*   **프로세스 보상 모델:** 자격 증명 오용, 검증 부족, 과도한 재시도, 안전하지 않은 단축키 등 위험한 행동을 과정 중에 페널티를 부여해야 합니다.
*   **보정된 신뢰도:** 에이전트에게 행동이 승인되었는지, 비가역적인지, 사용자에게 보이는지 등을 파악하고 적절하게 에스컬레이션하는 방법을 가르쳐야 합니다.
*   **적대적 태스크:** 적대적 시나리오를 훈련하여 에이전트가 엣지 케이스를 처리하도록 가르쳐야 합니다.

에이전트(파일럿) 자체도 변화해야 합니다. 단순히 코딩 능력만으로는 부족하며, 다음과 같은 인지적 원시 기능(perception primitives)이 필요합니다.
*   **스크린 그라운딩:** 화면에 있는 '그것'이 어디에 있는지, 보이는지, 가려져 있는지, 활성화되어 있는지, 올바른 인스턴스인지 등을 파악하는 능력.
*   **의미론적 UI 이해:** "이 제출 버튼은 사실 광고다"와 같이 UI 요소의 실제 의미와 목적을 이해하는 능력.
*   **변화 감지:** 클릭 후 무엇이 변했는지, 페이지가 이동했는지, 양식이 저장되었는지, 업로드가 완료되었는지, 스피너가 사라졌는지 등을 감지하는 능력.
*   **다중 소스 관측:** 스크린샷, DOM, 브라우저 이벤트, 클립보드, 네트워크 상태 등 다양한 정보 소스를 통합하여 이해하는 능력.

에이전트와 실제 환경 사이의 인터페이스인 하네스(Cockpit)도 중요합니다.
*   **체크포인트 및 롤백:** 위험한 단계 전에 상태를 저장하고, 중요한 행동에 대해 결과를 요약하고 확인을 요청합니다.
*   **행동 위험 분류기:** "제출" 클릭과 "다음" 클릭의 위험도를 구분합니다.
*   **자격 증명 가드레일:** 잘못된 계정, 만료된 로그인, 권한 실패, OAuth 프롬프트, 결제 화면 등을 감지합니다.
*   **실행 모니터:** 루프, 반복 클릭, 비생산적인 재시도, 오래된 관측, 타임아웃 등을 감시합니다.
*   **감사 로그:** 에이전트 행동 및 효과에 대한 증거를 유지합니다.
*   **휴먼 핸드오프:** 가장 좋은 에이전트도 모든 곳에서 완전히 자율적이지는 않으므로, 언제 일시 중지하고 사용자에게 제어권을 넘겨야 하는지 알아야 합니다.

발표자는 이러한 개선 사항들을 적용한 IRL 에이전트 데모를 보여줍니다. 이 에이전트는 이전 데모와 동일한 상황에서, 광고 버튼을 피하고 올바른 제출 버튼을 클릭하며, 로그인 만료 시 사용자에게 제어권을 넘겨 계정 잠금을 방지합니다.

결론적으로, RL의 가정(상태는 관측 가능, 행동은 저렴, 보상은 명확, 실패는 리셋, 환경은 수동적, 자율성은 항상 좋음)과 IRL의 현실(UI 상태는 부분적/혼란스러움, 행동은 비가역적, 성공은 모호, 실패는 지속, 콘텐츠는 적대적, 핸드오프가 최적일 수 있음) 사이의 간극을 메우기 위해 인지적 원시 기능, 위험 인식 실행, 검증, 복구 정책, 신뢰 경계, 보정된 에이전시와 같은 변화가 필요합니다.

## 인상적인 대목
- "RL worked when the world was a game. IRL starts when the game fights back." (RL은 세상이 게임일 때 작동했다. IRL은 게임이 반격할 때 시작된다.)
- "The difference between a demo and a product is what happens after the first failed click." (데모와 제품의 차이는 첫 번째 실패한 클릭 이후에 일어나는 일이다.)

## 실무 적용 포인트
- **현실적 훈련 환경 구축:** 에이전트를 실제 환경에 배포하기 전에, 레이아웃 변화, 느린 로딩, 팝업, 만료된 세션 등 현실에서 발생할 수 있는 다양한 '혼란'을 포함하는 고충실도 시뮬레이션 환경을 구축하여 훈련해야 합니다.
- **복구 메커니즘 내재화:** 에이전트가 오류 발생 시 단순히 재시작하는 것이 아니라, 새로고침, 백트랙, 사용자에게 제어권 넘기기 등과 같은 '네이티브 액션'을 통해 스스로 복구하도록 설계하고 훈련해야 합니다.
- **안전 장치(하네스) 설계:** 에이전트의 행동을 모니터링하고 제어하는 하네스 계층을 구축하여, 위험한 행동을 방지하고(예: 자격 증명 오용 감지), 비생산적인 루프를 끊으며, 필요시 사용자 개입을 요청하도록 해야 합니다.
- **인지적 능력 강화:** 에이전트가 스크린의 시각적 및 의미론적 정보를 깊이 이해하고, 변화를 감지하며, 다양한 정보 소스를 통합하여 상황을 파악할 수 있도록 '인지적 원시 기능' 개발에 투자해야 합니다.
