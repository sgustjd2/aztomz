# From coding to Knowledge work agents — Karan Vaidya, Composio

## 한 줄 요약
Composio의 Karan Vaidya는 LLM이 실제 애플리케이션과 상호작용하여 복잡한 지식 작업을 자동화하는 '지식 작업 에이전트'를 구축하기 위한 API 우선 플랫폼을 소개하며, 에이전트가 도구 발견, 사용, 상태 관리, 인간 개입 등을 처리하는 방식을 시연한다.

## 발표자·소속
Karan Vaidya, Composio 공동 창업자

## 핵심 주장
-   **LLM의 실행 능력 한계 극복**: 대규모 언어 모델(LLM)은 추론 능력은 뛰어나지만, 실제 세상의 애플리케이션과 상호작용하여 행동을 실행하는 데 어려움을 겪습니다. Composio는 수천 개의 애플리케이션에 대한 통합 API 계층을 제공하여 LLM이 실제 작업을 수행할 수 있도록 돕습니다.
-   **복잡한 에이전트 워크플로우 간소화**: 기존 에이전트 프레임워크는 간단한 작업에 적합하지만, 여러 단계와 도구를 사용하는 복잡한 워크플로우에서는 도구 발견, 파라미터 사용, 상태 관리, 오류 처리 등의 문제에 직면합니다. Composio는 이러한 복잡성을 추상화하여 에이전트 개발을 용이하게 합니다.
-   **'지식 작업 에이전트'의 부상**: 발표자는 소프트웨어 애플리케이션을 사용하여 사람이 수행하는 작업을 자동화하는 에이전트를 '지식 작업 에이전트'라고 정의합니다. Composio는 이러한 에이전트가 HubSpot, Gmail 등 다양한 SaaS 및 내부 도구와 연동하여 실질적인 비즈니스 가치를 창출하도록 지원합니다.
-   **엔지니어링 패러다임의 변화**: 에이전트 기반 시스템은 명시적인 코드 지시 대신 목표 지향적이고 적응적인 접근 방식을 요구합니다. 엔지니어는 이제 모든 단계를 코딩하는 대신 에이전트의 목표를 정의하고, 적절한 도구를 제공하며, 피드백 루프를 관리하는 역할로 전환해야 합니다.

## 세부 내용
발표는 대규모 언어 모델(LLM)의 강력한 추론 능력에도 불구하고 실제 세계의 애플리케이션과 상호작용하여 행동을 실행하는 데 한계가 있다는 문제 제기로 시작합니다. 발표자는 LLM을 "몸 없는 뇌"에 비유하며, 실제 작업을 수행하기 위한 도구와 실행 계층의 필요성을 강조합니다. 기존 에이전트 프레임워크는 간단한 작업에는 유용하지만, 여러 도구를 사용하고 장기 실행되는 복잡한 워크플로우에서는 도구 발견, 파라미터 사용, 인증, 상태 관리, 오류 처리, 인간 개입 등의 문제에 직면한다고 지적합니다.

이러한 문제를 해결하기 위해 Composio는 "AI 에이전트 구축을 위한 API 우선 플랫폼"으로 소개됩니다. Composio의 목표는 LLM이 어떤 애플리케이션과도 상호작용할 수 있도록 하는 것입니다. 이를 위해 Composio는 수천 개의 SaaS 애플리케이션 및 내부 도구에 대한 통합 API 계층을 제공하며, 인증 및 API 정규화를 처리합니다. 핵심 기능으로는 LLM이 사용자 의도에 따라 관련 도구를 발견하고, 도구의 파라미터와 스키마를 이해하여 올바르게 사용하는 능력, 장기 실행 작업의 상태 관리, 검증이나 복잡한 결정을 위한 인간 개입(Human-in-the-Loop), 그리고 에이전트 실행 모니터링 및 디버깅을 위한 관측성(Observability)이 포함됩니다.

발표자는 Composio의 기능을 시연하기 위해 "HubSpot에서 'New' 단계에 있는 모든 리드를 찾아 Gmail을 통해 개인화된 이메일을 보내라"는 시나리오를 제시합니다.
데모 과정은 다음과 같습니다:
1.  사용자가 LLM에 자연어 프롬프트를 입력합니다.
2.  LLM은 Composio의 도구 오케스트레이터의 도움을 받아 필요한 도구를 식별합니다. 이 시나리오에서는 `hubspot_crm_get_contacts`와 `gmail_send_email` 도구가 발견됩니다.
3.  LLM은 `hubspot_crm_get_contacts` 도구를 `stage='New'` 파라미터와 함께 호출하여 HubSpot에서 해당 리드 정보를 가져옵니다.
4.  가져온 각 연락처(이름, 이메일)에 대해 LLM은 개인화된 이메일 내용을 생성합니다.
5.  생성된 이메일 내용을 사용하여 `gmail_send_email` 도구를 호출, 각 리드에게 이메일을 발송합니다.
Composio 대시보드에서는 에이전트의 실행 과정, 사용된 도구, 입력/출력, 로그 등을 시각적으로 확인할 수 있어 디버깅과 모니터링이 용이함을 보여줍니다. 이 데모는 LLM이 각 애플리케이션의 복잡한 API를 직접 알 필요 없이, Composio가 제공하는 추상화 계층을 통해 고수준의 추론과 계획에 집중할 수 있음을 명확히 보여줍니다.

발표는 '코딩에서 지식 작업 에이전트로'의 패러다임 전환에 대해 논하며 마무리됩니다. 전통적인 코딩이 명시적이고 결정적이며 경직된 지시를 따르는 반면, LLM 에이전트는 목표 지향적이고 적응적이며 확률적이고 피드백을 통해 학습한다고 설명합니다. 미래에는 에이전트가 더욱 자율적이고 복잡한 작업을 처리하며 워크플로우에 깊이 통합될 것이라고 전망합니다. 엔지니어의 역할은 모든 단계를 코딩하는 것에서 에이전트를 설계하고 오케스트레이션하며, 목표를 정의하고, 도구를 제공하고, 피드백을 관리하는 것으로 변화할 것이라고 강조합니다.

## 인상적인 대목
-   "LLMs are like a brain without a body." (LLM은 몸 없는 뇌와 같습니다.)
-   "The shift is from explicit instructions to goal-oriented, adaptive, probabilistic, and feedback-driven systems." (변화는 명시적인 지시에서 목표 지향적이고, 적응적이며, 확률적이고, 피드백 기반 시스템으로의 전환입니다.)

## 실무 적용 포인트
-   **에이전트 개발 시 추상화 계층 활용**: 복잡한 다단계 작업을 자동화할 때, LLM이 직접 각 애플리케이션의 API 세부 사항을 다루게 하기보다는 Composio와 같은 통합 API 플랫폼을 활용하여 도구 발견, 파라미터 매핑, 인증 등의 복잡성을 추상화하는 것을 고려할 수 있습니다.
-   **인간 개입(Human-in-the-Loop) 설계**: 에이전트가 중요한 결정이나 불확실한 상황에 직면했을 때, 인간이 개입하여 검증하거나 지시를 내릴 수 있는 메커니즘을 반드시 포함하여 에이전트의 신뢰성과 안전성을 확보해야 합니다.
-   **관측성(Observability) 및 디버깅 도구 구축**: 에이전트의 실행 과정을 명확하게 추적하고, 사용된 도구, 입력/출력, 오류 로그 등을 시각적으로 확인할 수 있는 대시보드나 로깅 시스템을 구축하여 에이전트의 행동을 이해하고 문제를 진단하는 데 활용해야 합니다.
-   **점진적 개발 및 목표 중심 접근**: 에이전트 시스템을 처음부터 완벽하게 만들려 하기보다는, 명확하고 단순한 목표를 설정하고 작은 단위부터 반복적으로 개발하며 점진적으로 기능을 확장해 나가는 것이 효과적입니다.
