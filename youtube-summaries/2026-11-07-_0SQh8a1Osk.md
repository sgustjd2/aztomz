# Don't Vibe Code Your Agent Infrastructure - Akshat Bubna, Modal

🔗 https://youtu.be/_0SQh8a1Osk · 📅 2026-11-07 · 🎙 AI Engineer

## 한 줄 요약
Modal의 CTO Akshat Bubna는 AI 에이전트가 워크스페이스, 영구적인 작업 저장, 탄력적인 리소스, 가속기, 협업, 자체 개선, 안전한 리소스 접근, 뛰어난 관찰 가능성 등 복잡한 인프라 요구사항을 가지고 있으며, 이러한 요구사항을 충족시키기 위해 직접 샌드박스 플랫폼을 구축하는 것은 신뢰성, 보안, 확장성 문제로 인해 비효율적이라고 주장하며, Modal이 제공하는 강력한 인프라 프리미티브가 에이전트의 역량을 확장할 것이라고 강조했습니다.

## 발표자·소속
Akshat Bubna, Modal CTO

## 핵심 주장
- AI 에이전트는 복잡하고 동적인 인프라 요구사항을 가지고 있으며, 기존의 인프라 솔루션으로는 이를 효율적으로 충족시키기 어렵습니다. 에이전트는 안전하고 격리된 워크스페이스, 작업의 영속성, 탄력적인 컴퓨팅 리소스, GPU와 같은 가속기, 다른 에이전트 및 인간과의 협업, 자체 개선 능력, 그리고 안전하고 통제된 외부 리소스 접근 및 뛰어난 관찰 가능성을 필요로 합니다.
- 에이전트 인프라를 직접 구축하는 것은 신뢰성, 보안, 확장성 측면에서 엄청난 도전 과제입니다. 시스템의 안정성을 유지하고, 빠르게 진화하는 AI 환경에서 보안 경계를 방어하며, 초당 수천 개의 샌드박스를 생성하고 수십만 개를 동시에 실행하는 대규모 워크로드를 처리하는 것은 고도로 전문화된 엔지니어링 역량을 요구합니다.
- Modal은 AI 애플리케이션을 위해 특별히 구축된 인프라 프리미티브(추론, 샌드박스, 훈련, 함수)를 제공하여 에이전트 개발자들이 복잡한 인프라 문제에 대한 걱정 없이 에이전트의 핵심 로직에 집중할 수 있도록 돕습니다. Modal은 자체 파일 시스템, 스케줄링, 런타임을 개발하여 뛰어난 성능과 개발자 경험을 제공합니다.
- 에이전트의 미래는 "펫(Pets)"이나 "가축(Cattle)"처럼 관리되는 정적인 서비스가 아니라, 동적으로 생성되고 상호작용하며 자체 진화하는 "자기 진화 유기체의 바다(Ocean of self-evolving organisms)"와 같을 것이며, 이를 위해서는 강력하고 유연한 인프라 프리미티브가 필수적입니다.

## 세부 내용
발표는 "에이전트가 인프라로부터 무엇을 필요로 하는가?"라는 질문으로 시작됩니다. 발표자는 금융 분석가가 포트폴리오의 모든 회사에 대해 복잡한 분석을 실행하는 스프레드시트의 예를 들며, 과거에는 며칠이 걸렸던 작업이 에이전트를 통해 훨씬 쉬워질 수 있다고 설명합니다. Modal의 고객인 Hebbla는 실제로 스프레드시트의 모든 셀이 에이전트에 의해 백업되는 시스템을 구축했습니다.

이러한 시스템을 구축하기 위한 아키텍처는 다음과 같습니다.
1.  **샌드박스(Sandbox)**: 각 에이전트는 Modal 샌드박스에 의해 백업됩니다. 샌드박스는 신뢰할 수 없는 코드를 실행하기 위한 보안 환경입니다. Modal은 단일 샌드박스 내에서 여러 컨테이너(예: 에이전트 하네스 및 도구 실행 사이드카)를 실행할 수 있는 기능을 제공합니다.
2.  **에이전트 하네스(Agent Harness)**: 에이전트 루프를 실행하며, 작업 배치, 모델 API 호출(추론), 도구 호출 실행, 다음 목표 반복 등의 작업을 수행합니다.
3.  **도구 실행(Tool Execution)**: 셸/파이썬 스크립트, 파일 작업, 작업별 도구를 실행합니다.
4.  **공유 볼륨(Shared Volumes)**: 문서, 작업 파일, 생성된 아티팩트를 포함하며, 에이전트 간의 협업과 영구적인 상태 저장을 가능하게 합니다. 이 모든 것은 매우 빠르게 생성되고 해체되어야 합니다.

발표자는 Modal을 "AI를 위해 구축된 인프라 프리미티브 플랫폼"으로 소개합니다. Modal은 추론, 샌드박스, 훈련, 함수와 같은 AI 사용 사례를 위해 자체 파일 시스템, 스케줄링, 런타임을 처음부터 구축하여 뛰어난 성능과 개발자 경험을 제공합니다.

에이전트가 필요로 하는 구체적인 인프라 요소들은 다음과 같습니다.
-   **워크스페이스(Workspace)**: Ramp Inspect(Ramp의 내부 코딩 에이전트)는 코드 저장소, 종속성, 개발 서비스(Postgres, Redis 등)를 필요로 합니다. Basis(회계 에이전트)는 문서, 작업 보고서, 스크립트를 필요로 합니다. 게임 개발 에이전트는 게임 엔진과 에셋을 필요로 합니다.
-   **작업의 영속성(Persistence)**: 에이전트의 작업은 인간의 응답을 기다리는 등 장시간 중단될 수 있으므로, 컴퓨팅 리소스는 해제되더라도 상태는 영구적으로 저장되어야 합니다. 이는 전체 파일 시스템 스냅샷, 특정 디렉토리 스냅샷, 또는 공유 파일 시스템(볼륨) 형태로 구현될 수 있습니다.
-   **탄력적인 리소스(Elastic Resources)**: Ramp Inspect의 데이터는 샌드박스의 CPU 및 메모리 사용량이 매우 가변적임을 보여줍니다. 피크에 맞춰 리소스를 미리 프로비저닝하면 비효율적이므로, Modal은 에이전트가 필요할 때 리소스를 안정적으로 확보하고 사용한 만큼만 비용을 지불하도록 합니다.
-   **가속기(Accelerators)**: Claude Science와 같은 고객은 Modal을 통해 CPU에서 데이터 전처리, GPU에서 과학 모델 실행 등 집약적인 컴퓨팅 작업을 오프로드합니다. 게임 디자인, 비디오 편집, 3D 개발 등 다양한 분야에서 GPU 사용이 증가하고 있습니다.
-   **협업(Collaboration)**: 에이전트는 다른 에이전트나 인간과 공유된 워크페이퍼(Modal 볼륨)를 통해 협업해야 합니다. 이를 위해서는 빠르고 일관적이며 개발자 친화적인 파일 시스템이 필요합니다.
-   **자체 개선(Self-improve)**: 에이전트는 실행 중 메모리를 저장하고 업데이트하며, 백그라운드 작업(dreaming)을 통해 시간이 지남에 따라 메모리를 통합하여 자체 개선합니다. 이는 고성능 파일 시스템을 통해 지원됩니다.
-   **안전한 리소스 접근(Secure Access)**: 에이전트는 외부 리소스에 접근할 때 보안이 중요합니다. 어떤 IP가 에이전트와 통신할 수 있는지, 인증 방식, 어떤 도메인에 접근할 수 있는지 등을 제어해야 합니다. 특히, 에이전트가 민감한 자격 증명을 직접 보지 못하도록 주입하는 방식이 필요합니다. Ramp의 사례처럼 프록시 사이드카를 통해 에이전트의 외부 통신을 세밀하게 제어할 수 있습니다.
-   **뛰어난 관찰 가능성(Great Observability)**: 에이전트와 인간 모두에게 중요합니다. 훈련 실패 시 로그를 확인하고, 메트릭(GPU 활용률, 예산 등)을 모니터링하여 에이전트가 스스로 문제를 진단하고 개선할 수 있도록 해야 합니다.

발표자는 "샌드박스 플랫폼을 직접 구축하지 마세요(You wouldn't vibecode a sandbox platform)"라고 강조하며, 그 이유로 **신뢰성**, **보안**, **확장성**을 꼽습니다. Modal은 현재 주당 약 2천만 개의 스냅샷을 처리하고, 하루에 약 8.4페타바이트의 스냅샷 데이터를 처리하며, 주당 약 260만 개의 볼륨을 생성하는 등 대규모로 확장되고 있습니다. 한 고객의 개인 비서 워크로드의 경우, 초당 1만 개의 샌드박스를 생성하고 피크 시 80만 개 이상의 샌드박스가 동시에 실행되며, 평균 수명은 3분, 상호작용까지 걸리는 시간은 1초 미만입니다. 또한, CPU 자원도 부족해지고 있어 단일 클라우드에 의존할 수 없으며, Modal은 여러 하이퍼스케일러 및 뉴클라우드의 용량을 통합하여 제공합니다.

결론적으로, 에이전트의 미래는 "펫"이나 "가축"이 아닌 "자기 진화 유기체의 바다"와 같을 것이며, 에이전트가 더 많은 것을 할 수 있도록 하는 것은 바로 "훌륭한 프리미티브(Great primitives)"라고 주장하며 발표를 마칩니다.

## 실무 적용 포인트
-   **에이전트 인프라 요구사항 이해**: 에이전트 개발 시 워크스페이스, 영속성, 탄력성, 보안, 관찰 가능성 등 다양한 인프라 요구사항을 초기 단계부터 고려해야 합니다. 특히 동적인 환경과 협업, 자체 개선 기능을 염두에 두어야 합니다.
-   **샌드박스 환경 활용**: 신뢰할 수 없는 에이전트 코드를 실행할 때는 보안과 격리를 위해 샌드박스 환경을 적극적으로 활용해야 합니다. Modal처럼 여러 컨테이너를 단일 샌드박스 내에서 실행하는 모델을 고려하여 에이전트의 '두뇌'와 '손'을 분리하는 아키텍처를 설계할 수 있습니다.
-   **탄력적인 리소스 관리**: 에이전트의 리소스 사용량은 매우 가변적이므로, 피크에 맞춰 고정적으로 리소스를 할당하기보다는 필요에 따라 동적으로 확장/축소되는 탄력적인 리소스 프로비저닝 방식을 채택하여 비용 효율성을 높여야 합니다.
-   **보안 및 관찰 가능성 강화**: 에이전트의 외부 리소스 접근을 세밀하게 제어하고(예: 프록시 사이드카를 통한 도메인/경로 기반 규칙), 자격 증명 주입 방식을 안전하게 설계해야 합니다. 또한, 에이전트의 동작과 성능을 모니터링할 수 있는 강력한 관찰 가능성 도구를 구축하여 문제 진단 및 개선에 활용해야 합니다.
