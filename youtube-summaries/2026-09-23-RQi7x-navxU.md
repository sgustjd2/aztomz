# Building the Document Context Layer for AI Agents — Jerry Liu, LlamaIndex

🔗 https://youtu.be/RQi7x-navxU · 📅 2026-09-23 · 🎙 AI Engineer

## 한 줄 요약
LlamaIndex는 LLM의 한계를 극복하고 AI 에이전트가 다양한 데이터 소스와 상호작용하며 고급 검색 전략을 활용할 수 있도록 돕는 문서 컨텍스트 레이어 구축 프레임워크를 제공합니다.

## 발표자·소속
Jerry Liu, LlamaIndex 공동 창립자 및 CEO

## 핵심 주장
- **LLM의 한계를 극복하기 위해 문서 컨텍스트 레이어가 필수적입니다.** LLM은 제한된 컨텍스트 창, 환각 현상, 도메인/최신 지식 부족, 투명성 결여 등의 문제를 가지고 있으며, 이를 해결하기 위해 외부 데이터 소스에서 관련 컨텍스트를 검색하여 LLM 프롬프트에 공급하는 RAG(Retrieval Augmented Generation)가 필요합니다.
- **RAG는 단순한 챗봇을 넘어 AI 에이전트의 핵심 구성 요소입니다.** AI 에이전트는 추론하고 도구를 사용할 수 있는 LLM으로 정의되며, 이러한 도구에는 API, 데이터베이스뿐만 아니라 LlamaIndex가 제공하는 문서 컨텍스트 레이어(즉, 데이터 도구)가 포함되어 에이전트가 외부 데이터를 활용할 수 있게 합니다.
- **LlamaIndex는 LLM을 데이터에 쉽게 연결하기 위한 포괄적인 프레임워크를 제공합니다.** 데이터 수집(다양한 커넥터), 데이터 인덱싱(벡터 스토어, 지식 그래프 등 다양한 인덱스 유형), 쿼리(다양한 쿼리 엔진), 그리고 LLM 및 임베딩 모델과의 통합을 위한 추상화 계층을 제공하여 RAG 애플리케이션 구축을 간소화합니다.
- **단순한 벡터 검색을 넘어선 고급 RAG 전략이 복잡한 데이터 활용에 필수적입니다.** LlamaIndex는 쿼리 재작성, 하위 질문 쿼리, HyDE와 같은 쿼리 변환, 문장 창 검색, 자동 병합 검색, 지식 그래프 검색과 같은 다양한 검색 전략을 지원하여 복잡한 쿼리, 구조화/반구조화 데이터 처리, 하이브리드 검색 등의 문제를 해결합니다.
- **LlamaIndex는 멀티 도큐먼트 및 멀티 모달 에이전트 구축을 지원하며, RAG의 미래는 '에이전트적(Agentic)'이라고 강조합니다.** 에이전트는 여러 데이터 소스(각각 QueryEngineTool로 표현)를 쿼리하고, 텍스트 외 이미지 등 다양한 모달리티의 데이터를 처리할 수 있습니다. 궁극적으로 에이전트는 정보를 검색하는 방법을 동적으로 결정하고, 실패 시 다른 전략을 시도하는 등 RAG 파이프라인을 더욱 지능적이고 적응력 있게 만들 것입니다.

## 세부 내용
발표는 LLM의 근본적인 한계(제한된 컨텍스트 창, 환각, 도메인/최신 지식 부족, 투명성 결여)를 지적하며 시작됩니다. 이러한 문제에 대한 해결책으로 RAG(Retrieval Augmented Generation)를 제시합니다. RAG는 외부 데이터 소스에서 관련 컨텍스트를 검색하여 LLM 프롬프트에 제공하는 핵심 아이디어를 가지며, 이것이 바로 "문서 컨텍스트 레이어"의 역할입니다. 발표자는 RAG가 단순히 챗봇을 넘어, 추론하고 도구를 사용하는 AI 에이전트에게 필수적인 "데이터 도구"로서 중요하다고 강조합니다.

이어서 LlamaIndex가 "LLM을 데이터에 쉽게 연결"하기 위한 프레임워크임을 소개합니다. LlamaIndex는 데이터 수집(PDF, Notion, Slack, SQL, API 등 다양한 커넥터), 데이터 인덱싱(벡터 스토어, 지식 그래프, 트리 인덱스, 키워드 테이블 등 다양한 구조화 방식), 쿼리(다양한 쿼리 엔진), 그리고 LLM, 벡터 스토어, 임베딩 모델과의 통합을 위한 도구를 제공합니다.

LlamaIndex의 핵심 추상화는 다음과 같습니다:
*   **Documents**: 원본 데이터.
*   **Nodes**: 메타데이터를 포함한 문서의 청크.
*   **Indexes**: 노드 위에 구축된 데이터 구조 (예: VectorStoreIndex, TreeIndex, KeywordTableIndex, KnowledgeGraphIndex).
*   **Query Engines**: 인덱스를 쿼리하는 인터페이스 (예: `index.as_query_engine()`).
*   **Retrievers**: 인덱스에서 노드를 검색.
*   **Response Synthesizers**: 검색된 노드를 결합하여 최종 답변 생성.

간단한 RAG 애플리케이션 구축 예시 코드가 제시됩니다:
```python
from llama_index import VectorStoreIndex, SimpleDirectoryReader

documents = SimpleDirectoryReader("data").load_data()
index = VectorStoreIndex.from_documents(documents)
query_engine = index.as_query_engine()
response = query_engine.query("What did the author do in college?")
```
이 코드는 데이터를 로드하고, 벡터 스토어 인덱스를 생성한 다음, 쿼리 엔진을 통해 질문에 대한 응답을 얻는 기본적인 RAG 파이프라인을 보여줍니다.

LlamaIndex는 AI 에이전트와의 통합을 강조합니다. `QueryEngineTool`을 사용하여 쿼리 엔진을 에이전트가 사용할 수 있는 도구로 변환하고, `OpenAIAgent`와 같은 에이전트가 이 도구를 포함한 여러 도구를 활용하여 복잡한 질문에 답변할 수 있도록 합니다.

발표자는 "단순한 벡터 검색만으로는 충분하지 않다"고 지적하며, 고급 RAG의 필요성을 역설합니다. LlamaIndex는 복잡한 쿼리, 구조화/반구조화 데이터, 하이브리드 검색 등을 처리하기 위한 다양한 고급 RAG 기능을 제공합니다.
*   **쿼리 변환**: 쿼리 재작성, 하위 질문 쿼리, HyDE(가설 문서 임베딩) 등을 통해 검색 품질을 향상시킵니다.
*   **검색 전략**: 문장 창 검색(작은 청크 검색 후 주변 문장 확장), 자동 병합 검색(겹치는 청크 병합), 지식 그래프 검색 등을 지원합니다.
*   **구조화된 데이터 통합**: SQL 쿼리 엔진, Pandas 쿼리 엔진, API 쿼리 엔진을 통해 자연어를 SQL, Pandas, API 호출로 변환하여 구조화된 데이터와 상호작용할 수 있습니다.

또한, LlamaIndex는 여러 데이터 소스를 쿼리할 수 있는 **멀티 도큐먼트 에이전트**와 텍스트 외 이미지 등 다양한 모달리티의 데이터를 처리하고 생성하는 **멀티 모달 에이전트** 구축을 지원합니다. 마지막으로, "RAG의 미래는 에이전트적(agentic)"이라고 강조하며, 에이전트가 정보를 검색하는 방법을 동적으로 결정하고, 실패 시 다른 전략을 시도하거나 추가 질문을 하는 등 RAG 파이프라인을 더욱 지능적이고 적응력 있게 만들 것이라고 전망하며 발표를 마무리합니다.

- **다양한 데이터 유형 및 복잡한 쿼리 처리 준비**: 단순한 텍스트 문서 외에 SQL 데이터베이스, Pandas DataFrame, API 등 다양한 형태의 구조화/반구조화 데이터와 상호작용해야 하는 경우, LlamaIndex의 SQL/Pandas/API 쿼리 엔진과 같은 기능을 활용하여 통합 솔루션을 구축할 수 있습니다.
- **고급 검색 전략 탐색 및 적용**: 애플리케이션의 검색 정확도와 관련성을 높이기 위해 단순한 벡터 검색을 넘어 쿼리 재작성, 하위 질문 쿼리, 문장 창 검색, 지식 그래프 검색 등 LlamaIndex가 제공하는 다양한 고급 RAG 전략을 실험하고 적용하여 최적의 방법을 찾아야 합니다.
- **AI 에이전트의 '데이터 도구'로서 LlamaIndex 활용**: AI 에이전트를 구축할 때, LlamaIndex의 `QueryEngineTool`을 사용하여 특정 데이터 소스에 대한 질의 기능을 에이전트의 도구 세트에 포함시킴으로써 에이전트가 외부 지식을 활용하여 더 복잡하고 정확한 작업을 수행하도록 설계할 수 있습니다.
