# 500 Skills, Zero Fine-Tuning: LinkedIn's Playbook for AI Agents — Ajay Prakash, LinkedIn

🔗 https://youtu.be/9wZpvF3QleU · 📅 2026-09-09 · 🎙 AI Engineer

## 한 줄 요약
LinkedIn은 LLM의 한계를 극복하고 미세 조정 없이 500개 이상의 다양한 기술을 수행할 수 있는 AI 에이전트를 구축하기 위해, LLM에 도구, 메모리, 플래너, 리플렉터를 결합한 강력한 에이전트 프레임워크를 활용하여 복잡한 작업을 처리하고 실제 비즈니스 가치를 창출하고 있습니다.

## 발표자·소속
Ajay Prakash, LinkedIn

## 핵심 주장
-   **LLM의 한계 극복을 위한 에이전트 프레임워크 도입**: LLM은 강력하지만 일반적이며, 환각, 최신 정보 부족, 복잡한 다단계 작업 처리의 어려움, 외부 도구 사용 능력 부재 등의 한계를 가집니다. LinkedIn은 이러한 한계를 극복하기 위해 LLM에 도구, 메모리, 플래너, 리플렉터(비평가)를 결합한 에이전트 프레임워크를 구축하여 LLM을 특정 작업을 수행하는 "전문가"로 전환합니다.
-   **미세 조정 없는 500개 이상의 기술 구현**: 전통적인 미세 조정 방식의 높은 비용과 데이터 요구사항을 피하기 위해, LinkedIn은 에이전트가 잘 정의된 도구들을 활용하고 강력한 에이전트 루프를 통해 500개 이상의 다양한 기술을 미세 조정 없이 수행할 수 있도록 합니다. 이는 LLM이 도구 사용법을 학습하고 복잡한 작업을 단계별로 처리하도록 유도하는 프롬프트 엔지니어링 기반의 접근 방식입니다.
-   **플래너, 실행자, 리플렉터 중심의 강력한 에이전트 루프**: 에이전트의 핵심은 사용자 질의를 받아 계획을 세우고(플래너), 해당 계획에 따라 도구를 실행하며(도구 실행자), 실행 결과를 검토하고 개선점을 제안하는(리플렉터) 반복적인 루프입니다. 이 루프는 에이전트가 오류를 수정하고, 다단계 작업을 효율적으로 처리하며, 사용자에게 정확하고 신뢰할 수 있는 결과를 제공하는 데 필수적입니다.
-   **실제 비즈니스 문제 해결을 위한 다양한 활용 사례**: LinkedIn은 채용 정보 검색, 프로필 업데이트, 콘텐츠 초안 작성 등 실제 사용자 시나리오에 에이전트를 적용하여 LLM이 단순한 텍스트 생성기를 넘어 실제 비즈니스 가치를 창출하는 도구로 활용될 수 있음을 보여줍니다. 각 사례는 에이전트가 복잡한 사용자 의도를 이해하고 적절한 도구를 조합하여 목표를 달성하는 과정을 포함합니다.

## 세부 내용
발표는 LLM의 강력함에도 불구하고 일반적인 특성으로 인해 발생하는 환각, 최신 정보 부족, 복잡한 다단계 작업 처리의 어려움, 외부 도구 사용 능력 부재 등의 한계를 지적하며 시작됩니다. 기존의 미세 조정(fine-tuning) 방식은 비용이 많이 들고 데이터 요구량이 높으며 적용 범위가 제한적이라는 문제점을 제기합니다.

LinkedIn은 이러한 한계를 극복하고 LLM을 "전문가"로 만들기 위해 **AI 에이전트** 접근 방식을 채택했습니다. 목표는 미세 조정 없이 500개 이상의 기술을 수행할 수 있는 에이전트를 구축하는 것입니다. 발표자는 LLM을 "두뇌", 도구를 "손", 메모리를 "노트북"에 비유하며 에이전트의 핵심 구성 요소를 설명합니다.

**에이전트의 핵심 구성 요소**:
1.  **LLM**: 추론 엔진 역할을 합니다.
2.  **도구(Tools)**: 에이전트가 호출할 수 있는 함수나 API (예: 검색, 데이터베이스 쿼리, API 호출, 코드 실행).
3.  **메모리(Memory)**: 단기(컨텍스트 윈도우) 및 장기(벡터 DB, 지식 그래프) 기억을 저장합니다.
4.  **플래너(Planner)**: 복잡한 작업을 하위 작업으로 분해하고 어떤 도구를 사용할지 결정합니다.
5.  **리플렉터/비평가(Reflector/Critic)**: 출력물을 평가하고, 오류를 식별하며, 개선 사항을 제안하고, 실수로부터 학습합니다.

LinkedIn의 **"Skill Agent" 아키텍처**는 사용자 질의를 받아 LLM, 플래너, 도구 실행자, 메모리, 리플렉터, 도구 라이브러리로 구성된 에이전트가 처리하는 방식입니다. 플래너는 질의, 사용 가능한 도구, 메모리를 기반으로 계획을 생성하고, 도구 실행자는 계획에 따라 도구를 호출합니다. 메모리는 대화 기록과 검색된 컨텍스트를 저장하며, 리플렉터는 실행을 검토하고 개선을 제안합니다. 도구 라이브러리에는 `search_jobs`, `get_profile_data`, `send_message`와 같은 다양한 도구들이 포함됩니다. 핵심 원칙은 "미세 조정 없음(Zero Fine-Tuning)"으로, 이는 LLM에 잘 정의된 도구와 강력한 에이전트 루프를 제공함으로써 달성됩니다. 각 "기술"은 본질적으로 에이전트가 조율하는 도구 또는 도구 호출 시퀀스입니다.

**데모 사례**:
1.  **채용 정보 검색 에이전트**: "샌프란시스코에서 20만 달러 이상을 받는 AI 직업을 찾아줘."라는 사용자 질의에 대해 에이전트는 `search_jobs` 도구를 호출하고, 결과를 급여 기준으로 필터링하여 관련 채용 정보를 제시합니다. 이는 다단계 추론, 도구 사용, 필터링 능력을 보여줍니다.
2.  **프로필 업데이트 에이전트**: "내 프로필을 'LinkedIn의 AI 엔지니어'로 업데이트해 줘."라는 질의에 에이전트는 `update_profile` 도구를 사용하여 사용자 데이터를 업데이트하고 사용자에게 확인을 요청합니다. 이는 사용자 데이터와 상호 작용하고 실제 작업을 수행하는 능력을 보여줍니다.
3.  **콘텐츠 생성 에이전트**: "채용 분야 AI의 미래에 대한 게시물 초안을 작성해 줘."라는 질의에 에이전트는 `draft_post` 도구를 사용하고, 필요시 `search_articles` 도구를 통해 관련 정보를 검색한 후 초안을 작성합니다. 리플렉터는 초안의 톤, 정확성, 길이를 검토하고 개선을 제안합니다. 이는 창의적인 작업과 외부 정보 활용 능력을 보여줍니다.

**평가 및 지표**: 성공률, 지연 시간(latency), 비용(API 호출, 컴퓨팅), 사용자 만족도 등을 측정하며, A/B 테스트와 인간 평가를 통해 에이전트의 성능을 검증합니다.

**도전 과제**: 도구 발견(어떤 도구가 관련 있는지), 도구 오케스트레이션(도구를 효과적으로 연결하는 방법), 오류 처리, 안전 및 가드레일 구현, 확장성 등이 언급됩니다.

**LinkedIn의 AI 에이전트 "플레이북"**:
1.  **명확한 기술/도구 정의**: 각 도구는 명확한 목적, 입력, 출력을 가져야 합니다.
2.  **강력한 에이전트 루프**: 플래너, 실행자, 리플렉터, 메모리의 중요성을 강조합니다.
3.  **반복적인 개발**: 간단하게 시작하여 복잡성을 점진적으로 추가합니다.
4.  **포괄적인 평가**: 지표, A/B 테스트, 인간 피드백을 활용합니다.
5.  **안전 우선**: 가드레일을 구현합니다.

**향후 과제**: 자율 에이전트, 다중 에이전트 시스템, 개인화된 에이전트, 자가 개선 에이전트 등이 있습니다. 발표는 AI 에이전트가 실용적인 AI 애플리케이션의 미래이며, LinkedIn이 미세 조정 없이 500개 이상의 기술을 위한 플랫폼을 구축하고 있다는 결론으로 마무리됩니다.

## 인상적인 대목
-   "LLMs are generalists, not specialists." (LLM은 전문가가 아니라 제너럴리스트입니다.)
-   "Zero Fine-Tuning: Achieved by giving the LLM access to well-defined tools and a robust agentic loop." (미세 조정 없음: LLM에 잘 정의된 도구와 강력한 에이전트 루프를 제공함으로써 달성됩니다.)
-   "The LLM is the brain, tools are the hands, memory is the notebook." (LLM은 두뇌이고, 도구는 손이며, 메모리는 노트북입니다.)

## 실무 적용 포인트
-   **도구 중심의 에이전트 설계**: LLM의 특정 도메인 지식 부족이나 최신 정보 한계를 극복하기 위해, LLM에 외부 API, 데이터베이스 쿼리, 검색 엔진 등 잘 정의된 도구들을 제공하여 "미세 조정 없이" 다양한 기술을 수행하도록 설계할 수 있습니다. 각 도구는 명확한 기능, 입력, 출력을 가져야 합니다.
-   **플래너-실행자-리플렉터 루프 구현**: 복잡한 사용자 질의를 처리하고 에이전트의 신뢰성을 높이기 위해, 사용자 질의를 하위 작업으로 분해하는 플래너, 도구를 실행하는 실행자, 그리고 실행 결과를 평가하고 개선하는 리플렉터로 구성된 반복적인 에이전트 루프를 시스템에 통합하는 것을 고려할 수 있습니다. 이는 오류 처리 및 다단계 작업 처리에 효과적입니다.
-   **메모리 활용을 통한 컨텍스트 유지 및 학습**: 에이전트가 대화의 맥락을 유지하고 장기적인 지식을 활용하도록 단기 메모리(컨텍스트 윈도우)와 장기 메모리(예: 벡터 데이터베이스, 지식 그래프)를 구현하여 에이전트의 일관성과 성능을 향상시킬 수 있습니다.
-   **체계적인 평가 지표 도입**: 에이전트 시스템의 성공 여부를 측정하기 위해 성공률, 지연 시간, 비용, 사용자 만족도와 같은 명확한 평가 지표를 설정하고, A/B 테스트 및 인간 평가를 통해 지속적으로 성능을 검증하고 개선하는 접근 방식을 채택해야 합니다.
