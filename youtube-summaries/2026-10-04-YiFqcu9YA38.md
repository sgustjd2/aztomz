# Dashboards Are Dead — Sarah Simionescu, Composio

🔗 https://youtu.be/YiFqcu9YA38 · 📅 2026-10-04 · 🎙 AI Engineer

## 한 줄 요약
대시보드는 인간 사용자를 위해 설계되었지만, AI 에이전트 시대에는 에이전트가 효율적으로 사용할 수 있도록 설계된 '에이전트 경험(AX)'이 새로운 사용자 경험(UX)이 될 것이며, Composio는 이를 위한 새로운 인터페이스를 제공한다.

## 발표자·소속
Sarah Simionescu, Composio 기술 스태프 (Member of Technical Staff, Composio)

## 핵심 주장
- **대시보드는 죽었다**: 발표자는 지난 6개월간 Datadog을 매일 사용했지만, 실제로 대시보드를 열어본 적이 없다는 개인적인 경험을 통해 대시보드의 효용성에 의문을 제기하며, 대시보드가 더 이상 효과적인 정보 전달 수단이 아니라고 주장한다.
- **기존 도구들의 비효율성**: 개발자들이 문제를 해결하기 위해 Slack, Datadog, PostHog, VS Code, GitHub 등 여러 도구를 동시에 사용하며 각기 다른 쿼리 언어를 익혀야 하는 비효율적인 현실을 지적한다.
- **AI 네이티브 대시보드의 한계**: 2023년에 등장한 '스파클 버튼'과 AI 네이티브 대시보드가 자연어 질문을 SQL 쿼리로 변환해주는 등 개선을 가져왔지만, 복잡한 질문이나 여러 데이터베이스 조인이 필요한 경우 여전히 부정확하며, 에이전트가 충분한 컨텍스트를 학습하지 못하고 각 앱이 고립되어 있다는 한계를 가진다.
- **에이전트 경험(AX)의 중요성**: AI 에이전트는 시각적 인터페이스나 스파클 버튼을 클릭하지 않으며, 오직 목표 달성 여부로만 평가된다. 따라서 미래의 제품은 인간 사용자뿐만 아니라 에이전트가 쉽고 효율적으로 사용할 수 있도록 설계되어야 한다고 강조한다.

## 세부 내용
발표자는 Datadog 대시보드를 6개월 동안 한 번도 열어보지 않았다는 개인적인 고백으로 발표를 시작하며, 대시보드가 죽었다는 파격적인 주장을 펼쳤다. 그녀는 2022년의 '암흑기'를 회상하며, 동료가 Slack에서 "[prod]" 검색 오류를 보고했을 때, Slack, Datadog 로그 탐색기, PostHog 세션 재생, VS Code, GitHub PR 등 5가지 도구를 동시에 열어 컨텍스트를 파악하고, 쿼리를 작성하고, 버그를 수정하고, PR을 여는 과정을 보여주었다. 이 과정에서 각 도구마다 다른 쿼리 언어(Datadog의 쿼리 문법, Jira의 JQL, Slack의 검색 수정자 등)를 익혀야 하는 비효율성을 지적했다.

발표자는 사용자가 대시보드나 쿼리 언어를 원하는 것이 아니라 '답변'을 원한다고 강조하며, 2023년 '스파클 버튼'의 등장이 변화를 가져왔다고 설명했다. 이 버튼은 LLM이 자연어 질문을 SQL 쿼리로 변환하여 답변을 제공하는 AI 네이티브 대시보드를 가능하게 했다. 그러나 이러한 방식은 두 개 이상의 데이터베이스 조인이 필요한 복잡한 질문에는 "때때로 정확한 쿼리"만 제공하는 한계가 있었다.

2024년 11월, Anthropic이 '모델 컨텍스트 프로토콜(MCP)'을 발표하며 AI 시스템과 데이터 소스 연결을 위한 개방형 표준을 제시했지만, 발표자는 MCP에도 세 가지 문제가 있다고 지적했다.
1.  **에이전트는 학습하지 않는다**: 모든 대화가 처음부터 시작되며, 에이전트는 이전 대화에서 링크 형식을 잘못 지정했던 실수를 기억하지 못하고 다시 반복한다.
2.  **컨텍스트가 많아질수록 에이전트는 멍청해진다**: 더 많은 도구와 스킬을 로드할수록 컨텍스트 창이 가득 차 모델이 혼란스러워하며, 잘못된 도구를 선택하거나 의존성 해결에 어려움을 겪는다. Composio의 GitHub 툴킷만 해도 200개 이상의 도구를 포함한다.
3.  **모든 앱은 고립되어 있다**: 각 MCP 서버는 자신에 대해서만 알고 다른 앱에 대해서는 알지 못한다. 따라서 작업이 두 개 이상의 앱에 걸쳐 있을 때, 에이전트가 이를 통합하는 것은 서비스의 몫이 된다.

Composio는 이러한 문제를 해결하기 위해 에이전트 전용의 새로운 인터페이스를 개발하고 있다고 밝혔다. 발표자는 Composio의 MCP를 활용한 데모를 통해 버그 보고서 해결 과정을 시연했다. Slack 메시지 링크를 복사하여 Claude에 붙여넣고 Sentry와 Datadog을 사용하여 근본 원인을 찾고 PR을 생성하라는 명령을 내렸다. Claude는 Composio Search를 사용하여 Slack 메시지 가져오기, Sentry 이슈 검색, Datadog 로그 검색이라는 세 가지 작업을 식별하고, 각 작업에 필요한 도구와 실행 계획을 반환했다. 특히 Slack 채널 ID를 먼저 찾아야 하는 것과 같은 선행 작업을 자동으로 처리하며, Datadog과 Sentry에서 데이터를 병렬로 가져오고 코드베이스를 스캔하여 5분 이내에 PR을 생성하는 모습을 보여주었다.

두 번째 데모에서는 사용자 데이터 분석을 시연했다. 온보딩 과정에서 사용자가 선택한 산업 분야(vertical) 분포를 알고 싶다는 질문에 Claude는 Composio Search를 실행하여 PostHog에서 전자상거래를 선택한 사용자 ID를 쿼리하고, 이 ID를 기반으로 Metabase에서 데이터베이스 스키마와 샘플 데이터를 조회했다. Composio Remote Workbench라는 도구를 사용하여 사용자 ID를 검색하는 SQL 쿼리를 동적으로 생성하고, 전체 결과를 컨텍스트 창에 로드하지 않고도 PostHog와 Metabase에서 데이터를 가져와 가장 인기 있는 툴킷 목록을 몇 분 안에 보여주었다.

발표자는 "AX is the new UX"라는 슬로건을 제시하며, 현재 많은 스타트업이 웹사이트를 AI 친화적으로 만들고 있지만, 에이전트가 애플리케이션을 사용할 수 있도록 준비하는 데는 소홀하다고 지적했다. 그녀는 에이전트가 눈이 없고 '스파클 버튼'을 클릭하지 않으며, 오직 목표 달성 여부로만 평가한다고 강조했다. 지난 10년간 인간을 위한 제품을 만들었지만, 다음 시대는 에이전트가 사용하기 쉬운 제품의 시대가 될 것이라고 결론지었다.

## 실무 적용 포인트
- **에이전트 중심의 API 설계**: AI 에이전트가 효율적으로 데이터를 쿼리하고 작업을 수행할 수 있도록, API를 명확하고 일관성 있게 문서화하며, 복잡한 의존성을 줄이는 방향으로 설계해야 한다.
- **컨텍스트 효율성 고려**: 에이전트가 과도한 컨텍스트로 인해 성능 저하를 겪지 않도록, 필요한 정보만 선별적으로 제공하고, 에이전트가 컨텍스트를 효율적으로 관리할 수 있는 메커니즘을 고려해야 한다.
- **다중 도구 연동 자동화**: 에이전트가 여러 앱과 도구에 걸쳐 작업을 수행할 때, 각 앱의 고립성을 극복하고 작업을 원활하게 연결할 수 있는 통합된 에이전트 인터페이스나 플랫폼을 활용하는 것이 중요하다.
- **워크플로우 자동화 대신 에이전트 자율성 강화**: 특정 워크플로우를 미리 구축하거나 스킬을 일일이 가르치기보다는, 에이전트가 스스로 문제 해결 계획을 세우고 필요한 도구를 찾아 사용할 수 있도록 자율성을 부여하는 방향으로 시스템을 구축해야 한다.
