# Trading Desks to Clinical Trials: Parallels in Applied Vertical AI — Ayush Bhardwaj, Allos AI

🔗 https://youtu.be/Yphdry8ttAQ · 📅 2026-08-19 · 🎙 AI Engineer

## 한 줄 요약
수직적 AI(Vertical AI) 프로젝트의 성공은 모델, 인프라, 생태계와 같은 상품화된 요소가 아닌, 해당 산업의 도메인 전문 지식과 이를 활용한 데이터 큐레이션 및 학습 루프 구축에 달려 있습니다.

## 발표자·소속
Ayush Bhardwaj, Allos AI

## 핵심 주장
- **문제의 명확한 정의**: 수직적 AI 에이전트는 특정 산업 내의 좁고 구체적인 작업을 위해 설계되어야 하며, 너무 많은 기능을 한 번에 수행하려 하면 실패할 가능성이 높습니다.
- **독점 데이터의 중요성**: 공개적으로 접근 가능한 데이터는 상품화되어 경쟁 우위를 제공하지 못합니다. 기업 내부의 독점적인 데이터(예: 금융의 거래 논문, 제약의 실패한 실험 데이터)가 진정한 해자(moat)를 형성합니다.
- **인간 전문가의 역할**: AI 모델은 스스로 검증하거나 실제 가치를 판단할 수 없으므로, 해당 도메인에 대한 깊은 이해를 가진 인간 전문가를 고용하여 에이전트의 학습 루프를 구축하고 출력을 평가해야 합니다.
- **학습 루프를 통한 반복**: 전문가가 프롬프트 작성, 데이터 큐레이션, 사고 모델 구축에 참여하여 에이전트의 성능을 지속적으로 개선하는 학습 루프를 만들어야 합니다.
- **AI는 아직 보조 도구**: 현재 AI는 대부분의 산업에서 인간의 작업을 완전히 대체하기보다는 전문가의 작업을 보조하여 효율성을 높이는 "AI-in-the-loop" 단계에 머물러 있습니다.

## 세부 내용
발표자는 헤지펀드에서 제약 기술 스타트업으로 이직한 경험을 바탕으로, 겉보기에는 매우 다른 두 산업에서 수직적 AI를 구축하는 과정이 놀랍도록 유사했다고 말합니다. 수직적 AI는 특정 산업을 위해 구축되며, 해당 분야의 독점 데이터를 사용하여 그곳의 사람들이 실제로 하는 일을 수행합니다. 예를 들어, 구글 번역이 일반적인 AI라면, Allos AI는 연구실의 자체 데이터를 기반으로 AI를 통해 약물을 개발하는 수직적 AI입니다.

수직적 AI를 구축하는 과정은 7단계 레시피로 요약됩니다.
1.  **문제 정의**: 에이전트가 수행할 좁고 구체적인 작업을 선택합니다. 금융에서는 "채권이 잘못 평가되었을 때 플래그 지정", 제약에서는 "다음으로 테스트할 분자 순위 지정"과 같이 명확해야 합니다.
2.  **데이터 식별**: 독점 데이터가 핵심 해자입니다. 금융에서는 거래, 포지션, 대체 데이터가, 제약에서는 분석, 실패한 실험, 임상 시험 데이터가 중요합니다. 이러한 데이터는 기본 모델이 학습하지 못한 것으로, 기업이 직접 큐레이션해야 합니다.
3.  **프롬프트 작성**: 작업이 실제로 수행되는 방식을 인코딩합니다. 금융에서는 "트레이더의 논문 체크리스트", 제약에서는 "과학자의 스크리닝 프로토콜"과 같이 인간 전문가의 작업 흐름을 반영해야 합니다.
4.  **관찰 가능성**: 에이전트가 무엇을 했는지 확인할 수 있어야 합니다. 금융에서는 모든 도구 호출과 추출한 숫자를 기록하고, 제약에서는 모든 단계와 인용을 추적하여 디버깅하고 개선할 수 있도록 합니다.

발표자는 이 1~4단계는 "쉬운 부분"이며, 10배 엔지니어라면 몇 분 안에 해낼 수 있다고 말합니다. 하지만 문제는 "그것이 작동하는지 알 수 없다"는 것입니다. LLM은 단순히 다음 단어를 예측할 뿐, 실제 산업의 "알파"와 "전문 용어"를 구별하지 못합니다. 금융과 제약 분야에서는 모델이 스스로 검증할 수 없고, 수익을 창출하거나 손실을 피하는 방법을 알 수 없습니다. 또한, 돈을 버는 거래 논문이나 실패한 실험 데이터는 독점적이며 온라인에 공개되지 않으므로, 모델이 개선하는 데 필요한 정확한 데이터를 얻을 수 없습니다.

이러한 문제를 해결하기 위한 5단계는 **사용자 고용(Hire the user)**입니다. 해당 도메인에서 경력을 쌓은 전문가, 즉 트레이더나 과학자를 고용해야 합니다. 이들은 모델이 "헛소리"를 하는지 아닌지 즉시 알 수 있는 사람입니다.

이 전문가들은 다음의 학습 루프를 구축합니다.
1.  **분해(Decompose)**: 자신의 작업 흐름을 에이전트로 분해하여 손으로 해결하는 방식을 정확히 구현합니다.
2.  **정제(Refine)**: 에이전트가 실제 "알파"를 반환할 때까지 프롬프트, 기술, 단계를 개선합니다.
3.  **판단(Judge)**: 출력이 전문 용어인지, 실제 가치(알파)인지 즉시 판단합니다.

전문가의 판단을 신호로 바꾸는 방법에는 지도 미세 조정(Supervised fine-tuning), 인간 피드백을 통한 강화 학습(Reinforcement learning from human feedback), 보상으로서의 루브릭(Rubrics as rewards), 오류 분석(Error analysis) 등이 있습니다. 이 모든 방법은 희소한 전문가의 판단을 재사용 가능한 신호로 전환하는 데 목적이 있습니다.

마지막으로, 6단계 **반복(Iterate)**과 7단계 **출시(Ship)**가 있습니다. 더 많은 사용자가 더 많은 쿼리를 생성하고, 더 많은 범위와 데이터를 통해 에이전트가 더 날카로워지는 끊임없는 루프가 형성됩니다. 발표자는 기업 AI 에이전트의 89%가 프로덕션에 도달하지 못한다는 통계에 동의하지 않습니다. 모든 AI는 프로덕션에 도달하지만, 비용을 정당화하거나 제대로 작동하지 못하는 경우가 많다고 지적합니다. 성공적으로 출시된 에이전트들은 **도메인 전문가**를 루프 안에 유지했습니다.

결론적으로, 모델, 인프라, 생태계는 상품화된 요소이지만, **도메인 전문 지식**이 진정한 해자입니다. AI는 아직 "인과 관계"를 추론하지 못하고 과거의 패턴에만 의존하므로, 인간 전문가가 작업을 수행하고 AI가 이를 보조하는 "AI-in-the-loop" 방식이 현재의 현실입니다.

## 인상적인 대목
- "I could build it. I just couldn't tell if it worked." (나는 그것을 만들 수 있었다. 단지 그것이 작동하는지 알 수 없었을 뿐이다.)
- "An LLM judge can't tell alpha from jargon. A human who has lived the problem can tell instantly." (LLM 심사관은 전문 용어에서 알파를 구별할 수 없다. 문제를 겪어본 사람은 즉시 알 수 있다.)
- "The work that encodes real judgment was never on the internet, so it was never in the model." (진정한 판단을 인코딩하는 작업은 인터넷에 없었으므로, 모델에도 없었다.)
- "model / infra / ecosystem = commodity, domain expertise = moat" (모델 / 인프라 / 생태계 = 상품, 도메인 전문 지식 = 해자)

## 실무 적용 포인트
- **좁은 문제 정의**: AI 프로젝트 시작 시, 에이전트가 해결할 구체적이고 좁은 문제부터 명확히 정의하여 초기 성공 가능성을 높이고 점진적으로 확장합니다.
- **독점 데이터 확보 및 큐레이션**: 공개 데이터에만 의존하지 않고, 기업 내부의 독점적인 데이터를 발굴하고 구조화하여 AI 모델의 핵심 경쟁력을 확보합니다.
- **도메인 전문가와의 긴밀한 협업**: AI 엔지니어는 해당 산업의 도메인 전문가와 적극적으로 소통하여 프롬프트 설계, 데이터 큐레이션, 모델 평가 및 개선 과정에 전문가의 지식을 반영해야 합니다.
- **학습 루프 구축**: 에이전트의 성능을 지속적으로 모니터링하고, 전문가의 피드백을 통해 모델을 개선하는 반복적인 학습 루프를 시스템에 통합하여 장기적인 가치를 창출합니다.
