# Security Firewall for Agents — Ryan Dahl, Deno

Deno의 내장된 권한 시스템을 활용하여 AI 에이전트의 잠재적 위험을 제어하고 보안을 강화하는 방안을 제시하며, 에이전트의 행동을 명시적으로 제한하는 "보안 방화벽" 역할을 강조합니다.

## 발표자·소속
라이언 달 (Ryan Dahl), Deno

## 핵심 주장
-   **AI 에이전트의 잠재적 위험성**: AI 에이전트는 강력한 자율성과 기능을 가지지만, 이는 동시에 네트워크 접근, 파일 시스템 조작, 임의 코드 실행 등 예상치 못한 보안 위협으로 이어질 수 있습니다. 발표자는 이를 "너무 똑똑한 인턴"에 비유하며 무제한적인 권한 부여의 위험성을 경고합니다.
-   **Deno의 권한 시스템을 통한 보안 방화벽**: Deno는 에이전트가 수행할 수 있는 작업을 명시적으로 제한하는 강력한 권한 시스템을 제공합니다. 이는 에이전트의 행동을 제어하는 "보안 방화벽" 역할을 하여, 개발자가 에이전트의 잠재적 위험을 관리할 수 있게 합니다.
-   **최소 권한 원칙 적용**: 에이전트에게 필요한 최소한의 권한만 부여하는 '최소 권한 원칙'을 강조합니다. Deno는 `--allow-net`, `--allow-read`, `--allow-run` 등 세분화된 플래그를 통해 네트워크, 파일 시스템, 서브프로세스 실행 등 각 자원에 대한 접근을 정밀하게 제어할 수 있도록 합니다.
-   **명시적이고 감사 가능한 권한 관리**: Deno의 권한 시스템은 에이전트가 어떤 자원에 접근할 수 있는지 명확하게 보여줍니다. 이는 에이전트의 보안 상태를 쉽게 감사하고 이해할 수 있게 하여, 개발자가 에이전트의 행동을 예측하고 통제하는 데 도움을 줍니다.

## 세부 내용
발표는 AI 에이전트가 가진 강력한 능력과 그에 따른 보안 위험에 대한 경고로 시작합니다. 라이언 달은 AI 에이전트를 "너무 똑똑한 인턴"에 비유하며, 이들이 네트워크 요청, 파일 읽기/쓰기, 서브프로세스 실행 등 다양한 작업을 수행할 수 있지만, 통제되지 않을 경우 심각한 보안 문제를 야기할 수 있다고 설명합니다.

이러한 문제에 대한 해결책으로 Deno의 내장된 권한 시스템을 제시합니다. Deno는 기본적으로 모든 권한이 비활성화된 샌드박스 환경에서 코드를 실행하며, 개발자가 `--allow-*` 플래그를 통해 필요한 권한만 명시적으로 부여하도록 설계되었습니다. 발표자는 이를 에이전트의 행동을 제어하는 "보안 방화벽"으로 설명합니다.

구체적인 권한 플래그와 기능은 다음과 같습니다:
-   `--allow-net`: 네트워크 접근을 허용합니다. `fetch` API를 사용하거나 `Deno.serve`로 HTTP 서버를 생성할 때 필요합니다.
-   `--allow-read`: 파일 시스템 읽기 접근을 허용합니다. 특정 경로만 허용할 수도 있습니다 (예: `--allow-read=/tmp`).
-   `--allow-write`: 파일 시스템 쓰기 접근을 허용합니다. 특정 경로만 허용할 수도 있습니다.
-   `--allow-env`: 환경 변수 접근을 허용합니다.
-   `--allow-run`: 서브프로세스 실행을 허용합니다. `Deno.Command` API를 사용할 때 필요합니다.
-   `--allow-sys`: 시스템 정보 접근을 허용합니다.

발표자는 여러 데모를 통해 Deno의 권한 시스템이 어떻게 작동하는지 보여줍니다.
1.  **네트워크 접근 제어**: `fetch` 요청을 수행하는 에이전트 코드를 `--allow-net` 플래그 없이 실행하면 권한 오류가 발생하고, 플래그를 추가하면 성공적으로 요청을 보냅니다.
2.  **파일 시스템 접근 제어**: `/etc/passwd` 파일을 읽으려는 에이전트 코드를 `--allow-read` 플래그 없이 실행하면 권한 오류가 발생합니다.
3.  **서브프로세스 실행 제어**: `ls` 명령어를 실행하는 `Deno.Command` 코드를 `--allow-run` 플래그 없이 실행하면 권한 오류가 발생합니다.
4.  **복합적인 에이전트 예시**: HTTP 요청을 처리하고, 외부 API를 호출하며, 서브프로세스를 실행하는 에이전트의 경우, 해당 모든 작업에 필요한 `--allow-net`, `--allow-run` 등의 권한을 명시적으로 부여해야만 정상적으로 작동함을 보여줍니다.

또한, Deno의 내장 키-값 스토어인 `Deno.Kv`는 기본적으로 보안이 강화되어 있으며, 에이전트가 데이터를 안전하게 저장하고 접근할 수 있는 방법을 제공한다고 언급합니다. 발표자는 Deno의 권한 시스템이 에이전트가 무엇을 할 수 있는지 개발자가 명확하게 결정하고, 에이전트의 행동을 감사할 수 있게 하여, AI 에이전트의 보안 문제를 해결하는 데 매우 적합하다고 결론지었습니다.

## 실무 적용 포인트
-   **최소 권한 원칙 적용**: AI 에이전트를 Deno 환경에서 실행할 때, 에이전트가 수행해야 하는 기능에 필요한 최소한의 권한만 `--allow-*` 플래그를 통해 명시적으로 부여해야 합니다. 불필요한 권한은 절대 부여하지 마십시오.
-   **세분화된 권한 제어 활용**: 네트워크 접근 (`--allow-net`), 파일 시스템 접근 (`--allow-read`, `--allow-write`), 서브프로세스 실행 (`--allow-run`) 등 Deno가 제공하는 세분화된 권한 플래그를 활용하여 에이전트의 각 기능을 정밀하게 제어하는 보안 정책을 수립하십시오.
-   **코드 감사 및 권한 명확화**: 에이전트 코드를 개발하거나 배포하기 전에, 해당 코드가 어떤 권한을 필요로 하는지 명확히 식별하고 문서화해야 합니다. 이를 통해 보안 취약점을 사전에 파악하고, 에이전트의 행동을 예측 가능하게 만듭니다.
-   **Deno를 에이전트 런타임으로 고려**: 보안과 통제된 자원 접근이 중요한 AI 에이전트 플랫폼을 구축할 때, Deno의 강력한 샌드박스 및 권한 시스템을 활용하여 안전한 실행 환경을 제공하는 것을 적극적으로 고려할 수 있습니다.
