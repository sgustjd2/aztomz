# From Vibes to Production: Evaluating and Shipping AI Agents That Work 201 — Laurie Voss, Arize AI

🔗 https://youtu.be/F0TNSmbo5hE · 📅 2026-10-05 · 🎙 AI Engineer

## 한 줄 요약
AI 에이전트의 비결정적 특성으로 인해 발생하는 개발 및 개선의 병목 현상을 해결하기 위해, 추적(tracing)과 자동화된 평가(evals)를 넘어 에이전트가 스스로 문제를 감지하고 수정하는 '시그널(Signal)' 기반의 자동화된 개선 루프를 구축하는 것이 AI 엔지니어링의 미래입니다.

## 발표자·소속
Laurie Voss, Arize AI

## 핵심 주장
*   **AI 에이전트의 비결정성으로 인한 새로운 진실의 원천 필요:** 전통적인 소프트웨어와 달리 AI 에이전트는 비결정적이며, 코드만으로는 에이전트의 실제 동작을 파악하기 어렵습니다. 따라서 에이전트의 모든 실행 단계에 대한 '추적(traces)'이 새로운 진실의 원천이 됩니다.
*   **인간은 AI 개발 및 개선 루프의 병목 현상:** 수많은 에이전트가 프로덕션 환경에서 실행될 때 발생하는 방대한 양의 추적 데이터를 인간이 수동으로 검토하거나 평가하는 것은 불가능합니다. 이는 에이전트의 빠른 개발 속도에 비해 개선 속도가 현저히 느려지는 원인이 됩니다.
*   **관찰 가능성(Observability)의 다음 단계는 '액션'**: AI 엔지니어링의 미래는 단순히 에이전트의 동작을 관찰하고 평가하는 것을 넘어, 시스템이 자동으로 문제를 감지하고(시그널), 해결책을 제안하며, 심지어 코드 수정(자동화된 수정)까지 수행하여 지속적인 개선 루프를 완성하는 것입니다.
*   **Arize AI의 플랫폼이 자동화된 개선 루프를 지원:** Arize AI는 에이전트의 추적 데이터를 수집하고, 평가를 통해 문제점을 식별하며, '시그널' 기능을 통해 반복되는 문제 패턴을 자동으로 감지하고, 제안된 수정 사항을 GitHub PR로 생성하여 에이전트가 스스로 개선될 수 있도록 돕습니다.

## 세부 내용

Laurie Voss는 AI 에이전트가 기존 소프트웨어와 달리 비결정적이라는 점을 강조하며 발표를 시작합니다. 에이전트는 여러 단계를 거쳐 의사결정을 내리고, 동일한 입력에도 매번 다른 경로와 결과를 낼 수 있습니다. 이로 인해 코드는 더 이상 에이전트 동작의 유일한 진실 원천이 아니며, 에이전트의 모든 실행 과정을 기록하는 '추적(traces)'이 중요해집니다.

발표자는 Arize AI의 플랫폼을 통해 에이전트의 추적 데이터를 시각화하는 방법을 시연합니다. Arize UI에서 에이전트의 입력, 출력, LLM 호출, 도구 호출, 에이전트 턴 등 모든 단계가 상세하게 기록된 추적을 확인할 수 있습니다. 각 추적은 지연 시간, 토큰 사용량 등 메타데이터를 포함하여 에이전트의 동작을 깊이 있게 이해하는 데 도움을 줍니다.

그러나 Voss는 프로덕션 환경에서 수많은 에이전트가 작동할 때 발생하는 방대한 추적 데이터를 인간이 모두 검토하는 것은 불가능하며, 이것이 AI 개발 루프의 병목 현상이라고 지적합니다. 이 문제를 해결하기 위해 '평가(evals)'가 도입됩니다. 평가는 코드나 다른 LLM을 사용하여 추적 데이터를 분석하고, 에이전트의 동작이 미리 정의된 기준에 따라 '좋음' 또는 '나쁨'인지 판단하며, 그 이유를 설명해줍니다. 이는 인간이 이해할 수 있는 설명을 제공하면서도 기계가 처리할 수 있는 형태로 데이터를 압축합니다.

하지만 여전히 수많은 평가 결과가 생성될 수 있으므로, 인간은 여전히 병목 현상으로 남습니다. Voss는 여기서 한 단계 더 나아가 '관찰 가능성이 행동으로 전환되는' 미래를 제시합니다. Arize AI의 '시그널(Signal)' 기능은 이러한 자동화를 가능하게 합니다. 시그널은 Arize AX 플랫폼 내에서 실행되는 에이전트로, 모든 추적을 지속적으로 모니터링하여 반복되는 문제 패턴을 자동으로 감지합니다.

데모에서 Voss는 "Wonder Toys"라는 에이전트 기반 쇼핑 앱을 사용합니다.
1.  **관찰 가능성 추가:** 먼저, 앱에 관찰 가능성이 없는 상태에서 에이전트가 질문에 답변하는 것을 보여줍니다. 이후 VS Code의 Claude Code 플러그인을 사용하여 에이전트에게 Arize AX 관찰 가능성을 추가하도록 지시합니다. 에이전트는 `backend/main.py` 및 `backend/requirements.txt` 파일을 자동으로 수정하여 OpenInference를 통합하고 Arize AX로 추적을 보냅니다.
2.  **문제 식별:** 앱을 재시작한 후, Arize AX UI에서 추적 데이터가 실시간으로 유입되는 것을 확인합니다. Voss는 에이전트에게 "내 추적을 분석하고 문제가 있는지 찾아줘"라고 요청합니다. 에이전트는 추적을 분석하여 "검색 결과가 0개인 경우가 42%에 달함", "모든 인수가 null인 검색 호출이 발생함", "min_age=max_age 필터링 로직 문제" 등 여러 문제점을 식별합니다.
3.  **문제 해결:** Voss는 에이전트에게 "가격 필터링 기능을 추가해줘"라고 요청합니다. 에이전트는 해당 기능을 구현하는 코드를 자동으로 생성하고 기존 코드에 적용합니다. (데모 중 에이전트가 이미 해결된 버전의 코드를 복사하는 예상치 못한 "영리한" 행동을 보여주기도 합니다.)
4.  **자동화된 개선 루프:** 수정된 앱을 재시작하고 가격 필터링 기능이 정상적으로 작동하는 것을 확인합니다. Voss는 Arize AX의 '시그널' 대시보드를 보여주며, 시그널이 어떻게 "프롬프트 주입이 에이전트 페르소나를 무시함", "에이전트가 모호한 사용자 표현에서 연령 제한을 환각함", "가격 필터가 0개의 스팬을 반환함"과 같은 문제를 자동으로 감지하는지 설명합니다. 시그널은 각 문제에 대한 개요, 증거(관련 추적 링크), 제안된 수정 사항을 제공하며, 심지어 GitHub에 PR을 직접 생성할 수도 있습니다.

이러한 과정을 통해 AI 에이전트 개발의 전체 루프(관찰 → 평가 → 시그널 감지 → 자동 수정)가 인간의 개입을 최소화하면서 에이전트 속도로 이루어질 수 있음을 보여줍니다.

## 인상적인 대목
*   "코드는 더 이상 진실의 원천이 아니다. 추적이 새로운 진실의 원천이다." (Code is no longer the source of truth. Traces are the new source of truth.)
*   "우리는 이제 에이전트 속도로 구축할 수 있다. 하지만 에이전트 속도로 개선할 수는 없다." (We can now build at agent speed. We still can't improve at agent speed.)
*   "관찰 가능성은 인간이 대시보드를 읽는 것에서 에이전트가 추적을 읽는 것으로 변화하고 있다." (Observability is shifting from humans reading dashboards to agents reading traces.)
*   "에이전트가 너무 똑똑하면 문제가 될 수 있다." (One of the things that can happen when you have agents being clever is that agents can be too clever.)

## 실무 적용 포인트
1.  **AI 에이전트 개발 시 추적(Tracing) 필수 도입:** 에이전트의 비결정적 특성을 고려하여, 개발 초기부터 OpenInference와 같은 표준을 활용해 모든 LLM 호출, 도구 사용, 에이전트 턴을 상세히 추적하는 시스템을 구축해야 합니다. 이는 에이전트의 실제 동작을 이해하고 디버깅하는 데 핵심적인 역할을 합니다.
2.  **자동화된 평가(Evals)로 데이터 압축 및 패턴 식별:** 대규모 추적 데이터를 효율적으로 관리하기 위해, 에이전트의 성능과 동작을 자동으로 평가하는 시스템을 도입해야 합니다. LLM 기반의 평가를 통해 '좋음/나쁨' 판단과 함께 설명까지 얻어, 인간이 직접 모든 추적을 검토하는 부담을 줄일 수 있습니다.
3.  **'시그널' 기반의 선제적 문제 해결 시스템 구축:** Arize AI의 Signal과 같은 자동화된 문제 감지 도구를 활용하여, 프로덕션 환경에서 에이전트의 추적 및 평가 데이터를 지속적으로 모니터링하고 반복되는 문제 패턴을 자동으로 식별해야 합니다. 이는 문제 발생 시 즉각적인 대응을 가능하게 합니다.
4.  **자동화된 수정(Automated Fixes)으로 개선 루프 가속화:** 시그널이 식별한 문제에 대해 에이전트가 스스로 해결책을 제안하고, 필요한 경우 코드 수정(예: GitHub PR 생성)까지 자동화하는 시스템을 구축하여, 에이전트의 개선 주기를 획기적으로 단축하고 개발자의 개입을 최소화해야 합니다.
