# Designing CLIs for Agents, Not Humans — Pedro Lopez, Airbyte

🔗 https://youtu.be/3wj6sgbi1YA · 📅 2026-10-09 · 🎙 AI Engineer

## 한 줄 요약
Airbyte는 AI 에이전트가 다양한 SaaS 도구의 데이터에 접근하고 조작할 수 있도록 돕는 데이터 인프라 계층을 제공하며, 이를 위해 MCP(Model Context Protocol)와 CLI(Command Line Interface)라는 두 가지 주요 인터페이스를 구축하고 그 과정에서 얻은 교훈을 공유합니다.

## 발표자·소속
Pedro Lopez, Airbyte 소프트웨어 엔지니어

## 핵심 주장
- AI 에이전트 인터페이스는 데이터 관리, 안전한 연결, 질의 및 실행의 세 가지 핵심 기능을 제공해야 합니다.
- MCP와 CLI는 플랫폼의 핵심 비즈니스 로직을 재구현하지 않고 API 위에 구축된 얇고 통합된 인터페이스여야 합니다.
- MCP는 비기술 사용자에게 적합하며, CLI는 기술 사용자에게 더 많은 제어와 유연성을 제공하므로 각자의 장점을 활용해야 합니다.
- 에이전트 친화적인 CLI를 설계하려면 JSON 기반 입출력, 일관된 명령어 구조, 도구와 함께 제공되는 스킬, 헤드리스 인증 방식이 필수적입니다.

## 세부 내용

발표는 Airbyte가 오픈 소스 데이터 인프라 계층으로서 분석 및 AI 에이전트를 위해 어떻게 발전해왔는지 설명하며 시작됩니다. Airbyte는 데이터 팀과 AI 에이전트에게 다양한 시스템의 데이터에 원활하게 접근, 검색 및 조치를 취할 수 있는 통합 계층을 제공합니다. 현재 F500 기업의 18%와 7,000개 이상의 일일 활성 기업이 Airbyte를 사용하고 있습니다.

Airbyte Agent 제품은 Claude, ChatGPT, Perplexity, Cursor와 같은 AI 에이전트 및 LangChain, OpenAI SDK와 같은 프레임워크와 연결됩니다. 이들은 Airbyte Agent MCP를 통해 Context Store에 연결되며, Context Store는 Facebook Ads, GitHub, Jira, Salesforce, Zendesk, Stripe, Google Cloud 등 다양한 SaaS 도구와 통합되어 데이터의 검색 최적화된 인덱스를 제공합니다.

Airbyte의 목표는 데이터를 어디서든 사용 가능하고 실행 가능하게 만드는 것입니다. 이를 위해 SDK(Python), MCP(Claude/ChatGPT), CLI(터미널), UI(Airbyte 웹 앱)의 네 가지 인터페이스를 제공합니다. 이 발표에서는 MCP와 CLI에 중점을 둡니다.

에이전트 인터페이스는 세 가지 주요 기능을 수행할 수 있어야 합니다:
1.  **관리(Manage)**: 조직, 작업 공간, 커넥터를 구성하고 활성 작업 공간 환경을 쉽게 전환하거나 설정할 수 있습니다.
2.  **연결(Connect)**: 타사 서비스에 대한 커넥터를 안전하게 인증하여 에이전트에 자격 증명이 노출되지 않도록 합니다.
3.  **질의 및 실행(Ask & Act)**: Context Store를 통해 연결된 시스템을 검색하고, 라이브 시스템에 직접 읽고 쓸 수 있습니다.

MCP와 CLI는 플랫폼의 API 위에 구축된 얇고 통합된 인터페이스이며, 플랫폼의 핵심 비즈니스 로직은 재구현되지 않습니다. 플랫폼은 자주 배포되며 인터페이스는 최신 상태를 유지해야 하므로, OpenAPI 기반 생성이 빠른 업데이트를 가능하게 합니다.

**MCP 구축 시 얻은 교훈:**
1.  **도구 수를 적게 유지**: 에이전트가 최소한의 지침으로 무엇을 호출해야 할지 알기 쉽도록 도구 수를 적게 유지합니다. `describe_connector`와 `execute` 두 가지 주요 도구만 노출하여 데이터 가져오기/생성/업데이트를 처리합니다. 점진적 발견(Progressive discovery)을 통해 에이전트가 초기에 모든 컨텍스트를 과부하하지 않고도 다양한 커넥터를 쿼리하는 방법을 알 수 있도록 합니다.
2.  **OAuth가 답**: MCP 클라이언트와 사양은 주로 OAuth를 지원합니다. 사용자는 모바일 앱과 유사하게 장기 세션을 기대하므로, Airbyte 웹 앱과 별도로 저장되는 오프라인 OAuth 세션을 사용합니다.
3.  **Elicitation은 현재로서는 답이 아님**: MCP 사양에는 사용자로부터 추가 정보를 요청하는 Elicitation 기능(폼 모드, URL 모드)이 있지만, 클라이언트 간 지원이 균일하지 않습니다. 특히 민감한 상호작용을 위한 URL 모드 Elicitation은 클라이언트 지원이 부족하여 Airbyte는 자체적인 OAuth 흐름을 구현해야 했습니다.

**CLI 설계 시 얻은 교훈:**
1.  **JSON 입력, JSON 출력**: 플래그 외에도 모든 명령은 페이로드 및 출력 형식으로 JSON을 지원합니다. 이는 기본 인터페이스로 간주됩니다. JSON은 복잡한 스키마 작업에 더 쉽고, `jq`와 같은 도구로 파이프하여 더 큰 응답을 처리할 수 있습니다.
2.  **일관성이 핵심**: 에이전트가 노출된 모든 리소스에 걸쳐 무언가를 수행하는 방법을 아는 것이 명확해야 합니다. 에이전트가 같은 실수를 계속 반복한다면, 이를 계약(contract)으로 만들어 명확하게 정의하는 것을 고려해야 합니다. (예: `connectors list`, `connectors create`와 같이 명사-동사 구조를 일관되게 유지).
3.  **도구와 함께 스킬 제공**: 스킬은 필수입니다. 에이전트가 CLI를 발견하고 효과적으로 사용하는 방법을 알 수 있도록 합니다. 메인 `skill.md`에 모든 것을 넣기보다는 단일 스킬 내에서 참조(references)를 사용하여 컨텍스트 과부하를 방지하고 점진적 발견을 가능하게 합니다.
4.  **인증은 헤드리스여야 함**: 인간이 상호작용적으로 프롬프트를 통해 진행할 수 있다고 가정해서는 안 됩니다. 브라우저를 필요로 하고 완료를 기다리는 대화형 OAuth 대신 환경 변수 또는 API 키를 사용한 구성 파일과 같은 대체 인증 방법을 우선시해야 합니다.

**MCP와 CLI의 장단점:**
-   **MCP**:
    *   **단점**: 사양이 클라이언트 간에 균일하게 구현되지 않음. 지시 및 설명 크기 제한, 도구 호출 제한, 시간 초과 등 제한이 있을 수 있음.
    *   **장점**: 비기술 사용자에게 적합, 빠른 프로토타이핑 또는 일회성 보고서에 유용, 다른 MCP와의 결합 가능.
-   **CLI**:
    *   **단점**: 버전 관리가 필요하여 새 기능으로 패키지를 최신 상태로 유지하기 어려움. 가드레일이 없어 에이전트가 제대로 지시받지 않으면 계속 잘못된 호출을 할 수 있음.
    *   **장점**: 기술 사용자에게 적합, 장기 실행 작업 및 더 무거운 요청 처리, `tail`, `jq` 등으로 파이프하여 더 큰 응답을 더 잘 처리.

결론적으로, MCP와 CLI는 각자의 장단점이 있으며, 사용자와 작업의 특성에 따라 적절한 인터페이스를 선택해야 합니다.

## 인상적인 대목
- "Keep the tool count small. Easier for an agent to know what to call with minimal guidance. One execute tool handles get / create / update." (도구 수를 적게 유지하는 것이 에이전트가 최소한의 지침으로 무엇을 호출해야 할지 알기 쉽고, 하나의 실행 도구가 가져오기/생성/업데이트를 처리한다.)
- "If agents keep making the same mistake, consider making it the contract." (에이전트가 같은 실수를 계속 반복한다면, 이를 계약(contract)으로 만드는 것을 고려하라.)

## 실무 적용 포인트
-   **에이전트용 CLI 설계 시 JSON 우선**: 에이전트가 복잡한 데이터를 처리하기 쉽도록 CLI의 기본 입출력 형식을 JSON으로 설계합니다. 이를 통해 에이전트가 명령을 구성하고 응답을 파싱하는 효율성을 높일 수 있습니다.
-   **일관된 명령어 구조 유지**: `[명사] [동사]` 형태와 같이 일관된 명령어 구조를 사용하여 에이전트가 새로운 기능을 쉽게 추론하고 사용할 수 있도록 합니다. 이는 에이전트의 학습 부담을 줄이고 예측 가능성을 높입니다.
-   **헤드리스 인증 방식 구현**: CLI가 에이전트에 의해 호출될 때 대화형 프롬프트(예: 브라우저 기반 OAuth)를 처리할 수 없으므로, API 키를 환경 변수나 구성 파일을 통해 제공하는 등 헤드리스 인증 방식을 우선적으로 지원해야 합니다.
-   **스킬을 통한 점진적 발견 지원**: CLI 도구와 함께 스킬(skill)을 제공하여 에이전트가 도구의 존재와 사용법을 발견하도록 돕습니다. 스킬 내에서 참조(references)를 활용하여 모든 정보를 한 번에 로드하지 않고 필요할 때 확장하여 컨텍스트 과부하를 방지합니다.
