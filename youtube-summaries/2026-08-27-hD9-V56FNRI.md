## 핵심 주장
- **AI 에이전트는 LLM 기반의 복합 시스템이다**: AI 에이전트는 대규모 언어 모델(LLM)을 '두뇌'로 삼아 도구 사용, 메모리 관리, 계획 수립 능력을 결합하여 복잡한 작업을 수행한다. 이는 인간이 도구, 기억, 계획 능력을 활용하는 방식과 유사하게 작동한다.
- **AI 에이전트 개발은 분산 시스템과 유사한 난제를 가진다**: 에이전트는 LLM의 비결정성으로 인한 신뢰성 문제, 반복적인 LLM 호출로 인한 높은 비용과 지연 시간, 그리고 확장성, 관측 가능성, 보안 등 분산 시스템이 겪는 고유한 문제들을 공통적으로 안고 있다.
- **분산 시스템 원칙을 적용하여 에이전트 문제를 해결할 수 있다**: 에이전트의 오케스트레이션, 상태 관리, 통신, 관측 가능성, 신뢰성, 보안 문제를 해결하기 위해 마이크로서비스 아키텍처, 메시지 큐, 로깅/트레이싱, 재시도 메커니즘, 접근 제어 등 분산 시스템에서 검증된 설계 패턴과 도구들을 활용해야 한다.
- **에이전트 아키텍처는 오케스트레이터, LLM, 도구, 메모리, 관측성, 보안으로 구성된다**: 에이전트 오케스트레이터가 전체 흐름을 제어하고, LLM이 계획을 수립하며, 도구 실행기가 외부 시스템과 상호작용한다. 메모리(단기/장기)는 상태를 유지하고, 로깅, 트레이싱, 모니터링을 통해 관측성을 확보하며, 가드레일과 접근 제어로 보안을 강화한다.

## 세부 내용
발표는 AI 에이전트의 정의, 당면 과제, 구축 방법, 그리고 미래 방향 순으로 진행되었다.

**AI 에이전트란?**
발표자는 AI 에이전트를 LLM(두뇌)에 도구(행동), 메모리(상태), 계획(추론) 능력을 결합한 시스템으로 정의했다. 이는 마치 도구와 기억, 계획 능력을 가진 인간과 같다고 비유했다. ChatGPT 플러그인, AutoGPT, BabyAGI 등이 대표적인 예시로 언급되었다.

**왜 어려운가? (당면 과제)**
AI 에이전트 구축의 주요 난제는 다음과 같다:
*   **신뢰성**: LLM의 비결정성과 환각 현상으로 인해 에이전트의 행동을 예측하기 어렵다.
*   **비용**: LLM API 호출마다 비용이 발생하며, 에이전트는 많은 호출을 생성할 수 있다.
*   **지연 시간**: 순차적인 LLM 호출은 높은 전체 지연 시간으로 이어진다.
*   **확장성**: 에이전트 시스템을 어떻게 효율적으로 확장할 것인가가 문제다.
*   **관측 가능성**: 에이전트의 복잡한 동작을 디버깅하고 이해하기 어렵다.
*   **보안**: 에이전트가 도구를 오용하거나 민감한 데이터에 접근할 위험이 있다.

**어떻게 구축할 것인가? (아키텍처)**
발표의 핵심은 AI 에이전트를 분산 시스템으로 간주하고, 분산 시스템의 설계 원칙을 적용하는 것이다. 모놀리식 애플리케이션에서 마이크로서비스로 전환하는 것과 유사하게, 에이전트도 분산 시스템의 구성 요소로 볼 수 있다. 분산 시스템의 주요 구성 요소인 오케스트레이션, 상태 관리, 통신, 관측 가능성, 신뢰성, 보안을 에이전트 아키텍처에 적용하는 방법을 설명했다.

*   **오케스트레이션**: LangChain, LlamaIndex와 같은 에이전트 프레임워크가 오케스트레이터 역할을 한다. 에이전트 루프(계획 -> 행동 -> 관찰 -> 반영)를 통해 작업을 조정한다. 도구는 API나 함수로, 메모리는 단기(컨텍스트 윈도우) 및 장기(벡터 DB)로 관리된다.
*   **상태 관리**: 메모리(컨텍스트 윈도우, 벡터 DB, 전통 DB), 도구 상태(외부 시스템), 에이전트 자체의 진행 상태 등을 관리한다.
*   **통신**: LLM API 호출, 도구 호출은 HTTP/RPC를 사용하며, 다중 에이전트 시스템에서는 Kafka, RabbitMQ와 같은 메시지 큐를 활용할 수 있다.
*   **관측 가능성**: LLM 입출력, 도구 호출, 에이전트 상태에 대한 로깅, LangSmith와 같은 도구를 활용한 트레이싱, 지연 시간, 비용, 오류율 모니터링을 통해 확보한다.
*   **신뢰성**: LLM 및 도구 호출에 대한 재시도, 멱등성 보장, PII 감지 및 콘텐츠 조정과 같은 가드레일 적용, 중요한 결정에는 Human-in-the-loop를 도입한다.
*   **보안**: 도구 접근 제어, 에이전트 실행 샌드박싱, 프롬프트 및 도구 출력에 대한 입력/출력 유효성 검사, 최소 권한 원칙 적용 등을 강조했다.

발표자는 사용자 요청이 에이전트 오케스트레이터를 통해 LLM(계획), 도구 실행기, 그리고 실제 도구(API, DB 등)로 이어지는 아키텍처 다이어그램을 제시했다. 이 과정에서 메모리(벡터 DB, 전통 DB)가 오케스트레이터와 LLM에 연결되고, 로깅, 트레이싱, 모니터링을 포함한 관측성 시스템이 모든 구성 요소에 연결되며, 가드레일과 보안 계층이 LLM과 도구 실행기를 감싸는 형태로 설명되었다.

**다음 단계는? (미래)**
발표자는 미래 AI 에이전트의 발전 방향으로 다중 에이전트 시스템, 자율 에이전트, 에이전트 전용 프로그래밍 언어, 표준화, 더 나은 평가 방법, 그리고 윤리적 AI를 언급하며 발표를 마무리했다.

## 실무 적용 포인트
- **분산 시스템 설계 패턴 적용**: AI 에이전트 개발 시 마이크로서비스 아키텍처, 메시지 큐, 캐싱, 데이터베이스 등 분산 시스템에서 검증된 설계 패턴과 도구들을 적극적으로 활용하여 신뢰성, 확장성, 성능 문제를 해결한다.
- **강력한 관측성 구축**: LLM 입출력, 도구 호출, 에이전트 상태 변화를 상세히 로깅하고, LangSmith와 같은 도구를 활용하여 에이전트의 실행 경로를 추적하며, 핵심 지표(지연 시간, 비용, 오류율)를 모니터링하여 디버깅 및 성능 최적화를 용이하게 한다.
- **안전 장치(Guardrails) 및 보안 강화**: 에이전트의 오용을 방지하기 위해 PII 감지, 콘텐츠 조정과 같은 가드레일을 구현하고, 도구 접근 제어, 샌드박싱, 입력/출력 유효성 검사, 최소 권한 원칙을 적용하여 보안 취약점을 최소화한다.
- **Human-in-the-loop 도입 고려**: 특히 중요한 결정이나 민감한 작업의 경우, 에이전트의 자율성을 제한하고 인간의 개입을 통해 최종 승인 또는 검토를 거치도록 시스템을 설계하여 신뢰성과 안전성을 확보한다.
