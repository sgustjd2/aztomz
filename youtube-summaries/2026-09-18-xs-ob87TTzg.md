# Total Recall: Agent Memory and Harness Engineering — Ignacio Martinez, Oracle

## 한 줄 요약
LLM 에이전트의 한계를 극복하기 위한 메모리(단기/장기)의 중요성과, 외부 시스템(특히 Oracle Database)을 활용하여 메모리 및 도구를 통합하는 '하네스 엔지니어링'의 개념 및 실제 구현 방안을 제시한다.

## 발표자·소속
Ignacio Martinez, Oracle

## 핵심 주장
- **LLM 에이전트에게 메모리는 필수적이다**: LLM은 본질적으로 상태가 없어 이전 대화나 학습 내용을 기억하지 못한다. 에이전트가 복잡한 작업을 수행하고, 지속적인 상호작용을 하며, 학습 능력을 갖추려면 단기 및 장기 메모리 기능이 반드시 필요하다.
- **하네스 엔지니어링은 LLM을 실용적인 에이전트로 만드는 핵심이다**: 하네스 엔지니어링은 LLM을 외부 데이터베이스, 도구, 시스템과 통합하여 LLM의 한계를 보완하고 실제 애플리케이션에 활용 가능하게 만드는 과정이다. 이는 LLM에 메모리, 도구 사용 능력, 제어 흐름을 부여하는 것을 포함한다.
- **다양한 유형의 메모리를 전략적으로 활용해야 한다**: 에이전트 메모리는 크게 컨텍스트 윈도우 내의 단기 메모리(대화 기록)와 외부 저장소에 기반한 장기 메모리(벡터 스토어, 지식 그래프)로 나뉜다. 이들을 적절히 조합하여 에이전트가 현재 대화를 기억하고, 과거의 지식을 검색하며, 새로운 정보를 학습하도록 설계해야 한다.
- **관계형 데이터베이스는 에이전트의 강력한 장기 메모리 백엔드가 될 수 있다**: Oracle Autonomous Database와 같은 관계형 데이터베이스는 대화 기록, 벡터 임베딩, 구조화된 데이터(도구 사용을 위한)를 저장하는 데 적합하다. 특히 Oracle Database의 벡터 스토어 기능(DBMS_VECTOR)은 시맨틱 검색을 위한 효율적인 장기 메모리 솔루션을 제공한다.

## 세부 내용
발표는 LLM 에이전트의 메모리 필요성으로 시작한다. LLM은 본질적으로 상태가 없으며, 이전 대화나 학습 내용을 기억하지 못하기 때문에 복잡한 작업을 수행하거나 지속적인 상호작용을 하기 어렵다. 이를 해결하기 위해 에이전트에게 메모리가 필요하며, 이는 크게 두 가지 유형으로 나뉜다. 첫째는 '단기 메모리'로, LLM의 컨텍스트 윈도우 내에서 현재 대화 기록을 유지하는 방식이다. 둘째는 '장기 메모리'로, 외부 저장소(데이터베이스 등)를 활용하여 지속적인 정보 저장, 학습, 검색을 가능하게 한다.

발표자는 이러한 장기 메모리 및 외부 시스템 통합을 '하네스 엔지니어링(Harness Engineering)'이라고 정의한다. 이는 LLM을 외부 데이터베이스, 도구, 제어 로직과 연결하여 실제 애플리케이션에서 유용하게 만드는 과정이다. 하네스 엔지니어링은 LLM에 메모리, 도구 사용 능력, 그리고 복잡한 작업을 위한 제어 흐름을 부여한다.

메모리 아키텍처는 여러 계층으로 구성될 수 있다.
1.  **대화 메모리(Conversational Memory)**: 에이전트와 사용자 간의 대화 기록을 저장한다. 간단한 메시지 목록부터 대화 요약, 엔티티 추출 등 복잡한 형태로 발전할 수 있다.
2.  **벡터 메모리(Vector Memory)**: 문서나 데이터의 임베딩을 저장하고, 시맨틱 유사성을 기반으로 관련 정보를 검색하는 데 사용된다. RAG(Retrieval Augmented Generation) 패턴의 핵심이다.
3.  **지식 그래프(Knowledge Graphs)**: 구조화된 관계형 지식을 저장하여 복잡한 추론과 사실 검색을 지원한다.

발표자는 LangChain과 LlamaIndex와 같은 프레임워크가 이러한 에이전트 구축 및 메모리 관리에 널리 사용된다고 언급한다. 특히 Oracle Autonomous Database를 장기 메모리 백엔드로 활용하는 방안을 강조한다. Oracle Database는 대화 기록을 위한 일반 테이블, 벡터 임베딩을 위한 `DBMS_VECTOR` 패키지를 활용한 벡터 스토어, 그리고 에이전트가 사용할 도구(예: SQL 쿼리)를 위한 구조화된 데이터를 저장하는 데 적합하다.

**데모 시연**에서는 LangChain과 Oracle Autonomous Database를 활용한 에이전트가 소개되었다.
*   **대화 기억**: 에이전트는 사용자의 이름(예: "Ignacio")을 기억하고, 이전 질문(예: "Oracle Database에 대해 알려줘")에 대한 맥락을 유지하며 후속 질문(예: "그것의 장점은?")에 답변한다. 이는 Oracle Database에 대화 기록이 저장되어 있기 때문이다.
*   **벡터 스토어를 통한 정보 검색**: 특정 주제(예: "Oracle Database의 특징")에 대해 질문하면, 에이전트는 Oracle Database에 저장된 벡터 임베딩에서 관련 문서를 검색하여 답변을 생성한다. `OracleVectorStore`를 LangChain과 통합하여 사용한다.
*   **도구 사용**: 에이전트는 외부 도구(예: SQL 쿼리 도구)를 사용하여 데이터베이스에서 실시간 데이터를 조회할 수 있다. 예를 들어, "현재 Oracle Database의 CPU 사용률은 얼마야?"와 같은 질문에 대해 SQL 쿼리를 실행하여 실제 데이터를 가져와 답변한다. `SQLDatabaseToolkit`과 같은 LangChain 도구를 활용한다.

데모는 에이전트가 단순히 LLM의 지식에 의존하는 것을 넘어, 외부 메모리와 도구를 통해 동적으로 정보를 검색하고, 대화의 맥락을 유지하며, 실시간 데이터를 활용하는 능력을 보여주었다. 발표는 메모리가 에이전트의 핵심이며, Oracle Database가 이러한 메모리 및 도구 통합을 위한 강력한 플랫폼임을 재차 강조하며 마무리된다.

## 인상적인 대목
- "LLMs are stateless. They don't remember anything." (LLM은 상태가 없습니다. 아무것도 기억하지 못합니다.)
- "Harness Engineering is the discipline of building and integrating external systems to augment LLMs." (하네스 엔지니어링은 LLM을 보강하기 위해 외부 시스템을 구축하고 통합하는 분야입니다.)
- "Memory is the core of any agent." (메모리는 모든 에이전트의 핵심입니다.)

## 실무 적용 포인트
- **LLM 에이전트 설계 시 다양한 메모리 유형 고려**: 단기 대화 메모리(컨텍스트 윈도우 내)와 장기 외부 메모리(벡터 스토어, 관계형 DB)를 명확히 구분하고, 각자의 역할에 맞춰 설계하여 에이전트의 기억력과 지식 활용 능력을 극대화한다.
- **관계형 데이터베이스를 장기 메모리 백엔드로 적극 활용**: Oracle Database와 같은 관계형 데이터베이스는 대화 기록, 벡터 임베딩, 도구 사용을 위한 구조화된 데이터 등 에이전트의 다양한 장기 메모리 요구사항을 충족시킬 수 있는 강력하고 안정적인 솔루션이다.
- **LangChain, LlamaIndex와 같은 에이전트 프레임워크 활용**: 이러한 프레임워크는 메모리 관리, 도구 통합, LLM 호출 등을 추상화하여 에이전트 개발을 가속화하고 복잡성을 줄여준다. 특히 Oracle Database와의 통합을 지원하는 라이브러리를 활용한다.
- **RAG(Retrieval Augmented Generation) 패턴을 통한 지식 확장**: 벡터 스토어를 활용하여 LLM이 학습하지 않은 최신 정보나 특정 도메인 지식을 검색하고 답변 생성에 활용함으로써, LLM의 환각(hallucination)을 줄이고 답변의 정확성과 신뢰성을 높인다.
