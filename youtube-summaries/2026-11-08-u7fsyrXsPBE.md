# Claude Code Looked Right but Missed $800K - Natalia Connolly & Kevin Madura, AlixPartners

🔗 https://youtu.be/u7fsyrXsPBE · 📅 2026-11-08 · 🎙 AI Engineer

## 한 줄 요약
AlixPartners는 Claude Code AI 에이전트를 실제 조달 분석에 적용하여 데이터 구조화의 중요성과 비즈니스 맥락 이해의 필요성을 강조하며, 에이전트가 정확한 결과를 도출하기 위해 맞춤형 도구와 엄격한 데이터 처리 파이프라인이 필수적임을 보여주었습니다.

## 발표자·소속
- 나탈리아 코놀리 (Natalia Connolly), AlixPartners AI 및 데이터 팀 파트너
- 케빈 마두라 (Kevin Madura), AlixPartners AI 엔지니어링 팀

## 핵심 주장
- **데이터 구조화에 선행 투자:** AI 에이전트가 복잡한 계약 데이터를 정확하게 처리하고 분석하려면, 전처리 및 구조화 단계에 충분한 시간과 노력을 투자하여 데이터의 품질과 접근성을 높여야 합니다.
- **맞춤형 도구로 에이전트의 능력 강화:** 에이전트가 데이터에 접근하고 상호작용하는 방식을 제한하고 안내하는 맞춤형 도구를 개발함으로써, 에이전트의 오류를 줄이고 특정 비즈니스 로직을 효과적으로 적용할 수 있습니다.
- **비즈니스 맥락의 중요성:** AI 에이전트는 데이터 자체를 잘 처리할 수 있지만, 현재 진행 중인 비즈니스 상황이나 이미 조치된 사항과 같은 외부 맥락을 이해하지 못하면 비효율적이거나 잘못된 권장 사항을 제시할 수 있습니다.

## 세부 내용

발표는 대규모 헬스케어 기업이 소규모 전문 기업을 인수하면서 발생한 조달 분석 문제를 다루었습니다. 인수 후, 두 회사에 걸쳐 수백 개의 벤더, 40,000개 이상의 계약 문서, 그리고 서로 연결되지 않은 3개의 데이터베이스가 존재했습니다. 조달 팀은 특정 벤더(Acme Health Services)와의 관계에서 잠재적인 비용 절감 기회를 파악하고 싶었으며, 이를 위해 AI 에이전트인 Claude Code를 활용했습니다.

초기 시도에서 Claude Code는 총 연간 지출, 회사별 지출 분할, 활성 계약 건수 등은 정확하게 제시했지만, 총 계약 가치와 다음 통지 기한 두 가지 중요한 수치에서 오류를 범했습니다. 총 계약 가치는 약 80만 달러가 누락되었고, 다음 통지 기한은 실제 날짜(11월 1일)보다 한 달 늦은 12월 1일로 잘못 제시되어 계약 자동 갱신을 막을 기회를 놓칠 뻔했습니다.

발표자들은 이러한 오류의 원인을 "엉망인 계약 데이터(messier contract data)"에서 찾았습니다.
- **Break 01 - Length:** 매우 긴 계약 문서가 전처리 단계에서 로드되지 않아 데이터베이스에 포함되지 않았습니다.
- **Break 02 - Missing Link:** 80만 달러가 누락된 것은 부모 계약에 제대로 연결되지 않은 "고아 수정안(unlinked amendment)" 때문이었습니다. 에이전트는 이 수정안을 찾지 못했습니다.
- **Break 03 - History:** 여러 수정안이 원본 계약 조건을 재명시(restates)하는 경우, 에이전트는 단순히 모든 금액을 합산하여 잘못된 총액(1700만 달러 대신 700만 달러가 정확)을 계산했습니다.
- **Break 04 - Layout:** 요율표와 같은 데이터가 페이지를 넘어가면서 헤더 정보가 누락되어 에이전트가 각 값의 의미를 파악하기 어려웠습니다.

이러한 문제를 해결하기 위해 AlixPartners는 데이터 구조화에 중점을 두었습니다. 40,000개 이상의 계약 문서를 처리하기 위한 5단계 데이터 처리 파이프라인을 구축했습니다.
1.  **전처리 (Preprocess):** 문서 지능, OCR, DB 추출.
2.  **분류 (Classify):** MSA(Master Service Agreement), SOW(Statement of Work), 수정안 등 계약 유형 분류.
3.  **조건, 요율, 지출 (Terms, rates, spend):** 3개의 데이터베이스를 교차 참조하여 결합.
4.  **SOW 서비스 (SOW services):** 서비스들을 지출 카테고리에 매핑.
5.  **분석 에이전트 (Analyst agent):** Claude Code가 이 구조화된 데이터를 분석.

이 파이프라인을 구축하는 데 약 2주가 소요되었고, 이후 40,000개 이상의 계약이 하룻밤 사이에 처리되었습니다. 특히, 차트에 있는 데이터와 같은 멀티모달 데이터를 처리하기 위해 모델이 페이지 이미지를 직접 읽어 구조화된 출력을 생성하도록 했습니다.

또한, 에이전트가 데이터에 접근하는 방식을 통제하기 위해 "맞춤형 도구(custom tools)"를 사용했습니다. Claude Code 에이전트는 `execute_sql`, `list_tables`, `get_rate_card_page`, `get_amendment_chains`, `get_vendor_spend`와 같은 특정 도구를 통해서만 데이터 웨어하우스에 접근할 수 있었습니다. 이 도구들은 읽기 전용 연결을 사용하고, SQL 문당 시간 제한을 두며, 모든 쿼리를 기록하고, 에이전트가 실패하면 피드백을 제공하도록 설계되었습니다. 이를 통해 에이전트가 데이터에 대한 비즈니스 로직과 규칙을 따르도록 강제할 수 있었습니다.

발표자들은 몇 가지 추가적인 교훈을 공유했습니다.
- **규칙을 코드로 구현:** 에이전트가 잘못된 통지 기한을 제시한 문제(Lesson 1)는, 계약 해지 조항이 아닌 갱신 조항에서 날짜를 계산하도록 규칙을 코드로 구현하여 해결했습니다.
- **데이터 복구:** 누락된 80만 달러의 수정안 문제(Lesson 2)는, 두 번째 Claude 프로세스가 누락된 부모 계약을 찾아내고 코드가 링크를 확인하도록 하여 해결했습니다.
- **실패 보고:** 접근 제어로 인해 Summit의 지출이 0으로 보고된 문제(Lesson 3)는, 도구가 경고를 발생시키고 승인된 뷰에서 총계를 가져오도록 하여 해결했습니다.
- **중복 계산 방지:** 여러 에이전트가 병렬로 절감액을 찾을 때 중복 계산이 발생할 수 있는 문제(Lesson 4)는, 하네스(harness)가 인보이스 라인 ID를 매칭하고 가장 높은 우선순위의 절감액만 인정하는 규칙을 적용하여 해결했습니다.
- **딜 맥락:** 에이전트가 이미 진행 중인 절감 기회를 추천하는 문제(Lesson 5)는, 분석가가 데이터가 알 수 없는 딜 및 클라이언트 맥락을 추가하고, 매 실행마다 업데이트된 리셋으로 에이전트가 학습하도록 하여 해결했습니다.

## 인상적인 대목
- "Real contract data are messier than they appear." (실제 계약 데이터는 보이는 것보다 훨씬 지저분합니다.) - 데이터 품질과 구조화의 중요성을 강조하는 핵심 문구.
- "Two weeks of building, then 40,000 contracts processed overnight." (2주간 구축 후, 40,000개의 계약이 하룻밤 사이에 처리되었습니다.) - 잘 설계된 파이프라인이 가져오는 엄청난 효율성을 보여주는 대목.
- "The agent sees the data only through custom tools." (에이전트는 맞춤형 도구를 통해서만 데이터를 봅니다.) - AI 에이전트의 통제와 거버넌스에 대한 실용적인 접근 방식을 제시.

## 실무 적용 포인트
1.  **데이터 파이프라인 구축에 선행 투자:** 대규모 비정형 데이터를 AI 에이전트에 투입하기 전에, 문서 지능, OCR, 분류, 엔티티 추출 등을 포함하는 견고한 데이터 처리 파이프라인을 구축하여 데이터를 구조화하고 정제하는 데 충분한 시간을 할애해야 합니다.
2.  **맞춤형 도구로 에이전트 행동 제어:** 에이전트가 데이터베이스와 상호작용하는 방식을 제한하는 맞춤형 도구를 개발하여, 에이전트가 특정 비즈니스 로직을 따르고, 잘못된 쿼리를 방지하며, 오류 발생 시 적절한 피드백을 받도록 설계해야 합니다.
3.  **멀티모달 데이터 처리 능력 확보:** 텍스트 외에 차트, 표 등 이미지 형태의 데이터가 포함된 경우, DS 파이(DS Py)와 같은 기술을 활용하여 이미지에서 구조화된 데이터를 추출하는 멀티모달 처리 기능을 파이프라인에 통합해야 합니다.
4.  **지속적인 지식 축적 및 맥락 주입:** 에이전트가 이미 진행 중인 프로젝트나 비즈니스 맥락을 이해하지 못해 비효율적인 권장 사항을 제시하는 것을 방지하기 위해, 분석가가 수동으로 추가하는 맥락 정보나 학습된 지식을 에이전트가 다음 분석에 활용할 수 있도록 시스템을 설계해야 합니다.
