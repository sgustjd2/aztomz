# Rethinking Claude Code Best Practices — Lydia Hallie, Anthropic

🔗 https://youtu.be/vlfCjWuv4es · 📅 2026-11-12 · 🎙 AI Engineer

## 한 줄 요약
Anthropic의 최신 Claude 모델은 코드 작업 능력이 크게 향상되어, 개발자가 모델과 상호작용하는 방식이 수동적인 개입에서 자동화된 관리 및 감독으로 변화하고 있으며, 이를 위한 새로운 모범 사례가 필요합니다.

## 발표자·소속
Lydia Hallie, Anthropic Claude Code 팀

## 핵심 주장
- Claude 모델의 코드 작업 능력이 크게 향상되어, 개발자는 이제 개별 작업에 대한 수동적인 개입 대신 여러 세션을 동시에 관리하는 역할로 전환해야 합니다.
- 새로운 Claude 모델(Opus 5.5, Fable 5.2 등)은 사용자의 의도와 코드베이스를 더 잘 이해하므로, `CLAUD.md` 파일에 모델이 스스로 파악할 수 있는 지시사항을 포함하는 것은 비효율적이며, 모델이 알 수 없는 정보(예: 레거시 시스템)만 포함해야 합니다.
- `autoMode`와 `deny` 규칙을 활용하여 모델의 명령 실행을 자동화하고 위험한 작업을 사전에 차단함으로써 코드 품질과 안전성을 보장할 수 있습니다.
- 클라우드 세션(Cloud Session)을 통해 모델이 격리된 환경에서 작업을 수행하고, 개발자는 랩톱을 닫아도 작업이 계속 진행되며, 민감한 정보에 대한 접근을 제한하여 보안을 강화할 수 있습니다.
- `Hooks`와 CI/CD 파이프라인을 통해 모델이 생성한 코드의 품질을 지속적으로 검증하고, 문제가 발생하면 자동으로 수정하도록 유도하여 개발자의 수동 검토 부담을 줄일 수 있습니다.

## 세부 내용

발표자는 Anthropic의 Claude Code 팀에서 일하는 Lydia Hallie입니다. 그녀는 최근 Claude 모델, 특히 Opus 5.5와 Fable 5.2의 SWE-bench Pro 점수가 52%에서 93%로 크게 향상되었음을 보여주며, 이 모델들이 장기 실행 작업과 코드베이스 이해에 매우 능숙해졌다고 강조했습니다. 특히 Fable 모델은 자체 출력을 검증하는 데 탁월합니다.

이러한 모델의 발전은 개발자가 Claude Code와 상호작용하는 방식을 변화시켰습니다. 이전에는 Claude 4.5와 같은 모델을 사용할 때, 개발자는 "읽기", "편집", "테스트 실행" 등 모든 단계에서 수동으로 개입하고 명령을 승인해야 했습니다. `CLAUD.md` 파일에는 "IMPORTANT: always use the auth helper"와 같은 명시적인 지시사항이 포함되었고, `git reset --hard`와 같은 위험한 명령은 수동으로 승인해야 했습니다. 개발자는 작업 흐름에 깊이 관여했습니다.

하지만 이제는 수십 개의 세션을 동시에 실행하고, 각 세션이 몇 시간 동안 실행되며, 자체적으로 결과를 검증하고 심지어 다른 세션을 오케스트레이션하는 방식으로 변화했습니다. 개발자는 이제 개별 명령을 승인하는 대신, 여러 세션을 관리하는 역할로 전환되었습니다. Anthropic의 내부 데이터에 따르면, 2026년 5월에는 하루에 약 2,500건의 코드 변경이 병합되었지만, 2026년 9월에는 30,000건 이상으로 증가했습니다. 이는 개발자가 무엇에 집중해야 할지 재고해야 함을 의미합니다.

발표자는 이전 작업 흐름을 최신 모델에 맞춰 변경하는 방법을 시연했습니다.
1.  **모델 업데이트**: Opus 4.5에서 Opus 5.5로 모델을 변경했습니다. Opus 5.5는 사용자의 의도와 코드베이스를 더 잘 이해하므로, 세션 중간에 모델을 직접 "조종"할 필요가 줄어듭니다.
2.  **자동 모드 활성화**: 수동 승인 모드에서 `autoMode`로 변경했습니다. `autoMode`는 2026년 8월부터 기본 권한 모드가 되었으며, 읽기/편집 외의 모든 작업에 대해 별도의 분류기를 실행합니다. 이를 통해 모델은 안전하다고 판단되는 명령(예: 테스트 실행, 종속성 설치)을 자동으로 허용하고, 안전하지 않다고 판단되는 명령(예: `git reset --hard`)은 차단합니다.
3.  **`CLAUD.md` 최적화**: 이전 `CLAUD.md` 파일에 있던 "IMPORTANT"와 같은 지시사항은 이제 필요 없으며, 오히려 모델을 오도할 수 있습니다. `CLAUD.md`는 Claude가 코드에서 직접 파악할 수 없는 정보(예: 레거시 소스 사용)만 포함해야 합니다. `/doctor prompt-audit` 명령을 사용하여 `CLAUD.md`와 스킬을 감사하고 최적화할 수 있습니다.
4.  **안전성 확보**: `autoMode`는 사람보다 위험한 명령을 더 잘 차단합니다(테스트 결과, 사람이 14%만 위험한 명령을 감지한 반면, `autoMode`는 89%를 차단). 그러나 10% 정도는 여전히 통과할 수 있으므로, `deny` 규칙을 `settings.json`에 추가하여 특정 도구 호출을 영구적으로 차단할 수 있습니다. `deny` 규칙은 `autoMode` 분류기보다 먼저 적용되어 확실한 안전을 보장합니다.
5.  **샌드박스 활용**: `npm test`와 같이 외부 코드를 실행하는 명령은 `.env` 파일이나 SSH 키와 같은 민감한 정보에 접근할 수 있습니다. 이를 방지하기 위해 `settings.json`에서 샌드박스 기능을 활성화하여, 특정 명령이 읽을 수 있는 파일, 쓸 수 있는 폴더, 접근할 수 있는 호스트를 운영체제 수준에서 제한할 수 있습니다.
6.  **클라우드 세션**: 클라우드 세션은 모델에게 리포지토리의 깨끗한 복사본이 있는 자체 머신을 제공하며, 랩톱을 닫아도 작업이 계속 실행됩니다. 이 환경에서는 `.env` 파일, SSH 키, GitHub 토큰 등이 기본적으로 존재하지 않아 보안 위험을 줄입니다. 네트워크 접근도 기본적으로 제한되어 있어, 필요한 도메인만 명시적으로 허용해야 합니다.
7.  **검증(Verification)**: 모델이 장시간 백그라운드에서 작업할 때, 그 결과가 올바른지 확인하는 것이 중요합니다. `Hooks`를 사용하여 특정 시점(예: 파일 편집 후 린트 실행, 작업 완료 후 관련 테스트 실행, 세션 종료 시 전체 테스트 스위트 실행)에 자동으로 검증 스크립트를 실행할 수 있습니다. 스크립트가 `2`의 종료 코드를 반환하면 Claude는 문제를 수정하기 위해 다시 시도합니다.
8.  **세션 오케스트레이션**: Claude Code Projects(베타)와 같은 도구를 사용하여 하나의 메인 세션(오케스트레이터)이 전체 작업을 여러 하위 작업으로 분할하고, 각 하위 작업에 대해 새로운 세션을 시작하도록 할 수 있습니다. 메인 세션은 Fable과 같이 "무엇을 할지 결정하고 판단하는" 데 능숙한 모델을 사용하고, 하위 세션은 Opus 5.5와 같이 "실제 작업을 수행하는" 데 능숙한 모델을 사용할 수 있습니다. 이를 통해 개발자는 여러 세션의 컨텍스트를 직접 관리할 필요 없이, 오케스트레이터 세션과만 상호작용하면 됩니다.

결론적으로, 개발자가 이전에 직접 수행했던 거의 모든 작업은 이제 모델, 하네스(harness), 또는 환경에 의해 처리됩니다. 개발자는 이제 초기 세션을 시작하고 결과물을 검토하는 역할에 집중하게 됩니다.

## 실무 적용 포인트
- **`CLAUD.md` 파일 최적화**: 모델이 코드에서 직접 추론할 수 있는 일반적인 지시사항(예: "항상 인증 헬퍼를 사용하라")은 제거하고, 모델이 알 수 없는 프로젝트 특유의 정보나 레거시 시스템 관련 정보만 포함하도록 `CLAUD.md`를 간소화합니다. `/doctor prompt-audit` 명령을 활용하여 불필요한 지시를 식별합니다.
- **`autoMode` 및 `deny` 규칙 활용**: `settings.json` 파일에서 `autoMode`를 활성화하고, `deny` 규칙을 사용하여 `git reset --hard`와 같이 절대로 실행되어서는 안 되는 위험한 명령을 명시적으로 차단합니다. 또한, 모델이 접근해야 하는 외부 도메인이나 클라우드 버킷을 `autoMode` 환경 설정에 추가하여 불필요한 수동 승인을 줄입니다.
- **샌드박스 환경 구성**: `settings.json`의 샌드박스 설정을 통해 `npm test`와 같이 외부 코드를 실행하는 명령이 접근할 수 있는 파일, 폴더, 호스트를 제한하여 민감한 정보 유출 위험을 줄입니다.
- **`Hooks`를 통한 자동 검증**: `PostToolUse`, `TaskCompleted` 등 특정 이벤트에 `Hooks`를 설정하여 린트, 단위 테스트, 통합 테스트, 스크린샷 캡처 등 코드 품질 검증 작업을 자동으로 실행합니다. 스크립트가 `2`의 종료 코드를 반환하도록 설정하여 실패 시 모델이 자동으로 수정 작업을 수행하도록 유도합니다.
