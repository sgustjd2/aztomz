# Harness Engineering: Building the Production Cage for Powerful Domain Agents — Mike Chambers, AWS

🔗 https://youtu.be/gxVZ_1tuuq4 · 📅 2026-09-14 · 🎙 AI Engineer

## 한 줄 요약
본 발표는 AI 에이전트를 프로덕션 환경에 배포하기 위한 "하네스 엔지니어링"의 중요성을 강조하며, AWS AgentCore를 활용하여 에이전트의 메모리, 도구, 런타임 및 확장성 등을 효과적으로 관리하는 방법을 시연합니다.

## 발표자·소속
Mike Chambers, Snr AI Specialist DA // AWS

## 핵심 주장
-   **에이전트의 두 가지 유형:** 에이전트를 개인적으로 "사용"하는 것과 프로덕션 환경에서 "구축"하는 것은 다른 접근 방식이 필요하며, 특히 구축 시에는 더 많은 엔지니어링 고려 사항이 요구됩니다.
-   **하네스의 정의:** 에이전트의 핵심 모델을 제외한 모든 코드, 구성, 실행 로직을 "하네스"라고 정의하며, 이는 에이전트를 단순한 모델에서 기능적인 시스템으로 만드는 필수 요소입니다.
-   **하네스 엔지니어링의 중요성:** 클라우드 규모에서 프로덕션 에이전트를 배포할 때는 루프 관리, 확장성, 보안, 메모리, 관찰 가능성 등 다양한 복잡한 구성 요소를 개별적으로 관리하는 "하네스 엔지니어링"이 필수적입니다.
-   **AWS AgentCore의 역할:** AWS AgentCore는 이러한 하네스 구성 요소를 인프라스트럭처 코드로 자동 생성하고 관리하여, 개발자가 멀티테넌트 격리 및 확장성 문제에 대한 복잡한 코드를 직접 작성하지 않고도 생산 에이전트를 쉽게 구축하고 배포할 수 있도록 돕습니다.

## 세부 내용
발표자는 먼저 자신의 배경을 소개하며, 2023년 DLAI의 LLM을 활용한 생성형 AI 과정에 참여하여 43만 9천 명 이상의 수강생을 기록했고, 2025년에는 서버리스 MCP(Model Context Protocol) 서빙을 위한 `mcp-lambda-handler`를 개발하여 월 3만 5천 건의 다운로드를 기록했다고 언급했습니다. 또한 2026년에는 리눅스 재단의 Agentic AI Foundation의 창립 멤버로 활동하고 있다고 밝혔습니다.

이어서 에이전트의 개념을 "우리가 사용하는 에이전트"와 "우리가 구축하는 에이전트"로 나누어 설명했습니다. "우리가 사용하는 에이전트"는 Claude Code, Cursor, Kiro와 같은 생산성 도구를 포함하며, 주로 토큰 최적화 등에 중점을 둡니다. 반면 "우리가 구축하는 에이전트"는 더 복잡한 엔지니어링 고려 사항을 필요로 합니다.

발표자는 "하네스"의 정의를 사전적 의미("동물을 제어하는 데 사용되는 끈과 고정 장치 세트")에서 시작하여, "모델을 제어하는 데 사용되는 것"으로 확장했습니다. LangChain과 Martin Fowler의 정의를 인용하며, 하네스는 모델 자체를 제외한 모든 코드, 구성 및 실행 로직이라고 설명했습니다. 즉, `에이전트 - 모델 = 하네스`입니다.

"우리가 사용하는 에이전트"의 하네스는 메모리, 스킬, 도구/MCP(Model Context Protocol) 등으로 구성됩니다. 발표자는 AWS Agent Toolkit for AWS를 소개하며, 이는 GitHub에서 무료로 제공되며 서버리스 MCP 서빙을 돕는다고 말했습니다. 그는 "클릭 옵스(click-ops)는 더 이상 안 된다"며, 프로덕션 환경에서는 인프라스트럭처 코드를 통해 배포해야 한다고 강조했습니다.

"우리가 구축하는 에이전트"의 하네스는 훨씬 더 많은 고려 사항을 포함합니다. 루프 관리, 관찰 가능성, 평가, 결제, 보안, 컨텍스트 관리, 런타임, 확장성, 아이덴티티 등이 모두 하네스 엔지니어링의 영역입니다. 발표자는 이러한 요소들을 개별적으로 관리하고 확장하는 것이 중요하다고 설명했습니다.

라이브 코딩 데모에서는 Kiro IDE를 사용하여 Strands Agent SDK 기반의 에이전트를 시연했습니다.
1.  **간단한 에이전트:** `get_time` 및 `calculator` 도구를 사용하는 에이전트를 보여주며, 에이전트가 사용자의 질문에 도구를 활용하여 답변하는 방식을 설명했습니다. 이 에이전트는 발표자가 직접 작성한 코드와 Kiro가 생성한 코드를 포함합니다.
2.  **세션 관리 에이전트:** `FileSessionManager`를 사용하여 세션 간 대화 기록을 유지하는 에이전트를 시연했습니다. 에이전트가 사용자의 이전 대화 내용을 기억하고 맥락에 맞는 답변을 제공하는 모습을 보여주었습니다.
3.  **AWS AgentCore를 사용한 확장 가능한 에이전트:** `agentcore create` 명령줄 도구를 사용하여 새로운 에이전트 프로젝트를 생성하는 과정을 보여주었습니다. 프로젝트 이름, 에이전트 이름, 언어(Python), 배포 방식(Direct Code Deploy), 프로토콜(HTTP), 프레임워크(Strands Agents SDK), 모델(Claude Sonnet 4.5), 메모리(장기 및 단기 메모리) 등을 선택하여 에이전트를 구성했습니다. AgentCore는 선택된 구성에 따라 클라우드 인프라스트럭처를 자동으로 생성하며, 이는 메모리, 런타임 등을 에이전트와 분리하여 관리함으로써 확장성과 멀티테넌트 격리를 가능하게 합니다. `agentcore dev` 명령을 통해 로컬 웹 UI에서 에이전트와 상호작용하며 디버깅할 수 있는 기능도 시연했습니다. 마지막으로 `harness.json`과 `system-prompt.md` 파일을 보여주며, 에이전트의 설정이 간단한 JSON 및 Markdown 파일로 관리될 수 있음을 강조했습니다.

결론적으로, AWS AgentCore는 에이전트 구축, 배포, 평가를 위한 다양한 구성 요소를 모듈화하고 자동화하여, 개발자가 프로덕션 수준의 AI 에이전트를 효율적으로 만들 수 있도록 지원하는 프레임워크입니다.

## 인상적인 대목
-   "Agent = Model + Harness." 이 간결한 공식은 AI 에이전트 개발의 복잡성을 명확히 구분하여 이해도를 높입니다.
-   "no more slop_ops." AI 에이전트 배포 시 수동적인 클릭 기반 작업 대신 인프라스트럭처 코드를 통한 자동화의 중요성을 강조하는 강력한 메시지입니다.
-   에이전트가 "어떤 월드컵을 말씀하시는지 모르겠습니다"라고 답변하면서도 "호주가 이길 것이라고 말하면 무대에서 멋져 보일 수 있겠지만, 그건 제가 지어내는 것일 겁니다"라고 덧붙이는 대목은 AI의 정직성과 맥락 이해 능력을 유머러스하게 보여줍니다.

## 실무 적용 포인트
1.  **하네스 분리 설계:** AI 에이전트 개발 시 LLM 모델 자체와 주변 로직(메모리, 도구, 런타임, 보안 등)을 명확히 분리하여 설계함으로써, 각 구성 요소의 독립적인 개발, 테스트 및 확장을 용이하게 합니다.
2.  **인프라스트럭처 코드 활용:** 프로덕션 에이전트 배포 시 AWS AgentCore와 같은 도구를 활용하여 인프라스트럭처를 코드로 관리하고 자동화함으로써, 수동 작업을 줄이고 일관성 있는 배포 및 운영을 보장합니다.
3.  **멀티테넌트 및 확장성 고려:** 에이전트 구축 초기 단계부터 멀티테넌트 격리 및 클라우드 규모의 확장성을 고려하여 설계하고, 이를 지원하는 프레임워크를 선택하여 복잡한 로직을 직접 구현하는 부담을 줄입니다.
4.  **관찰 가능성 및 평가 통합:** 에이전트의 성능을 지속적으로 모니터링하고 개선하기 위해, 개발 단계부터 관찰 가능성(observability) 및 평가(evaluations) 기능을 하네스에 통합하여 에이전트의 동작을 투명하게 파악하고 최적화할 수 있도록 합니다.
