# Your AI Agent Wants Your Data. Here's How to Lock It Down - Jeff Smith, Oracle

## 한 줄 요약

## 핵심 주장
*   **Oracle AI 데이터베이스는 AI 파이프라인을 위한 통합 플랫폼입니다.** 데이터베이스 내에서 네이티브 벡터 데이터 유형을 지원하여 RAG(Retrieval Augmented Generation) 파이프라인에 직접 참여할 수 있으며, 금융, HR, ERP 등 다양한 기업 데이터를 단일 SQL 인터페이스로 통합하여 데이터 복제 없이 AI 활용을 가능하게 합니다.
*   **NL2SQL(자연어-SQL 변환)은 강력하지만, 신뢰성과 비용 측면에서 위험합니다.** LLM이 생성한 SQL 쿼리는 의도와 다를 수 있고, 데이터베이스에 대한 무차별적인 쿼리 시도는 비용을 증가시킬 수 있습니다. Oracle은 이를 해결하기 위해 에이전트가 사전 정의되고 검증된 SQL 보고서를 실행하도록 하는 방식을 제안합니다.
*   **AI 에이전트의 데이터베이스 접근은 엄격한 보안 및 거버넌스 하에 이루어져야 합니다.** Oracle은 SSO(Single Sign-On)를 통한 사용자 식별, 읽기 전용 접근 권한, 모든 쿼리 및 응답에 대한 완전한 감사 추적(Full Audit Trail)을 강조합니다. 또한, 데이터베이스 수준에서 동적으로 데이터를 필터링하는 딥 데이터 보안(Deep Data Security)을 통해 민감한 정보 노출을 방지합니다.

## 세부 내용

발표자는 Oracle AI 데이터베이스가 무엇인지에 대한 질문으로 강연을 시작했습니다. Oracle AI 데이터베이스는 네이티브 벡터 데이터 유형을 지원하여 RAG 파이프라인에 참여할 수 있도록 하며, 금융, HR, ERP, 소매, 정부, 헬스케어 등 다양한 분야의 데이터를 벡터화하여 데이터베이스 내에 저장하고 단일 SQL 인터페이스를 통해 접근할 수 있도록 합니다. 이는 여러 플랫폼에 데이터를 복제할 필요 없이 AI 활용을 가능하게 합니다. Oracle은 30년 동안 관계형 외의 다양한 데이터 유형(텍스트, 공간, XML, 그래프, JSON)과 워크로드(OLTP, 분석, 분산 데이터 레이크, AI 벡터 검색)를 동일한 엔진에 추가하며 혁신을 지속해왔습니다.

발표는 세 가지 주요 부분으로 구성됩니다: 실제 사용 사례, 발전 및 다음 단계, Q&A 및 로드맵. 발표자는 특히 "월요일 아침에 바로 사용할 수 있는 개념"으로 MCP 개발, NL2SQL 정확도 향상, 토큰 사용 및 비용 관리를 강조했습니다.

**1. 실제 사용 사례**

*   **사용 사례 1: 셀프 서비스 데이터 접근 (NL2SQL)**
    *   **문제점:** 비즈니스 사용자나 개발자가 자연어로 질문하고 SQL로 변환하여 답을 얻는 NL2SQL은 강력하지만, LLM이 생성한 SQL 쿼리가 항상 정확하거나 의도한 바를 반영하지 못할 수 있어 "신뢰할 수 없고(Unreliable)" "비용이 많이 든다(Expensive)"는 문제가 있습니다. LLM은 데이터베이스 스키마를 무작위로 탐색하여 불필요한 토큰을 소모할 수 있습니다.
    *   **Oracle의 해결책:** 에이전트가 임의의 SQL 쿼리를 생성하는 대신, 사전 정의되고 검증된 "SQL 보고서"를 활용하도록 합니다. 에이전트는 `List Reports` 도구를 사용하여 사용 가능한 보고서 목록을 받고, `Execute Reports` 도구를 사용하여 특정 보고서를 실행합니다. 보고서에는 설명, 매개변수, 샘플 질문 등이 포함되어 에이전트가 적절한 보고서를 선택하도록 돕습니다. 이는 LLM이 잘못된 SQL을 생성할 위험을 줄이고, 비용을 절감하며, 데이터 거버넌스를 유지할 수 있게 합니다.

*   **사용 사례 2: 자율 성능 튜닝**
    *   **문제점:** AI 에이전트가 데이터베이스 성능 문제를 스스로 진단하고 해결하는 것은 매력적이지만, 프로덕션 환경에서 에이전트가 임의로 인덱스를 생성하거나 삭제하는 등의 변경 작업을 수행하는 것은 "위험(DANGER)"합니다.
    *   **Oracle의 해결책:** 에이전트에게 프로덕션 데이터베이스에 대한 "읽기 전용 접근(Read-Only Access)" 권한만 부여합니다. 에이전트는 `Oracle perf ops`와 같은 "맞춤형 MCP 도구(Custom MCP Tools)"를 사용하여 느린 쿼리의 실행 계획을 분석하고, 데이터 통계(statistics)를 수집하여 성능 프로파일을 생성합니다. 이를 통해 에이전트는 문제 해결을 위한 "제안된 수정(proposed fix)"을 제시하지만, 실제 변경 작업은 DBA의 승인(DBA approval)을 거치도록 하여 통제력을 유지합니다. Oracle Data Guard와 같은 기술을 활용하여 읽기 전용 스탠바이 인스턴스에서 성능 테스트를 수행할 수 있습니다.

*   **사용 사례 3: 스키마 탐색 및 문서화**
    *   **문제점:** 새로운 직원이 온보딩하거나 익숙하지 않은 스키마를 다룰 때, 데이터베이스 구조와 의미를 파악하는 데 많은 시간(예: DDL 스크립트를 통한 일주일간의 탐색)이 소요됩니다. 기존 문서화는 종종 오래되거나 불완전합니다.
    *   **Oracle의 해결책:** "AI 강화 / 자동화된 주석(AI Enrichment / Automated Annotations)" 기능을 통해 스키마 정보를 LLM에 제공합니다. `Schema Information` 도구를 사용하여 데이터베이스의 테이블, 컬럼, 주석, 샘플 데이터 등을 LLM이 이해할 수 있는 압축된 JSON 형식으로 추출합니다. `Generate Annotations` 도구를 사용하여 기존 문서(SharePoint, PDF, PowerPoint, Excel, Word 등)의 텍스트를 추출하고 정리하여 데이터베이스 메타데이터에 주석으로 추가합니다. 이는 LLM이 데이터 모델을 더 잘 이해하고, 정확한 쿼리를 생성하며, 새로운 사용자의 온보딩 시간을 단축하는 데 기여합니다.

**2. 세 가지 사용 사례를 관통하는 원칙 (보안)**

*   **SSO 신원 확인 (SSO Identity):** 모든 요청은 실제 인증된 사용자를 통해 이루어지며, 공유 서비스 계정은 사용하지 않습니다.
*   **읽기 전용 접근 (Read-Only Access):** 에이전트 쿼리는 범위가 지정되고, 읽기 전용 규칙을 따르며, 사용 사례에 필요한 것 이상의 권한을 부여하지 않습니다.
*   **완전한 감사 추적 (Full Audit Trail):** 모든 질문과 응답은 누가 실제로 질문했는지까지 기록됩니다.

Oracle은 이 세 가지 원칙을 통해 AI 에이전트가 안전하고 책임감 있게 데이터베이스와 상호작용하도록 보장합니다. 또한, 데이터베이스 수준에서 동적으로 데이터를 필터링하여 사용자 역할에 따라 볼 수 있는 데이터를 제한하는 "딥 데이터 보안"을 구현합니다.

**3. FinOps(재무 운영)를 통한 에이전트 관리**

*   **문제점:** AI 지출을 개인이나 팀에 귀속시키기 어렵고, AI 지출의 25% 이상이 설명되지 않으며, 52%의 조직이 전담 AI 비용 소유자가 없습니다.
*   **해결책:**
    *   **문제:** 개인이나 팀에 지출을 귀속시킬 수 없음 → **해결책:** 데이터베이스 내에서 실제 사용자 신원 확인 및 완전한 감사 추적.
    *   **문제:** 모든 호출에서 도구 정의가 부풀려짐 → **해결책:** AI 스킬, 스키마 강화, 더 적은 도구로 컨텍스트 팀 유지.
    *   **문제:** 에이전트가 SQL을 개선하고 데이터 계층에서 반복 작업을 수행 → **해결책:** 임의의 쿼리 대신 검증된 보고서 실행.
    *   **문제:** 프로덕션에서 폭주하는 리소스 사용 → **해결책:** 소비자 그룹 및 읽기 전용 스탠바이로 폭주 반경 제한.

**4. 발전 및 다음 단계**

*   **OCI 관리형 MCP 서비스:** Oracle은 Azure, AWS, GCP 등 멀티클라우드 환경에서 MCP 서비스를 제공하여 팀이 직접 호스팅할 필요 없이 쉽게 AI 데이터베이스를 구축하고 관리할 수 있도록 합니다. Terraform 템플릿을 통해 배포를 더욱 간소화합니다.
*   **MCP 앱:** 에이전트가 JSON/CSV 데이터 덤프를 받는 대신, 직접 정렬, 필터링, 쿼리 결과를 브라우징하고, 차트를 통해 성능을 시각화하며, 변경 사항을 직접 POST할 수 있는 GUI 기반의 MCP 앱을 개발 중입니다. 모든 상호작용은 기존 SSO 신원 확인, 제어 및 감사 추적을 통해 이루어집니다.
*   **AI 스킬 배포 및 업데이트:** Oracle은 에이전트가 Oracle 관련 최신 스킬을 갖도록 보장하는 내장 도구를 제공합니다. `sync_skills`와 같은 도구를 통해 공식 Oracle 스킬 저장소에서 스킬을 다운로드하고 설치할 수 있습니다.
*   **자동화된 RAG 파이프라인:** `SQL model ingest` 명령어를 통해 문서(예: PPTX 파일)를 자동으로 임베딩하고 벡터 테이블에 추가하는 과정을 시연했습니다. 이는 문서 기반 RAG 파이프라인 구축을 자동화합니다.

## 실무 적용 포인트
*   **NL2SQL 활용 시 검증된 보고서 우선:** LLM이 임의의 SQL을 생성하도록 하기보다, `List Reports` 및 `Execute Reports`와 같은 MCP 도구를 활용하여 사전 정의되고 검증된 SQL 보고서를 에이전트가 사용하도록 유도하여 신뢰성과 비용 효율성을 확보할 수 있습니다.
*   **AI 에이전트의 프로덕션 접근 권한 최소화:** 성능 튜닝과 같은 민감한 작업의 경우, 에이전트에게 "읽기 전용 접근"만 허용하고, 실제 변경 사항은 DBA의 명시적인 승인을 거치도록 하는 워크플로우를 구축하여 시스템 안정성을 보장해야 합니다.
*   **스키마 메타데이터의 AI 친화적 문서화:** `Schema Information` 및 `Generate Annotations` 도구를 사용하여 데이터베이스 스키마에 대한 풍부한 메타데이터와 주석을 생성하고 관리하여, LLM이 데이터 모델을 더 정확하게 이해하고 활용할 수 있도록 컨텍스트 엔지니어링을 수행합니다.
*   **데이터베이스 수준의 보안 및 감사 강화:** 조직의 SSO 시스템과 통합하여 에이전트의 모든 데이터베이스 접근에 대한 사용자 신원을 확인하고, 딥 데이터 보안을 통해 역할 기반의 데이터 접근 제어를 구현하며, 모든 AI-데이터베이스 상호작용에 대한 완전한 감사 추적을 유지해야 합니다.
