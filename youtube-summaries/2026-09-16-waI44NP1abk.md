# Rebuilding the web for agents — Liad Yosef, MCP Apps

🔗 https://youtu.be/waI44NP1abk · 📅 2026-09-16 · 🎙 AI Engineer

## 한 줄 요약
발표자는 MCP Apps를 통해 에이전틱 웹(Agentic Web)의 가능성을 제시하며, 웹사이트와 브라우저가 개인 비서 에이전트에게 자리를 내주고, 에이전트가 웹의 주요 인터페이스가 될 미래를 위해 웹이 에이전트 친화적으로 준비되어야 한다고 주장합니다.

## 발표자·소속
Liad Yosef, Co-creator & maintainer, MCP Apps / Co-founder, ora / Led Agentic Commerce, Shopify / Analog Astronaut, ESA

## 핵심 주장
- **MCP Apps는 에이전틱 웹의 "마지막 한 걸음"을 해결했습니다:** MCP Apps는 챗봇 내에서 풍부한 UI를 가능하게 하여, 사용자가 앱의 브랜드와 신뢰성을 유지하면서 에이전트를 통해 다양한 기능을 활용할 수 있도록 합니다.
- **개인 비서 에이전트가 웹의 새로운 운영 체제가 될 것입니다:** 기존의 웹사이트와 브라우저 중심의 상호작용은 비효율적이며, 미래에는 개인 비서 에이전트가 사용자의 의도를 이해하고 여러 서비스를 통합하여 작업을 수행하는 주요 인터페이스가 될 것입니다.
- **웹은 "거의 헤드리스(Nearly Headless)" 상태로 진화해야 합니다:** 에이전트가 웹사이트와 헤드리스 방식으로 상호작용하되, 필요한 경우에만 서버에서 맞춤형 UI를 전송받아 "마지막 한 걸음"의 인간-에이전트 상호작용을 지원하는 모델이 필요합니다.
- **에이전트 준비성(Agent Readiness)은 새로운 웹의 핵심 과제입니다:** 웹사이트는 에이전트가 자신을 발견하고, 이해하고, 인증하고, 통합하며, 신뢰할 수 있도록 모든 면에서 준비되어야 하며, 이는 에이전트 피드백을 통해 정의되어야 합니다.

## 세부 내용
발표자는 먼저 자신이 MCP Apps의 공동 제작자이자 유지보수자이며, Ora라는 회사에서 인간-에이전트 상호작용을 연구하고 Shopify에서 에이전틱 커머스를 이끌었다고 소개합니다. 그는 이 발표가 전날 만들어졌기 때문에 "구식일 수 있다"는 유머러스한 경고로 시작합니다.

MCP Apps는 ChatGPT, Claude, GitHub Copilot 등 현재 사용되는 대부분의 챗 기반 앱의 기반이 되는 사양입니다. 이는 채팅 내에서 풍부한 인터페이스를 허용하여, 앱(제공자)은 브랜드와 아이덴티티를 유지하고, 사용자(인간)는 신뢰와 친숙함을 얻으며, 에이전트(호스트)는 새로운 기능의 세계에 접근할 수 있게 합니다. 발표자는 Booking.com과 AllTrails 앱의 예시를 통해 에이전트가 사용자의 요청에 따라 여러 앱의 UI 요소를 채팅 내에서 통합하여 보여주는 방식을 시연합니다. 이는 에이전트가 사용자의 "마지막 한 걸음" 상호작용을 해결하는 데 도움을 줍니다.

발표자는 이러한 변화를 "에이전틱 웹(Agentic Web)"이라고 부르며, 이는 기존 웹의 근본적인 변화를 의미한다고 설명합니다. 현재 우리는 기념일을 계획하기 위해 구글 캘린더, 아마존, 부킹닷컴 등 여러 탭을 열고 각 서비스에 의도를 다르게 전달해야 합니다. 그러나 미래에는 개인 비서 에이전트가 이 모든 것을 통합하여 처리할 것입니다. 그는 "브라우저 에이전트"가 단순히 "더 빠른 말" 솔루션에 불과하며, 에이전트가 웹사이트를 브라우징하며 버튼을 클릭하는 방식은 비효율적이라고 비판합니다. 대신, 에이전트가 웹사이트와 "헤드리스(headless)" 방식으로 상호작용하고, 필요한 경우에만 맞춤형 UI를 전송받는 "거의 헤드리스(Nearly Headless)" 웹이 미래라고 제시합니다.

새로운 사용자 경험(UX)은 AX(Agent Experience) + UAX(User Agent Experience)로 정의됩니다. 즉, 에이전트가 제품을 경험하는 방식과 인간이 그 에이전트를 경험하는 방식이 결합된 것입니다. 이는 앱 아이콘 그리드(현재)에서 에이전트 작업 스트림(미래)으로의 전환을 의미합니다. 발표자는 웹사이트와 브라우저가 쓸모없어지고 개인 비서가 웹에 접근하는 유일한 관문이 될 것이라고 예측하며, 이는 9살짜리 자녀가 검색을 위해 구글 대신 ChatGPT를 사용하는 현실에서 이미 나타나고 있다고 말합니다.

Salesforce와 Cloudflare 같은 주요 기업들이 이미 "헤드리스" 전략을 채택하고 있으며, Cloudflare CEO는 에이전트 트래픽이 이미 인간 트래픽을 넘어섰다고 언급했습니다. 이는 웹사이트가 에이전트 친화적으로 준비되어야 함을 의미합니다.

Ora는 에이전트 준비성(Agent Readiness)을 측정하는 벤치마크를 개발했습니다. 이 벤치마크는 발견 가능성(Discovery), 아이덴티티(Identity), 인증 및 접근(Auth & Access), 통합(Integration), 사용자 경험(User Experience) 등 여러 요소를 평가합니다. Ora.directory는 에이전트가 웹사이트를 어떻게 탐색하는지 시각화하는 도구인 Ora.journey를 통해 웹사이트의 에이전트 준비성을 보여줍니다. 흥미로운 점은 많은 웹사이트가 LLMs.txt 파일을 게시하지만, 대부분의 에이전트는 이 파일을 직접 사용하기보다 문서 페이지나 홈페이지를 통해 정보를 얻는다는 것입니다. 이는 에이전트가 인간이 정의한 방식이 아닌, 스스로의 방식으로 정보를 찾는다는 것을 시사합니다.

발표자는 에이전트가 에이전트 준비성을 정의해야 하며, 인간이 정의해서는 안 된다고 강조합니다. 이를 위해 .well-known/ai-catalog.json과 Agentic Resources Discovery와 같은 새로운 표준들이 등장하고 있습니다. Ora.directory는 이러한 표준을 준수하며, 에이전트가 도메인이나 기능별로 웹의 에이전트 인덱스를 검색할 수 있도록 합니다. 마지막으로, 에이전트 접근성(Agentic accessibility)이 인간 접근성(human accessibility)과 매우 유사하며, 웹사이트를 인간에게 접근 가능하게 만드는 것이 에이전트에게도 도움이 된다고 언급하며 발표를 마무리합니다.

## 실무 적용 포인트
- **API-First 및 헤드리스 아키텍처 채택:** 웹사이트는 에이전트가 데이터를 직접 소비하고 상호작용할 수 있도록 강력하고 잘 문서화된 API를 제공하는 헤드리스 아키텍처로 전환해야 합니다.
- **에이전트 친화적인 메타데이터 및 표준 구현:** .well-known/ai-catalog.json과 같은 에이전틱 리소스 디스커버리(ARD) 표준을 활용하여 웹사이트의 기능과 데이터를 에이전트가 쉽게 발견하고 이해할 수 있도록 명확하게 노출해야 합니다.
- **에이전트 여정(Agent Journey) 분석 및 최적화:** Ora.journey와 같은 도구를 사용하여 실제 에이전트가 웹사이트에서 특정 목표를 달성하는 과정을 시뮬레이션하고 분석하여, 에이전트가 효율적으로 작업을 수행할 수 있도록 웹사이트 구조와 데이터 노출 방식을 개선해야 합니다.
- **접근성(Accessibility) 개선:** 시각 장애인을 위한 웹 접근성 표준(WCAG)을 준수하는 것은 에이전트가 웹사이트를 이해하고 상호작용하는 데도 도움이 되므로, 인간 접근성과 에이전트 접근성을 동시에 고려하여 웹사이트를 설계해야 합니다.
