# Let Anyone at Your Company Ship Internal Apps with AI — Garrett Galow, WorkOS

🔗 https://youtu.be/HTzgC3FoYsI · 📅 2026-10-08 · 🎙 AI Engineer

## 한 줄 요약
WorkOS는 AI를 활용하여 비기술 직군도 내부 애플리케이션을 쉽게 구축하고 배포할 수 있도록 지원하는 플랫폼 'Atlas'와 CLI 도구 'wow'를 개발하여, 사내 앱 개발 및 배포의 장벽을 낮추고 생산성을 향상시켰습니다.

## 발표자·소속
Garrett Galow, WorkOS

## 핵심 주장
- **누구나 앱을 만들고 배포할 수 있도록 지원:** AI를 통해 앱 구축은 쉬워졌지만, 배포는 여전히 복잡한 문제로 남아있었습니다. WorkOS는 비기술 직군도 아이디어를 실제 앱으로 구현하고 사내에 공유할 수 있도록 지원하는 도구와 플랫폼을 제공합니다.
- **인프라를 투명하게 제공:** 개발자가 인프라 세부 사항(배포 대상, 스토리지, 컴퓨팅 등)에 신경 쓰지 않고 앱 개발에만 집중할 수 있도록, 모든 필수 요소가 내장된 '보이지 않는 인프라'를 제공합니다.
- **기본적으로 보안을 강화:** 모든 내부 앱은 엔터프라이즈 SSO(Single Sign-On)를 통해 보호되며, 모든 요청은 기록되고 감사 가능하며, 비밀 정보는 안전하게 저장되어 보안 위험을 최소화합니다.
- **쉬운 앱 발견 및 공유:** 개발된 앱들은 중앙 카탈로그를 통해 쉽게 발견할 수 있으며, 별도의 공유 절차 없이 사내 모든 직원이 접근할 수 있어 협업과 활용도를 높입니다.

## 세부 내용
발표자는 WorkOS에서 겪었던 내부 앱 개발 및 배포의 어려움을 설명하며 발표를 시작했습니다. 약 6~8개월 전, 한 영업 담당자(Perona)가 출산 휴가를 앞두고 동료들을 돕기 위해 'PeronaGPT'라는 챗봇을 만들었습니다. 이 챗봇은 그녀의 영업 통화 기록과 제품 지식을 학습한 AI 챗봇이었습니다. 그러나 CEO인 Michael이 이 챗봇에 접근하려 했을 때, 권한 문제로 사용할 수 없었습니다. 결국 두 명의 AI 엔지니어가 이 챗봇을 내부 서비스로 전환하는 데 시간을 할애해야 했습니다.

발표자는 이 사례를 통해 "구축은 쉬워졌지만, 배포는 그렇지 않다"는 문제점을 지적했습니다. 비엔지니어는 앱 인프라 설정, 보안, 인증 문제에 부딪히고, 엔지니어는 이러한 앱을 마이그레이션하고 관리하는 데 시간을 소모하게 됩니다.

WorkOS는 이 문제를 해결하기 위해 두 가지 목표를 세웠습니다.
1.  **역량(Capability):** 누구나 앱을 구축할 수 있도록 지원합니다.
2.  **배포(Distribution):** 내부 앱 공유의 모든 장벽을 제거합니다.

이러한 목표를 달성하기 위해 WorkOS는 'Claude Day'라는 회사 전체 해커톤을 진행했습니다. 이 행사에서는 비엔지니어와 엔지니어가 팀을 이루어 내부 앱을 개발하며, 비엔지니어가 직접 앱을 구축하고 엔지니어는 컨설팅 역할을 수행합니다.

핵심 솔루션은 **'wow CLI'**입니다. 이 CLI는 모든 직원의 Mac에 MDM(모바일 기기 관리)을 통해 배포되어 있습니다.
-   `wow app create <앱 이름>` 명령어를 실행하면, Git, Node.js, GitHub CLI, Doppler CLI 등 개발 환경을 자동으로 설정하고, GitHub 리포지토리를 생성하며, Cloudflare(Wrangler)에 로그인하고, 데이터베이스 및 R2 스토리지를 프로비저닝하며, npm 종속성을 설치하는 등 모든 초기 설정 작업을 한 번의 명령으로 처리합니다. 이를 통해 개발자는 즉시 앱 개발을 시작할 수 있습니다.
-   `wow skills push/pull` 명령어를 통해 공유된 'Claude Code skill registry'를 활용할 수 있습니다. 유용한 스킬을 한 번 만들면 모든 직원이 공유하고 사용할 수 있습니다.

발표자는 데모를 통해 `wow app create aie-demo` 명령어를 실행하여 새로운 앱을 생성하고 로컬에서 실행하는 과정을 보여주었습니다. 또한, WorkOS 내부에서 개발된 'Internal Tools Registry'를 통해 278개의 앱이 배포되었고, 이 중 21개가 당일 배포되었으며, 지난주에 330만 건의 요청이 처리되었음을 보여주었습니다. 이 앱들은 단순한 대시보드가 아니라 API, Slack 봇 등 다양한 형태로 활용되고 있습니다.

이러한 시스템의 기반이 되는 플랫폼은 **'Atlas'**입니다. Atlas는 세 가지 원칙을 따릅니다.
1.  **보이지 않는 인프라(Invisible Infrastructure):** Atlas는 Cloudflare의 개발자 플랫폼에서 실행되며, 모든 앱에는 컴퓨팅, 스토리지(D1 데이터베이스, KV 스토리지 등)가 내장되어 있어 개발자가 인프라에 대해 걱정할 필요가 없습니다. 또한, `workos.tools` 도메인 아래에 자동으로 호스팅됩니다.
2.  **기본적으로 보안(Secure by default):** 모든 앱은 엔터프라이즈 SSO를 통해 보호되며, 모든 요청은 기록되고 감사 가능합니다. API 키와 같은 비밀 정보는 Doppler를 통해 안전하게 저장됩니다.
3.  **쉬운 발견(Easy discovery):** 모든 앱은 카탈로그를 통해 쉽게 발견할 수 있으며, Slack 링크를 통해 누구나 접근할 수 있습니다.

현재까지의 통계에 따르면, 60개의 실제 앱이 배포되었고, 주당 300만 건의 요청이 발생하고 있으며, 배포 관련 도움 요청은 0건입니다. 가장 중요한 것은 **37%의 앱이 엔지니어의 개입 없이 비기술 직군에 의해 구축되었다**는 점입니다.

향후 Atlas는 더욱 세분화된 인증(granular authz), 더 많은 데이터 통합(`wow add <capability>`), 그리고 0-effort Slack 통합 기능을 추가할 예정입니다.

## 실무 적용 포인트
- **내부 앱 개발 간소화:** `wow CLI`와 같은 도구를 활용하여 Git, Node.js, GitHub, Doppler 등 개발 환경 설정을 자동화하고, 템플릿 기반으로 앱을 생성하여 비기술 직군도 쉽게 내부 앱 개발을 시작할 수 있도록 지원합니다.
- **중앙 집중식 앱 관리 및 배포:** 모든 내부 앱을 'Atlas'와 같은 중앙 레지스트리에 등록하고 Cloudflare Workers와 같은 서버리스 플랫폼에 자동 배포하여 인프라 관리 부담을 줄이고 일관된 배포 환경을 제공합니다.
- **보안 및 접근성 강화:** 엔터프라이즈 SSO를 통해 모든 내부 앱에 대한 접근을 통제하고, 모든 요청을 로깅하여 감사 가능성을 확보하며, Doppler와 같은 도구를 사용하여 API 키 등 민감 정보를 안전하게 관리합니다.
- **협업 및 지식 공유 촉진:** 'Claude Day'와 같은 해커톤을 통해 비엔지니어와 엔지니어 간의 협업을 장려하고, 'wow skills'와 같은 공유 스킬 레지스트리를 구축하여 재사용 가능한 코드와 기능을 쉽게 공유하고 활용할 수 있도록 합니다.
