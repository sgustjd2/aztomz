# How to Build Voice Agents That Don't Fall Apart When You Interrupt - Jesse Hall, LiveKit

🔗 https://youtu.be/OmyqelTwpOo · 📅 2026-10-26 · 🎙 AI Engineer

## 한 줄 요약
발표자는 인간과 같은 실시간 음성 에이전트를 구축하기 위한 과제와 해결책을 제시하며, 개별 모델의 성능보다는 전체 대화 흐름과 사용자 경험을 측정하는 벤치마크의 중요성을 강조합니다.

## 발표자·소속
Jesse Hall, LiveKit

## 핵심 주장
-   **인간과 같은 음성 에이전트의 필요성**: 기존 에이전트는 백그라운드 작업을 처리하는 데 중점을 두었지만, 실시간 음성 에이전트는 사람처럼 자연스럽게 대화하고 상호작용해야 합니다. 이는 고객 서비스, 금융 서비스 등 다양한 분야에서 중요합니다.
-   **개별 모델 리더보드의 한계**: 음성 에이전트의 구성 요소(STT, LLM, TTS)를 개별적으로 평가하는 리더보드는 실제 대화에서 발생하는 오류 전파(errors flow downhill)나 실시간 상호작용의 복잡성을 반영하지 못합니다.
-   **실시간 대화의 핵심 지표**: "첫 바이트까지의 시간"이나 "첫 토큰까지의 시간" 같은 기술적 지표보다는 사용자가 실제로 듣고 느끼는 "첫 오디오까지의 시간"과 "첫 문장까지의 시간"을 측정해야 합니다. 또한, 에이전트가 도구를 사용하는 동안에도 대화를 지속하는 비동기적 처리와 적절한 턴 감지(turn-taking)가 중요합니다.
-   **대화 기반 벤치마크의 중요성**: 음성 에이전트의 성능을 제대로 평가하려면 개별 구성 요소가 아닌 완전한 에이전트와 실제와 유사한 시뮬레이션된 발화자(simulated callers) 간의 대화를 테스트해야 합니다. 이를 통해 실제 사용 사례에서 에이전트가 목표를 달성하는지, 대화 품질은 어떤지 종합적으로 평가할 수 있습니다.

## 세부 내용

발표는 대부분의 AI 에이전트가 백그라운드에서 코드를 작성하거나 연구를 수행하는 등 비동기적으로 작동하는 반면, 음성 에이전트는 실시간으로 인간과 상호작용해야 한다는 점을 지적하며 시작합니다. 현재의 음성 에이전트들은 사용자가 말을 끊거나 혼란스러워하면 대화가 부자연스러워지거나 무너지는 경향이 있습니다. 발표자는 금융 서비스 분야에서 이러한 문제가 발생할 경우 리스크가 더 커진다고 언급하며, 인간과 같은 음성 에이전트를 구축하는 방법에 대해 논의합니다.

많은 업계 리더들이 음성 AI의 중요성을 강조하고 있으며, LiveKit은 OpenAI의 ChatGPT 고급 음성 모드를 지원하는 실시간 인프라를 제공합니다. LiveKit은 에이전트가 듣고(Hear), 보고(See), 말하는(Speak) 능력을 갖추도록 돕습니다.

기존 음성 에이전트는 STT(Speech-to-Text), LLM(Large Language Model), TTS(Text-to-Speech) 세 가지 모델이 순차적으로 작동하는 캐스케이드 파이프라인(cascaded pipeline) 방식을 사용합니다. 발표자는 수많은 모델과 제공업체 중에서 어떤 모델을 선택해야 할지 고민하는 "선택 문제"를 제기합니다.

**구성 요소 리더보드가 실패하는 이유**
발표자는 개별 모델의 리더보드 점수에만 의존하는 것이 위험하다고 경고합니다. 예를 들어, 사용자가 "3일에 결제하고 싶다"고 말했지만 STT 모델이 "30일"로 잘못 들으면, 이 오류는 LLM과 TTS 모델로 전파되어 잘못된 정보로 대화가 진행됩니다. 리더보드는 개별 모델의 성능을 측정할 뿐, 이러한 오류 전파를 고려하지 않습니다. 또한, 리더보드는 깨끗한 오디오 데이터를 기반으로 평가되지만, 실제 사용자는 스피커폰, 교통 체증, 아이들 소음 등 열악한 환경에서 통화하는 경우가 많습니다.

**지연 시간: 두 개의 시계**
발표자는 지연 시간(latency) 측정의 중요성을 강조하며, 대시보드에서 측정하는 "첫 바이트까지의 시간(Time to First Byte)"이 빠르다고 해서 실제 사용자가 빠르게 느끼는 것은 아니라고 설명합니다. 실제로는 첫 바이트 이후에도 상당한 침묵(silence)이 발생할 수 있습니다. 따라서 사용자가 실제로 오디오를 듣기 시작하는 "첫 오디오까지의 시간(Time to First Audio)"을 측정해야 합니다. 마찬가지로 LLM의 경우 "첫 토큰까지의 시간"보다는 "첫 문장까지의 시간"이 더 중요합니다.

**실제 에이전트의 작업 처리 시간**
음성 에이전트는 단순히 대화만 하는 것이 아니라, 트랜잭션 찾기, 결제 상태 확인, 분쟁 제출과 같은 실제 작업을 수행해야 합니다. 이러한 작업은 2초, 10초, 심지어 40초 이상 걸릴 수 있습니다. 발표자는 이 긴 지연 시간을 인간처럼 처리하는 방법을 제시합니다. `async def`와 `await ctx.update("Checking transactions.")`와 같은 비동기 도구(async tool)를 사용하여 백엔드 작업이 진행되는 동안에도 에이전트가 대화를 계속 이어갈 수 있도록 합니다. 데모 영상에서 호텔 접수원 에이전트는 사용자의 요청을 처리하는 동안에도 자연스럽게 대화를 이어가며 필요한 정보를 수집합니다.

**턴 감지(Turn-Taking)**
인간과 같은 대화를 위해서는 에이전트가 언제 말하고 언제 들어야 할지 아는 턴 감지 능력이 필수적입니다. LiveKit의 턴 감지 기능은 단순히 텍스트 스크립트뿐만 아니라 오디오의 리듬, 피치, 억양까지 분석하여 사용자가 말을 마쳤는지 정확하게 판단합니다. 이를 통해 다른 대안보다 훨씬 낮은 4.5%의 오인식률(false cutoffs)을 달성했습니다 (다른 대안은 9.9%).

**실시간 창(The Realtime Window)**
발표자는 사용자의 마지막 음절과 에이전트의 첫 오디오 응답 사이의 간격을 "실시간 창"이라고 정의합니다. 이 간격이 1.5초를 넘어가면 대화가 어색하게 느껴지기 시작하고, 500~600ms 이내여야 인간처럼 자연스럽게 느껴집니다. 에이전트가 이 실시간 창 내에서 모든 처리(턴 감지, LLM 응답 생성, TTS 오디오 생성)를 완료해야 합니다.

**결론 및 실무 적용 포인트**
음성 에이전트는 스피커가 달린 챗봇이 아니라, 사람처럼 감지하고 반응하는 실시간 시스템입니다.

-   "Errors flow downhill." (오류는 아래로 흐릅니다.)

-   "The winner wasn't the smartest model. It was the one that got to the point." (승자는 가장 똑똑한 모델이 아니었습니다. 요점을 파악한 모델이었습니다.)
-   "A voice agent isn't a chatbot with a speaker attached. It's a realtime system that senses and responds like a person." (음성 에이전트는 스피커가 달린 챗봇이 아닙니다. 사람처럼 감지하고 반응하는 실시간 시스템입니다.)

## 실무 적용 포인트
1.  **사용자 관점의 지연 시간 측정**: "첫 바이트까지의 시간" 대신 "첫 오디오까지의 시간"과 "첫 문장까지의 시간"을 측정하여 실제 사용자 경험을 반영하세요.
2.  **비동기 처리 도입**: 에이전트가 백엔드 도구(API 호출, 데이터베이스 조회 등)를 사용하는 동안에도 대화를 지속할 수 있도록 비동기 처리(`async/await`)를 구현하여 사용자에게 끊김 없는 경험을 제공하세요.
3.  **대화 기반 벤치마크 활용**: 개별 모델의 성능보다는 완전한 에이전트와 시뮬레이션된 발화자 간의 대화를 통해 에이전트의 전반적인 성능과 대화 품질을 평가하는 벤치마크를 구축하세요. LiveKit의 오픈소스 벤치마크(`livekit.com/benchmarks`)를 참고할 수 있습니다.
4.  **정확한 턴 감지 구현**: 텍스트 스크립트뿐만 아니라 오디오의 억양, 피치, 리듬을 분석하여 사용자의 발화 종료 시점을 정확히 파악하는 턴 감지 기능을 사용하여 부자연스러운 끼어들기나 긴 침묵을 줄이세요.
