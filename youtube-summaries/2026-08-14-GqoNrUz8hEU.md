# Bringing agents onto the world wide web — Paul Klein IV, Browserbase

🔗 https://youtu.be/GqoNrUz8hEU · 📅 2026-08-14 · 🎙 AI Engineer

## 한 줄 요약
브라우저 에이전트의 잠재력을 완전히 실현하기 위해서는 모델 자체의 발전뿐만 아니라, 웹 환경에 최적화된 하네스 엔지니어링과 견고한 인프라 구축이 필수적인 공학적 과제입니다.

## 발표자·소속
Paul Klein IV, Browserbase 창립자

## 핵심 주장
- **모델 성능 향상에도 불구하고 웹 에이전트의 활용은 여전히 정체되어 있습니다.** 과거에는 모델의 한계가 병목이었으나, 이제 모델들은 복잡한 작업을 수행하고 인터페이스를 사용하는 능력이 크게 향상되었습니다.
- **에이전트가 웹을 효과적으로 사용하지 못하는 이유는 적절한 하네스와 도구가 부족하기 때문입니다.** 모델의 능력을 최대한 끌어내기 위해서는 모델 주변에 스캐폴딩과 시스템을 구축하는 하네스 엔지니어링이 중요합니다.
- **하네스 엔지니어링은 코딩 분야에서 이미 성능 향상을 입증했습니다.** 동일한 모델을 사용하더라도 도메인에 최적화된 하네스를 통해 모델 자체의 성능을 뛰어넘는 결과를 얻을 수 있습니다.
- **웹 자체의 개선도 필요합니다.** 에이전트가 웹을 더 잘 활용하도록 접근성, 인증, 신뢰 문제를 해결해야 하며, 이는 웹 표준과 인프라 수준에서의 노력을 요구합니다.
- **신뢰할 수 있는 브라우저 에이전트를 구축하는 것은 모델 문제가 아닌 공학적 문제입니다.** 이는 멀티모달 접근, 하네스 엔지니어링, 견고한 인프라라는 세 가지 핵심 요소에 달려 있습니다.

## 세부 내용

발표자는 AI 에이전트가 전 세계 웹에서 작업을 수행하는 "컴퓨터 사용(Computer Use)" 분야에 초점을 맞춥니다. 그는 청중이 이미 AutoGPT나 Operator와 같은 도구를 사용해 보았을 것이며, 왜 에이전트가 아직 웹에서 널리 활용되지 못하는지에 대한 의문을 가지고 있을 것이라고 말합니다.

**웹은 에이전트를 위해 만들어지지 않았습니다.** 웹은 사람을 위해 설계되었기 때문에 에이전트가 웹과 상호작용하고 자동화하는 데 어려움이 있습니다. 깨진 브라우저, 불안정한 페이지, 복잡한 레이아웃, 차단기 등이 에이전트의 웹 접근을 제한합니다. 발표자 자신도 과거에 웹 자동화 스크립트 유지보수로 고통받았다고 언급합니다.

**최근까지 병목은 모델 자체였습니다.** 1년 전 모델들은 긴 컨텍스트의 작업을 잘 처리하지 못했지만, 이제 모델의 성능은 비약적으로 발전하여 인터페이스를 사용하는 능력도 크게 향상되었습니다. METR의 그래프는 LLM이 소프트웨어 작업을 완료하는 데 걸리는 시간이 2023년 GPT-3.5에서 2026년 Claude Mythos에 이르기까지 급격히 단축되었음을 보여줍니다. 특히 컴퓨터 사용 모델의 정확도는 2024년부터 2026년까지 가파르게 상승했습니다.

**그렇다면 에이전트가 여전히 웹을 사용하는 데 어려움을 겪는 이유는 무엇일까요?** 발표자는 에이전트가 "올바른 하네스와 도구"를 놓치고 있다고 주장합니다. Andrej Karpathy의 2023년 11월 트윗을 인용하며, LLM 주변의 시스템(CPU, 디스크, 파일 시스템, 주변 장치, 이더넷, 브라우저, 다른 LLM)이 바로 하네스라고 설명합니다. 이 하네스는 모델이 세상과 상호작용할 수 있도록 하는 스캐폴딩과 도구입니다.

**하네스 엔지니어링은 이미 코딩 분야를 변화시켰습니다.** Cursor, Claude Code, Droid by Factory와 같은 도구들은 동일한 모델을 사용하면서도 커스텀 하네스를 통해 모델 자체의 성능을 뛰어넘는 결과를 보여주었습니다. Terminal-Bench Accuracy 그래프는 Factory의 Scout 모델이 Claude Code, GPT-4, GPT-3.5보다 높은 정확도를 달성했음을 보여줍니다. 이는 도메인에 최적화된 하네스를 구축하는 것이 모델 성능을 향상시키는 데 매우 효과적임을 의미합니다.

**컴퓨터 사용 분야에는 엄청난 "역량 오버행(capabilities overhang)"이 존재합니다.** 코딩/SWE(소프트웨어 엔지니어링) 작업의 해결률이 약 60%에 달하는 반면, 컴퓨터 사용, 지식, 웹 자동화(CUA)는 약 16%에 불과합니다. 이는 모델이 충분히 좋음에도 불구하고, 이를 활용할 수 있는 엔지니어링 작업이 부족하다는 뜻입니다. Greg Brockman의 트윗("오버행이 지금은 크게 느껴진다")도 이 점을 지적합니다.

**신뢰할 수 있는 브라우저 에이전트를 구축하는 것은 공학적 문제입니다.** 이를 위해서는 세 가지 핵심 요소가 필요합니다.
1.  **멀티모달(Multi-model):** 코딩 모델과 컴퓨터 사용 모델을 함께 사용하여 에이전트가 최상의 추론과 행동을 할 수 있도록 합니다. 웹 자동화는 단순히 화면 클릭이 아니라 네트워크 요청 가로채기, 스크립트 작성 등 다양한 작업을 포함할 수 있습니다.
2.  **하네스 엔지니어링(Harness engineering):** 에이전트가 장기적인 실제 작업을 수행할 때 효율적으로 작동하도록 기술(skills)과 메모리 같은 컨텍스트 효율적인 기술을 제공합니다. Browserbase의 `browse.sh`처럼 웹사이트에 대한 기술을 게시하여 에이전트가 이전에 수행한 작업을 기억하고 학습하도록 돕습니다. 이는 토큰 사용을 최적화하여 비용을 절감합니다.
3.  **인프라(Infrastructure):** 에이전트가 언제 어디서나 올바른 가드레일(guardrails) 내에서 작동하도록 합니다. 수천 개의 에이전트를 운영할 때 일관된 환경(페이지 레이아웃, 크기)을 제공하는 것이 중요합니다.

**웹 자체를 개선하는 것도 필요합니다.**
-   **접근성(Accessibility):** 에이전트가 읽을 수 있는 페이지(표준 접근성 트리, 에이전트 친화적 형식, WebMCP 내장)를 구축해야 합니다. Chrome의 WebMCP는 에이전트가 웹사이트에 직접 도구 호출을 할 수 있게 합니다.
-   **인증(Authentication):** 인증은 인간을 위해 만들어졌으므로, 에이전트가 안전하게 자격 증명을 위임받거나 접근할 수 있는 방법이 필요합니다. WorkOS의 AuthMD와 같이 에이전트가 웹사이트에서 계정을 만들고 로그인하는 새로운 방법을 제공해야 합니다.
-   **신뢰(Trust):** 웹은 나쁜 봇을 막기 위해 만들어졌지만, 이제는 좋은 에이전트와 나쁜 봇을 구별해야 합니다. Web Bot Auth와 같은 검증된 신원 시스템을 통해 에이전트의 신뢰성을 증명할 수 있어야 합니다.

**Browserbase는 이러한 문제 해결을 돕기 위해 Browserbase Agents를 출시했습니다.** 이는 브라우징, 검색, 가져오기(fetch), 샌드박스, 코드 실행 기능을 포함하는 완전 관리형 에이전트 제품입니다. 목표는 개발자들이 바퀴를 재발명할 필요 없이, 웹 자동화에 필요한 모든 것을 포함하는 배터리 내장형 에이전트와 하네스를 제공하는 것입니다.

**데모 시연:**
발표자는 Browserbase Agents의 데모를 보여줍니다. 사용자가 "Check nursing license for AMERICA, LINDA MARIE"라는 프롬프트를 입력하면, 에이전트가 캘리포니아 DCA 웹사이트에서 간호사 면허를 검색합니다. 이 과정에서 에이전트는 페이지를 탐색하고, 양식을 채우고, 검색 버튼을 클릭하며, 결과를 추출합니다. 데모는 에이전트의 실행 단계와 스크린샷, 추출된 JSON 데이터를 시각적으로 보여줍니다. 또한, "최적화(Optimize)" 기능을 통해 에이전트의 실행 기록을 분석하여 불필요한 호출, 캡차 대기, 픽셀 좌표 클릭 대신 요소 참조 사용, 상세 페이지 URL 추측 등의 비효율적인 부분을 식별하고 개선된 시스템 프롬프트를 제안하는 과정을 보여줍니다. 이는 에이전트가 여러 루프를 통해 스스로 개선할 수 있는 데이터 피드백 루프의 중요성을 강조합니다.

## 실무 적용 포인트
- **하네스 엔지니어링에 투자:** 모델의 성능이 충분하다면, 도메인에 특화된 하네스를 구축하여 에이전트의 실제 작업 수행 능력을 향상시키는 데 집중해야 합니다. 이는 모델 자체의 훈련보다 더 효율적인 접근일 수 있습니다.
- **멀티모달 에이전트 설계:** 웹 자동화 시 컴퓨터 사용 모델과 코딩 모델을 결합하여 복잡한 작업을 처리하고, 네트워크 요청 가로채기나 스크립트 작성 등 다양한 상호작용 방식을 활용하는 것을 고려해야 합니다.
- **에이전트의 메모리 및 스킬 활용:** 에이전트가 이전에 수행한 작업을 기억하고 학습할 수 있도록 메모리 및 스킬 메커니즘을 구축하여 반복적인 작업에서 효율성을 높이고 토큰 사용을 최적화해야 합니다.
- **에이전트 친화적인 웹 환경 구축 고려:** 웹사이트 개발 시 접근성 트리, ARIA 태그, WebMCP와 같은 에이전트 친화적인 표준을 도입하고, 에이전트 전용 인증 및 신뢰 메커니즘을 설계하여 에이전트의 원활한 접근과 안전한 사용을 지원해야 합니다.
