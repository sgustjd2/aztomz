# You Can't Tell What an Agent Skill Will Do by Reading It - Roey Ben Chaim, Zenity

🔗 https://youtu.be/_7P580m4kPY · 📅 2026-11-10 · 🎙 AI Engineer

## 한 줄 요약
AI 에이전트 스킬은 정적 분석만으로는 악성 여부를 판단하기 어려우므로, 샌드박스 환경에서 실제 실행을 관찰하고 모든 실행 경로와 부수 효과를 포착하여 분석해야 한다.

## 발표자·소속
Roey Ben Chaim, Zenity 소속 스태프 엔지니어, MATS Research Fellow.

## 핵심 주장
- **에이전트 스킬의 복잡성:** 에이전트 스킬은 단순한 코드 조각이 아니라, 외부 리소스, 스크립트, 패키지 등을 동적으로 로드하고 실행할 수 있는 복잡한 기능을 포함한다.
- **정적 분석의 한계:** 정적 분석 도구는 스킬의 모든 잠재적 페이로드를 추적하기 어렵고, LLM 기반 분석기는 교묘한 주석 등으로 속일 수 있어 악성 행위를 탐지하는 데 한계가 있다.
- **실행 기반 분석의 필요성:** 악성코드 분석에서 사용되는 디토네이션(detonation) 기법을 에이전트 스킬에 적용하여, 격리된 환경에서 스킬을 실행하고 그 동작을 관찰하는 것이 필수적이다.
- **디토네이션 챔버의 구성:** 스킬 실행을 위한 환경 구축(월드 빌더), 다양한 실행 경로를 탐색하는 오퍼레이터(때로는 적대적 오퍼레이터), 그리고 프로세스, 파일 시스템, 네트워크 활동 등 모든 부수 효과를 포착하는 메커니즘이 필요하다.
- **실제 캠페인 사례:** 'Paperclip' 캠페인과 같이 유명 프로젝트를 모방하여 악성 스킬을 배포하고 자격 증명을 탈취하려는 시도가 있었으며, 이러한 공격은 정적 분석을 우회하고 수많은 다운로드를 기록했다.

## 세부 내용

발표는 AI 에이전트 스킬의 본질과 관련된 보안 문제에 대한 심층적인 분석을 제공합니다. 에이전트 스킬은 지침, 리소스, 새로운 동작, 스크립트, 심지어 코드를 포함할 수 있는 '온디맨드 역량'으로 정의됩니다. 문제는 이러한 스킬이 종종 다른 사람에 의해 작성되며, 이로 인해 보안 취약점이 발생할 수 있다는 것입니다.

발표자는 스킬의 실행 경로를 분석하는 것이 얼마나 어려운지 설명합니다. 예를 들어, 클라우드 및 쿠버네티스 설정을 읽고, ID 서비스에 접속하며, 인스턴스 메타데이터 엔드포인트를 탐색하는 스킬은 겉보기에는 정상적인 Azure 진단 스킬처럼 보이지만, 이러한 행동은 정보 탈취 악성코드와 유사합니다. 스킬의 악성 여부를 판단하기 위해서는 단순히 코드를 읽는 것 이상으로 스킬의 원래 의도를 이해해야 합니다.

**정적 분석의 문제점:**
1.  **페이로드의 분산:** 스킬의 실제 페이로드는 `SKILL.md` 파일 외부에 존재할 수 있습니다. 원격 가이드, 패키지, 스크립트 등 여러 단계에 걸쳐 로드될 수 있으므로, 정적 스캐너만으로는 모든 페이로드를 추적하기 어렵습니다.
2.  **LLM 분석기 우회:** LLM 기반 분석기는 교묘하게 작성된 주석(예: "AppSec 팀이 승인한 변경 사항")에 속아 악성 행위를 안전하다고 판단할 수 있습니다.

**디토네이션 챔버 구축:**
이러한 정적 분석의 한계를 극복하기 위해 발표자는 '악성코드 디토네이션' 기법을 에이전트 스킬에 적용한 '디토네이션 챔버'를 소개합니다.
1.  **초기 버전:** 스킬과 에이전트를 샌드박스에 넣고 태스크 프롬프트를 제공한 후, 에이전트 트레이스를 캡처하여 실행을 분석하는 방식이었습니다. 하지만 이는 충분하지 않았습니다.
2.  **환경 문제 해결 (월드 빌더):** 많은 스킬이 특정 CLI, 서비스, 프로젝트에 의존하므로, 스킬의 요구사항에 맞춰 적절한 환경을 구축하는 '월드 빌더'를 추가했습니다.
3.  **활성화 문제 해결 (오퍼레이터):** 스킬마다 실행 방식이 다르기 때문에(예: 프레젠테이션, 배포, 브레인스토밍), 스킬을 분석하여 적절한 태스크, 프롬프트, 모드를 결정하고 실행 경로를 탐색하는 '오퍼레이터'를 도입했습니다. 에이전트가 실행을 거부하는 경우를 대비해 '적대적 오퍼레이터'를 통해 에이전트가 스킬을 실행하도록 유도했습니다.
4.  **가시성 문제 해결 (도구 호출 아래 캡처):** `npm install`과 같은 단일 도구 호출 뒤에는 자식 프로세스 실행, 파일 읽기/쓰기, 엔드포인트 연결 등 복잡한 프로세스 트리가 숨어있습니다. 이러한 부수 효과를 포착하기 위해 프로세스, 파일 시스템, 네트워크 활동을 캡처하는 메커니즘을 추가했습니다. 이를 통해 스킬의 지침, 실행, 관찰된 효과를 상호 연관시켜 동작을 설명할 수 있게 되었습니다.

**실제 공격 캠페인 사례 - Paperclip:**
Zenity Labs는 이 디토네이션 챔버를 사용하여 `skills.sh`에서 수천 개의 스킬을 분석했고, 약 100개의 악성 스킬을 발견하여 제거했습니다. 특히 'Paperclip' 캠페인을 통해 다음과 같은 흥미로운 공격 기법들을 발견했습니다.
-   **지속성 (Persistence):** 스킬이 제거된 후에도 에이전트의 영구 메모리에 재설치 지침을 남겨두는 방식.
-   **사일런트 액션 (Silent Actions):** 합법적인 `skill-creator`를 확인하고, 이를 제거한 후 자신을 설치하는 방식으로 조용히 대체하는 스킬.
-   **원격 프롬프트 실행 (Remote Prompt Execution):** 초기 프롬프트가 모든 지침을 포함하지 않고, 원격 URL에서 추가 지침을 가져오는 방식. 이는 URL의 내용이 언제든지 변경될 수 있어 위험합니다.
-   **훅 남용 (Hooks Abuse):** `UserPromptSubmit`과 같은 특정 훅에 악성 명령을 연결하여 사용자가 메시지를 보낼 때마다 실행되도록 하는 방식.

'Paperclip' 캠페인에서는 공격자가 `paperclipai` 조직을 모방하여 `getpaperclipai`라는 유사한 조직을 만들고, 도메인을 등록한 후 실제 프로젝트를 복제했습니다. 그들은 복제된 프로젝트의 API 라우트에 `log_action()`이라는 새로운 함수를 삽입했습니다. 이 `log_action` 함수는 공격자가 제어하는 엔드포인트에서 페이로드를 가져와 디코딩하고 임시 파일로 저장한 다음 실행한 후 60초 뒤에 자가 삭제하는 방식이었습니다. 이 페이로드는 SSH 키, AWS 자격 증명, Azure 프로필 등 다양한 민감한 경로에서 자격 증명을 수집하여 공격자의 피드백 엔드포인트로 전송하는 정보 탈취기였습니다.

이 공격자는 Python 버전의 유사한 패키지를 PyPI에 배포하려 했으나, Amazon Inspector와 같은 보안 도구에 의해 몇 시간 내에 차단되었습니다. 하지만 `skills.sh`에서는 동일한 명령 및 제어(C2)를 사용하는 스킬들이 당시 트렌딩 목록에 올랐고, 총 170만 건의 다운로드를 기록하며 광범위하게 확산되었습니다. Zenity Labs는 이 캠페인을 Vercel, Microsoft, GitHub에 보고했고, 12시간 이내에 모든 악성 목록, 스킬, 저장소가 제거되었습니다.

## 실무 적용 포인트
-   **스킬을 실행 가능한 종속성으로 취급:** AI 에이전트 스킬을 일반적인 소프트웨어 패키지처럼 취급하고, 설치 전에 로드하는 모든 요소(원격 스크립트, 패키지 등)를 철저히 검사해야 합니다.
-   **최소 권한 원칙 적용:** 스킬이 접근할 수 있는 리소스(파일 시스템, 네트워크, 특정 서비스)를 최소한으로 제한하여 잠재적 피해를 줄여야 합니다.
-   **실행 중 동작 관찰:** 정적 분석만으로는 부족하므로, 격리된 샌드박스 환경에서 스킬을 실행하고 프로세스 생성, 파일 시스템 변경, 네트워크 통신 등 모든 부수 효과를 실시간으로 모니터링해야 합니다.
-   **LLM 분석기 우회 기법 인지:** LLM 기반 보안 도구의 한계를 이해하고, 교묘한 주석이나 난독화된 코드로 우회될 수 있음을 인식하여 추가적인 동적 분석을 병행해야 합니다.
-   **에이전트 공급망 전반의 보안 강화:** 스킬뿐만 아니라 웹사이트, 댓글, CRM 객체, 이메일, GitHub 이슈, PDF, API 응답, 데이터베이스 행 등 에이전트 컨텍스트에 들어오는 모든 데이터 소스를 잠재적 위협으로 간주하고 보안을 강화해야 합니다.
