# How to Let AI Agents Sign Up for Your App Safely — Isabelle Williams, WorkOS

🔗 https://youtu.be/uTrY8slys0w · 📅 2026-10-23 · 🎙 AI Engineer

## 한 줄 요약
AI 에이전트가 애플리케이션에 안전하게 접근하고 사용자 대신 작업을 수행할 수 있도록 `auth.md` 프로토콜과 ID-JAG 표준을 활용하여 에이전트의 접근 권한을 관리하고 제한하는 방법을 설명합니다.

## 발표자·소속
Isabelle Williams, WorkOS 제품 매니저

## 핵심 주장
- **에이전트 중심의 사용자 확보:** 에이전트가 애플리케이션을 발견하고 사용자를 대신하여 작업을 시작할 수 있도록 `auth.md`와 같은 개방형 프로토콜을 통해 에이전트의 접근을 허용해야 합니다. 이는 제품 주도 성장(PLG)의 새로운 형태로, 에이전트가 제품의 가치를 입증하고 사용자를 유입시키는 역할을 합니다.
- **에이전트를 실제 고객과 연결:** 에이전트가 익명으로 수행한 작업을 사용자가 소유권을 주장하거나, 에이전트 제공자가 사용자의 신원을 보증하는 ID-JAG(Identity Assertion JWT Authorization Grant)와 같은 표준을 통해 에이전트의 활동을 실제 사용자와 연결해야 합니다. 이를 통해 에이전트가 사용자 대신 안전하게 API를 호출할 수 있습니다.
- **에이전트의 행동 제한 및 권한 회수:** 기업 환경에서 에이전트가 재정적 위험이나 규정 준수 문제를 일으키지 않도록, 에이전트의 권한을 제한하고 필요할 때 회수할 수 있는 메커니즘을 구축해야 합니다. 이는 에이전트 토큰에 사용자 권한과 에이전트 블루프린트(최대 권한)의 교집합을 적용하여 달성할 수 있습니다.

## 세부 내용

발표자는 WorkOS의 제품 매니저인 Isabelle Williams로, AI 에이전트가 앱의 다음 사용자가 될 것이라는 전제하에 에이전트의 안전한 앱 접근 및 관리 방안을 제시합니다.

먼저 WorkOS는 앱, 에이전트, API 구축을 위한 인증 인프라를 제공하며, OpenAI, Prophetic, Cursor 등 3,000개 이상의 고객사를 보유하고 있다고 소개합니다. 발표자는 Waypoint라는 가상의 여행 계획 앱을 사용하여 에이전트 통합의 세 가지 주요 질문을 탐구합니다.

**1. 에이전트를 어떻게 앱에 들여보낼 것인가?**
개인 여행 계획의 경우, 에이전트가 제품을 발견하고 사용자를 대신하여 빠르게 가치를 입증하는 것이 중요합니다. 이를 위해 `auth.md`라는 개방형 프로토콜을 사용합니다. `auth.md`는 앱과 함께 호스팅되는 마크다운 파일로, 에이전트가 앱에 접근하고 계정을 등록하는 방법을 설명합니다.

`auth.md`는 두 가지 모드를 지원합니다:
- **익명 모드:** 에이전트가 계정 등록 없이 제한된 작업을 수행하여 제품의 가치를 테스트할 수 있습니다.
- **사용자 대신 모드:** 에이전트가 사용자 대신 더 많은 작업을 수행할 수 있도록 권한을 확장합니다.

**2. 에이전트를 고객과 어떻게 연결할 것인가?**
에이전트가 익명으로 수행한 작업을 사용자가 소유권을 주장하거나, 에이전트 제공자가 사용자의 신원을 보증하는 방식으로 에이전트의 활동을 실제 사용자와 연결합니다.

- **익명 작업 소유권 주장 흐름:**
    1.  에이전트가 익명으로 API 작업을 수행하고 `claim token`을 받습니다.
    2.  에이전트가 사용자에게 링크와 일회용 코드를 제공합니다.
    3.  사용자는 Waypoint 앱에 로그인/가입하고 코드를 입력하여 에이전트의 작업을 자신의 계정으로 가져옵니다.
    4.  Waypoint의 인증 서버는 OAuth를 사용하여 사용자 대신 에이전트에게 액세스 토큰을 발급하고, 에이전트는 이 토큰으로 API를 호출합니다.

- **에이전트 검증 흐름 (ID-JAG):**
    1.  사용자가 에이전트에게 Waypoint와 신원 공유에 동의합니다.
    2.  에이전트가 에이전트 제공자(예: Claude)에게 Waypoint를 위한 "ID-JAG"를 요청합니다.
    3.  에이전트 제공자는 ID-JAG를 에이전트에게 발급합니다.
    4.  에이전트는 이 ID-JAG를 Waypoint의 인증 서버로 보냅니다.
    5.  Waypoint는 ID-JAG의 서명을 검증하고, 페이로드에 포함된 사용자 정보(이름, 이메일, 이메일 인증 여부)를 확인합니다.
    6.  Waypoint는 이 정보를 바탕으로 사용자 계정을 생성하거나 기존 계정에 연결하고, 에이전트에게 부여할 액세스 권한(스코프)을 결정합니다.
    7.  Waypoint는 에이전트에게 스코프가 적용된 액세스 토큰을 발급하고, 에이전트는 이 토큰으로 API를 호출합니다.

ID-JAG(Identity Assertion JWT Authorization Grant)는 IETF에서 개발 중인 개방형 표준으로, 에이전트 제공자가 사용자의 신원을 보증하는 JWT(JSON Web Token) 형태의 어설션(assertion)입니다. 이를 통해 에이전트가 사용자 대신 앱에 로그인하는 번거로운 과정을 생략하고, 앱은 신뢰할 수 있는 에이전트 제공자의 보증을 통해 사용자를 식별할 수 있습니다.

**데모:** 발표자는 CLI 기반의 에이전트 하네스를 통해 Waypoint에서 여행 일정을 계획하는 과정을 시연합니다. 에이전트는 사용자(Sam Rivera)의 지시를 받아 Waypoint에 자동으로 가입하고(ID-JAG 사용), 저녁 식사 예약 및 여행 일정을 생성한 후 공유 링크를 제공합니다. 이 모든 과정은 사용자 개입 없이 에이전트가 수행합니다.

**3. 에이전트의 행동을 어떻게 제한하고 회수할 것인가?**
기업 여행과 같이 재정적 위험이 따르는 경우, 에이전트의 권한을 세밀하게 제어하는 것이 필수적입니다.

- **역할 기반 에이전트:**
    -   **읽기 전용 에이전트:** 사용자 및 자금에 대한 질문에 답변하지만, 자금을 이동하거나 예산/승인 규칙을 편집할 수 없습니다.
    -   **자금 에이전트:** 사용자 간에 자금을 이동할 수 있지만, 예산/승인 규칙을 편집할 수 없습니다.
- **권한 관리 메커니즘:**
    1.  사용자(Jordan)가 에이전트를 호출합니다.
    2.  앱 백엔드는 에이전트 토큰을 발급합니다. 이 토큰의 스코프는 사용자(Jordan)의 권한과 에이전트 블루프린트(에이전트의 최대 허용 권한)의 교집합으로 결정됩니다.
    3.  에이전트는 이 스코프가 적용된 에이전트 토큰으로 API를 호출합니다.

이 방식은 에이전트의 활동을 감사하고, 필요할 때 사용자 세션에 영향을 주지 않고 에이전트의 권한만 회수할 수 있도록 합니다.

**데모:** 발표자는 Waypoint에서 자금 에이전트를 시연합니다. Alex Morgan에게 $250의 자금 부족이 발생하자, Jordan(사용자)은 자금 에이전트에게 자금 재조정을 지시합니다. 에이전트는 팀 예비 자금에서 $70을 Alex에게 이동하지만, 예산이 부족하여 더 이상 이동할 수 없다고 보고합니다. 에이전트는 예산 변경 권한이 없으므로, Jordan이 직접 총 예산을 $1500에서 $2000로 늘립니다. 이후 에이전트는 나머지 $180을 Alex에게 성공적으로 재조정합니다. 이는 에이전트의 제한된 권한과 사용자의 최종 통제권을 보여줍니다.

## 실무 적용 포인트
- **`auth.md` 구현 고려:** 에이전트가 앱을 쉽게 발견하고 익명으로 기능을 탐색할 수 있도록 `auth.md` 파일을 앱에 호스팅하는 것을 고려해야 합니다. 이는 에이전트 중심의 제품 온보딩 및 성장을 위한 첫 단계입니다.
- **ID-JAG 표준 활용:** 에이전트가 사용자 대신 작업을 수행할 때, 사용자 계정과의 연결 및 신원 확인을 위해 ID-JAG와 같은 개방형 표준을 활용하여 안전하고 신뢰할 수 있는 인증 흐름을 구축해야 합니다.
- **에이전트 블루프린트 및 스코프 기반 권한 관리:** 에이전트에게 사용자 토큰을 직접 부여하는 대신, 에이전트 블루프린트를 정의하여 에이전트의 최대 권한을 설정하고, 실제 에이전트 토큰은 사용자 권한과 블루프린트의 교집합으로 스코프를 제한하여 발급해야 합니다. 이는 감사, 권한 회수, 보안을 강화하는 데 필수적입니다.
- **에이전트 활동 감사 및 회수 메커니즘:** 에이전트가 수행하는 모든 작업에 대한 감사 및 속성(attribution) 기록을 유지하고, 사용자 세션에 영향을 주지 않으면서 에이전트의 접근 권한을 개별적으로 회수할 수 있는 기능을 구현해야 합니다.
