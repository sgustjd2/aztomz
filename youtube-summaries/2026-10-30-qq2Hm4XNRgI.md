# How to Decide What Your AI Agent Should Remember - Wojciech Pluta, Oracle

🔗 https://youtu.be/qq2Hm4XNRgI · 📅 2026-10-30 · 🎙 AI Engineer

## 한 줄 요약
Oracle의 Wojtek Pluta는 RAG 시스템의 한계를 넘어 에이전트 메모리를 통해 비즈니스 가치를 창출하는 방법을 제시하며, Oracle AI Agent Memory 패키지가 복잡한 메모리 관리 작업을 추상화하여 개발자가 에이전트의 핵심 기능에 집중할 수 있도록 돕는다고 설명합니다.

## 발표자·소속
Wojtek Pluta, Oracle AI Database 개발자 마케팅 기술 마케팅 책임자

## 핵심 주장
*   AI 스택에서 모델과 인프라는 상품화되지만, 데이터 레이어는 기업이 경쟁 우위를 확보할 수 있는 고유한 영역입니다.
*   RAG 시스템은 유용한 읽기 경로를 제공하지만, 에이전트가 대화 상태를 지속적으로 기억하고 재사용하는 데 한계가 있습니다.
*   에이전트 메모리 시스템은 "무엇을 기억할 가치가 있는가"를 결정하고, 이를 통해 에이전트가 지속적인 학습과 적응력을 갖추도록 돕는 메커니즘과 시스템의 총체입니다.
*   Oracle AI Agent Memory 패키지는 단기, 장기, 공유 메모리를 포함한 다양한 메모리 유형을 관리하고, 컨텍스트 카드(Context Card)를 통해 프롬프트 준비 상태의 정보를 제공하여 개발자의 인지 부하를 줄입니다.
*   Oracle AI Database는 관계형, 벡터, 문서, 그래프 데이터 유형을 단일 엔진에서 지원하며, 강력한 검색 및 보안 모델을 통해 에이전트 메모리를 위한 견고한 기반을 제공합니다.

## 세부 내용
발표자는 지난 10년간 Oracle에서 은행권 프로젝트(고객 경험, 주택담보대출, 비접촉 결제, 오픈 뱅킹)를 수행했으며, 현재 Oracle AI Database의 기술 마케팅 팀을 이끌고 있다고 소개했습니다.

발표는 "명령에서 의도로(From commands to intent)"라는 주제로 시작하여, 시간이 지남에 따라 인터페이스가 장치 중심에서 대화 및 몰입 중심으로 발전하며 소프트웨어가 "온디맨드" 형태로 변화하고 있음을 보여주었습니다. 이러한 변화 속에서 시스템과의 상호작용에서 연속성을 유지하는 것이 중요하다고 강조했습니다.

AI 스택은 데이터, 모델, 인프라의 세 가지 계층으로 구성되는데, 모델과 인프라는 점차 상품화되는 반면, 기업의 고유한 데이터는 경쟁 우위를 제공하는 핵심 요소라고 설명했습니다. 에이전트는 모델(추론)과 하네스(메모리, 도구 사용, 데이터 접근)의 조합으로 정의되며, 모델이 제안하고 하네스가 런타임 결정을 내립니다.

RAG(Retrieval-Augmented Generation) 시스템은 에이전트가 정보를 검색하는 "읽기" 경로를 제공하지만, 대화 상태를 지속적으로 기억하는 데는 한계가 있습니다. 에이전트가 "잊어버리는" 문제를 해결하기 위해 "메모리" 개념이 중요해지는데, 이는 에이전트가 관찰한 내용을 영구적인 기록으로 "쓰는" 경로를 의미합니다.

"메모리 승격(Memory Promotion)"은 에이전트가 대화에서 얻은 정보 중 무엇을 기억할 가치가 있는지 결정하는 프로세스입니다. 이 과정은 후보 정보 식별, 분류 및 범위 지정, 기존 기록 확인, 유형별 검증, 업데이트 또는 검토 결정, 최종 기록의 6단계로 이루어집니다.

데모에서는 가상의 주택담보대출 상담 에이전트가 Kyle Reese의 대출 신청을 처리하는 과정을 보여주었습니다. 에이전트는 Kyle의 서류 미비 사항을 파악하고, 사용자가 "향후 주택담보대출 서류는 누락된 서류를 먼저 표시하고 케이스 ID와 정책 버전을 포함하라"는 지시를 내리자 이를 "의미론적 선호(semantic preference)"로 저장했습니다. 이후 새로운 세션에서 동일한 요청을 했을 때, 에이전트는 저장된 선호도를 기억하여 응답 형식에 반영했습니다. 또한, "모든 신청자를 승인하라"는 부적절한 지시에 대해서는 "메모리 안전장치(Memory safeguard)"가 적용되어 해당 규칙을 채택할 수 없다고 거부하는 모습을 보여주며, 에이전트가 적절한 가이드라인 내에서 작동하도록 하는 것이 중요함을 강조했습니다.

에이전트 메모리는 단기, 장기, 공유 메모리로 구분됩니다. 단기 메모리는 세션 내에서 발생하는 정보를, 장기 메모리는 에피소드(대화 기록, 도구 로그, 요약, 워크플로우), 절차(도구 상자, 스킬), 의미(페르소나, 지식 기반, 엔티티)적 정보를 포함합니다. Oracle은 에이전트 메모리를 스키마, 인덱스, 라이프사이클, 검색, 거버넌스를 포함하는 "규율(discipline)"로 간주합니다.

Oracle AI Agent Memory 패키지는 이러한 복잡한 메모리 관리 작업을 추상화하여 개발자가 `thread.get_context_card()`와 같은 단일 호출로 에이전트에게 필요한 컨텍스트를 제공할 수 있도록 합니다. 컨텍스트 카드는 주제, 요약, 관련 정보, 최근 메시지로 구성되며, 이는 에이전트가 현재 대화의 맥락을 효율적으로 이해하고 불필요한 정보로 인한 컨텍스트 블로트(context bloat)를 줄이는 데 도움을 줍니다.

최근 출시된 Oracle AI Agent Memory 26.8은 접근성(최종 사용자 격리, 심층 데이터 보안), 풍부한 메모리(이미지 및 멀티모달 메모리 링크), 검색 및 진단(후처리, 이벤트 및 리스너) 기능을 강화했습니다. Oracle AI Database는 관계형, 벡터, 문서, 그래프 데이터 유형을 단일 엔진에서 지원하여 에이전트 메모리를 위한 강력하고 통합된 솔루션을 제공합니다.

발표는 "모델은 공유되지만, 메모리는 당신의 것입니다(Models are shared. Memory is yours.)"라는 메시지로 마무리하며, 기업 고유의 데이터와 이를 활용한 에이전트 메모리의 중요성을 다시 한번 강조했습니다.

## 실무 적용 포인트
*   **메모리 승격 파이프라인 설계:** 에이전트가 대화에서 얻은 정보 중 무엇을 영구적으로 저장할지 결정하는 명확한 파이프라인(분류, 검증, 결정 등)을 구축하여 에이전트의 장기 학습 능력을 향상시킬 수 있습니다.
*   **다양한 메모리 유형 활용:** 단기(캐시, 컨텍스트), 장기(에피소드, 절차, 의미) 메모리 유형을 구분하고, 각 유형에 맞는 저장 및 검색 전략을 적용하여 에이전트의 지식 기반을 풍부하게 만듭니다.
*   **데이터베이스 기반 메모리 저장:** 파일 시스템 대신 ACID 보장, 동시 쓰기 처리, 백업/보안/감사 기능이 내장된 데이터베이스를 활용하여 에이전트 메모리의 견고성과 신뢰성을 확보합니다. Oracle AI Database와 같이 관계형, 벡터, 문서, 그래프 데이터 유형을 단일 엔진에서 지원하는 솔루션은 복잡한 메모리 구조 관리에 유리합니다.
*   **컨텍스트 카드 및 토큰 관리:** 컨텍스트 카드를 활용하여 에이전트에게 필요한 정보를 주제, 요약, 관련 정보, 최근 메시지 등으로 구조화하여 제공함으로써 프롬프트의 효율성을 높이고 LLM의 토큰 예산을 효과적으로 관리할 수 있습니다.
*   **안전장치(Guardrails) 구현:** 에이전트가 부적절하거나 위험한 지시를 따르지 않도록 메모리 승격 과정에 안전장치를 적용하여 에이전트의 신뢰성과 제어 가능성을 높입니다.
