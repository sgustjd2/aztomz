# Stop Giving Your AI Agents API Keys - Kim Maida, Keycard & Mason Egger, Temporal

🔗 https://youtu.be/YqJ4asgj1R8 · 📅 2026-11-05 · 🎙 AI Engineer

## 한 줄 요약
Keycard와 Temporal은 AI 에이전트의 신원 관리 및 워크플로우 내구성 보장을 통해 안전하고 신뢰할 수 있는 에이전트 시스템 구축을 지원합니다.

## 발표자·소속
-   **Kim Maida**: Keycard 소속.
-   **Mason Egger**: Temporal 소속, Solutions Architect.

## 핵심 주장
-   **에이전트 접근 문제 해결**: 기존 에이전트가 API 키를 공유하여 신원 불분명, 무제한 접근, 감사 추적 어려움 등의 문제를 겪는 것을 Keycard의 토큰 교환(Token Exchange) 표준을 통해 해결합니다.
-   **세분화된 접근 제어**: Keycard는 에이전트와 사용자 신원을 기반으로 정책을 평가하여 특정 도구 호출에 필요한 최소한의 권한만 부여하는 단기 토큰을 발행, 에이전트의 권한을 제한합니다.
-   **워크플로우 내구성 보장**: Temporal은 에이전트의 모델 호출과 도구 호출을 워크플로우로 관리하여, 에이전트 프로세스가 실패하더라도 마지막 성공 지점부터 상태를 재구성하고 실행을 재개하여 데이터 손실과 불필요한 컴퓨팅 비용을 방지합니다.
-   **민감 데이터 보안**: Temporal의 이벤트 기록은 에이전트 워크플로우의 모든 단계를 기록하지만, Keycard 토큰과 같은 민감한 자격 증명은 페이로드 인코더(Payload Encoder)를 통해 암호화되어 기록되지 않으므로 보안을 유지하면서 감사 추적을 가능하게 합니다.

## 세부 내용

발표는 AI 에이전트가 직면하는 신원 및 접근 제어 문제에 대한 설명으로 시작됩니다. 기존 방식에서는 에이전트가 공유된 API 키를 사용하므로, 누가 어떤 작업을 수행했는지 명확히 알기 어렵고, 에이전트가 API 키에 부여된 모든 권한에 무제한으로 접근할 수 있다는 문제가 있습니다. 또한, 자율적으로 작동하는 에이전트의 경우 인간의 개입을 통한 오류 방지가 어렵습니다.

Keycard는 OAuth 2.0 토큰 교환(RFC 8693) 표준을 활용하여 이 문제를 해결합니다.
1.  **사용자 인증**: 사용자는 먼저 구글, 옥타(Okta)와 같은 권한 부여 서버(Authorization Server)를 통해 인증하고, 에이전트에게 특정 범위(scopes) 내에서 자신의 접근 권한 일부를 위임(delegate)합니다.
2.  **사용자 토큰 발행**: 권한 부여 서버는 사용자 신원과 위임된 접근 수준을 포함하는 토큰을 발행합니다.
3.  **에이전트 실행 경로**: 사용자가 LLM(Large Language Model)을 통해 리소스와 상호작용하기 위해 프롬프트를 제출하면, 에이전트 런타임(예: Expense Desk 애플리케이션)이 이를 처리합니다.
4.  **에이전트 신원 확인**: 에이전트 런타임은 Keycard의 보안 토큰 서비스(STS)에 자체 클라이언트 자격 증명과 사용자 토큰(subject token)을 보내어 인증합니다.
5.  **정책 평가 및 토큰 발행**: Keycard는 에이전트 신원, 사용자 신원, 요청된 리소스 및 범위에 대한 정책을 평가하여, 해당 도구 호출에 필요한 최소한의 권한만 포함하는 단기 접근 토큰을 발행합니다. 이 토큰은 몇 분 내에 만료되며 저장되지 않습니다.
6.  **리소스 접근**: 에이전트의 MCP(Microservice Control Plane) 서버는 이 토큰을 베어러 자격 증명(bearer credential)으로 사용하여 다운스트림 리소스(예: Ledger API)에 접근합니다. MCP 서버 또한 Keycard에 토큰 교환을 요청하여 Ledger API에 접근할 수 있습니다. 각 단계에서 토큰은 검증 후 즉시 폐기됩니다.

Temporal은 에이전트 워크플로우의 내구성을 보장합니다.
1.  **워크플로우 및 활동**: 에이전트의 루프는 Temporal 워크플로우로, 각 도구 호출은 활동(Activity)으로 정의됩니다.
2.  **상태 유지 및 재개**: Temporal은 워크플로우의 상태를 이벤트 히스토리(Event History)에 기록합니다. 에이전트 프로세스가 충돌하거나 오프라인이 되더라도, Temporal은 마지막 성공 지점부터 상태를 재구성하고 실행을 재개하여 중복 호출이나 데이터 손실을 방지합니다.
3.  **민감 데이터 관리**: Temporal의 이벤트 히스토리는 워크플로우의 모든 단계를 기록하지만, Keycard 토큰과 같은 민감한 자격 증명은 직접 저장하지 않습니다. 대신, Keycard의 페이로드 인코더(Payload Encoder)를 사용하여 암호화된 형태로 기록하거나, 아예 기록에서 제외할 수 있습니다. 이는 감사 추적을 유지하면서도 민감 데이터의 노출을 막습니다.

데모에서는 다음을 보여주었습니다.
-   **신원 없는 에이전트**: Expense Desk 앱에서 공유 API 키를 사용할 때, 누가 어떤 작업을 수행했는지 감사 로그에 명확히 기록되지 않는 문제를 시연했습니다.
-   **에이전트 신원 부여**: Keycard 콘솔에서 Expense Desk 에이전트를 애플리케이션 및 리소스로 등록하여 에이전트에게 고유한 신원을 부여하는 과정을 보여주었습니다.
-   **사용자 위임**: 사용자가 Keycard를 통해 로그인하고 에이전트에게 접근 권한을 위임한 후, 에이전트가 사용자 대신 작업을 수행할 때 감사 로그에 사용자 신원이 명확히 기록되는 것을 확인했습니다.
-   **내구성 시연**: Temporal 워크플로우로 실행 중인 에이전트 프로세스를 강제로 중단시킨 후 재시작했을 때, 에이전트가 중단된 지점부터 작업을 재개하는 것을 보여주었습니다.

-   Temporal이 에이전트의 실패를 마치 "아무 일도 없었던 것처럼" 처리하고 실행을 재개하는 능력은 분산 시스템의 복잡성을 추상화하는 강력한 솔루션임을 보여줍니다.

## 실무 적용 포인트
-   **API 키 관리 개선**: 에이전트가 사용하는 API 키를 직접 코드에 하드코딩하거나 공유하는 대신, Keycard와 같은 토큰 교환 시스템을 도입하여 에이전트별/사용자별로 세분화된 권한을 부여하고 관리할 수 있습니다.
-   **감사 추적 강화**: 에이전트의 모든 활동에 대해 누가(사용자) 무엇을(에이전트) 했는지 명확한 감사 로그를 확보하여 보안 및 규정 준수 요구사항을 충족시킬 수 있습니다.
-   **에이전트 워크플로우 내구성 확보**: Temporal과 같은 내구성 있는 실행 프레임워크를 활용하여 장기 실행되는 에이전트 워크플로우가 시스템 장애나 네트워크 문제에도 불구하고 중단 없이 완료되도록 설계할 수 있습니다.
-   **민감 정보 보호**: 에이전트 워크플로우의 이벤트 히스토리에 민감한 자격 증명이나 데이터를 평문으로 저장하지 않고, 암호화하거나 기록에서 제외하는 정책을 적용하여 보안 침해 위험을 줄일 수 있습니다.
