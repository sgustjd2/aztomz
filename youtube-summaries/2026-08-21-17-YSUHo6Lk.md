# Agentic SDLC at Uber — Uday Kiran Medisetty & Adam Huda, Uber

🔗 https://youtu.be/17-YSUHo6Lk · 📅 2026-08-21 · 🎙 AI Engineer

## 한 줄 요약
Uber는 LLM 기반 에이전트를 활용하여 ML SDLC의 각 단계를 자동화하고 효율성을 높이는 'Agentic SDLC' 플랫폼을 구축하여 ML 엔지니어의 생산성을 향상시키고 모델 개발 및 배포 속도를 가속화합니다.

## 발표자·소속
*   Uday Kiran Medisetty, Uber
*   Adam Huda, Uber

## 핵심 주장
*   **ML SDLC의 복잡성 및 비효율성**: 기존 소프트웨어 개발 수명 주기(SDLC)는 데이터 및 모델 드리프트, 지속적인 모니터링 및 재학습이 필요한 ML 시스템의 특성에 적합하지 않으며, Uber의 방대한 ML 모델 및 엔지니어 규모에서 비효율성을 야기합니다.
*   **LLM 기반 에이전트 도입을 통한 자동화**: Uber는 LLM(대규모 언어 모델)을 기반으로 하는 에이전트(코드 에이전트, 데이터 에이전트, ML 에이전트, Ops 에이전트)를 개발하여 ML SDLC의 각 단계(코드 생성, 데이터 탐색, 모델 학습/배포, 운영)를 자동화하고 조율합니다.
*   **Agentic SDLC 플랫폼의 통합적 접근**: 이 플랫폼은 기존의 Uber ML 플랫폼(Michelangelo), 데이터 플랫폼, CI/CD 시스템 등 다양한 내부 도구와 통합되어, 에이전트들이 실제 작업을 수행할 수 있도록 하며, LLM은 이러한 에이전트들의 작업을 지시하고 조율하는 오케스트레이터 역할을 합니다.
*   **인간 중심의 자동화**: Agentic SDLC는 완전 자동화가 아닌 '인간-인-더-루프(Human-in-the-loop)' 방식을 채택하여, 에이전트가 제안한 작업(코드, 피처, 모델 등)을 ML 엔지니어가 검토하고 승인함으로써 안전성, 신뢰성 및 제어권을 유지하면서도 생산성을 극대화합니다.
*   **생산성 및 효율성 향상**: 이 시스템은 ML 엔지니어가 반복적이고 시간이 많이 소요되는 작업을 줄이고, 새로운 피처 추가, 모델 학습 및 배포와 같은 복잡한 워크플로우를 몇 분 안에 완료할 수 있도록 지원하여 전반적인 ML 개발 속도와 모델 품질을 향상시킵니다.

## 세부 내용
발표는 Uday Kiran Medisetty가 ML 시스템 개발의 고유한 도전 과제와 기존 SDLC의 한계를 설명하며 시작됩니다. Uber는 수천 개의 ML 모델과 수백 명의 ML 엔지니어를 보유하고 있으며, 데이터 드리프트, 모델 드리프트, 개념 드리프트와 같은 문제로 인해 ML 시스템의 SDLC가 매우 복잡하고 비효율적이라고 지적합니다. 이러한 문제를 해결하기 위해 Uber는 LLM 기반 에이전트를 활용하는 'Agentic SDLC' 개념을 도입했습니다.

Agentic SDLC의 핵심은 LLM을 오케스트레이터로 사용하여 ML SDLC의 다양한 단계에서 작업을 수행하는 전문 에이전트들을 조율하는 것입니다. 발표자는 이 시스템의 아키텍처를 보여주며, 중앙의 'Agentic SDLC Platform'이 코드 리포지토리, 데이터 플랫폼, ML 플랫폼, 모니터링, 알림, CI/CD 시스템 등 Uber의 기존 인프라와 상호작용한다고 설명합니다. 주요 에이전트 유형은 다음과 같습니다:
*   **Code Agent**: 코드 생성, 리팩토링, 코드 리뷰를 돕습니다.
*   **Data Agent**: 데이터 검색, 유효성 검사, 피처 엔지니어링을 수행합니다.
*   **ML Agent**: 모델 학습, 평가, 배포, 모니터링을 관리합니다.
*   **Ops Agent**: 인프라 프로비저닝, 배포, 스케일링을 담당합니다.

이후 Adam Huda가 Agentic SDLC 플랫폼의 실제 작동 방식을 보여주는 데모를 진행합니다. 데모 시나리오는 ML 엔지니어가 기존 모델에 새로운 피처를 추가하고, 이를 바탕으로 모델을 학습 및 배포하는 과정입니다.

1.  **피처 탐색 (Feature Discovery)**: 엔지니어는 "이 모델에 어떤 피처를 추가할 수 있을까?"와 같은 자연어 질문을 플랫폼에 입력합니다. Data Agent는 기존 데이터셋과 도메인 지식을 바탕으로 관련성 높은 피처 후보들을 제안합니다. 예를 들어, `user_past_trips`, `avg_trip_distance` 등을 제안합니다.
2.  **피처 엔지니어링 (Feature Engineering)**: 엔지니어는 제안된 피처 중 하나를 선택하거나, 새로운 피처(예: `avg_trip_distance_last_7_days`)를 생성하도록 요청합니다. Data Agent는 이 요청을 이해하고, 해당 피처를 생성하는 PySpark 코드를 자동으로 생성합니다. 이 코드는 엔지니어의 검토를 거쳐 승인되면 실제 데이터 파이프라인에 통합됩니다.
3.  **모델 학습 및 평가 (Model Training & Evaluation)**: 새로운 피처가 추가된 후, 엔지니어는 "새로운 피처로 모델을 학습하고 평가해줘"라고 요청합니다. ML Agent는 Uber의 ML 플랫폼(Michelangelo)을 활용하여 모델을 학습시키고, 기존 모델과 성능을 비교하는 보고서를 생성합니다. 이 보고서에는 AUC, 정밀도, 재현율 등의 지표가 포함되며, 엔지니어는 이를 바탕으로 새 모델의 배포 여부를 결정합니다.
4.  **모델 배포 (Model Deployment)**: 엔지니어가 새 모델 배포를 승인하면, Ops Agent는 필요한 인프라를 프로비저닝하고 모델을 프로덕션 환경에 배포합니다.
5.  **모니터링 설정 (Monitoring Setup)**: ML Agent는 배포된 모델의 성능 및 데이터 드리프트를 지속적으로 모니터링하기 위한 대시보드와 알림을 자동으로 설정합니다.

발표자들은 Agentic SDLC가 LLM 오케스트레이터, 다양한 도구(Uber의 내부 플랫폼), 그리고 안전하고 신뢰할 수 있는 운영을 위한 가드레일(Guardrails) 및 인간-인-더-루프(Human-in-the-loop) 원칙을 기반으로 한다고 강조합니다. LLM은 GPT-4와 Llama 2와 같은 모델을 활용하며, 에이전트가 제안한 모든 작업은 엔지니어의 명시적인 승인을 거쳐야 합니다. 이를 통해 생산성을 높이면서도 제어권을 유지합니다.

결론적으로 Agentic SDLC는 ML 엔지니어의 생산성을 크게 향상시키고, ML 모델의 개발 및 배포 주기를 단축하며, 전반적인 모델 품질과 신뢰성을 높이는 것을 목표로 합니다. 향후 계획으로는 더 많은 사용 사례로 확장하고, 에이전트의 추론 및 문제 해결 능력을 더욱 정교하게 만드는 것이 언급되었습니다.

## 실무 적용 포인트
*   **ML SDLC의 병목 지점 식별 및 자동화 대상 선정**: ML 모델 개발 및 운영 과정에서 반복적이고 시간이 많이 소요되는 작업(예: 피처 탐색, 코드 생성, 모델 평가 보고서 작성)을 식별하고, LLM 기반 에이전트 도입을 통해 자동화할 수 있는 영역을 우선적으로 고려합니다.
*   **기존 ML 플랫폼 및 도구와의 통합**: 새로운 에이전트 기반 시스템을 구축할 때, 기존에 사용 중인 데이터 플랫폼, ML 플랫폼, CI/CD 시스템 등 내부 도구들과의 원활한 통합을 최우선으로 고려하여 실제 작업을 수행할 수 있도록 합니다.
*   **'인간-인-더-루프' 설계**: 에이전트의 제안을 ML 엔지니어가 검토하고 승인하는 '인간-인-더-루프' 방식을 필수적으로 도입하여, 자동화의 효율성을 높이면서도 안전성, 신뢰성, 그리고 최종적인 제어권을 확보합니다.
*   **LLM 기반 에이전트의 역할 분담 및 전문화**: 코드, 데이터, ML, 운영 등 ML SDLC의 각 단계별로 전문화된 에이전트를 설계하여, 각 에이전트가 특정 도메인 지식과 도구를 활용해 효율적으로 작업을 수행하도록 합니다. 이는 LLM 오케스트레이터의 부담을 줄이고 전체 시스템의 견고성을 높입니다.
