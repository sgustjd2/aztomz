# Taming the AI Hardware Cambrian Explosion — Abdul Dakkak, Modular

Abdul Dakkak, Modular

## 핵심 주장
- **AI 하드웨어의 파편화와 소프트웨어의 확장성 문제 해결**: 현재 AI 컴퓨팅 자원은 부족하고, NVIDIA, Intel, ARM, AMD, Apple, AWS 등 다양한 벤더의 AI 하드웨어가 폭발적으로 증가하고 있습니다. 그러나 기존 소프트웨어 스택은 이러한 하드웨어 다양성을 효율적으로 프로그래밍하고 확장하는 데 어려움을 겪고 있습니다.
- **Mojo를 통한 이식성, 성능, 프로그래밍 용이성 제공**: Modular는 Python과 유사한 시스템 프로그래밍 언어인 Mojo를 개발하여, 개발자들이 CUDA나 ROCm과 같은 특정 벤더 기술에 묶이지 않고 CPU, GPU 및 기타 가속기에서 최고 수준의 성능을 발휘하는 이식성 높은 커널을 작성할 수 있도록 합니다.
- **MAX 프레임워크로 GenAI 모델 개발 및 배포 간소화**: MAX 프레임워크는 PyTorch에 익숙한 AI 개발자를 위해 직관적인 Python API를 제공하며, KV 캐싱, 연속 배치 처리 등을 지원하는 CLI를 통해 GenAI 모델의 서빙을 최적화합니다. 또한, 최첨단 그래프 컴파일러와 Mojo 기반 커널을 활용하여 모델 최적화 및 배포를 단순화합니다.
- **Modular Cloud를 통한 풀 스택 제어 및 비용 효율성**: Modular Cloud는 Mojo와 MAX를 프로덕션 GenAI 엔드포인트로 전환하는 성능 중심의 이종 제어 플레인입니다. 이를 통해 사용자는 온프레미스 또는 클라우드 환경에서 모델을 배포하고 관리하며, 최적화된 성능과 비용 효율성을 달성할 수 있습니다.

## 세부 내용

발표는 AI 컴퓨팅 환경의 현황과 Modular의 솔루션을 소개하는 것으로 시작됩니다. 현재 컴퓨팅 자원은 심각하게 부족하며, NVIDIA, Intel, ARM, Qualcomm, AMD, Groq, Meta, Google, Microsoft, Apple, AWS 등 다양한 벤더에서 AI 하드웨어가 폭발적으로 증가하고 있습니다. 그러나 이러한 하드웨어의 다양성은 소프트웨어 스택의 복잡성을 가중시켜 프로그래밍 및 확장을 어렵게 만듭니다. PyTorch와 같은 기존 프레임워크는 오늘날의 추론 환경에 맞게 설계되지 않아 vLLM, SGLang, TRT-LLM, Llama.cpp와 같은 도구들이 그 간극을 메우고 있지만, 이는 PyTorch의 복잡성과 특정 벤더 도구에 대한 의존성을 심화시킵니다.

Modular는 이러한 문제를 해결하기 위해 "첫 번째 원칙"부터 플랫폼을 재구축하여 이식성, 성능, 프로그래밍 용이성을 갖춘 통합 컴퓨팅 레이어를 제공합니다. Modular 플랫폼은 세 가지 주요 구성 요소로 이루어져 있습니다.

1.  **Mojo (커널)**: Python과 유사한 시스템 프로그래밍 언어로, 이종 AI 하드웨어(CPU, GPU, 기타 가속기)에서 최고 수준의 성능을 발휘하는 새로운 AI 알고리즘을 작성할 수 있습니다. Mojo는 CLI 툴체인과 VS Code를 지원하며, 강력한 Python 및 C 언어 상호 운용성을 제공합니다. Mojo는 CUDA나 ROCm과 같은 기존 기술이 성능에 집중하는 반면, OpenCL이 이식성에 집중하는 것과 달리, 이식성, 성능, 사용 편의성 세 가지를 모두 만족하는 "스위트 스팟"을 목표로 합니다. 발표자는 Mojo가 CUDA와 성능 면에서 경쟁하며, Python 개발자들이 90% 이상을 바로 이해할 수 있다고 강조합니다. Mojo 1.0(베타)은 API 안정화를 거쳐 몇 달 내에 오픈 소스화될 예정입니다.

2.  **MAX (서빙)**: Mojo 위에 구축된 AI 추론 엔진으로, 텍스트, 이미지, 비디오, 음성 모델을 NVIDIA 및 AMD GPU에서 단일 통합 프레임워크로 최고 성능으로 서빙합니다. MAX는 70만 줄 이상의 커널 코드를 오픈 소스화했으며, 행렬 곱셈에서 cuBLAS/hipBLAS보다 빠르고, FlashAttention 4보다 빠른 어텐션 커널을 포함하여 최첨단 성능을 제공합니다. MAX 프레임워크는 PyTorch와 유사한 직관적인 Python API를 통해 GenAI 모델을 구축할 수 있도록 하며, 그래프 컴파일러와 Mojo 기반 커널 퓨전을 통해 최적화를 수행합니다. 또한, 다중 GPU 및 다중 노드 시스템, 심지어 이종 하드웨어(예: 전처리(prefill)는 하드웨어 X에서, 디코딩은 하드웨어 Y에서)에서도 분산 그래프를 기본적으로 지원합니다.

3.  **Modular Cloud (클라우드)**: MAX와 Mojo를 프로덕션 GenAI 엔드포인트로 전환하는 성능 중심의 이종 제어 플레인입니다. 공유 엔드포인트(고성능 추론, 인프라 관리 불필요, 토큰당 과금), 전용 엔드포인트(NVIDIA 및 AMD GPU에 최적화된 배포, 분당 과금), 맞춤형 모델(자체 모델 배포)을 제공합니다. 사용자는 웹사이트를 통해 모델을 선택하고 API 키를 받아 HTTP 요청으로 실행할 수 있으며, 온프레미스 또는 Modular 클라우드에 배포할 수 있습니다. Modular Cloud Lab을 통해 다양한 파라미터를 실험하고 최적의 성능 지점을 찾을 수 있습니다.

**성능 벤치마크**:
- **Kimi-K2.5 on MAX**: vLLM 대비 P50 TTFT(Time To First Token)에서 5.5배 빠르고, GPU당 처리량(TPM)에서 1.5배 빠릅니다 (NVIDIA B200 기준).
- **FLUX.2 on MAX**: PyTorch Diffusers(torch.compile) 대비 NVIDIA H200에서 6.9배 빠르고, AMD MI300X에서 3.8배 빠릅니다 (1024x1024 텍스트-이미지 생성 기준). AMD GPU는 NVIDIA 대비 30% 저렴한 비용 이점을 제공합니다.
- **API 이미지 생성 시간**: FLUX.2 데모에서 이미지는 0.3초 이내에 생성됩니다.
- **Gemma 4 31B Time to First Token**: Modular는 0.53초로, Lightning AI (0.81s), Google AI Studio (1.13s), Sambanova (2.78s) 등 다른 모든 경쟁사보다 훨씬 빠릅니다.

Modular는 이러한 기술을 통해 비용 절감, 유연성 증대, 이식성 향상 등 다양한 이점을 제공하며, 지속적인 최적화를 통해 성능을 개선하고 있다고 밝힙니다.
