# Your PR Says the Tests Passed. Prove It. - Stephen Chin & Cassandra Chin

🔗 https://youtu.be/gbeuC0ud1p4 · 📅 2026-11-10 · 🎙 AI Engineer

## 한 줄 요약
AI 에이전트가 생성하는 풀 리퀘스트(PR)의 품질을 높이고 비용을 절감하기 위해, 에이전트의 작업 맥락을 그래프 데이터베이스에 저장하여 PR 설명을 자동 생성하고 검토 과정을 효율화하는 Tracetoon 및 Relate 도구를 소개합니다.

## 발표자·소속
- Stephen Chin: [neo4j]
- Cassandra Chin: Tracetoon 프레임워크 개발자

## 핵심 주장
- **AI 에이전트가 생성한 PR의 품질 문제:** AI 에이전트가 작성한 PR은 코드 자체의 문제가 아니라 부정확하거나 불완전한 설명으로 인해 거부되는 경우가 많습니다. 이는 에이전트가 작업 맥락을 제대로 이해하고 전달하지 못하기 때문입니다.
- **Tracetoon을 통한 PR 설명 개선:** Tracetoon은 에이전트의 세션 로그, 결정, 검사 등 작업 맥락을 읽어 PR 설명을 자동으로 생성하여 검토자가 변경 사항의 '이유', '예외', '통과 여부' 등을 명확하게 이해할 수 있도록 돕습니다.
- **Relate를 활용한 증거 그래프 구축:** Relate는 애플리케이션 내부에 내장되는 Rust 기반의 오픈소스 그래프 데이터베이스로, 에이전트의 작업 과정에서 발생하는 모든 증거(요청, 편집, 실행 기록, 검사 등)와 그 관계를 연결하여 '증거 그래프'를 구축합니다.
- **비용 절감 및 효율성 증대:** 증거 그래프를 통해 에이전트가 더 정확한 PR 설명을 작성하고, 검토자는 필요한 정보만 담긴 간결한 브리프를 받아볼 수 있어 전체 워크플로우의 토큰 비용을 최대 41% 절감하고 PR 품질 점수를 향상시킵니다.

## 세부 내용
발표는 AI 에이전트가 생성하는 풀 리퀘스트(PR)의 품질 문제에 대한 Cassandra Chin의 설명으로 시작됩니다. 많은 PR이 코드 자체의 문제보다는 부정확하거나 불완전한 설명 때문에 거부되며, 이는 AI 에이전트가 작업 맥락을 제대로 전달하지 못하기 때문입니다. Cassandra는 이러한 문제를 개선하기 위해 Tracetoon을 개발했다고 밝힙니다.

Stephen Chin은 "AI 엔지니어" 후디를 얻기 위해 PR 품질 개선 사례를 발표하려는 Alex라는 가상의 인물을 소개하며 이야기를 풀어갑니다. Alex의 회사인 "토큰 팩토리"에는 재무 담당(오소리), 증거 담당(토끼), 검토 담당(Mira) 등의 에이전트들이 있습니다. Alex가 제출한 PR은 Mira의 까다로운 검토를 통과하지 못하고, Mira는 변경 사항의 이유, 검사 내용 등 상세한 설명을 요구합니다. 실제 Tracetoon PR #8 사례를 통해 Mira가 요구하는 구체적인 정보(미리보기 링크, 커밋 속성, 이전 작업 증명 등)가 PR에 포함되어야 함을 보여줍니다.

반복되는 PR 거부는 토큰 비용을 증가시키고, 재무 담당은 이에 불만을 표출합니다. Cassandra는 자신이 Tracetoon을 개발하면서 많은 토큰을 사용했음을 "토큰 억만장자 카드"를 보여주며 유머러스하게 언급합니다. Alex와 증거 담당 Pip은 밤늦게까지 로그를 뒤져 증거를 재구성하려 하지만, 에이전트가 맥락을 압축하여 부정확해지는 문제가 발생합니다.

이때 Pip이 친구를 소개하는데, 바로 Relate라는 임베디드 그래프 데이터베이스입니다. Relate는 Rust로 작성된 오픈소스 그래프 데이터베이스로, 애플리케이션 내에서 로컬 및 오프라인으로 실행되며 별도의 서버가 필요 없습니다. Relate는 에이전트의 요청, 편집, 실행 기록, 검사 등 모든 작업의 증거와 그 관계를 연결하여 '증거 그래프'를 구축합니다. 이를 통해 Tracetoon은 전체 아카이브를 매번 로드할 필요 없이, 특정 변경 사항과 관련된 증거 패킷만 가져와서 활용할 수 있습니다.

Relate를 통해 Tracetoon은 PR 설명을 위한 '브리프'를 생성합니다. 이 브리프는 변경 사항의 이유, 코드, 검사 내용을 연결하고 속성을 부여하여 에이전트가 더 정확한 드래프트를 작성하도록 돕습니다. 이 과정에서 더 높은 품질의 라이터(예: Sonnet 또는 Tera 클래스 모델)를 사용하여 초안을 작성하고, 비용 효율적인 검토자(예: Haiku 모델)를 활용하여 정확성과 완전성을 검토합니다. 이러한 '그래프 경로' 방식은 전체 워크플로우를 최적화하여 인간 검토자의 승인을 더 쉽게 얻을 수 있도록 합니다.

실제 테스트 결과, Tracetoon과 Relate를 함께 사용했을 때 PR 품질 점수가 Claude 모델의 경우 +2.0, Codex 모델의 경우 +4.4 향상되었습니다. 또한, PR당 평균 드래프팅 비용이 Claude의 경우 38%, Codex의 경우 41% 절감되는 효과를 보였습니다. Cassandra는 그래프 도입 후 비용이 거의 절반으로 줄어든 것에 놀라움을 표하며, 에이전트가 데이터 분석 및 큐레이션에 약하다는 점을 보완하는 Relate의 중요성을 강조합니다.

결과적으로 Alex는 성공적인 발표를 통해 "AI 엔지니어" 후디를 얻고, 재무 담당도 비용 절감에 만족합니다. 발표는 Tracetoon과 Relate를 통해 PR을 더 신뢰할 수 있고, 검토하기 쉽게 만들 수 있으며, 이는 에이전트에게 맥락을 제공하고 검토자에게 유용한 스토리를 전달함으로써 가능하다고 결론짓습니다.

## 인상적인 대목
- Cassandra Chin이 "토큰 억만장자 카드"를 보여주며 Tracetoon 개발에 많은 토큰을 썼다고 말하는 대목. 이는 AI 개발의 현실적인 비용 문제를 유머러스하게 표현합니다.
- "A confident explanation can still mislead the evidence." (자신감 있는 설명도 여전히 증거를 오도할 수 있다.)라는 문장은 AI 에이전트의 설명이 항상 정확한 것은 아니며, 근거 기반의 검증이 필수적임을 시사합니다.
- Stephen Chin이 "Agents are not that good at doing the data analysis, at doing all the evaluation and the curation." (에이전트는 데이터 분석, 모든 평가 및 큐레이션을 그렇게 잘하지 못합니다.)라고 언급하며, AI의 한계와 인간의 역할이 여전히 중요함을 강조합니다.

## 실무 적용 포인트
- **AI 에이전트의 작업 맥락 기록:** AI 에이전트를 활용하여 코드를 생성하거나 PR을 작성할 때, 단순히 최종 결과물만 제출하는 것이 아니라 에이전트의 의사결정 과정, 실행된 명령어, 테스트 결과 등 모든 작업 맥락을 기록하는 시스템을 구축해야 합니다.
- **그래프 데이터베이스 활용:** Relate와 같은 임베디드 그래프 데이터베이스를 사용하여 에이전트의 작업 맥락 데이터를 연결하고 관리하면, PR 검토 시 필요한 정보를 효율적으로 검색하고 이해할 수 있습니다. 이는 특히 복잡한 변경 사항이나 여러 에이전트가 협업하는 프로젝트에서 유용합니다.
- **PR 설명 자동화 및 표준화:** Tracetoon과 같은 도구를 활용하여 에이전트의 작업 맥락을 기반으로 PR 설명을 자동 생성하고 표준화하면, 검토자가 변경 사항의 '이유', '예외', '통과된 검사' 등을 명확하게 파악할 수 있어 검토 시간을 단축하고 품질을 높일 수 있습니다.
- **비용 효율적인 검토 모델 도입:** 고품질의 AI 모델(예: Sonnet, Tera)을 사용하여 PR 초안을 작성하고, 비용이 저렴한 AI 모델(예: Haiku)을 활용하여 기계적인 검토 및 교차 확인 작업을 수행하는 하이브리드 검토 시스템을 구축하여 전체 워크플로우의 토큰 비용을 최적화할 수 있습니다.
