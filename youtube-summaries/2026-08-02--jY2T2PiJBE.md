# MCP Apps: Extending the Frontier — Ido Salomon & Liad Yosef

🔗 https://youtu.be/-jY2T2PiJBE · 📅 2026-08-02 · 🎙 AI Engineer

## 한 줄 요약
MCP 앱스는 대화형 AI 에이전트가 텍스트 대신 풍부하고 상호작작용적인 UI 컴포넌트를 직접 챗에 렌더링하고 호스트와 통신할 수 있도록 하는 개방형 프로토콜로, 새로운 웹 상호작용 방식과 앱 배포 표면을 제시합니다.

## 발표자·소속
*   **Ido Salomon**: MCP-UI 크리에이터, MCP Apps 공동 크리에이터 및 관리자, AgentCraft 크리에이터.
*   **Liad Yosef**: MCP-UI 협력자, MCP Apps 공동 크리에이터 및 관리자, Ora 공동 창립자.

## 핵심 주장
*   **텍스트 기반 상호작용의 한계 극복**: 기존 챗 클라이언트의 텍스트 위주 정보 전달 방식은 비효율적이며, 앱의 브랜드 아이덴티티와 UX를 저해합니다. MCP 앱스는 앱이 자체 UI를 챗에 직접 전송하여 이 문제를 해결합니다.
*   **MCP 앱스의 개방형 프로토콜 표준화**: MCP 앱스는 MCP(Model Context Protocol) 위에서 상호작용적인 앱을 위한 개방형 프로토콜로, UI 전송 및 UI와 호스트 간의 통신을 표준화하여 모든 앱이 챗 환경에서 풍부한 사용자 경험을 제공할 수 있도록 합니다.
*   **빠른 생태계 채택 및 확장성**: 2026년 1월 공식 MCP 확장으로 출시된 MCP 앱스는 Anthropic의 Claude, OpenAI의 ChatGPT, Microsoft Copilot, VS Code, Slack 등 주요 AI 에이전트 및 개발 도구에 빠르게 채택되었으며, 다양한 기업들이 이를 활용하고 있습니다.
*   **새로운 웹 상호작용 및 앱 배포 모델 제시**: MCP 앱스는 사용자가 여러 탭을 오가며 서비스를 이용하는 대신, 개인 비서가 여러 서비스의 UI 구성 요소를 조합하여 사용자에게 맞춤형 경험을 제공하는 '에이전트 웹' 시대를 열어갑니다.
*   **"한 번 작성, 어디서든 실행" 원칙**: MCP 앱스는 한 번 개발하면 다양한 MCP 지원 호스트(챗봇, IDE 등)에서 실행될 수 있어, 개발 효율성을 높이고 앱의 도달 범위를 획기적으로 확장합니다.

## 세부 내용

발표는 텍스트 기반의 챗 상호작용이 정보를 전달하는 데 있어 비효율적이라는 문제 제기에서 시작됩니다. 발표자들은 긴 텍스트 응답이 사용자 경험(UX)을 저해하며, 기업들이 자신들의 브랜드와 데이터를 텍스트로만 표현하는 것을 원치 않는다고 지적합니다. 이들은 "만약 세상의 모든 앱이 자체 UI를 챗으로 보낼 수 있다면 어떨까?"라는 질문을 던지며 MCP 앱스의 필요성을 강조합니다.

**MCP 앱스 소개 및 작동 방식:**
MCP 앱스는 MCP(Model Context Protocol) 위에서 상호작용적인 앱을 위한 개방형 프로토콜입니다. 이는 UI 전송과 UI-호스트 간 통신을 표준화합니다.
*   **UI 전송**: 기존 방식에서는 사용자가 챗봇에 질문하면 서버가 텍스트 응답을 반환했습니다. MCP 앱스를 사용하면 서버는 HTML 형태의 리소스(예: `text/html;profile=mcp-app` 마임 타입의 `<div>Hello World!</div>`)를 반환할 수 있습니다. 호스트는 이 HTML을 샌드박스 내에서 상호작용적인 애플리케이션으로 렌더링합니다.
*   **통신**: UI는 사용자 상호작용(클릭 등) 시 호스트에게 액션을 보냅니다. 이 액션은 사용자 의도 또는 UI에서 호스트로의 지시를 나타내며, 호스트는 이 액션을 기반으로 적절한 도구를 호출하거나 추가적인 작업을 수행합니다. 예를 들어, Spotify 앱에서 사용자가 '즐겨찾기' 버튼을 클릭하면, 앱은 `{tool: add_favorite, params: {songId}}`와 같은 메시지를 호스트에 보내고, 호스트는 이를 처리합니다.

**데모 시연:**
Claude를 이용한 데모에서는 사용자가 "6단계 퍼널에 대한 인사이트는 무엇인가요?"라고 질문합니다.
1.  **텍스트 응답**: 처음에는 PostHog 통합을 통해 텍스트 기반의 퍼널 분석 결과가 나옵니다. 이는 사실적이지만 한눈에 파악하기 어렵습니다.
2.  **시각화**: 사용자가 "보여줘"라고 요청하자, Claude는 PostHog에서 제공하는 인터랙티브한 퍼널 시각화(막대 차트)를 렌더링합니다. 이 차트는 각 단계의 전환율과 이탈률을 시각적으로 보여줍니다.
3.  **상호작용**: 사용자가 차트의 특정 단계("payment_submitted")를 클릭하자, Claude는 해당 단계에 대한 상세한 지표와 주요 관찰 내용을 제공하며, 사용자는 이를 통해 특정 문제점을 깊이 파고들 수 있습니다.
4.  **생성형 UI**: 사용자가 "퍼널을 시각적으로 설명해줘"라고 요청하자, Claude는 퍼널의 개념을 설명하는 생성형 UI 다이어그램을 스트리밍하여 렌더링합니다.

**MCP-UI 아키텍처:**
1.  사용자가 모델에 프롬프트를 보냅니다.
2.  모델이 MCP 서버에 툴 콜을 보냅니다.
3.  MCP 서버는 `ui://` 스키마를 가진 리소스(HTML 포함)를 반환합니다.
4.  모델은 이 리소스를 호스트에 전달합니다.
5.  호스트는 클라이언트 SDK를 사용하여 샌드박스 내에서 리소스를 렌더링합니다.
6.  사용자가 렌더링된 UI와 상호작용(클릭)합니다.
7.  클라이언트 SDK는 이벤트를 호스트에 보냅니다.
8.  호스트는 이벤트를 모델에 전달합니다.
9.  모델은 이벤트를 기반으로 추가적인 툴 콜을 트리거하여 에이전트 플로우를 완료합니다.

**새로운 웹의 비전:**
발표자들은 MCP 앱스가 '새로운 웹'을 가져올 것이라고 말합니다. 이는 사용자가 여러 웹사이트(Google Calendar, Amazon, Booking.com 등)를 직접 방문하여 정보를 입력하고 상호작용하는 대신, 개인 비서(AI 에이전트)가 이 모든 서비스를 통합하여 사용자에게 필요한 UI 조각(atoms)을 가져와 맞춤형으로 구성하고 상호작용하는 방식입니다. 이를 통해 애플리케이션이 더 이상 사용자 여정을 독점하지 않고, 모든 상호작용이 챗을 통해 이루어지며 감사 가능성(auditability)이 확보됩니다.

**MCP 앱스의 발전과 미래:**
*   **타임라인**: 2025년 5월 MCP-UI가 생성되었고, 2026년 1월 MCP 앱스가 공식 MCP 확장으로 출시되었으며, 2026년 1분기에는 빠른 생태계 채택이 이루어졌습니다. 2026년에는 UI를 위한 글로벌 표준이 될 것으로 예상됩니다.
*   **지속적인 발전**: 샌드박스 기능, 용어, 테마, 모바일 SDK, UI 종료 요청, React 렌더러, 앱을 위한 도구, 뷰의 고유한 출처, 스킬 및 문서, 인라인 스크립트 제한, 앱 샘플링, 모델 및 뷰 상태, 컨텍스트 업데이트 메커니즘, 앱 이식성 등 다양한 측면에서 사양이 계속 발전하고 있습니다.
*   **재사용 가능한 뷰**: Autodesk 앱 데모를 통해 무거운 3D 렌더링 앱의 경우, UI를 매번 다시 렌더링하는 대신 식별자를 전달하여 동일한 뷰를 업데이트하는 방식이 개발 중임을 보여줍니다.
*   **앱 도구(WebMCP-like)**: 사용자가 앱 내에서 특정 작업을 수행하면 (예: Spotify에서 노래 추가), 앱이 호스트에 `notify` 메시지를 보내고, 호스트는 이를 기반으로 사용자에게 추가적인 프롬프트나 도구 호출을 제안할 수 있습니다.
*   **생성형 UI 스펙트럼**: MCP 앱스는 미리 정의된 UI부터 선언적 UI(A2UI, JSON 렌더)를 거쳐 완전히 생성형 UI에 이르는 스펙트럼을 지원합니다. Claude의 "imagine" 기능도 MCP 앱스를 기반으로 합니다.
*   **상호운용성**: MCP 앱스는 A2UI, AG-UI, WebMCP 등 다른 UI 프로토콜과의 상호운용성을 목표로 합니다. Google for Developers는 A2UI와 MCP 앱스를 결합하여 선언적이고 커스텀 에이전트 UI의 장점을 모두 활용하는 가이드를 발표했습니다.
*   **범용성**: MCP 앱스는 한 번 만들면 LibreChat(오픈소스 MCP 지원 클라이언트)과 ChatGPT 모두에서 동일한 코드베이스로 실행될 수 있음을 계산기 앱 데모로 보여줍니다.
*   **새로운 앱 배포 표면**: ChatGPT가 몇 달 만에 8억 명의 주간 사용자를 확보한 것은 인터넷이 13년 걸린 성과이며, 이는 Apple App Store 출시 당시 TAM(Total Addressable Market)의 170배가 넘는 수치입니다. MCP 앱스는 이러한 거대한 챗 플랫폼을 새로운 앱 배포 표면으로 활용할 수 있게 합니다.

## 실무 적용 포인트
*   **MCP 앱스 SDK 활용**: `ext-apps` GitHub 저장소(github.com/modelcontextprotocol/ext-apps)를 방문하여 공식 SDK를 사용하면, 한 번 작성한 UI 컴포넌트를 다양한 MCP 지원 호스트(챗봇, IDE 등)에서 실행할 수 있습니다.
*   **UI 컴포넌트의 모듈화**: 기존 앱의 UI를 텍스트로만 제공하는 대신, 재사용 가능한 작은 UI 컴포넌트(아톰) 형태로 분리하여 MCP 앱스 프로토콜에 맞춰 개발하면, AI 에이전트가 이를 조합하여 사용자에게 맞춤형 경험을 제공할 수 있습니다.
*   **상호작용 설계의 변화**: 앱이 사용자 여정을 직접 제어하는 대신, `notify`, `tool`, `prompt`와 같은 액션 타입을 활용하여 호스트(AI 에이전트)에게 사용자 의도를 전달하고, 호스트가 다음 단계를 결정하도록 하는 새로운 상호작용 마인셋을 채택해야 합니다.
*   **생성형 UI 통합 고려**: MCP 앱스는 미리 정의된 UI뿐만 아니라 선언적 UI 및 생성형 UI도 지원하므로, AI 모델이 동적으로 UI를 생성하는 기능을 MCP 앱스 프로토콜과 연동하여 더욱 유연하고 지능적인 사용자 경험을 제공할 수 있습니다.
