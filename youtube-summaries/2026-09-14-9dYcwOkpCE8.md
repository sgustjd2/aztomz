# How We Solved Agent Building — Andrew Qu, Vercel

## 발표자·소속

## 핵심 주장
- **AI 에이전트 구축은 복잡하며 신뢰성, 관측 가능성, 확장성 측면에서 어려움이 있습니다.** 발표자는 AI 에이전트가 단순히 프롬프팅을 넘어 추론, 행동, 학습이 가능한 복잡한 시스템이며, LLM의 확률적 특성으로 인한 신뢰성 문제, 블랙박스 같은 관측 가능성 부족, 그리고 확장성 문제를 지적합니다.
- **웹은 AI 에이전트 구축을 위한 최적의 플랫폼입니다.** Vercel은 React, Next.js와 같은 기존 웹 개발 도구와 패러다임을 활용하여 AI 에이전트를 웹 애플리케이션처럼 구축함으로써, 개발자들이 익숙한 환경에서 신뢰성 있고 관측 가능하며 확장 가능한 에이전트를 만들 수 있다고 주장합니다.
- **AI SDK는 스트리밍 UI와 함수 호출을 통해 LLM 통합을 간소화합니다.** 이 오픈소스 라이브러리는 LLM의 응답을 실시간으로 스트리밍하고, LLM이 외부 도구 및 API와 상호작용할 수 있도록 함수 호출 기능을 제공하여, 기본적인 AI 애플리케이션 개발의 진입 장벽을 낮춥니다.
- **Vercel AI Agent SDK는 React Server Components를 활용하여 복잡한 에이전트의 상태 관리, 계획, 추론 및 동적 UI 렌더링을 가능하게 합니다.** 단순한 함수 호출을 넘어 에이전트가 복잡한 작업을 계획하고, 기억하며, 실시간으로 인터랙티브한 UI를 생성하여 사용자 경험을 향상시키는 고급 에이전트 구축을 지원합니다.

## 세부 내용
발표는 AI 에이전트 구축의 어려움으로 시작합니다. 발표자는 AI 에이전트가 단순한 프롬프팅을 넘어 추론, 행동, 학습이 가능한 복잡한 시스템이며, LLM의 확률적 특성으로 인한 신뢰성 문제, 블랙박스 같은 관측 가능성 부족, 그리고 확장성 문제를 지적합니다.

Vercel은 이러한 문제에 대한 해결책으로 웹을 AI 에이전트 구축의 최적 플랫폼으로 제시합니다. React, Next.js, Vercel 플랫폼과 같은 기존 웹 개발 도구와 패러다임을 활용하여 AI 에이전트를 웹 애플리케이션처럼 다루는 접근 방식을 소개합니다.

첫 번째 핵심 도구는 **AI SDK**입니다. 이는 React 및 Next.js로 AI 애플리케이션을 구축하기 위한 오픈소스 라이브러리 세트로, 스트리밍 UI와 함수 호출에 중점을 둡니다. 발표자는 간단한 챗봇 데모를 통해 `useChat` 훅을 사용하여 메시지를 관리하고, `streamText` 함수로 LLM 응답을 실시간으로 스트리밍하는 과정을 보여줍니다. 백엔드에서는 `@ai-sdk/openai`의 `createOpenAI`와 `model.streamText`를 사용하여 LLM과 통신합니다.

이어서 발표자는 에이전트의 진정한 힘은 "실세계와 상호작용하는 능력"에서 나온다고 강조하며 **함수 호출(Function Calling)** 기능을 소개합니다. 샌프란시스코 날씨를 묻는 예시를 통해 LLM이 `getWeather` 함수를 호출하고, 그 결과를 바탕으로 응답을 생성하는 과정을 설명합니다. 데모에서는 `useChat` 훅에 `tools` 옵션을 추가하여 `getWeather` 도구를 정의하고, Zod 라이브러리를 사용하여 `location` 파라미터의 스키마를 검증하는 코드를 보여줍니다. LLM은 정의된 도구 중 적절한 것을 선택하여 호출하고, 애플리케이션은 해당 도구의 `call` 함수를 실행하여 실제 API 호출을 수행합니다.

마지막으로, 발표자는 함수 호출이 에이전트의 빌딩 블록이지만, 더 복잡한 에이전트에는 상태 관리, 메모리, 계획, 추론 기능이 필요하다고 말하며 **Vercel AI Agent SDK**를 소개합니다. 이 SDK는 Next.js와 React Server Components(RSC)를 활용하여 복잡한 AI 에이전트를 구축하기 위한 프레임워크입니다. 여행 계획 에이전트 데모를 통해 사용자가 "파리로 3일 여행 계획"을 요청하면, 에이전트가 다단계 계획을 세우고(예: 에펠탑, 루브르 박물관), 각 단계에 대한 동적인 UI 컴포넌트(예: 지도, 예약 위젯)를 실시간으로 렌더링하는 것을 보여줍니다. `createAI` 함수와 `actions` 객체 내의 `render` 함수를 사용하여 JSX를 반환함으로써, 에이전트가 단순히 텍스트를 제공하는 것을 넘어 인터랙티브한 사용자 경험을 제공할 수 있음을 시연합니다. 이는 에이전트가 "생각하고(think)" "행동하며(act)" UI를 통해 이를 표현하는 방식입니다.

발표는 웹이 에이전트 구축을 위한 최고의 플랫폼이며, AI SDK가 스트리밍 UI와 함수 호출을, Vercel AI Agent SDK가 복잡한 에이전트와 동적 UI를 가능하게 한다는 핵심 메시지로 마무리됩니다.

## 인상적인 대목

- "Function calling is how LLMs can interact with external tools and APIs." (함수 호출은 LLM이 외부 도구 및 API와 상호작용하는 방식입니다.)
- "The agent can think, and the agent can act, and it can render UI." (에이전트는 생각하고, 행동하며, UI를 렌더링할 수 있습니다.)

## 실무 적용 포인트
- **웹 개발 스택을 활용한 AI 에이전트 개발:** 기존 React, Next.js, Vercel 플랫폼에 익숙한 개발자라면 AI SDK를 활용하여 LLM 기반 애플리케이션을 빠르게 구축할 수 있습니다. 웹 개발의 강점(UI/UX, 배포 용이성)을 AI 에이전트에 적용하는 것을 고려해볼 수 있습니다.
- **AI SDK를 통한 스트리밍 UI 및 함수 호출 구현:** 사용자 경험을 향상시키기 위해 LLM 응답을 실시간으로 스트리밍하고, LLM이 외부 API와 연동하여 동적인 정보를 가져오거나 특정 작업을 수행하도록 `useChat` 훅과 `tools` 옵션을 적극적으로 활용할 수 있습니다.
- **Zod를 활용한 함수 호출 파라미터 유효성 검사:** 함수 호출 시 LLM이 생성하는 파라미터의 타입 안정성과 유효성을 보장하기 위해 Zod와 같은 스키마 유효성 검사 라이브러리를 도입하여 에이전트의 신뢰성을 높일 수 있습니다.
- **React Server Components를 활용한 동적 UI 렌더링 에이전트 구현:** Vercel AI Agent SDK를 사용하여 에이전트가 단순 텍스트 응답을 넘어, 사용자의 요청에 따라 지도, 차트, 예약 위젯 등 인터랙티브한 UI 컴포넌트를 직접 렌더링하도록 설계하여 사용자 경험을 혁신할 수 있습니다.
