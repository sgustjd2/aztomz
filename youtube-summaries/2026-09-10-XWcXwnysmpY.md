# The Spatial Harness: Bringing Agents to the Canvas — Max Drake, tldraw

## 한 줄 요약

## 발표자·소속
Max Drake, tldraw

## 핵심 주장
-   **LLM의 한계 극복을 위한 시각적 인터페이스 제공**: 현재 LLM은 텍스트 기반의 순차적 인터페이스로 인해 공간적 추론 능력이 부족하고 작업 과정이 불투명합니다. tldraw는 에이전트에게 시각적 캔버스를 제공하여 이러한 한계를 극복하고, 에이전트가 "보고 행동"할 수 있게 합니다.
-   **에이전트에게 '몸과 눈'을 부여하는 '공간적 하네스'**: tldraw는 에이전트가 캔버스 상의 객체를 인식(눈)하고 조작(몸)할 수 있도록 API를 통해 도구를 제공합니다. 이를 통해 에이전트는 캔버스 상태를 SVG나 JSON 형태로 인지하고, 도형 생성, 이동, 텍스트 추가 등의 작업을 수행할 수 있습니다.
-   **반복적이고 협력적인 작업 흐름 지원**: 에이전트는 캔버스에서 사용자의 지시에 따라 다이어그램을 그리거나 UI를 스케치하고, 사용자의 피드백을 받아 이를 수정하는 등 반복적인 작업을 수행합니다. 또한, 여러 에이전트가 하나의 캔버스에서 협력하여 디자인과 코드 생성 같은 복합적인 작업을 처리할 수 있습니다.
-   **시각적 맥락을 통한 복잡한 작업 자동화**: 에이전트는 캔버스에 그려진 시각적 요소를 바탕으로 웹 서버 다이어그램을 그리거나, UI 스케치를 React 코드로 변환하는 등 복잡한 작업을 자동화합니다. 이는 단순히 텍스트 명령을 처리하는 것을 넘어, 시각적 레이아웃과 관계를 이해하는 능력을 보여줍니다.

## 세부 내용
발표는 현재 LLM 인터페이스의 한계점을 지적하며 시작됩니다. LLM은 텍스트 기반으로 순차적이며, 공간적 추론 능력이 부족하고 작업 과정이 불투명하다는 문제점이 있습니다. 발표자는 tldraw를 이러한 LLM의 한계를 극복하기 위한 '공간적 하네스(Spatial Harness)'로 제안합니다. 이는 에이전트에게 "몸과 눈"을 부여하여 캔버스 위에서 보고 행동할 수 있게 하는 개념입니다.

**작동 방식**:
에이전트는 tldraw 캔버스의 상태를 SVG나 JSON 형태로 '인지(Perception)'하고, tldraw API를 통해 제공되는 '도구(Tools)'를 사용하여 캔버스에 '행동(Action)'합니다. 예를 들어, `createShape`, `deleteShape`, `updateShape`와 같은 함수들이 에이전트의 도구가 됩니다. 백엔드에서는 tldraw의 캔버스 상태를 LLM(예: OpenAI GPT-4)에 전달하고, LLM은 도구를 호출하여 캔버스에 변경 사항을 적용합니다.

**데모 1: 다이어그램 에이전트 (Diagramming Agent)**
사용자가 "웹 서버, 데이터베이스, 클라이언트 다이어그램을 그려줘"라고 명령하면, 에이전트는 `createShape` 도구를 사용하여 사각형과 텍스트를 생성하고, `createArrow` 도구로 연결선을 그립니다. 사용자가 "로드 밸런서를 추가해줘"라고 요청하면, 에이전트는 기존 다이어그램의 공간적 맥락을 이해하고 적절한 위치에 로드 밸런서를 추가합니다. "데이터베이스를 원으로 만들어줘"와 같은 수정 요청에도 에이전트는 기존 도형을 업데이트합니다. 에이전트는 또한 "어떤 종류의 데이터베이스인가요?"와 같이 사용자에게 질문하여 명확성을 높일 수 있습니다.

**데모 2: 코드 생성 에이전트 (Code Generation Agent)**
사용자가 tldraw 캔버스에 버튼, 텍스트 입력 필드, 레이블 등을 스케치합니다. 에이전트는 이 스케치를 인식하고, 이를 바탕으로 React 컴포넌트 코드를 생성합니다. 생성된 코드는 캔버스에 텍스트 형태로 표시되거나, 심지어 iframe을 통해 렌더링된 실제 UI로 다시 캔버스에 삽입될 수도 있습니다. 사용자가 스케치를 수정하면, 에이전트는 변경된 시각적 맥락에 맞춰 코드를 다시 생성합니다.

**데모 3: 협력 에이전트 (Collaborative Agent)**
두 명의 에이전트, '디자이너'와 '코더'가 등장합니다. 디자이너 에이전트가 캔버스에 UI 스케치를 그리면, 코더 에이전트가 이를 보고 React 코드를 생성합니다. 디자이너 에이전트는 생성된 코드를 평가하고, "버튼을 더 크게 만들어줘"와 같은 피드백을 제공하여 코더 에이전트가 코드를 수정하도록 유도합니다. 이는 여러 에이전트가 하나의 시각적 캔버스에서 협력하여 복잡한 작업을 수행할 수 있음을 보여줍니다.

발표자는 tldraw를 통해 에이전트가 공간적 추론, 반복적 개선, 투명한 작업 과정, 그리고 인간 및 다른 에이전트와의 협업이 가능해진다고 강조합니다. 미래에는 더욱 정교한 인지 능력, 복잡한 행동, 그리고 실제 도구와의 통합을 통해 자율적인 에이전트가 등장할 것으로 전망합니다.

## 실무 적용 포인트
-   **tldraw를 에이전트의 시각적 프런트엔드로 활용**: LLM 기반 에이전트가 시각적 출력을 생성하거나 시각적 입력을 처리해야 하는 경우, tldraw 캔버스를 활용하여 에이전트에게 시각적 '작업 공간'을 제공할 수 있습니다.
-   **에이전트 '도구' 설계**: tldraw API를 활용하여 `createShape`, `updateShape`, `deleteShape` 등 캔버스 조작 함수를 에이전트의 '도구'로 정의하고, LLM이 이 도구들을 호출하여 캔버스에 시각적 변화를 일으키도록 구현할 수 있습니다.
-   **반복적 피드백 루프 구현**: 사용자의 시각적 피드백(예: 캔버스 수정, 텍스트 명령)을 에이전트에게 전달하고, 에이전트가 이를 바탕으로 캔버스 내용을 수정하는 반복적인 작업 흐름을 구축하여 디자인 및 개발 프로세스를 개선할 수 있습니다.
-   **다중 에이전트 협업 시스템 탐색**: tldraw 캔버스를 공유 작업 공간으로 활용하여 여러 AI 에이전트가 각자의 역할을 수행하며 협력하는 시스템(예: 디자이너 에이전트와 코더 에이전트)을 설계하고 구현해 볼 수 있습니다.
