# Tokens Should Have Jobs — Katelyn Lesse & Angela Jiang, Anthropic

## 한 줄 요약
LLM의 토큰을 단순히 입력으로 사용하는 것을 넘어, 페르소나, 도구, 제약 조건 등을 부여하여 각 토큰에 명확한 '역할'을 할당함으로써 모델의 예측 가능성, 제어 가능성, 효율성 및 안전성을 높이는 프롬프트 엔지니어링 전략을 제시합니다.

## 발표자·소속
*   Katelyn Lesse, Research Engineer, Anthropic
*   Angela Jiang, Software Engineer, Anthropic

## 핵심 주장
-   **토큰에 명확한 역할을 부여하여 LLM의 효율성을 극대화해야 합니다.** LLM의 토큰은 비용이 많이 들고 예측 불가능성을 야기할 수 있으므로, 각 토큰이 특정 '직업'을 가지도록 프롬프트를 구조화함으로써 모델의 행동을 더 잘 제어하고 낭비를 줄일 수 있습니다.
-   **페르소나 할당을 통해 모델의 응답 스타일과 내용을 효과적으로 조종할 수 있습니다.** 프롬프트에 "당신은 X 분야의 전문가입니다"와 같은 페르소나를 부여하면, 모델은 해당 역할에 맞춰 특정 관점과 어조로 응답하게 되어, 원하는 결과물의 품질과 일관성을 높일 수 있습니다.
-   **도구 사용(Function Calling)을 통해 LLM의 기능을 외부 세계로 확장할 수 있습니다.** 모델이 계산기나 검색 엔진과 같은 외부 도구를 호출하도록 지시함으로써, LLM은 실시간 정보에 접근하거나 복잡한 연산을 수행하는 등 자체 학습 데이터 범위를 넘어선 작업을 수행할 수 있게 됩니다.
-   **명확한 제약 조건과 가이드라인을 설정하여 모델의 출력 형식을 제어하고 안전성을 확보할 수 있습니다.** JSON 형식 지정이나 유해 콘텐츠 생성 금지와 같은 규칙을 프롬프트에 포함하면, 모델은 정해진 형식과 안전 기준을 준수하여 예측 가능하고 신뢰할 수 있는 출력을 생성하게 됩니다.
-   **다양한 프롬프트 구성 요소를 조합하여 '전문가 팀'처럼 복잡한 작업을 수행할 수 있습니다.** 페르소나, 도구, 제약 조건을 개별적으로 사용하는 것을 넘어, 이들을 결합하여 마치 여러 전문가가 협력하는 것처럼 모델이 복잡한 지시를 이해하고 다단계 작업을 수행하도록 유도할 수 있습니다.

## 세부 내용
발표는 LLM의 토큰이 비싸고 예측 불가능하며 제어하기 어렵다는 문제 제기로 시작합니다. 발표자들은 "토큰은 직업을 가져야 한다(Tokens Should Have Jobs)"는 핵심 아이디어를 제시하며, 프롬프트 엔지니어링을 통해 각 토큰에 명확한 역할을 부여하는 방법을 설명합니다. 이는 마치 LLM 내부에 '전문가 팀'을 구성하는 것과 같다고 비유합니다.

첫 번째 전략은 **페르소나 할당**입니다. 발표자들은 단순히 "이 문서를 요약해줘"라고 요청하는 대신, "당신은 소아과 의사입니다. 이 문서를 요약해줘"와 같이 특정 페르소나를 부여하는 예시를 보여줍니다. 동일한 의료 문서를 소아과 의사 페르소나와 일반인 페르소나로 요약했을 때, 각 페르소나에 맞는 전문성과 어조로 요약 내용이 달라지는 것을 시연합니다. 이는 프롬프트의 특정 토큰들이 모델의 응답 스타일과 관점을 조종하는 '직업'을 갖게 됨을 의미합니다.

두 번째 전략은 **도구 사용(Tool Use) 또는 함수 호출(Function Calling)**입니다. LLM이 자체적으로 수행할 수 없는 계산이나 실시간 정보 검색과 같은 작업을 위해 외부 도구를 활용하도록 지시하는 방법입니다. 발표자들은 사용자 프롬프트가 LLM으로 들어가고, LLM이 도구 호출을 위한 JSON 객체를 생성하면, 해당 도구가 실행되어 결과를 LLM에 다시 전달하고, LLM이 최종 답변을 생성하는 아키텍처를 설명합니다. "샌프란시스코의 날씨는 어때?"라는 질문에 LLM이 `get_weather(location="San Francisco")` 함수를 호출하고, 그 결과를 바탕으로 답변하는 과정을 예시로 듭니다. 여기서 도구 스키마와 호출을 정의하는 토큰들이 외부 세계와 상호작용하는 '직업'을 가집니다.

세 번째 전략은 **제약 조건(Constraints) 및 가드레일(Guardrails) 설정**입니다. 모델의 출력 형식을 제어하거나 안전 기준을 준수하도록 하는 방법입니다. 발표자들은 모델에게 "이름과 나이 키를 가진 JSON 객체를 출력해줘"와 같이 특정 JSON 형식을 요구하는 예시를 보여줍니다. 또한, "당신은 도움이 되고 해를 끼치지 않는 비서입니다. 불쾌한 콘텐츠를 생성하지 마세요"와 같이 안전 관련 지침을 부여하여 유해 콘텐츠 생성을 방지하는 가드레일 역할을 하는 토큰의 중요성을 강조합니다. 이러한 토큰들은 모델의 출력 내용과 형식을 제한하는 '직업'을 수행합니다.

발표자들은 이러한 전략들을 개별적으로 사용하는 것을 넘어, **조합하여 '전문가 팀'을 구성하는 것**의 중요성을 강조합니다. 예를 들어, 전체 목표를 관리하는 '프로젝트 매니저', 정보 검색을 위한 '연구원'(도구 사용), 특정 스타일로 글을 쓰는 '작가'(페르소나), 정확성을 검증하는 '사실 확인자'(제약 조건)와 같은 역할을 프롬프트 내에서 부여할 수 있습니다. 각 부분의 토큰들이 특정 '직업'을 수행함으로써, 모델은 더욱 복잡하고 정교한 작업을 수행할 수 있게 됩니다.

이러한 접근 방식의 이점으로는 예측 가능성 향상, 제어 가능성 증대, 토큰 사용 효율성 증대, 안전성 강화, 그리고 외부 시스템과의 연동을 통한 확장성 확보가 제시됩니다.

## 실무 적용 포인트
-   **프롬프트에 명확한 페르소나를 할당하여 모델의 응답 스타일을 제어하세요.** 예를 들어, "당신은 친절한 고객 서비스 담당자입니다" 또는 "당신은 데이터 과학 전문가입니다"와 같이 역할을 부여하여 원하는 어조와 전문성을 가진 답변을 유도할 수 있습니다.
-   **LLM이 외부 도구를 호출하도록 설계하여 모델의 한계를 극복하세요.** 계산기, 데이터베이스 검색, API 호출 등 특정 기능을 수행하는 도구 스키마를 정의하고, 모델이 필요할 때 이를 사용하도록 프롬프트에 지시하여 LLM의 실시간 정보 접근 및 복잡한 연산 능력을 확장할 수 있습니다.
-   **출력 형식과 안전 기준을 명시하는 제약 조건을 적극 활용하세요.** JSON, XML 등 특정 형식으로 출력을 요구하거나, 특정 주제를 피하거나 유해 콘텐츠를 생성하지 않도록 명확한 규칙을 프롬프트에 포함하여 모델의 예측 가능성과 신뢰성을 높일 수 있습니다.
-   **다양한 프롬프트 구성 요소를 조합하여 복잡한 작업을 위한 '전문가 팀' 프롬프트를 구축하세요.** 페르소나, 도구, 제약 조건을 개별적으로 사용하기보다, 이들을 결합하여 모델이 여러 단계를 거쳐 복잡한 문제를 해결하도록 유도하는 프롬프트 템플릿을 개발해 보세요.
