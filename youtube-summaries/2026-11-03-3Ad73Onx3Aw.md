# Better Search Took This AI Agent From 36% to 98% Accuracy - Aamir Shakir, Mixedbread

🔗 https://youtu.be/3Ad73Onx3Aw · 📅 2026-11-03 · 🎙 AI Engineer

## 한 줄 요약
Mixedbread는 독점적인 멀티모달 데이터를 에이전트가 검색 가능하도록 인덱싱하여 금융 에이전트의 답변 정확도를 36%에서 98%로 향상시키고 토큰 비용을 3배 절감합니다.

## 발표자·소속
Aamir Shakir - CEO, Mixedbread

## 핵심 주장
*   기존의 데이터 검색 방식(grep, 기본적인 RAG 파이프라인)은 복잡하고 멀티모달적인 비공개 데이터에 대해 비효율적이며 정보 손실이 큽니다.
*   일반적인 RAG 파이프라인의 각 단계(파싱, OCR, 청킹, 임베딩)는 노이즈를 유발하고 특히 표나 차트와 같은 비텍스트 데이터에서 정보를 손실시킵니다.
*   데이터 볼륨이 증가함에 따라 기존 방식의 답변 품질은 저하되고, 과도한 토큰 사용으로 비용이 증가합니다.
*   AI 에이전트의 진정한 병목 현상은 인텔리전스 자체가 아니라 조직의 독점적인 지식에 효과적으로 접근하는 능력에 있습니다.
*   Mixedbread는 멀티모달 및 다국어 검색 솔루션을 제공하여, 페이지의 시각적 요소를 포함한 데이터를 있는 그대로 직접 인덱싱함으로써 에이전트의 정확도를 크게 높이고 토큰 비용을 절감합니다.

## 세부 내용
발표자는 Mixedbread가 PDF, 스프레드시트, 슬라이드, 이미지, 비디오, 오디오 등 100개 이상의 언어로 된 모든 데이터를 에이전트가 검색할 수 있도록 한다고 소개했습니다. Mixedbread는 자체 모델과 데이터베이스를 사용하여 SOC 2 및 ISO 27001을 준수하며, "Bring your own bucket" 방식을 통해 데이터 보존 없이 높은 보안을 제공합니다. 이는 은행 및 헤지펀드에서 수십억 개의 문서를 처리하는 데 사용되고 있습니다.

발표자는 금융 에이전트를 위한 증거 레이어를 구축하는 데 있어 두 가지 주요 문제점을 지적했습니다.
1.  **grep 방식의 한계**: 로컬에 저장된 수많은 PDF 문서에서 특정 정보를 찾기 위해 `grep` 명령어를 사용하면, 대부분의 PDF가 바이너리 형식이거나 스캔본, 차트 등을 포함하고 있어 텍스트 검색이 불가능합니다. 에이전트가 문서를 하나씩 열어보는 방식은 토큰 비용을 크게 증가시키고 관련성 없는 결과를 초래합니다.
2.  **자체 파이프라인 구축의 복잡성**: RAG(Retrieval Augmented Generation) 파이프라인을 직접 구축하는 것은 파싱, OCR, 청킹, 임베딩, 벡터 DB, 리랭킹 등 여러 단계를 거쳐야 합니다. 발표자는 이를 "프랑켄슈타인 스택"이라고 부르며, 각 단계마다 정보 손실이 발생하고 새로운 벤더를 추가해야 하며, 업데이트 시 전체 과정을 다시 실행해야 하는 비효율성을 강조했습니다. 특히 테이블이나 다이어그램 같은 복잡한 구조의 데이터는 파싱 과정에서 정보가 손실되기 쉽고, 이를 기반으로 생성된 임베딩은 원래 정보의 풍부함을 제대로 반영하지 못해 검색 품질을 저하시킵니다.

"더 많은 데이터, 더 많은 노이즈"라는 제목의 슬라이드에서는 데이터 볼륨이 증가할수록 답변 품질이 저하되는 현상을 그래프로 보여주었습니다. 오래된 버전이나 중복된 문서가 올바른 페이지를 가리거나, 파싱 오류가 수백만 페이지에 걸쳐 반복되어 에이전트의 컨텍스트를 노이즈로 채우게 됩니다. 특히 금융 보고서와 같이 복잡한 테이블과 다양한 정보가 담긴 문서의 경우, 임베딩 모델이 1996년과 2026년의 실적 보고서처럼 유사한 정보를 구분하기 어렵다는 점을 지적했습니다. 이는 에이전트가 불필요한 검색을 반복하게 하여 비용을 증가시키고 시스템 확장성을 저해합니다.

발표자는 "동일한 모델. 더 많은 데이터. 더 나쁜 답변. 병목 현상은 지식에 대한 접근이다"라고 결론지으며, 인텔리전스 자체는 충분하지만 데이터에 대한 효과적인 접근이 중요하다고 강조했습니다. Mixedbread는 이러한 문제 해결을 위해 1994년부터 현재까지의 검색 품질 변화를 보여주는 그래프를 제시하며, 2022년에야 BM25(키워드 매칭)보다 나은 임베딩 모델이 등장했지만, Mixedbread의 새로운 모델(다음 주 출시 예정)은 기존의 선형적인 개선을 넘어선 "단계적 변화"를 가져왔다고 주장했습니다. 이 모델은 "잠재적 상호작용 모델"로, 문서와 쿼리에 대해 여러 개의 임베딩을 생성하여 페이지 내의 세밀한 정보를 파악하고 컨텍스트를 이해합니다.

라이브 데모에서는 Mixedbread UI를 통해 인텔 실적 보고서를 업로드하고 검색하는 과정을 시연했습니다.
*   **데이터 업로드 및 인덱싱**: PDF 문서를 업로드하면 Mixedbread가 각 페이지를 시각적으로 인덱싱합니다. 데모 중 인터넷 연결 문제로 PDF 로딩이 지연되었으나, 발표자는 Mixedbread가 이미지, 레이아웃 정보, OCR 텍스트를 모두 제공하여 멀티모달 LLM이 아닌 경우에도 활용할 수 있음을 설명했습니다.
*   **질의응답**:
    *   "2025년 2분기 인텔 파운드리 부문의 영업 마진은 얼마였습니까?"라는 질문에 Mixedbread는 관련 페이지(인텔-Q2-2025-Earnings-Deck.pdf의 9페이지)를 찾아 정확한 수치와 함께 바운딩 박스로 차트 내의 해당 부분을 시각적으로 참조하여 답변했습니다. 이는 에이전트가 의사결정을 내릴 때 출처를 추적하고 인용할 수 있는 "증거 레이어" 역할을 합니다.
    *   "인텔 파운드리의 수익성이 개선되고 있는 이유와 원동력은 무엇입니까?"라는 복잡한 질문에는 Mixedbread의 "에이전틱 검색" 기능이 활성화되었습니다. 이 기능은 여러 쿼리를 수행하고 다단계 추론을 통해 관련 데이터를 종합하여 상세한 답변을 제공했습니다. 이 에이전틱 검색 모델은 Astra와 Fable만큼 우수하면서도 40배 빠르고 저렴하다고 언급했습니다.

Mixedbread를 도입한 실제 고객 사례로, 한 헤지펀드가 55개의 질문에 대해 자체 문서로 에이전트 벤치마크를 수행한 결과, 기존 검색 백엔드 사용 시 36%였던 답변 정확도가 Mixedbread 도입 후 98%로 크게 향상되었습니다. 특히 텍스트 질문은 79%에서 100%로, 테이블 및 차트 질문은 29%에서 100%로 정확도가 상승했습니다. 또한, Mixedbread는 에이전트가 증거를 찾는 데 필요한 도구 호출 횟수를 줄여 토큰 사용량을 3배 절감했습니다.

## 실무 적용 포인트
*   **멀티모달 데이터 처리 강화**: 금융 보고서, 연구 자료 등 복잡한 문서에 포함된 테이블, 차트, 이미지 등 비텍스트 정보를 효과적으로 활용하기 위해 시각적 레이아웃을 이해하고 인덱싱하는 멀티모달 검색 솔루션 도입을 고려해야 합니다.
*   **RAG 파이프라인의 정보 손실 최소화**: 기존 RAG 파이프라인의 파싱, OCR, 청킹, 임베딩 단계에서 발생하는 정보 손실과 노이즈 문제를 인지하고, 이를 최소화할 수 있는 통합적이고 고품질의 검색 백엔드를 선택하여 에이전트의 답변 정확도를 높여야 합니다.
*   **에이전트의 지식 접근성 개선**: 에이전트의 성능 향상을 위해 모델 자체의 인텔리전스뿐만 아니라, 에이전트가 기업의 방대한 독점 데이터에 빠르고 정확하게 접근하고 해석할 수 있는 "증거 레이어" 구축에 집중해야 합니다.
*   **비용 효율적인 검색 전략 수립**: 검색 품질 향상은 에이전트가 필요한 정보를 더 적은 횟수의 도구 호출로 찾을 수 있게 하여 LLM 토큰 비용을 절감합니다. 따라서 검색 백엔드 선택 시 정확도와 함께 토큰 효율성을 중요한 평가 기준으로 삼아야 합니다.
