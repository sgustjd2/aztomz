# Improving Agents is a Data Mining Problem — Vivek Trivedy, LangChain

🔗 https://youtu.be/CvRngaQZQ3Y · 📅 2026-08-12 · 🎙 AI Engineer

## 한 줄 요약
AI 에이전트의 지속적인 개선은 데이터 마이닝 문제이며, 에이전트가 생성하는 방대한 트레이스 데이터를 수집, 큐레이션, 분석하여 에이전트의 행동을 이해하고, 오픈 모델 미세 조정 및 하네스 엔지니어링을 통해 비용 효율적으로 성능을 향상시켜야 합니다.

## 발표자·소속
Vivek Trivedy, LangChain 응용 연구 리드 (Applied Research Lead)

## 핵심 주장
- **에이전트 개선은 데이터 마이닝 문제입니다:** 에이전트가 환경에서 작동하면서 생성하는 모든 트레이스(도구 호출, 출력 메시지, API 호출 등)는 에이전트의 행동을 이해하고 개선하는 데 필수적인 데이터가 됩니다. 이 데이터를 효과적으로 수집하고 분석하는 것이 지속적인 에이전트 개선의 핵심입니다.
- **관측 가능성(Observability)과 지속적 학습(Continual Learning)은 밀접하게 연결되어 있습니다:** 에이전트가 세상에서 행동하고, 그 행동에 대해 성찰하며, 피드백에 따라 지식이나 정의를 업데이트하는 과정은 관측 가능성(트레이스 캡처)과 지속적 학습(트레이스 학습)의 순환 고리를 형성합니다. 모든 지속적 학습 회사는 관측 가능성 회사입니다.
- **에이전트는 결정론을 자율성과 교환합니다:** 기존 소프트웨어 코드와 달리, 에이전트는 프롬프트, 도구, 스킬, 미들웨어 등으로 구성되어 예측 불가능한 자율성을 가집니다. 따라서 에이전트의 행동을 이해하고 개선하기 위해서는 단순히 코드를 읽는 것을 넘어, 실제 실행 트레이스를 분석하는 새로운 도구와 시스템이 필요합니다.
- **오픈 모델은 비용 효율적인 트레이스 심사관 역할을 할 수 있습니다:** 프론티어 모델(예: Opus)의 지능 수준에 도달한 오픈 모델들은 트레이스 데이터를 분석하고 판단하는 데 있어 훨씬 저렴한 비용으로 유사한 성능을 제공할 수 있습니다. 이는 하네스 엔지니어링과 결합하여 에이전트 개선의 비용 효율성을 크게 높입니다.
- **미세 조정(Fine-Tuning)은 프론티어 성능에 도달하게 합니다:** 특정 도메인에 특화된 태스크에서 오픈 모델을 미세 조정하면, 토큰 비용 대신 하드웨어 비용으로 전환하여 훨씬 저렴한 비용으로 프론티어 모델과 동등하거나 그 이상의 성능을 달성할 수 있습니다. 이는 고성능 에이전트를 대규모로 배포하는 데 중요한 경제적 이점을 제공합니다.

## 세부 내용
발표는 에이전트 개발자가 겪는 일반적인 문제 상황을 제시하며 시작합니다: 에이전트를 실행했더니 많은 일을 했지만 일부 실수를 저질렀고, 이제 무엇을 해야 할지 모르는 상황입니다. 발표자는 에이전트를 지속적으로 개선하기 위한 4단계 레시피를 제안합니다.

1.  **v1 에이전트 구축 및 실행:** 실제 환경에 에이전트를 배포하여 작동시킵니다.
2.  **많은 트레이스 수집:** 에이전트가 도구 호출, API 사용, 출력 메시지 생성 등 환경에서 수행하는 모든 상호작용을 데이터(트레이스)로 기록합니다.
3.  **트레이스 데이터 큐레이션 (데이터 마이닝):** 수집된 방대한 트레이스 데이터에서 유의미한 패턴과 정보를 추출합니다.
4.  **데이터 기반 실험 실행:** 큐레이션된 데이터를 바탕으로 새로운 프롬프트, 도구, 오케스트레이션 등이 에이전트 성능을 실제로 개선하는지 실험합니다.

발표자는 "모든 지속적 학습 회사는 관측 가능성 회사"라는 다소 도발적인 주장을 펼치며, 에이전트가 환경에서 행동하고, 그 행동을 관찰(관측 가능성)하며, 이를 통해 학습(지속적 학습)하여 자신을 업데이트하는 순환 고리의 중요성을 강조합니다.

기존 소프트웨어 개발과 달리, 에이전트는 프롬프트, 도구, 스킬, 훅, 서브에이전트 등으로 구성되어 예측 불가능한 자율성을 가집니다. 따라서 코드를 읽는 것만으로는 에이전트의 행동을 완전히 이해하기 어렵습니다. "아무도 에이전트가 무엇을 할지 실행하기 전까지는 모른다."는 점을 지적하며, 에이전트의 행동을 파악하기 위해 트레이스 데이터를 읽는 것이 필수적이라고 설명합니다.

LangChain은 에이전트가 다른 에이전트의 트레이스를 읽도록 하는 시스템을 구축했습니다. 이를 통해 좋은/나쁜 상호작용 사례를 찾고, 에이전트의 성능 변화(예: 압축 후 성능 저하 여부), 비용 효율성 등을 분석합니다. 현대 에이전트 실행은 수백만 토큰에 달하는 방대한 데이터를 생성하며, 이는 인간이 평생 생산한 데이터량을 곧 능가할 것입니다. 이러한 "긴 호라이즌 에이전트"가 생성하는 데이터를 읽는 것은 두 가지 주요 문제에 직면합니다.

1.  **비용 문제:** 방대한 트레이스 볼륨은 많은 입력 토큰을 의미하며, 이는 처리 비용이 매우 비쌉니다.
2.  **컨텍스트 문제:** 트레이스 데이터가 너무 커서 단일 컨텍스트 창에 모두 들어가지 않습니다.

이러한 문제를 해결하기 위해 발표자는 오픈 모델의 활용을 제안합니다. 최근 6개월간 오픈 모델들은 지능 면에서 변곡점을 맞이하여, 특정 작업에서 프론티어 모델(예: Opus)과 유사한 수준의 트레이스 심사 능력을 제공하면서도 1~2 자릿수 더 저렴한 비용을 보여줍니다. LangChain은 하네스 엔지니어링(프롬프트, 도구 등을 조정)을 통해 오픈 모델의 성능을 향상시키고, 이를 통해 Opus와 같은 프론티어 모델의 성능을 모방할 수 있음을 보여주었습니다.

더 나아가, 특정 도메인에 특화된 트레이스 데이터를 사용하여 오픈 모델을 미세 조정하면 프론티어 성능에 도달하거나 이를 능가할 수 있습니다. 이는 토큰 비용에서 하드웨어 비용으로의 경제적 전환을 가능하게 하여, 높은 추론 워크로드에서 훨씬 저렴한 비용으로 에이전트를 운영할 수 있게 합니다.

LangChain의 "LangSmith Engine"은 이러한 루프를 자동화하는 제품입니다. 사용자가 트레이스 데이터를 가지고 있을 때, LangSmith는 에이전트가 트레이스를 읽고, 문제를 찾아내고, 실험을 제안하며, 데이터셋을 준비하고, 피드백을 생성하는 과정을 돕습니다.

트레이스 마이닝은 세 가지 주요 결과를 제공합니다.
1.  **증류(Distillation) 및 미세 조정:** 프론티어 모델의 좋은 트레이스 예시를 사용하여 더 작고 저렴한 모델을 미세 조정하여 유사한 행동을 모방하게 합니다.
2.  **평가(Evals) 및 환경 생성:** 에이전트가 통과해야 할 평가를 정의하고, 이를 통해 에이전트의 행동을 형성합니다.
3.  **제품 분석 및 하네스 목표:** 사용자가 무엇을 원하는지, 에이전트가 무엇을 하는지 이해하여 인간이 검토할 수 있는 콘텐츠를 준비합니다.

발표자는 머신러닝의 'fit' 함수 개념을 에이전트 개발에 적용하여 `fit(model, harness, task)` 형태로 모델, 하네스, 태스크를 데이터에 맞춰 조정하는 것을 제안합니다. 이는 에이전트의 성능을 개선하기 위한 연구 질문이자 실무적 과제입니다.

"오토 리서치(Auto-Research)"는 에이전트가 스스로 실험을 실행하고, 트레이스를 읽고, 개선 사항을 제안하며, 수정 사항을 적용하는 루프를 의미합니다. 특히, 에이전트에게 "밀도 높은 피드백 신호"를 제공하는 것이 중요합니다. 단순히 통과/실패 여부만 알려주는 것이 아니라, 트레이스 자체가 에이전트가 다음 행동을 결정하는 데 필요한 풍부한 정보를 담고 있어야 합니다.

지속적 학습은 에이전트가 환경에서 생성하는 정보를 에이전트 시스템으로 다시 통합하는 것입니다. 이는 훈련 데이터 수집, 하네스 업데이트, 메모리 관리를 포함하며, 장기적인 시간 스케일(수년, 수십 년)에 걸쳐 에이전트가 스스로를 업데이트하고 개선하는 것을 목표로 합니다.

## 실무 적용 포인트
- **에이전트 트레이스 데이터 수집 및 분석 시스템 구축:** 에이전트의 모든 도구 호출, API 상호작용, 출력 메시지 등을 트레이스 데이터로 기록하고 중앙 집중화하여 에이전트의 행동을 이해하고 문제점을 식별하는 데 활용해야 합니다.
- **오픈 모델을 활용한 비용 효율적인 평가:** 프론티어 모델로 에이전트의 성능 가능성을 탐색한 후, 오픈 모델을 사용하여 트레이스 데이터를 평가하고 하네스 엔지니어링을 통해 비용 효율적으로 에이전트의 성능을 개선하는 전략을 고려할 수 있습니다.
- **도메인 특화 데이터로 오픈 모델 미세 조정:** 특정 도메인에 대한 에이전트의 성능을 극대화하기 위해, 해당 도메인의 트레이스 데이터에서 추출한 좋은 예시를 바탕으로 오픈 모델을 미세 조정하여 프론티어 성능을 달성하고 추론 비용을 절감할 수 있습니다.
- **에이전트의 지속적 학습 루프 설계:** 에이전트가 스스로 행동하고, 트레이스 데이터를 통해 피드백을 얻으며, 이를 바탕으로 프롬프트, 도구, 메모리 등을 업데이트하여 장기적으로 성능을 개선하는 "지속적 학습" 시스템을 구축하는 데 집중해야 합니다.
