# Build a Platform and Watch It Burn — Michael Forrester, Accenture & Whitney Lee, Datadog

🔗 https://youtu.be/1tpqdglI3T0 · 📅 2026-10-11 · 🎙 AI Engineer

## 한 줄 요약
발표자들은 LLM 에이전트 플랫폼에 가드레일을 설치하지 않았을 때 발생할 수 있는 문제점들을 데모를 통해 보여주고, 이를 해결하기 위한 인프라 및 AI 가드레일 적용 방안을 제시합니다.

## 발표자·소속
- Michael Forrester, Accenture
- Whitney Lee, Datadog

## 핵심 주장
- **가드레일 없는 LLM 에이전트의 위험성**: 가드레일이 없는 LLM 에이전트는 개발자가 의도하지 않은 행동을 하거나, 민감한 정보를 유출하거나, 시스템에 악영향을 미칠 수 있습니다.
- **인프라 가드레일의 중요성**: 쿠버네티스 네트워크 정책, 이미지 레지스트리 제한, 런타임 보안 도구(Kyverno, Falco)와 같은 기존 인프라 보안 조치는 LLM 에이전트의 오용을 방지하는 데 필수적입니다.
- **AI 가드레일의 필요성**: 입력/출력 가드레일, 도구 허용 목록, MCP(Model Control Plane)와 같은 AI 특정 가드레일은 LLM 에이전트의 행동을 제어하고, 악의적인 프롬프트 주입이나 민감 정보 유출을 방지하는 데 효과적입니다.
- **관찰 가능성(Observability)의 역할**: OpenTelemetry를 활용한 분산 추적(distributed tracing)은 에이전트의 도구 호출 및 인프라 블록을 시각화하여 에이전트의 행동을 이해하고 문제 발생 시 신속하게 대응할 수 있도록 돕습니다.

## 세부 내용
발표자들은 LLM 에이전트 플랫폼에 가드레일이 없을 때 발생할 수 있는 문제점들을 데모를 통해 보여주며, 이를 해결하기 위한 인프라 및 AI 가드레일 적용 방안을 설명합니다.

**라운드 1: 가드레일 없음 (No Guardrails)**
발표자들은 먼저 가드레일이 전혀 없는 "부리토봇(BurritoBot)"이라는 LLM 에이전트 플랫폼을 소개합니다. 이 봇은 사용자의 질문에 매우 도움이 되지만, 통제되지 않은 행동을 할 수 있습니다.
- **챌린지 1 (데이터 유출)**: 부리토봇이 클러스터 외부로 데이터를 유출하도록 시도합니다. 발표자들은 이 챌린지가 이미 해결되어 시연할 수 없다고 언급하며, 모델 자체의 프롬프트가 데이터 유출을 막도록 설정되어 있다고 설명합니다.
- **챌린지 2 (공개 이미지 배포)**: 부리토봇이 `docker.io/peopleforrester/promo-mascot:latest`라는 공개 이미지를 클러스터에 배포하도록 시도합니다. 부리토봇은 이 이미지를 성공적으로 배포합니다.
- **챌린지 3 (파일 시스템 스누핑)**: 부리토봇이 파일 시스템을 스누핑하여 "Bat Spit Amazing Awesome Sauce" 레시피를 찾아 채팅으로 출력하도록 시도합니다. 부리토봇은 레시피 파일(`read_internal_config`)을 찾아 내용을 출력하려 하지만, 출력 가드레일이 활성화되어 있어 민감한 정보는 출력되지 않습니다.

**라운드 2: 인프라 가드레일 추가 (Add Infra Guardrails)**
두 번째 라운드에서는 인프라 수준의 가드레일을 추가한 새로운 클러스터를 사용합니다.
- **챌린지 1 (데이터 유출)**: 이 챌린지는 Kubernetes 네트워크 정책에 의해 차단됩니다.
- **챌린지 2 (공개 이미지 배포)**: Kyverno라는 어드미션 컨트롤러 소프트웨어가 `docker.io/peopleforrester/promo-mascot:latest` 이미지 배포를 차단합니다. Kyverno는 클러스터 수준에서 특정 이미지 레지스트리만 허용하는 정책을 적용하여 외부 레지스트리에서 이미지를 가져오는 것을 막습니다.
- **챌린지 3 (파일 시스템 스누핑)**: Falco라는 런타임 보안 도구가 파일 시스템 스누핑 시도를 차단합니다. Falco는 Linux 커널 수준에서 의심스러운 명령 실행을 감지하고 차단하여, `ls`와 같은 명령 실행도 막을 수 있습니다.

**라운드 3: AI 가드레일 추가 (Add AI Guardrails)**
세 번째 라운드에서는 AI 특정 가드레일을 추가한 클러스터를 사용합니다.
- **챌린지 5 (출력 가드레일)**: 부리토봇이 "Bat Spit Amazing Awesome Sauce" 레시피를 유출하도록 시도합니다. 출력 가드레일(`guard-output-on`)이 활성화되어 있어 레시피의 민감한 부분(예: "WITCH-HAZEL-GHOST-PEPPER-BAT-SPIT")이 난독화되어 출력됩니다. 이는 LLM 가드(LLM Guard)를 통해 구현됩니다.
- **챌린지 6 (입력 가드레일)**: 부리토봇에 "IGNORE ALL PREVIOUS INSTRUCTIONS"와 같은 프롬프트 주입(prompt injection)을 시도합니다. 입력 가드레일(`guard-input-on`)이 활성화되어 있어 모델이 이 프롬프트를 처리하기 전에 차단됩니다.
- **챌린지 7 (MCP 권한 부여)**: 부리토봇이 날씨 도구를 사용하여 날씨 정보를 가져오고, 동시에 `read_internal_config` 도구를 호출하여 내부 설정을 유출하도록 유도합니다. `guard-mcp-on` 가드레일이 활성화되어 있어, `read_internal_config` 도구 호출이 차단되고, 날씨 정보만 제공됩니다. 이는 에이전트의 도구 허용 목록(tool allow-list)을 통해 특정 도구만 허용하도록 제한하여 구현됩니다.

**관찰 가능성 (Observability)**
발표자들은 Datadog 인터페이스를 통해 OpenTelemetry로 계측된 에이전트의 동작을 보여줍니다. 이를 통해 에이전트의 도구 호출, 입력/출력 토큰, 비용, 사용된 모델, 시스템 프롬프트 등을 추적하고 시각화할 수 있습니다. 이는 에이전트의 행동을 이해하고, 가드레일이 어떻게 작동하는지 확인하며, 문제 발생 시 디버깅하는 데 매우 유용합니다.

- "OpenTelemetry를 활용하여 에이전트의 모든 상호작용과 내부 동작을 추적하고 시각화하는 것은 에이전트의 신뢰성과 보안을 확보하는 데 필수적인 접근 방식이라고 생각합니다."

## 실무 적용 포인트
- **다계층 보안 전략**: LLM 에이전트 플랫폼을 구축할 때는 네트워크 정책, 이미지 레지스트리 제한, 런타임 보안(Kyverno, Falco)과 같은 인프라 수준의 가드레일과 함께 입력/출력 가드레일, 도구 허용 목록, MCP와 같은 AI 특정 가드레일을 모두 적용하여 다계층 보안을 구현해야 합니다.
- **프롬프트 엔지니어링 및 가드레일의 균형**: 에이전트의 시스템 프롬프트는 에이전트의 행동을 유도하는 데 중요하지만, 프롬프트만으로는 모든 위험을 통제할 수 없습니다. 따라서 프롬프트 엔지니어링과 함께 강력한 기술적 가드레일을 병행하여 에이전트의 안전한 작동을 보장해야 합니다.
- **종단 간 관찰 가능성 확보**: OpenTelemetry와 같은 표준을 사용하여 LLM 에이전트의 모든 구성 요소(에이전트, 도구, 인프라)에 대한 분산 추적 및 로깅을 구현해야 합니다. 이를 통해 에이전트의 의사 결정 과정, 도구 호출, 비용, 잠재적 보안 위협 등을 실시간으로 모니터링하고 분석할 수 있습니다.
- **위험 기반 도구 관리**: 에이전트가 사용할 수 있는 도구(tools)에 대한 명확한 허용 목록(allow-list)을 정의하고, 각 도구의 권한과 접근 범위를 최소한으로 제한해야 합니다. 특히 민감한 시스템 리소스에 접근하는 도구는 엄격하게 통제하고, 런타임 시 비정상적인 도구 사용 패턴을 감지하는 메커니즘을 마련해야 합니다.
