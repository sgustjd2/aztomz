# How Software Factories Improve Themselves — Suraj Gupta, Warp

발표자는 소프트웨어 팩토리가 스스로 개선하는 세 가지 핵심 방법인 스킬, 메모리, 모델 라우팅을 통해 에이전트가 시간이 지남에 따라 더 효율적이고 정확하게 작동하도록 하는 워프(Warp)의 접근 방식을 설명합니다.

## 핵심 주장
- **스킬을 통한 에이전트의 절차적 학습 및 개선**: 에이전트는 특정 작업을 수행하는 절차적 스킬을 부여받으며, "외부 루프 에이전트"가 "내부 루프 에이전트"의 실행을 관찰하고 피드백을 수집하여 스킬을 자동으로 개선합니다.
- **지속적인 메모리를 통한 에이전트의 컨텍스트 유지**: 에이전트는 이전에 수행한 작업의 사실, 학습, 결과를 저장하는 메모리 스토어를 활용하여, 유사한 문제가 발생했을 때 컨텍스트를 다시 수집하는 비용을 줄이고 효율성을 높입니다.
- **모델 라우팅을 통한 비용 효율적인 작업 분배**: 다양한 작업에 가장 적합한 대규모 언어 모델(LLM)을 동적으로 선택함으로써, 단순한 작업에 고비용 모델을 사용하는 비효율성을 방지하고 전반적인 비용 효율성을 최적화합니다.
- **Git 기반 버전 관리 및 인간 검토를 통한 신뢰성 확보**: 스킬 개선 및 메모리 업데이트는 Git을 통해 추적되고 인간의 검토를 거치므로, 에이전트의 자율적인 개선 과정에서 발생할 수 있는 오류를 방지하고 신뢰성을 유지합니다.

## 세부 내용
발표자는 워프(Warp)가 개발한 클라우드 에이전트 플랫폼을 통해 소프트웨어 팩토리가 스스로 개선하는 방법에 대해 설명합니다. 워프는 터미널 개발 환경으로 시작하여 현재는 팀이 소프트웨어 팩토리를 구축할 수 있는 클라우드 에이전트 플랫폼을 제공하고 있습니다.

**1. 스킬(Skills)**
에이전트에게 절차적 기억을 부여하는 방법으로 스킬을 사용합니다. 예를 들어, 이슈 분류(Triage) 에이전트에게 이슈를 재현하는 스킬을 부여할 수 있습니다. 시간이 지남에 따라 스킬은 구식이 되거나 에이전트가 새로운 것을 학습할 수 있으므로 개선이 필요합니다. 이를 위해 워프는 "외부 루프 에이전트"를 배포하여 "내부 루프 에이전트"의 실행을 관찰하고 스킬을 개선합니다.

데모에서는 GitHub의 `Triage Issue` 스킬을 보여줍니다. 이 스킬은 GitHub 이슈를 분류하고, 필요한 정보를 요청하며, 적절한 레이블을 적용하고, 코멘트를 게시하는 과정을 설명합니다. `triage-issue-loop.yml` 워크플로우는 새 이슈가 제출될 때마다 이 에이전트를 실행합니다.

`Improve Triage Skill`이라는 "외부 루프 에이전트"는 다음 단계를 수행합니다:
- **1단계: 과거 분류 결정 찾기**: 지난 14일 동안 분류 코멘트가 달린 이슈를 찾습니다.
- **2단계: 피드백 신호 수집**: 분류 코멘트에 대한 반응(좋아요/싫어요), 인간의 답변, 버킷 차이, 중복 정확도 등을 분석합니다.
- **3단계: 교훈 종합**: 수집된 신호를 바탕으로 일반화 가능한 교훈을 도출합니다(예: OS/브라우저 정보 없는 충돌 보고서는 우선순위가 낮음).
- **4단계: 분류 스킬 편집**: 내부 루프 스킬을 업데이트하여 새로운 교훈을 반영합니다.
- **5단계: 풀 리퀘스트 열기**: 변경 사항을 Git으로 추적하고 인간의 검토를 거쳐 스킬이 잘못 개선되는 것을 방지합니다.

**2. 에이전트 메모리(Agent Memory)**
스킬이 절차를 기억하는 데 유용하다면, 에이전트 메모리는 에이전트가 과거의 컨텍스트를 기억하도록 돕습니다. 에이전트가 이전에 해결했던 유사한 이슈에 대한 정보를 다시 수집하는 데 토큰을 낭비하지 않도록 합니다. 에이전트 메모리는 에이전트에 특화된 사실 저장소(fact store)로 작동합니다.

데모에서는 워프의 클라우드 에이전트 플랫폼인 Oz에서 "Sentry Demo" 에이전트의 메모리 스토어를 보여줍니다. 이 메모리 스토어에는 "Stripe 결제 취약점", "오류 처리 원칙", "GraphQL 구독 응답 처리" 등 에이전트가 과거에 수행한 근본 원인 분석에 대한 정보가 포함되어 있습니다. 이 메모리는 버전 관리, 인간에 의한 편집 및 삭제가 가능하며, 에이전트가 새로운 이슈를 처리할 때 이 메모리를 활용하여 작업 속도를 높입니다.

**3. 모델 라우팅(Model Routing)**
다양한 작업에 어떤 LLM을 사용할지 결정하는 것은 비용 효율성 측면에서 중요합니다. 단순한 작업에 고비용 모델을 사용하는 것은 비효율적입니다. 워프는 "오토 모델(Auto Models)"이라는 자체 모델 라우터를 제공하여 파레토 효율성(Pareto efficiency)을 기준으로 최적의 모델을 평가하고 선택합니다.

데모에서는 워프 데스크톱에서 `orchestrator.yaml` 파일을 통해 모델 라우팅 규칙을 정의하는 것을 보여줍니다. 이 파일에는 데이터베이스 마이그레이션에는 GLM 모델을, 프로덕션 문제 디버깅에는 GLM을, 새로운 서비스 스캐폴딩에는 Mixtral을, 런북 및 API 문서화에는 Qwen을 사용하는 등 특정 작업 클래스에 특정 모델을 할당하는 규칙이 포함되어 있습니다. 이는 사용자가 특정 워크플로우에 맞는 모델 선택을 커스터마이징할 수 있게 합니다.

발표자는 현재 모델 라우팅이 "과학이라기보다는 예술"에 가깝지만, 워프는 고객이 자체적으로 평가(evals)를 정의하여 특정 작업에 어떤 모델이 더 나은지 객관적으로 판단할 수 있도록 하는 기능을 제품에 통합할 예정이라고 언급합니다.

## 실무 적용 포인트
- **외부 루프 에이전트 구현**: 반복적인 에이전트 작업을 관찰하고, 피드백을 수집하며, 스킬을 자동으로 업데이트하는 외부 루프 에이전트를 구축하여 에이전트의 성능을 지속적으로 개선할 수 있습니다.
- **지속적인 메모리 스토어 활용**: 에이전트가 과거의 경험과 학습 내용을 저장하고 검색할 수 있는 영구적인 메모리 스토어를 구현하여, 반복적인 컨텍스트 수집 비용을 줄이고 에이전트의 효율성을 높일 수 있습니다.
- **Git 기반 스킬/메모리 버전 관리**: 에이전트 스킬 및 메모리 변경 사항을 Git과 같은 버전 관리 시스템으로 추적하고 인간의 검토 프로세스를 통합하여, 자율적인 개선 과정의 투명성과 신뢰성을 확보할 수 있습니다.
- **작업별 모델 라우팅 전략 수립**: 다양한 LLM의 비용과 성능 특성을 고려하여, 특정 작업 클래스에 가장 적합한 모델을 동적으로 선택하는 라우팅 규칙을 정의함으로써 비용 효율성을 최적화할 수 있습니다.
