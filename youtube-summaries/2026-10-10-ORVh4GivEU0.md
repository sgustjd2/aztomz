# Beyond RAG: A Relational Context Engine That Cuts Token Burn — Unblocked

## 핵심 주장
-   **컨텍스트 엔진은 분산된 지식을 통합합니다:** 코드, PR, 문서, 대화 등 여러 소스에 흩어진 기업의 기관 지식을 수집하여 통합된 시스템 컨텍스트를 생성합니다.
-   **토큰 소모를 최적화하고 정확도를 높입니다:** 에이전트에게 필요한 정보만 선별적으로 제공하여 프롬프트 창에 들어가는 토큰 수를 줄이고, 관련성 높은 정보를 통해 에이전트의 응답 품질을 향상시킵니다.
-   **구조화된 질의를 가능하게 합니다:** 단순한 의미론적 검색을 넘어 시간, 관계, 필터링, 집계 등 구조화된 질의를 통해 에이전트가 더 복잡한 질문에 답하고 작업을 수행할 수 있도록 합니다.
-   **동적 스키마 발견 및 신원 확인 기능을 제공합니다:** 데이터베이스 스키마를 하드코딩하는 대신 런타임에 데이터를 샘플링하여 스키마를 추론하고, 사용자 참조를 실제 신원(예: GitHub 로그인)에 매핑하여 에이전트의 이해도를 높입니다.

## 세부 내용

발표자는 AI 에이전트가 생성하는 코드가 마치 팀원이 작성한 것처럼 느껴져야 하지만, 현재는 그렇지 않다고 지적하며, 이는 에이전트가 충분한 컨텍스트를 갖지 못하기 때문이라고 설명합니다. 과거에는 사람이 코드, 문서, 대화 등 여러 소스를 뒤져가며 컨텍스트를 구축했지만, 이제는 에이전트가 이 문제를 겪고 있으며, 이는 비용 증가로 이어집니다.

Unblocked의 컨텍스트 엔진은 이러한 문제를 해결하기 위해 다음과 같이 작동합니다:
1.  **소스 통합:** 코드, PR, 문서, 대화, 인시던트 관리 시스템 등 다양한 소스에서 정보를 수집합니다.
2.  **통합 시스템 컨텍스트:** 모든 소스에서 신호를 병합하여 에이전트에 전달하기 전에 통합된 컨텍스트를 만듭니다.
3.  **충돌 해결:** 권한 및 권위가 충돌하는 컨텍스트를 자동으로 해결합니다.
4.  **토큰 최적화:** 순위가 매겨지고 압축된 컨텍스트를 제공하여 프롬프트 창의 토큰 수를 줄입니다.
5.  **타겟팅된 검색:** 에이전트가 그래프에서 필요한 정보만 검색합니다.
6.  **개인화된 관련성:** 주제, 팀원, 작업 기록에 따라 관련성을 조정합니다.
7.  **권한 적용:** 시스템 전반에 걸쳐 권한 및 정책을 자동으로 적용합니다.

**데모:**
발표자는 Claude 에이전트를 사용하여 "소스마크 엔진" 최적화 계획을 세우는 시나리오를 시연합니다.
-   **컨텍스트 엔진 없이:** Claude는 코드베이스를 grep하고 파일을 읽는 등 스스로 정보를 찾아야 하며, 약 3분 10초가 소요되고 2.19달러의 비용이 발생합니다.
-   **컨텍스트 엔진과 함께:** Unblocked 컨텍스트 엔진을 백엔드에 연결하자, Claude는 Notion 문서, PR, Slack 대화 등 다양한 소스를 참조하여 훨씬 더 포괄적이고 구체적인 계획을 제시합니다. 이 경우 약 1분 30초가 소요되고 1.29달러의 비용이 발생하여 50%의 비용 절감 효과를 보여줍니다.

또 다른 데모에서는 Unblocked UI에서 코드 리뷰 이슈 비율이 감소하는 현상을 발견하고, Unblocked에 이 현상의 원인을 묻자, Unblocked는 관련 PR, Slack 대화 등을 분석하여 Opus 4.6에서 4.8로 엔진을 전환한 것이 원인임을 밝혀냅니다. 심지어 Unblocked는 이 문제를 해결하는 PR을 자동으로 생성합니다.

발표자는 RAG(Retrieval Augmented Generation)가 콘텐츠 검색에는 뛰어나지만, 시간, 관계 추적, 필터링, 집계 등 구조화된 질의에는 한계가 있다고 설명합니다. 벡터 검색은 "비슷하게 생긴" 문서를 반환하지만, 에이전트가 필요한 것은 "일치하는" 것을 찾는 구조화된 검색입니다.

**구조화된 질의 합성 단계:**
발표자는 구조화된 질의 엔진을 구축하는 6단계를 설명합니다.
1.  **스키마 발견 (Schema discovery):** 스키마를 하드코딩하지 않고 데이터에서 동적으로 발견합니다. 라이브 컬렉션을 샘플링하여 형태를 추론하고, 열거형(enum) 값까지 포함합니다. (데모: GitHub PR 컬렉션에서 스키마를 발견하는 모습 시연)
2.  **신원 확인 (Identity resolution):** "나" 또는 "피터"와 같은 사람 참조를 GitHub 로그인과 같은 실제 신원에 매핑합니다. LLM의 추측에 의존하지 않고 코드 내에서 해결합니다. (예: "peter"를 "pwerry"로 매핑)
3.  **합성 (Synthesis):** 자연어 질의를 MongoDB 파이프라인과 같은 데이터베이스 질의로 변환합니다. LLM에 스키마와 하나의 도구를 제공하여 QueryPlan을 생성하도록 강제합니다. (데모: "Open PRs by Peter" 질의가 MongoDB 파이프라인으로 변환되는 모습 시연)
4.  **유효성 검사 (Validation):** LLM 출력은 신뢰할 수 없으므로 실행 전에 검사합니다. 위험한 연산자(예: `$function`), 텍스트에 대한 `$regex` 사용, 내부 필드 접근, 테넌트/ACL 격리 위반 등을 제한합니다. (데모: "PRs with authentication in the title" 질의가 `$regex` 사용으로 인해 거부되는 모습 시연)
5.  **재시도 루프 (Retry loop):** 첫 번째 시도를 신뢰하지 않고, 오류를 모델에 다시 피드백하여 자체적으로 질의를 수정하도록 합니다. 정적 유효성 검사 오류와 MongoDB 런타임 오류 모두에 대해 재시도합니다. (데모: `$regex` 오류 후 재시도하여 `$search` 연산자를 사용하도록 수정하는 모습 시연)
6.  **전문 검색 (Full-text search):** 필터가 자유 텍스트를 일치시키지 못하므로, 주제 질의를 위해 실제 텍스트 인덱스를 추가합니다. (데모: "PRs with authentication in the title" 질의가 `$search` 연산자를 통해 8개의 결과를 반환하는 모습 시연)

**결과:**
이러한 단계를 통해 필터링, 집계, 시간 범위 지정, 전문 검색, 매번 유효성 검사, 자체 수정이 가능하며, 궁극적으로 챗 에이전트를 강화하는 컨텍스트 엔진을 구축할 수 있습니다. Unblocked는 이러한 컨텍스트 엔진 시뮬레이터를 오픈 소스로 제공하여 사용자가 직접 실험하고 에이전트의 품질, 속도, 비용 개선 효과를 확인할 수 있도록 합니다.

## 실무 적용 포인트
-   **분산된 기업 지식 통합:** 코드, 문서, 대화 등 여러 소스에 흩어진 정보를 통합하여 에이전트가 활용할 수 있는 단일 컨텍스트 레이어를 구축하는 것을 고려해야 합니다.
-   **RAG의 한계 보완:** 단순한 의미론적 검색(RAG)만으로는 복잡한 구조화된 질의(시간, 관계, 집계 등)에 한계가 있으므로, 이를 보완할 수 있는 구조화된 질의 엔진 도입을 검토해야 합니다.
-   **LLM 기반 질의 생성 시 유효성 검사 및 재시도 루프 구현:** LLM이 생성한 질의는 신뢰할 수 없으므로, 위험한 연산자, 필드 접근 제한, 테넌트 격리 등을 검사하는 유효성 검사 로직과 오류 발생 시 LLM이 자체 수정하도록 피드백하는 재시도 루프를 반드시 구현해야 합니다.
-   **동적 스키마 발견 활용:** 데이터베이스 스키마를 하드코딩하는 대신 런타임에 데이터를 샘플링하여 스키마를 동적으로 추론하는 방식을 통해 시스템의 유연성을 높이고 유지보수 비용을 절감할 수 있습니다.
