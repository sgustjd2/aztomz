## 세부 내용
발표자는 많은 사람들이 SaaS(Software as a Service)가 죽었다고 말하며, 에이전트를 통해 직접 도구를 구축하는 추세에 대해 이야기합니다. 하지만 그는 "작동하는 소프트웨어"와 "실제로 사용하고 싶은 소프트웨어" 사이에는 큰 격차가 있다고 지적합니다. 발표자는 Railway에서 마케팅 목적으로 사용하던 여러 SaaS 솔루션을 대체하기 위해 에이전트를 활용하여 올인원 사내 도구를 직접 구축한 경험을 공유합니다.

이 도구는 웹사이트, 변경 로그, 블로그 콘텐츠 관리, 이메일 발송, 소셜 미디어 게시, 웹사이트 미디어 관리, 미니 CRM, 작업 및 출시 계획, 캘린더, 댓글 및 실시간 편집 기능 등을 포함합니다. 이 모든 것은 Railway 플랫폼에서 실행되며 자동 배포됩니다. 발표자는 GPT-6(영상에서 불명확하게 언급)가 출시되었을 때 이러한 돌파구를 느꼈다고 말하며, 에이전트가 기능을 추가할 때 앱의 나머지 부분과 일치하고 세련되게 만들 수 있도록 하는 원칙들을 소개합니다.

첫 번째 원칙은 **기술 스택의 중요성**입니다. 발표자는 프로그래밍 언어나 프레임워크가 중요하지 않다는 의견에 동의하면서도, 에이전트에게 견고한 추상화를 가진 적절한 코드베이스를 제공하면 훨씬 일관된 결과물을 얻을 수 있다고 강조합니다. 그는 웹 개발에는 TanStack 라이브러리, 콘텐츠 관련 작업에는 Payload CMS를 추천합니다.

두 번째 원칙은 **견고한 제품 패턴**입니다. 발표자는 사용자가 매일 사용하는 SaaS 제품에서 당연하게 여기는 많은 것들이 에이전트가 놓치기 쉬운 부분이라고 설명합니다.
- **자동 저장:** 수동으로 저장 버튼을 누르지 않고도 백그라운드에서 진행 상황이 자동으로 저장되어 편집기 잠김 현상 없이 계속 작업할 수 있습니다.
- **미저장 변경 경고:** 브라우저 탭을 닫으려 할 때 미저장 변경 사항이 있으면 경고를 표시하여 데이터 손실을 방지합니다.
- **낙관적 업데이트:** 사용자가 어떤 작업을 수행할 때 로딩 스피너를 보여주는 대신, 즉시 성공 상태를 보여주고 백그라운드에서 서버와 동기화합니다. 실패 시에는 롤백합니다.
- **삭제 취소:** 항목을 삭제할 때 즉시 UI에서 제거하지만, 짧은 시간 동안 "실행 취소" 옵션을 제공하여 사용자가 마음을 바꿀 수 있도록 합니다.
- **아카이빙:** 완료된 작업을 삭제하는 대신 아카이빙하여 UI에서 숨기지만, 나중에 찾아 복원할 수 있도록 합니다.
- **URL 상태:** 필터링이나 정렬과 같은 UI 상태를 URL에 유지하여, 링크를 공유할 때 다른 팀원도 동일한 뷰를 볼 수 있도록 합니다.
- **무한 스크롤:** "더 보기" 버튼을 계속 클릭하는 대신, 스크롤을 내리면 자동으로 다음 데이터 배치를 로드하여 끊김 없는 경험을 제공합니다.

세 번째 원칙은 **참조(에이전트 스킬)**입니다. 에이전트에게 기존 페이지를 참조하도록 명시적으로 지시하면 UI, 데이터 페칭, 전체 구조 등에서 일관성을 유지할 수 있습니다. 발표자는 `jakubkrehel/skills` (더 나은 UI, 타이포그래피, 레이아웃, 오류 메시지), `emilkowalski/skills` (디자인 엔지니어링, 애니메이션), `railwayapp/railway-skills` (배포, 데이터베이스 추가, 지표 확인, 디버깅)와 같은 에이전트 스킬을 사용했다고 언급합니다.

네 번째 원칙은 **검증**입니다. 에이전트가 단순히 빌드를 성공하고 테스트를 통과했다고 해서 기능이 제대로 작동한다고 볼 수 없습니다. 에이전트가 실제 UI를 사용하여 페이지를 로드하고, 변경 사항을 확인하며, 엔드투엔드로 기능을 검증하도록 지시해야 합니다. 발표자는 에이전트가 컴퓨터를 사용하여 브라우저를 열고, 페이지를 탐색하며, 변경 사항을 입력하고, 저장 여부를 확인하는 과정을 시연합니다.

결론적으로, 발표자는 이러한 원칙들을 통해 빠르고 일관되며, 세련되고 즐거운 사내 도구를 구축할 수 있다고 말하며, 시청자들도 "회사 SaaS 슬레이어"가 되기를 독려합니다.
