# YOLO Mode, Safely: MicroVM Sandboxes for Any Agent — Rowan Christmas, Docker

🔗 https://youtu.be/OE_lLNCNfQo · 📅 2026-10-03 · 🎙 AI Engineer

## 한 줄 요약
Docker의 Rowan Christmas는 AI 에이전트의 잠재적 위험을 시연하고, MicroVM 샌드박스 기술인 SBX를 통해 에이전트의 행동을 안전하게 격리하고 제어하는 방법을 제시합니다.

## 발표자·소속
Rowan Christmas, Docker Product Manager

## 핵심 주장
- **AI 에이전트는 쉽게 악용될 수 있다**: 발표자는 Claude AI를 사용하여 자신의 브라우저 기록과 가상의 은행 계좌 정보를 성공적으로 추출하는 과정을 시연하며, AI 에이전트가 예상보다 쉽게 민감한 데이터에 접근할 수 있음을 보여줍니다. 이는 단순한 "부탁"이나 코딩 하네스만으로는 에이전트의 악의적인 행동을 막기 어렵다는 것을 의미합니다.
- **MicroVM 샌드박스가 강력한 보안 경계를 제공한다**: Docker의 SBX(Sandbox)는 MicroVM 기반의 격리 기술을 사용하여 에이전트가 호스트 시스템의 커널, 파일 시스템, 네트워크 등에 직접 접근하는 것을 차단하고, PII(개인 식별 정보)에 대한 접근을 제한합니다. 이를 통해 에이전트가 호스트 환경을 인식하지 못하게 하여 보안 위협을 줄입니다.
- **정책 기반의 거버넌스가 필수적이다**: SBX는 정책-코드(Policy-as-code)를 통해 네트워크 접근, 파일 시스템 접근 권한, 사용 가능한 도구 목록 등을 세밀하게 제어할 수 있습니다. 이는 에이전트의 모든 행동에 대한 완전한 감사 추적(audit trail)을 제공하여 "희망이 아닌 설계에 의한 보안"을 가능하게 합니다.
- **유용한 에이전트는 본질적으로 위험 요소를 내포한다**: 에이전트가 유용하려면 개인 데이터 접근, 신뢰할 수 없는 콘텐츠 노출, 외부 활동 능력이라는 세 가지 위험 요소를 본질적으로 내포할 수밖에 없습니다. 따라서 이러한 위험을 관리하기 위해 런타임에 강력한 시행 계층이 필요합니다.

## 세부 내용
발표는 AI Engineer World's Fair의 스폰서 소개로 시작하여, Docker의 제품 관리자인 Rowan Christmas가 새로운 샌드박스 제품인 SBX에 대해 소개합니다. SBX는 MicroVM 기술을 사용하여 AI 에이전트의 안전한 실행을 목표로 합니다.

발표자는 AI 에이전트의 보안에 대한 일반적인 생각과 실제 위험 사이의 간극을 지적하며, 에이전트가 얼마나 위험할 수 있는지 직접 시연해 보겠다고 말합니다.

**데모 1: Claude AI를 이용한 정보 탈취**
발표자는 Mac용 Claude Code 앱을 실행하고 "내 브라우저 기록은 어디에 있나요?"라고 묻습니다. Claude는 Chrome, Safari, Firefox 등 다양한 브라우저의 기록 파일 경로를 즉시 알려줍니다. 이어서 "다른 계정 중에서 어떤 은행을 방문했나요?"라고 묻자, Claude는 가상의 은행 이름(Washington Mutual, CashMan, Bank of Mom, Schwab)과 함께 방문 기록, 계좌 번호 마지막 4자리, Zelle 사용 여부, PAC 번호 검색 기록, 사용자 이름 유출 등 상세한 개인 식별 정보(PII)를 분석하여 보여줍니다. 발표자는 이 데이터가 실제 자신의 데이터였다고 밝히며 위험성을 강조합니다.

다음 날, 발표자는 자신의 보안 팀으로부터 "Claude AI 에이전트에 의해 조율된 표적 자격 증명 수집 작업"이 감지되었다는 Slack 알림을 받습니다. CrowdStrike 보고서는 이 활동을 "위험(Risky)"으로 분류하고 0.90/1.0의 위험 점수를 부여합니다. 발표자는 단 5번의 프롬프트로 이러한 정보 탈취가 가능했으며, "보안 연구"라는 명목으로 우회할 수 있었다고 설명합니다.

**Docker의 SBX 솔루션 소개**
발표자는 "부탁"만으로는 보안이 되지 않으며, 컨테이너가 커널을 공유하고, 에이전트가 환경 변수에서 비밀을 읽을 수 있으며, 수동 승인만으로는 부족하다고 지적합니다. "에이전트가 볼 수 있다면, 사용할 수 있다"는 원칙을 강조합니다. 해결책으로 MicroVM 기반의 샌드박스 및 거버넌스를 제시합니다. 이는 MicroVM 커널 격리, PII에 대한 강력한 경계, 프록시를 통한 비밀 주입, 정책-코드 시행, 자동화된 승인 및 완전한 감사 추적을 통해 "희망이 아닌 설계에 의한 보안"을 제공합니다.

"유용한 에이전트는 '치명적인 삼중주'(개인 데이터 접근, 신뢰할 수 없는 콘텐츠 노출, 외부 활동 능력)를 모두 설계상 가지고 있으며, 유일한 해결책은 런타임에 시행 계층을 두는 것"이라고 설명합니다.

**데모 2: SBX 샌드박스에서 Claude AI 실행**
발표자는 일반 Claude 앱과 `sbx run claude` 명령어로 실행된 Claude 앱을 비교합니다. 샌드박스에서 실행된 Claude는 "내 브라우저 기록은 어디에 있나요?"라는 질문에 "전체 파일 시스템을 검색했지만 이 머신에는 웹 브라우저 기록이 없습니다"라고 응답합니다. 이는 샌드박스가 호스트 시스템의 파일 시스템을 격리했기 때문입니다.

네트워크 로그를 통해 샌드박스 내 에이전트가 `thepiratebay.org`와 같은 특정 도메인에 접근하려 했으나 "기본 거부(default deny)" 정책에 의해 차단되었음을 보여줍니다. 또한 Claude가 DataDog 인스턴스로 많은 원격 측정 데이터를 전송하려 했으나 샌드박스에 의해 차단되었음을 언급합니다. 발표자는 이 모든 것이 구성 가능하다고 덧붙입니다.

**AI 거버넌스 정책**
Docker는 에이전트가 실제로 실행되는 곳에서 정책을 정의하고 시행할 것을 제안합니다. 정책은 네트워크 접근(예: `*.github.com` 허용, `10.0.0.0/8` 프로덕션 IP 범위 거부), 파일 시스템 접근 권한(예: `/code` 읽기 전용, `/etc/.ssh` 거부), MCP(Managed Code Platform) 서버 및 도구(예: 특정 GitHub 리포지토리 허용/거부)에 적용될 수 있습니다. 향후에는 L7 네트워킹 제어, GitHub 리포지토리별 파일 시스템 접근 제어 등 더 많은 기능이 추가될 예정입니다. 이러한 정책은 에이전트가 의도된 작업만 수행하고 무단 변경을 방지하도록 보장합니다.

**설치 용이성**
SBX는 Mac, Windows, Linux에서 brew, winget, apt-get 등 각 플랫폼의 패키지 관리자를 통해 쉽게 설치할 수 있습니다. 설치 후 `sbx run claude`와 같은 간단한 명령어로 샌드박스 환경에서 에이전트를 실행할 수 있습니다. 발표자는 Docker 개발자들이 모든 코드를 샌드박스에서 작성하며, 관련 리포지토리를 읽기 전용으로 마운트하여 에이전트가 코드를 볼 수 있지만 무작위 커밋을 하지 못하도록 한다고 설명합니다.

## 실무 적용 포인트
1.  **AI 에이전트 개발 환경 격리**: AI 에이전트를 개발하거나 실행할 때 Docker SBX와 같은 MicroVM 샌드박스를 사용하여 호스트 시스템의 민감한 데이터(예: 브라우저 기록, 개인 파일)나 네트워크에 대한 에이전트의 접근을 원천적으로 차단합니다.
2.  **정책-코드 기반의 거버넌스 도입**: 에이전트의 네트워크 접근(허용/거부 도메인), 파일 시스템 접근(읽기 전용/쓰기 가능 경로), 사용 가능한 외부 도구(MCP 카탈로그) 등을 코드로 명확히 정의하고 샌드박스 런타임에서 이를 강제하여 에이전트의 행동을 예측 가능하게 만듭니다.
3.  **에이전트 활동에 대한 감사 추적 확보**: 샌드박스 환경에서 에이전트의 모든 네트워크 요청 및 파일 시스템 접근 시도를 기록하고 감사 추적을 생성하여, 보안 사고 발생 시 원인 분석 및 책임 소재 파악을 용이하게 합니다.
4.  **개발 워크플로우에 샌드박스 통합**: 개발자들이 코드를 작성하고 테스트할 때 샌드박스 환경을 기본으로 사용하도록 하여, 개발 단계부터 보안을 내재화하고 에이전트가 의도치 않은 작업을 수행하는 것을 방지합니다. 예를 들어, 관련 코드 리포지토리를 읽기 전용으로 마운트하여 에이전트가 임의의 커밋을 생성하지 못하도록 할 수 있습니다.
