# How We Got LLMs to Recommend Our Open Source Library — Christopher Burns, Inth

🔗 https://youtu.be/V_5bn4q-vAI · 📅 2026-08-26 · 🎙 AI Engineer

## 한 줄 요약
발표자는 LLM이 오픈소스 라이브러리를 효과적으로 추천하도록 돕기 위해 웹사이트 문서 구조를 최적화하는 방법과 이를 자동화하는 `leadtype.dev` 도구를 소개하며, 에이전트 경험(AX)을 개선하는 것이 개발자 경험(DX)만큼 중요해지고 있음을 강조합니다.

## 발표자·소속
Christopher Burns, Inth 창립자

## 핵심 주장
- LLM 에이전트가 웹사이트 콘텐츠를 이해하고 추천하도록 돕기 위해 `llms.txt` 및 마크다운 트윈과 같은 특정 파일과 구조를 제공하는 것이 필수적입니다.
- HTML은 토큰 비용이 많이 들기 때문에, 에이전트에게는 마크다운(MD) 형식의 문서를 제공하여 토큰 효율성을 높이고 처리 속도를 개선해야 합니다.
- `leadtype.dev`와 같은 도구를 사용하여 문서(MDX)를 `llms.txt`, `llms-full.txt`, `.md` 트윈, `search-index.json`, `sitemap.xml`, `robots.txt`, `AGENTS.md` 번들 등 다양한 에이전트 친화적 형식으로 자동 생성할 수 있습니다.
- 코딩 에이전트는 웹사이트를 직접 방문하기보다 `node_modules`를 읽고 과거 훈련 데이터에 의존하므로, 라이브러리 패키지 내에 최신 문서를 `AGENTS.md` 파일과 함께 번들로 제공하여 정확성을 유지해야 합니다.
- AI 에이전트 환경은 빠르게 변화하고 있으므로, 완벽함에 얽매이지 않고 작은 개선 사항들을 지속적으로 적용하여 에이전트 경험(AX)을 최적화하는 것이 중요합니다.

## 세부 내용
발표자는 자신이 만든 오픈소스 쿠키 배너 라이브러리인 c15t(c15t.com)가 NextConf에서 1,200회 다운로드에서 현재 200만 회 이상 다운로드되는 성공을 거두었음을 소개합니다. c15t.com은 현재 300만 NPM 다운로드, 45% 월별 성장률, 2,800개 이상의 프로덕션 웹사이트에서 사용 중이며 1,800개 이상의 GitHub 스타를 보유하고 있습니다.

흥미로운 점은 c15t의 가입 양식에서 사용자들이 "어떻게 알게 되었습니까?"라는 질문에 Claude, ChatGPT, Codex, Gemini와 같은 LLM 에이전트를 가장 일관된 유입원으로 보고한다는 것입니다. 발표자는 이를 "에이전트 가시성(Agent Visibility)"이라는 아이스버그에 비유하며, 웹사이트의 상단(c15t.com) 아래에 숨겨진 다양한 마이크로 최적화(llms.txt, sitemap.xml, RSS, JSON-LD, robots.txt 등)가 에이전트가 정보를 이해하는 데 중요하다고 설명합니다.

발표자는 "마법사가 소프트웨어를 설치할 것입니다"에서 "에이전트가 소프트웨어를 설치할 것입니다"로의 전환을 보여주는 밈을 통해 개발자 경험(DX)이 에이전트 경험(AX)으로 변화하고 있음을 시사합니다. 그는 Y Combinator를 통해 스타트업을 운영하면서, 과거 Stripe 공동 창업자들이 직접 설치를 도와주던 방식이 이제는 단순히 프롬프트 하나로 해결되는 시대가 왔다고 말합니다.

이러한 변화 속에서 웹사이트가 직면하는 문제와 해결책을 제시합니다:

**문제 01: 400페이지의 문서 중 어떤 페이지가 질문에 답하는가?**
- **해결책 01: 모든 웹사이트는 `llms.txt`가 필요하다.**
  - `llms.txt`는 LLM 에이전트가 웹사이트의 핵심 정보를 파악하도록 돕는 파일입니다. 발표자는 이를 자동 생성하기보다 직접 작성하여 40줄의 핵심 내용이 1,000줄의 불필요한 정보보다 훨씬 효과적임을 강조합니다.

**문제 02: 에이전트는 웹사이트를 탐색하지 않고, 한 번에 가져온다.**
- **해결책 02: `llms-full.txt`가 필요하다.**
  - `llms-full.txt`는 웹사이트의 모든 페이지, 링크, 짧은 설명을 포함하는 사이트맵과 같은 역할을 하여 에이전트가 한 번의 요청으로 전체 문맥을 파악할 수 있도록 합니다.

**문제 03: HTML은 토큰 비용이 많이 든다. 에이전트에게 마크다운을 제공하면 어떨까?**
- **해결책 03: 모든 페이지는 `.md` 트윈이 필요하다.**
  - 웹사이트의 HTML 페이지 헤더에 `link rel="alternate" type="text/markdown" href="/docs/nextjs/quickstart.md"`와 같은 태그를 추가하여 에이전트에게 마크다운 버전의 문서가 있음을 알립니다. 이는 토큰 비용을 절감하고 에이전트가 더 효율적으로 정보를 처리하게 합니다.
  - 마크다운에 접근하는 세 가지 방법: `.md` 확장자를 직접 사용, `Accept: text/markdown` 헤더를 통한 콘텐츠 협상, `?mode=agent`와 같은 쿼리 파라미터 사용.

**문제 04: 에이전트는 웹사이트에 아무것도 물어볼 수 없다.**
- **해결책 04: 모든 웹사이트는 WebMCP를 가져야 한다.**
  - WebMCP(Web Machine Comprehension Protocol)는 에이전트가 웹사이트에 질문을 던지고 답변을 받을 수 있도록 하는 표준입니다. `search-docs`, `get-page`, `ask-docs`와 같은 세 가지 도구를 통해 에이전트가 문서에서 근거 있는 답변을 얻을 수 있도록 합니다.

**문제 05: 코딩 에이전트는 웹사이트를 방문하지 않는다. 그들은 `node_modules`를 읽는다. 그들이 API에 대해 기억하는 것은 훈련 데이터에서 온 것이며, 몇 달 된 것이다.**
- **해결책 05: 패키지 내에 문서를 포함시켜라.**
  - 라이브러리 패키지(`node_modules`) 내에 `AGENTS.md` 파일과 함께 마크다운 문서를 번들로 제공합니다. `AGENTS.md`는 에이전트에게 문서의 위치와 버전 일치 여부를 알려주어, 항상 최신 정보를 참조하도록 합니다.
  - 이 방법은 LLM 모델에 따라 16%에서 50%까지 토큰 비용을 절감하고, 처리 시간을 24%에서 48%까지 단축하는 효과를 보였습니다.

발표자는 이러한 문제 해결을 위해 `leadtype.dev`라는 프레임워크 중립적인 문서 파이프라인 도구를 개발했습니다. 이 도구는 `.mdx` 파일을 입력받아 `llms.txt`, `llms-full.txt`, `.md` 트윈, `search-index.json`, `sitemap.xml`, `robots.txt`, `AGENTS.md` 번들 등 에이전트 친화적인 다양한 출력물을 생성합니다.

마지막으로 발표자는 "이 분야는 빠르게 움직이고 있다. 완벽함에 얽매이지 마라!"라고 조언하며, 모든 작은 개선이 중요하다고 강조합니다. 그는 `ora.ai`와 같은 에이전트 준비도 스캐너를 사용하여 웹사이트의 에이전트 친화도를 지속적으로 확인하고 개선할 것을 권장합니다.

## 실무 적용 포인트
- **`llms.txt` 및 `llms-full.txt` 수동 작성:** 웹사이트의 핵심 정보와 모든 페이지의 요약/링크를 담은 `llms.txt`와 `llms-full.txt`를 직접 작성하여 LLM 에이전트가 정확하고 효율적으로 정보를 파악하도록 합니다.
- **마크다운 트윈 페이지 구현:** HTML 페이지마다 `rel="alternate"` 링크 태그를 사용하여 마크다운 버전의 문서를 제공합니다. 이는 토큰 비용을 절감하고 에이전트의 처리 효율성을 높입니다.
- **패키지 내 문서 번들링:** 개발자 도구나 라이브러리를 제공하는 경우, `node_modules` 내에 `AGENTS.md` 파일과 함께 최신 마크다운 문서를 번들로 포함시켜 코딩 에이전트가 항상 최신 API 정보를 참조하도록 합니다.
- **`leadtype.dev` 활용:** 문서(MDX)를 다양한 에이전트 친화적 형식으로 자동 생성하고 관리하기 위해 `leadtype.dev`와 같은 도구를 도입하여 에이전트 가시성 및 효율성을 개선합니다.
