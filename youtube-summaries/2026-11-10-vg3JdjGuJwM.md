# Every Correction You Give Your Agent Is Data - Brian Douglas, Paper Compute

## 핵심 주장
- 에이전트와의 상호작용에서 발생하는 모든 수정 사항은 귀중한 학습 데이터입니다. 이를 수집하고 라벨링하여 에이전트의 성능을 미세 조정할 수 있습니다.
- 에이전트가 반복적인 작업을 자동화함에 따라, 주니어 엔지니어는 경험을 통해 "판단력"을 기를 기회를 잃을 수 있습니다. 에이전트의 실수를 수정하고 피드백을 제공하는 과정에서 얻는 데이터는 이러한 학습 격차를 해소하는 데 도움이 됩니다.
- `tapes.dev`와 `stereOS` 같은 도구를 사용하여 에이전트의 모든 LLM 호출과 세션 데이터를 캡처하고 재생 가능한 환경에서 실행함으로써, 에이전트의 행동을 분석하고 개선할 수 있는 "메모리 + 피드백" 시스템을 구축할 수 있습니다.
- 수집된 세션 데이터에 "pushback", "apology", "golden", "regression"과 같은 라벨을 지정하여 에이전트의 성공 및 실패 사례를 명확히 구분하고, 이를 통해 에이전트가 인간 엔지니어의 의사결정 패턴을 학습하도록 미세 조정할 수 있습니다.

## 세부 내용
발표자는 에이전트와의 상호작용에서 발생하는 모든 수정 사항이 데이터가 된다는 점을 강조하며, 이를 통해 에이전트의 성능을 개선하고 주니어 엔지니어의 학습 기회를 보존하는 방법을 설명합니다.

발표자는 Rick Rubin의 책 "The Creative Act: A Way of Being"에서 "예술에서 우리의 취향은 작품의 결정적인 요소이다"라는 문구를 인용하며, AI 시대에는 사람들이 직접 코드를 작성하지 않고도 에이전트를 통해 "바이브 코딩"을 할 수 있게 되었다고 말합니다. 이는 Addy Osmani의 "Earning Judgment"라는 글에서 에이전트가 반복적인 작업을 자동화하여 주니어 엔지니어의 성장 기회를 줄일 수 있다는 주장과 연결됩니다. 발표자는 에이전트가 이러한 "반복"을 자동화할 것이므로, 주니어 엔지니어는 의도적으로 "취향(판단력)"을 얻기 위해 노력해야 한다고 말합니다.

이러한 문제의식에서 발표자는 `tapes.dev`라는 오픈소스 프로젝트를 소개합니다. `tapes.dev`는 모든 LLM 호출을 캡처하고 데이터를 소유하며, `stereOS`는 에이전트가 실행되는 샌드박스로 재현 가능하고 재생 가능한 환경을 제공합니다. 이 두 도구는 에이전트 시스템에서 누락된 "메모리 + 피드백" 요소를 제공합니다.

발표자는 `sweeper agent`라는 프로젝트를 통해 "자체 치유 인프라"를 구축했다고 설명합니다. `sweeper agent`는 병렬 서브 에이전트를 사용하여 코드 유지보수 작업을 수행하며, 최대 10개의 에이전트(또는 200개의 Daytona 샌드박스)를 동시에 실행할 수 있습니다. 이는 문서화, 테스트 작성, 코드 정리 등 명확하게 정의된 작업을 여러 에이전트에 분산하여 처리하는 데 사용됩니다. 발표자는 이를 통해 에이전트가 반응적(reactive)에서 적응적(adaptive)으로 변화했다고 말합니다.

데모에서는 Paper Compute 콘솔을 통해 에이전트 세션 데이터를 보여줍니다. 이 콘솔은 세션 상태, 이름, 사용된 모델, 사용자, 턴 수, 비용 등을 표시합니다. 특히, "pushback"이라는 라벨이 지정된 세션을 보여주며, 이는 엔지니어가 에이전트의 결과에 대해 피드백을 제공한 경우를 나타냅니다. 발표자는 자신이 Rust 코드를 전문적으로 작성하지 않기 때문에, 에이전트가 생성한 Rust 코드에 대해 충분한 맥락 없이 "액면 그대로" 받아들이는 경향이 있으며, 이는 나중에 PR 리뷰에서 인간 엔지니어로부터 "pushback"을 받는 원인이 된다고 설명합니다.

이러한 "pushback"을 줄이기 위해 발표자는 `twin review`라는 커맨드라인 도구를 사용합니다. 이 도구는 특정 PR에 대해 팀원(Matt)이 과거에 제공했던 "pushback" 데이터를 기반으로 에이전트가 코드 리뷰를 수행하도록 훈련합니다. 이 과정에서 에이전트는 Matt의 어댑터(adapter)를 사용하여 Matt처럼 코드를 리뷰하고 코멘트를 남깁니다. 이는 GitHub PR 리뷰 데이터가 아닌, `tapes`에 캡처된 내부 트레이스 데이터만을 활용합니다. `twin review`는 Matt이 남길 코멘트를 예측하고, Matt이 넘어갈 8개의 덩어리(hunks)를 식별합니다.

발표자는 `tapes-eject-fireworks`라는 도구를 사용하여 Codex 및 Claude Code 세션 데이터를 Fireworks 서버리스 훈련으로 미세 조정하는 과정을 설명합니다. 이 도구는 에이전트 기록을 로컬 데이터베이스로 가져와 "pushback", "apology", "golden" (가치 있는 학습 세션), "regression" (잘못된 세션)과 같은 라벨을 찾아내고, 이를 훈련 및 평가 데이터셋으로 변환하여 LoRA 어댑터를 훈련합니다.

마지막으로, 발표자는 `paper -> skills`라는 개념을 제시하며, Paper Compute의 트레이스 데이터를 활용하여 에이전트가 특정 작업을 수행할 수 있는 "스킬"을 생성할 수 있다고 말합니다. 예를 들어, "tapes" 스킬은 사용자가 "check the tapes"와 같은 문구를 사용할 때 에이전트가 과거 세션 데이터를 조회하도록 합니다. 이러한 스킬을 통해 `skills -> models`로 이어져, Qwen 모델과 같은 LLM을 미세 조정할 수 있습니다. 발표자는 `Specialized Fine Tuning (SFT)`이 책 여백에 메모를 남기는 것과 같고, `Direct Preference Optimization (DPO)`은 요약본(Cliff's Notes)과 같다고 비유합니다. SFT는 4b Qwen 모델에서 잘 작동했지만, DPO는 70b Qwen 모델과 120GB 이상의 VRAM, 잘 구조화된 데이터셋, 그리고 많은 비용이 필요하다고 언급하며, 소규모 모델에서는 DPO가 어렵다고 결론 내립니다.

- **특정 작업에 대한 에이전트 "스킬" 개발:** 반복적이거나 잘 정의된 작업에 대해 에이전트가 수행할 수 있는 "스킬"을 개발하고, 이를 통해 에이전트가 특정 도메인 지식을 습득하도록 합니다. 이는 `SKILL.md`와 같은 문서화 형태로 시작할 수 있습니다.
- **미세 조정을 통한 에이전트 성능 최적화:** 수집된 라벨링된 데이터를 사용하여 `Specialized Fine Tuning (SFT)` 또는 `Direct Preference Optimization (DPO)`과 같은 기법으로 에이전트 모델을 미세 조정합니다. 특히 SFT는 적은 컴퓨팅 자원으로도 특정 작업에 대한 에이전트의 성능을 크게 향상시킬 수 있습니다.
