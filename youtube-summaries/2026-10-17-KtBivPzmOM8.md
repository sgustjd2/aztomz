# Memory-Aware Agent Harnesses for Anti-Money Laundering — Nacho Martinez, Oracle

🔗 https://youtu.be/KtBivPzmOM8 · 📅 2026-10-17 · 🎙 AI Engineer

## 한 줄 요약
AI 에이전트의 성능 향상은 기반이 되는 거대 언어 모델(LLM) 자체보다는 모델 주변의 엔지니어링 스캐폴딩인 '에이전트 하네스'에 달려 있으며, 이 워크숍은 금융 사기 방지를 위한 메모리 인식 에이전트 하네스를 구축하는 데 중점을 둡니다.

## 발표자·소속
Nacho Martinez, Oracle 데이터 과학자/AI 개발자 옹호자

## 핵심 주장
-   **에이전트 하네스의 중요성**: 대부분의 AI 에이전트 문제는 LLM 모델 자체의 한계가 아닌, 메모리, 도구 사용, 인지 등 에이전트의 기능을 확장하는 하네스 설계에서 비롯됩니다. 하네스는 에이전트의 신뢰성과 반복 가능한 결과를 보장합니다.
-   **데이터 계층에 집중**: 에이전트 스택의 여러 구성 요소 중, 데이터 계층(메모리, 지식, 검색)은 엔지니어가 가장 많은 제어권을 가지고 개선할 수 있는 부분입니다. 모델 자체는 '빌려 쓰는' 부분이지만, 데이터 계층은 '구축하고 소유하는' 부분입니다.
-   **지속적인 학습을 위한 세 가지 메모리 유형**: 에이전트의 지속적인 학습은 매개변수 메모리(가중치), 표현 메모리(잠재 공간), 비매개변수 메모리(컨텍스트/토큰 공간)의 세 가지 방식으로 이루어지며, 이 워크숍에서는 비매개변수 메모리에 초점을 맞춥니다.
-   **컨텍스트 엔지니어링의 필요성**: LLM의 컨텍스트 윈도우는 제한적이며, 윈도우가 커질수록 성능이 저하되는 '컨텍스트 부패(Context Rot)' 현상이 발생합니다. 이를 해결하기 위해 요약(Summarization)과 압축(Compaction) 같은 컨텍스트 엔지니어링 기법이 필수적입니다.

## 세부 내용
발표는 AI 엔지니어링 컨퍼런스에서 금융 사기 방지를 위한 메모리 인식 에이전트 하네스 구축 워크숍 세션으로 진행되었습니다. 발표자는 Nacho Martinez이며, Oracle 소속의 데이터 과학자이자 AI 개발자 옹호자입니다. 워크숍 참여를 위한 QR 코드와 웹사이트(workshopwaitingroom.com)가 제공되었으며, GitHub Codespaces를 통해 실습 환경에 접근할 수 있습니다.

발표자는 에이전트 스택을 애플리케이션, 데이터, 모델, 인프라, 컴퓨팅의 5가지 부분으로 나누고, 그중 데이터 계층에 주로 초점을 맞춘다고 설명했습니다. 데이터 계층은 메모리, 지식, 검색을 담당하며, 이는 에이전트가 무엇을 아는지를 결정합니다.

AI 애플리케이션은 LLM 챗봇, RAG 애플리케이션, LLM 기반 워크플로우, AI 에이전트의 네 가지 형태로 진화하며, 현재는 자동화와 자율성이 결합된 '에이전트 시스템'이 주목받고 있습니다. AI 에이전트는 언어 모델을 통한 추론, 데이터베이스를 통한 메모리 확장, 도구를 통한 행동, 환경을 인지하는 입력에 기반한 자율적인 컴퓨팅 개체로 정의됩니다.

에이전트의 해부학적 구조는 추론(LLM), 메모리(무엇을 알고 무엇을 했는지), 도구 사용(어떻게 행동하는지), 인지(입력을 어떻게 보는지)로 구성됩니다. 발표자는 LLM 모델 자체(추론)는 프론티어 AI 랩에서 제공하는 부분으로 제어하기 어렵지만, 메모리, 도구 사용, 인지 부분은 '하네스'를 통해 엔지니어가 직접 구축하고 소유할 수 있다고 강조했습니다.

에이전트 하네스는 모델과 에이전트 루프 주변의 엔지니어링 스캐폴딩으로, 메모리, 검색, 컨텍스트 및 제어 계층을 포함하여 상태 비저장 LLM을 신뢰할 수 있고 반복 가능한 결과를 생성하는 시스템으로 전환합니다. 발표자는 "대부분의 '내 에이전트가 나쁘다'는 문제는 하네스 문제이지 모델 문제가 아니다"라고 주장했습니다.

하네스는 모델 계층, 스토리지 계층, 인코딩 및 검색, 메모리 계층, 의미론적 계층, 에이전트 루프, 컨텍스트 엔지니어링의 7가지 계층으로 구성됩니다.
-   **스토리지 계층**: 파일 시스템과 데이터베이스의 장단점을 비교하며, 에이전트가 보는 것은 파일이고, 지속되는 것은 데이터베이스라고 설명했습니다. 여러 에이전트가 동시에 파일에 쓰기 작업을 할 때 발생하는 일관성 문제를 해결하기 위해 '워크트리(Worktree)'와 같은 해결책이 있지만, 데이터베이스는 ACID 속성, 벡터 검색, 관계 및 랭킹, 확장성, 보안, 백업 기능을 기본으로 제공하여 더 강력한 솔루션이 됩니다.
-   **에이전트 메모리**: 에이전트 메모리는 단기 기억(작업 컨텍스트 윈도우, 의미론적 캐시)과 장기 기억(에피소드, 절차, 의미론, 엔티티)으로 나뉩니다. 장기 기억은 대화, 도구 로그, 요약, 워크플로우, 지식 베이스, 페르소나, 엔티티 등으로 구성됩니다.
-   **컨텍스트 엔지니어링**: LLM의 컨텍스트 윈도우 한계를 극복하기 위해 요약(Summarization)과 압축(Compaction) 기법을 사용합니다. 이는 컨텍스트 윈도우의 품질 저하를 방지하고, 더 많은 정보를 효율적으로 처리할 수 있게 합니다.
-   **에이전트 루프**: 에이전트 루프는 '관찰(Observe) → 컨텍스트 어셈블(Assemble_context) → 모델 호출(Call_model) → 도구 디스패치(Dispatch_tools) → 지속(Persist) → 종료(End)'의 흐름으로 작동하며, 각 계층을 구동하는 핵심 드라이버입니다. 동적 리콜, 오류 복구, 휴먼 게이트(human gate)와 같은 기능이 포함됩니다.
-   **도구 및 스킬**: 에이전트가 사용할 수 있는 도구와 스킬은 검색 가능한 메모리처럼 작동합니다. 새로운 도구나 스킬을 등록할 때 메타데이터와 함께 임베딩하여 스킬박스에 저장하고, 사용자의 쿼리에 따라 LLM이 가장 적합한 도구를 선택하여 로드합니다. SHA-256 버전을 사용하여 해시가 변경될 때만 새로 고칩니다.

지속적인 학습은 매개변수 메모리(가중치), 표현 메모리(잠재 공간), 비매개변수 메모리(컨텍스트/토큰 공간)의 세 가지 방식으로 이루어지며, 이 워크숍의 에이전트는 비매개변수 메모리에 중점을 둡니다.

데모에서는 GitHub Codespaces에서 실행되는 Jupyter Notebook 환경을 보여주었습니다. 이 환경에서 Meridian Bank의 가상 데이터를 사용하여 금융 사기 및 AML(자금세탁방지) 에이전트를 구축하는 과정을 실습합니다. 에이전트는 백그라운드에서 24시간 내내 작동하며, 의심스러운 거래를 자동으로 분석하고 플래그를 지정하여 사람이 검토할 수 있도록 합니다. 이는 사람의 개입 없이도 회사에 대한 자율적인 의사 결정을 내릴 수 있게 합니다.

-   "Skills sit in the system layer." (스킬은 시스템 계층에 존재한다.)

-   **컨텍스트 엔지니어링 기법 적용**: LLM의 컨텍스트 윈도우 한계를 극복하기 위해 대화 요약, 정보 압축, 동적 스킬 검색 등의 컨텍스트 엔지니어링 기법을 도입하여 에이전트의 성능과 효율성을 개선할 수 있습니다.
-   **모듈화된 스킬박스 패턴**: 재사용 가능한 스킬과 워크플로우를 모듈화하여 스킬박스 형태로 관리하고, 이를 임베딩하여 필요할 때마다 동적으로 불러오는 방식을 채택하면 에이전트의 확장성과 유지보수성을 높일 수 있습니다.
