# The Dark Arts of Web Automation: Teaching Agents to Use Websites Like Humans — Corey Gallon, Rexmore

## 핵심 주장
- **CDP 브라우저는 사람과 동일하게 작동한다:** Chrome DevTools Protocol(CDP)을 통해 제어되는 브라우저는 사람의 마우스 클릭 및 키 입력과 동일한 경로로 작동하며, 웹사이트가 이를 구분하기 어렵게 만듭니다.
- **CLI 기반의 자동화가 효율적이다:** 모델이 매번 개입하는 MCP(Model-in-the-loop) 방식보다 CLI(Command Line Interface) 기반의 코드를 사용하는 것이 재사용성, 속도, 토큰 비용 면에서 훨씬 효율적입니다.
- **디지털 감각을 통한 웹 상호작용:** CDP는 브라우저의 DOM 구조, CSS 스타일, 스크린샷(시각), 네트워크 트래픽, 콘솔 로그(청각) 등 다양한 "디지털 감각"을 제공하여 에이전트가 웹페이지를 인지하고 상호작용할 수 있게 합니다.
- **"미트백 사다리" 방법론:** 에이전트가 웹페이지의 방어 메커니즘에 따라 '가짜(Fake)', '실제(Real)', '인간(Human)'의 세 가지 층위로 상호작용 방식을 조절하는 "미트백 사다리" 방법론을 통해 캡차와 같은 복잡한 도전을 극복할 수 있습니다.
- **탐색 후 자동화:** 수동으로 웹페이지를 탐색하며 작동하는 솔루션을 찾은 후, 이를 코드로 작성하여 영구적으로 자동화하는 2단계 접근 방식이 효과적입니다.

## 세부 내용

발표자는 웹 자동화의 "어두운 기술"에 대해 이야기하며, 자신이 이 발표를 준비하던 중 OpenAI로부터 "사이버 남용" 혐의로 계정 정지 위협을 받았던 경험을 공유합니다. 그는 이 위협이 웹 브라우저를 사용한 작업 때문이었음을 밝히며, AI 에이전트가 사람처럼 웹사이트를 사용하는 방법을 시연합니다.

발표의 핵심 주장은 "CDP 브라우저는 마우스를 가진 미트백과 같다"는 것입니다. Chrome DevTools Protocol(CDP)을 사용하여 에이전트가 브라우저를 제어하면, 에이전트의 클릭과 키 입력이 사람의 것과 동일한 경로로 Chrome 내부를 이동합니다. 이는 Google, Cloudflare 등 웹사이트 방어 시스템이 에이전트와 사람을 구분하기 어렵게 만듭니다.

이러한 자동화를 성공시키기 위한 세 가지 방법론을 제시합니다.

1.  **CLI, not MCP (Command Line Interface, not Model-in-the-loop):**
    *   에이전트에게 CLI 기반의 셸 도구를 제공하여 코드로 브라우저를 제어합니다.
    *   MCP 방식(모델이 매번 개입)과 비교했을 때, CLI는 재사용성(한 번 작성하면 모델 개입 없이 무한 실행), 속도(동일 작업에 MCP는 8분 71회 왕복, CLI는 1분 미만 7회 왕복), 토큰 비용(75배 저렴) 면에서 우월합니다.

2.  **CDP (Chrome DevTools Protocol):**
    *   CDP는 브라우저 전체를 제어할 수 있는 57개의 도메인(8개 버킷으로 그룹화)과 수백 개의 메서드 및 이벤트를 제공합니다.
    *   에이전트는 이 중 웹 상호작용에 필요한 핵심적인 "디지털 감각"을 활용합니다.
        *   **SEE (시각):** DOM 구조, CSS 스타일, DOM 스냅샷, 페이지 스크린샷을 통해 페이지의 시각적 정보를 얻습니다.
        *   **HEAR (청각):** 네트워크 요청, 콘솔 로그, 감사(Audits)를 통해 페이지의 보고 내용을 파악합니다.
        *   **OPERATE (조작):** 입력(신뢰할 수 있는 이벤트), 런타임 평가, 페이지 탐색 등을 통해 사용자처럼 페이지를 조작합니다.

3.  **A loop on a ladder (사다리 위의 루프):**
    *   **루프:** "감지(Sense) → 행동(Act) → 검증(Verify)"의 과정을 페이지가 응답할 때까지 반복합니다. 중요한 것은 클릭 자체의 성공 여부를 믿지 않고, 네트워크나 화면 변화 등 다른 채널을 통해 검증하는 것입니다.
    *   **사다리:** 페이지의 방어 수준에 따라 세 가지 층위의 기술을 사용합니다.
        *   **Rung 1 (FAKE - 가짜):** 가장 기본적인 수준으로, 사람처럼 행동하지 않고 프로그램적으로 API를 호출하거나 합성 자바스크립트 클릭을 사용합니다. Outlook 웹 클라이언트에서 여러 이메일을 일괄 전송하는 데모를 통해 보여줍니다. 웹 UI 자체가 범용 API처럼 작동하는 경우에 유용합니다.
        *   **Rung 2 (REAL - 실제):** '가짜' 방식이 통하지 않을 때 사용하며, Chrome의 Input 도메인을 사용하여 실제 마우스 입력과 구별할 수 없는 '신뢰할 수 있는 클릭'을 생성합니다. Demazon(아마존 패러디)에서 '장바구니에 추가' 버튼을 클릭하는 데모에서, 합성 클릭은 무시되지만 신뢰할 수 있는 클릭은 성공하는 것을 보여줍니다.
        *   **Rung 3 (HUMAN - 인간):** 가장 높은 수준으로, 인간의 행동 패턴(마우스 경로, 지연, 흔들림)과 시각적 인지 능력을 결합합니다. Cloudflare Turnstile, MTcaptcha, Lemin(크롭된 캡차) 등 다양한 캡차를 해결하는 데모를 시연합니다. 특히 Lemin 캡차에서는 시각으로 퍼즐 조각의 위치를 파악하고, 사람처럼 부드럽게 움직이는 마우스 동작으로 조각을 드래그하여 맞춥니다.

이러한 방법론은 두 가지 단계로 이루어집니다: **탐색(Explore)**과 **자동화(Automate)**. 먼저 수동으로 루프를 실행하며 사다리 층위를 오르내려 작동하는 솔루션을 찾고, 그 다음 이 솔루션을 코드로 작성하여 영구적으로 자동화합니다.

발표자는 자신이 개발한 `chrome-agent` 도구를 사용하여 이 모든 시연을 진행했으며, 이 도구는 Python 생태계에서 설치 가능하다고 언급합니다. 마지막으로 OpenAI가 자신의 계정 정지 위협을 철회했으며, 이는 "규율 있는 엔지니어링은 사이버 남용이 아니다"라는 점을 이해했기 때문이라고 말하며 발표를 마칩니다.

- **CDP 활용 능력 강화:** Chrome DevTools Protocol(CDP)의 다양한 도메인과 기능을 이해하고 활용하여, 에이전트가 웹페이지의 DOM, CSS, 네트워크, 콘솔 로그 등을 '감지'하고 '조작'할 수 있도록 에이전트의 "디지털 감각"을 확장해야 합니다.
- **"미트백 사다리" 전략 적용:** 웹사이트의 방어 메커니즘에 따라 '가짜(합성 클릭)', '실제(신뢰할 수 있는 입력 이벤트)', '인간(인간과 유사한 마우스 움직임 및 시각 인지)' 층위를 유연하게 적용하여 자동화의 성공률을 높일 수 있습니다.
- **탐색-자동화 2단계 접근:** 복잡한 웹페이지 자동화 시, 먼저 수동으로 최적의 상호작용 시퀀스를 "탐색"하고, 그 다음 이를 코드로 "자동화"하여 재현 가능하고 효율적인 솔루션을 구축하는 것이 중요합니다.
