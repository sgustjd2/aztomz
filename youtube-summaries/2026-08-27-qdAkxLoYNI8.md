# How to Generate Mergeable Code with a Context Engine — Peter Werry, Unblocked

🔗 https://youtu.be/qdAkxLoYNI8 · 📅 2026-08-27 · 🎙 AI Engineer

## 한 줄 요약
언블록드(Unblocked)는 AI 에이전트가 코드베이스와 조직의 컨텍스트를 이해하도록 돕는 컨텍스트 엔진을 구축하여, 인간 개발자처럼 코드 변경의 의도, 팀 규칙, 과거 결정 등을 파악하고 더 빠르고 정확하며 비용 효율적인 작업을 수행하게 합니다.

## 발표자·소속
Peter Werry, Unblocked

## 핵심 주장
-   **AI 에이전트의 컨텍스트 부족 문제:** AI 에이전트는 새로운 작업을 시작할 때마다 코드베이스, 테스트 방식, 배포 방법 등 조직의 모든 지식을 재학습해야 하는 "신입 사원"과 같으며, 이는 비용을 증폭시킵니다.
-   **접근이 이해를 의미하지 않음:** 에이전트가 코드와 문서에 접근할 수 있다고 해서 그것을 완전히 이해하는 것은 아니며, 이는 방사선과 의사가 X-레이에서 하나의 지표를 찾고 검색을 멈춰 다른 중요한 지표를 놓치는 것과 유사합니다.
-   **숨겨진 컨텍스트의 중요성:** 컴파일되는 코드(빙산의 일각) 외에도 원래 의도, 팀 규칙, 과거 결정, 아키텍처 논리, 사고 학습 등 에이전트가 볼 수 없는 "숨겨진 컨텍스트"가 실제 작업을 수행하는 데 필수적입니다.
-   **컨텍스트 엔진의 역할:** 언블록드의 컨텍스트 엔진은 풀 리퀘스트(PR) 데이터, 슬랙(Slack) 대화, 노션(Notion) 문서 등 다양한 조직 데이터 소스를 통합하여 에이전트에게 관련 컨텍스트를 제공함으로써, 에이전트가 더 나은 품질의 코드를 더 빠르게, 더 적은 비용으로 생성하도록 돕습니다.

## 세부 내용
발표자는 먼저 언블록드가 컨텍스트 엔진을 구축하고 있다고 소개하며, 이 엔진이 인간 작업자와 AI 에이전트 모두에게 조직 컨텍스트를 제공한다고 설명합니다. 과거에는 인간 개발자들이 GitHub, Notion, Jira, Slack, Confluence, Datadog 등 여러 데이터 소스를 직접 찾아다니며 부족한 정보를 채우고 "부족한 지식(tribal knowledge)"을 쌓아 컨텍스트를 구축했습니다.

하지만 AI 에이전트가 등장하면서 이 문제는 더욱 심화됩니다. 에이전트는 매번 새로운 작업을 시작할 때마다 지식을 "재설정"하여 코드베이스, 테스트 방식, 소프트웨어 배포 방법 등을 다시 학습해야 합니다. 이는 마치 매번 새로 온 신입 사원과 같아서 비용이 기하급수적으로 증가합니다.

발표자는 AI 성숙도 곡선(AI maturity curve)을 제시하며, 현재 대부분의 조직이 자동 완성(Tab complete)이나 에이전트 IDE(Agent IDE) 단계를 넘어 컨텍스트 엔지니어링(Context engineering)이나 병렬 에이전트(Parallel agents) 단계에 있다고 설명합니다. 궁극적인 목표는 소프트웨어 팩토리(Software Factories)와 같은 완전 자동화된 에이전트 시스템이지만, 이를 위해서는 컨텍스트 레이어(Context layer)가 필수적입니다.

핵심 문제는 "접근이 이해를 의미하지 않는다"는 것입니다. 에이전트가 코드와 문서에 접근할 수 있어도, 인간처럼 깊이 있는 이해를 하지 못합니다. 이는 방사선과 의사가 X-레이에서 암 지표 하나를 발견하고 다른 중요한 지표를 놓치는 "검색 만족(satisfaction of search)" 현상과 유사합니다. 에이전트는 올바른 정보를 찾았다고 생각하면 탐색을 멈추기 때문에, 모든 조각이 어떻게 연결되는지 이해하지 못합니다.

발표자는 "코드 컴파일(Code that compiles)"이라는 빙산의 일각 비유를 통해, 에이전트가 볼 수 있는 것은 코드뿐이지만, 실제 중요한 것은 코드 아래 숨겨진 "원래 의도, 팀 규칙, 과거 결정, 아키텍처 논리, 사고 학습" 등이라고 강조합니다. 에이전트가 이러한 컨텍스트 없이는 제대로 작동할 수 없습니다.

**데모:**
1.  **언블록드 Q&A:** 언블록드 웹 인터페이스에서 "Sourcemark 엔진은 어떻게 작동하나요?"라고 질문하자, 언블록드는 코드 스니펫과 함께 엔진의 아키텍처 다이어그램을 자동으로 생성하여 상세히 설명합니다. 이 다이어그램은 기존에 존재하지 않던 것으로, 언블록드가 코드를 분석하여 생성한 것입니다. 답변에는 관련 문서 링크도 포함되어 신뢰를 높입니다.
2.  **슬랙 통합:** 슬랙 채널에서 언블록드 봇에게 "언블록드의 사용자 참여 지표는 무엇이며 어떻게 작동하나요?"라고 질문하자, 언블록드는 관련 지표, 파이프라인, 데이터 흐름에 대한 상세한 답변을 제공합니다.
3.  **Claude Code와 비교:** Claude Code에 "Sourcemark 계산기를 최적화하기 위한 계획을 세워주세요"라고 요청하자, Claude Code는 계획을 제시합니다. 하지만 언블록드를 사용했을 때와 비교하여, 언블록드는 50% 더 적은 토큰을 사용하고, 더 빠른 분류(triage), 더 나은 답변을 제공하며, 비용도 더 저렴합니다(Claude Code: $1.22, 2분 35초 vs. Unblocked: $0.93, 1분 18초). 이는 언블록드가 불필요한 정보를 걸러내고 핵심 컨텍스트에 집중하기 때문입니다.
4.  **코드 리뷰 에이전트:** 언블록드는 GitHub 풀 리퀘스트에 대한 코드 리뷰를 수행하며, 과거의 관련 슬랙 대화나 PR 코멘트를 컨텍스트로 제시하여 리뷰 에이전트의 이해도를 높입니다. 발표자는 언블록드가 과거의 코멘트를 정확히 찾아내어 "내가 할 말이었는데!"라는 반응을 이끌어낸 사례를 보여줍니다.
5.  **오픈 소스 프로젝트:** 언블록드는 Document Query Engine(자연어 질의를 GitHub PR/이슈 데이터에 대한 MongoDB 집계 파이프라인으로 변환)과 Engineering Social Graph(GitHub PR 기여 패턴을 기반으로 개발자 협업 관계를 시각화)라는 두 가지 오픈 소스 프로젝트를 소개합니다.

**컨텍스트 엔진 시뮬레이터:** 언블록드는 컨텍스트 엔진 시뮬레이터를 통해 컨텍스트를 사용했을 때와 사용하지 않았을 때의 품질 개선(+7점), 작업 속도(-22%), 작업 비용(-33%) 차이를 시각적으로 보여줍니다.

## 인상적인 대목
-   "AI-generated code should feel like it was written by someone who's been on your team for years. But it doesn't today." (AI가 생성한 코드는 마치 수년간 팀에 있었던 사람이 작성한 것처럼 느껴져야 합니다. 하지만 오늘은 그렇지 않습니다.)
-   "Now your agents have the same problem. Only the cost compounds." (이제 에이전트들도 같은 문제를 겪습니다. 단지 비용이 복리로 증가할 뿐입니다.)
-   "The problem: access ≠ understanding" (문제: 접근이 이해를 의미하지 않는다)
-   "What your agent can't see" (당신의 에이전트가 볼 수 없는 것)이라는 빙산의 일각 비유는 에이전트가 코드 외의 중요한 컨텍스트를 놓치고 있음을 명확히 보여줍니다.
-   "~50% fewer tokens, faster triage, and Unblocked's answer was actually better because it wasn't buried in noise." (약 50% 더 적은 토큰, 더 빠른 분류, 그리고 언블록드의 답변은 노이즈에 묻히지 않았기 때문에 실제로 더 좋았습니다.)

## 실무 적용 포인트
-   **AI 에이전트 온보딩 개선:** AI 에이전트가 매번 새로운 작업을 시작할 때마다 지식을 재학습하는 비효율성을 줄이기 위해, 조직의 모든 문서, 코드, 대화 기록 등을 통합하는 컨텍스트 레이어를 구축하는 것을 고려해야 합니다.
-   **코드 리뷰 프로세스 강화:** AI 기반 코드 리뷰 도구를 활용하여 과거의 관련 논의, 결정, 모범 사례 등을 자동으로 리뷰어에게 제공함으로써 코드 품질을 높이고 리뷰 시간을 단축할 수 있습니다.
-   **조직 지식 그래프 구축:** Engineering Social Graph와 같은 도구를 사용하여 코드베이스 내 전문가와 팀 간의 관계를 시각화하고, 이를 통해 지식 격차를 파악하고 협업을 최적화할 수 있습니다.
-   **자연어 기반 코드베이스 질의:** Document Query Engine과 같은 도구를 도입하여 자연어로 코드베이스에 질문하고, 복잡한 쿼리나 파이프라인을 자동으로 생성하여 개발자들이 필요한 정보를 더 쉽게 찾을 수 있도록 지원합니다.
