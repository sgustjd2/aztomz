# Voice Agents Can Just Do Things — Charlie Guo, OpenAI

🔗 https://youtu.be/OpY6MmZFeHo · 📅 2026-09-15 · 🎙 AI Engineer

## 한 줄 요약
OpenAI의 개발자 경험 담당 Charlie Guo는 음성 에이전트가 단순히 음성으로 응답하는 것을 넘어, 행동을 수행하고 이벤트에 반응하며, 특히 실시간 모델을 통해 더 풍부하고 자연스러운 상호작용을 제공함으로써 접근성을 높이고 새로운 디자인 모드를 가능하게 한다고 주장합니다.

## 발표자·소속
Charlie Guo, OpenAI 개발자 경험(Developer Experience)

## 핵심 주장
- **음성 에이전트의 오해 극복**: 음성 모델이 반드시 음성으로 응답해야 한다는 오해를 넘어, 음성 입력에 대한 응답은 음성, 행동, 또는 이벤트에 대한 음성 반응 등 다양한 형태로 이루어질 수 있습니다.
- **세 가지 유용한 상호작용 모드**: 음성-음성, 음성-행동, 이벤트-음성 세 가지 모드를 통해 음성 에이전트의 활용 가능성을 확장하며, 이들은 상호 배타적이지 않고 조합될 때 최상의 제품 경험을 제공합니다.
- **음성-행동 모드의 잠재력**: 음성-행동 모드는 현재 가장 덜 탐구된 분야로, 양식 작성, 창의적 도구 활용, 컴퓨터 사용 등 다양한 영역에서 음성을 통해 소프트웨어를 제어하는 혁신적인 방법을 제시합니다.
- **실시간 모델을 통한 커뮤니케이션 개선**: OpenAI의 GPT-Realtime-2와 같은 실시간 모델은 음성 입력과 출력을 직접 처리하여 기존의 텍스트 변환 방식에서 발생하는 톤, 억양, 감정, 배경 소음 등의 손실을 줄이고 지연 시간을 대폭 단축합니다.
- **접근성 향상 및 AGI의 미래**: 음성 에이전트는 손의 움직임에 제약이 있는 개발자들에게 코딩 능력을 되찾아주는 등 접근성을 크게 향상시킬 수 있으며, 궁극적으로 AGI(범용 인공지능)는 타이핑이 아닌 음성으로 소통하게 될 것이라고 예측합니다.

## 세부 내용

발표자는 OpenAI의 개발자 경험 팀에서 개발자들이 OpenAI 모델(텍스트, 이미지, 오디오)을 사용하여 무엇을 어떻게 구축하는지 이해하는 일을 하고 있다고 소개하며 강연을 시작했습니다. 그는 음성 에이전트에 대한 한 가지 오해, 즉 "음성 모델은 반드시 응답해야 한다"는 생각에 대해 이야기했습니다. 그는 "음성은 응답하는 유일한 방법이 아니다"라고 강조하며, 모델이 충분히 지능적이고 유능해지면서 세 가지 새로운 디자인 모드가 등장하고 있다고 설명했습니다.

첫 번째 모드는 **음성-음성(Speech → speech)**입니다. 사용자가 말하면 모델이 다시 말하는 방식입니다. 이는 언어 학습을 위한 실시간 연습 및 코칭, 컨시어지 경험(고객 지원을 넘어선), 실시간 번역 등에 활용될 수 있습니다. 발표자는 모델이 충분히 빠르고 정확해져서 실시간으로 콘텐츠를 번역할 수 있으며, 내년 기조연설에서는 여러 언어로 실시간 더빙될 수도 있다고 언급했습니다.

두 번째 모드는 **음성-행동(Speech → action)**입니다. 사용자가 말하면 모델이 도구를 사용하는 방식입니다. 발표자는 이 모드가 가장 덜 탐구된 영역 중 하나라고 강조했습니다. 그는 인터넷의 많은 부분이 양식 작성으로 이루어져 있는데, 음성을 통해 양식을 채우고 빠르게 검토하는 것이 훨씬 우월한 경험이 될 것이라고 설명했습니다. 또한, 창의적 도구(음악, 그림) 분야에서도 음성으로 아이디어를 전달하여 결과물을 만드는 것이 가능해질 것이며, 궁극적으로는 컴퓨터 전체를 음성으로 제어하는 시대가 올 것이라고 예측했습니다. 그는 개발자들이 이미 가지고 있는 앱에 오디오를 지능 계층으로 추가하는 것이 생각보다 쉽다고 말하며, API 엔드포인트나 React 훅과 같은 기존 소프트웨어의 구성 요소를 모델이 사용할 수 있는 도구로 전환할 수 있다고 설명했습니다. 또한, 인터페이스는 또 다른 커뮤니케이션 채널이므로 알림, 상태 변경, 텍스트 하이라이트, 커서 애니메이션 등 다양한 시각적 피드백을 활용하여 사용자와 소통할 수 있다고 덧붙였습니다.

세 번째 모드는 **이벤트-음성(Event → speech)**입니다. 모델이 이벤트를 수신하고 사용자에게 말하는 방식입니다. 이는 핸즈프리 경험(예: 요리 중 레시피 앱 사용)이나 사전 예방적 아웃리치(모델이 사용자의 주의를 끌어야 할 때)에 유용합니다. 발표자는 아직 AI 네이티브가 이 분야에서 어떤 모습일지 완전히 알 수 없다고 말했습니다.

발표자는 이 모든 모드의 근간에는 **접근성(Accessibility)**이라는 더 큰 주제가 있다고 강조했습니다. 그는 손의 움직임에 제약이 생겨 프로그래머 경력이 끝났다고 생각했던 여러 개발자들이 대규모 언어 모델과 음성 에이전트 덕분에 이전보다 훨씬 많은 코드를 생성할 수 있게 되었다는 개인적인 일화를 공유하며, 음성 기술이 더 넓은 세상에 접근성을 제공할 수 있다고 말했습니다.

그는 이러한 세 가지 모드를 혼합하고 매칭하는 것이 중요하다고 언급하며, 인카(in-car) 어시스턴트(자연스러운 대화, 음악 재생, 교통 알림)나 AI 게임 캐릭터(정보 획득, 스토리 진행, 세계에 반응)와 같은 예시를 들었습니다.

발표자는 "왜 지금 구축해야 하는가?"라는 질문에 답하며, 기존 음성 에이전트가 음성 입력 → 음성 텍스트 변환 → 언어 모델 → 텍스트 음성 변환 → 음성 출력의 체인 방식으로 작동했다고 설명했습니다. 이 방식은 톤, 억양, 감정, 방해, 배경 소음 등 많은 정보를 손실시켰습니다. 또한, GPT-3.5 음성 모드는 2.8초, GPT-4 음성 모드는 5.4초의 높은 지연 시간을 보였습니다.

이에 비해 OpenAI는 **네이티브 오디오 접근 방식**을 채택하여 음성 입력 → 실시간 모델 → 음성 출력으로 직접 처리합니다. 이 방식은 전사(transcription) 과정 없이 네이티브 오디오를 토큰으로 학습하여 연속적인 스트리밍 오디오 입출력을 가능하게 합니다. OpenAI의 **GPT-Realtime-2** 모델은 이러한 접근 방식을 통해 320ms의 낮은 지연 시간을 달성했습니다. 이 모델은 추론 수준, 서문(preambles), 병렬 도구 호출, 더 긴 컨텍스트, 도메인 이해, 컨텍스트 오버턴, 더 자연스러운 음성, 제어 가능한 톤 등의 개선 사항을 포함합니다. 특히 서문 기능은 모델이 도구를 호출하거나 생각하는 동안 사용자에게 미리 알려주는 방식으로 지연 시간을 관리할 수 있게 합니다. 벤치마크에서는 "Big bench audio: intelligence"에서 96.0%의 정확도를 기록하여 GPT-Realtime 1.5의 81.4%보다 훨씬 뛰어난 성능을 보였습니다.

마지막으로 발표자는 음성 에이전트를 구축할 때 "어떤 종류의 음성 에이전트를 만들 것인가?"라는 질문 대신 "이 상호작용에서 음성과 오디오의 역할은 무엇인가?"라는 질문으로 시작해야 한다고 조언했습니다. 이 질문은 "모델이 무엇을 인지할 수 있는가?", "지금 어떻게 소통해야 하는가?", "어떤 행동을 안전하게 취할 수 있는가?", "시스템은 언제 조용히 있어야 하는가?"와 같은 더 많은 질문으로 이어진다고 말했습니다. 그는 "AGI는 타이핑이 아닌 음성으로 소통하게 될 것"이라는 말로 강연을 마무리했습니다.

## 실무 적용 포인트
- **음성 인터페이스 설계 시 역할 중심 사고**: 음성 에이전트를 구축할 때 특정 "음성 에이전트" 유형에 얽매이지 말고, 해당 상호작용에서 음성과 오디오가 수행해야 할 "역할"에 집중하여 디자인 목표를 설정합니다.
- **다중 모드 커뮤니케이션 활용**: 음성 응답 외에도 시각적 알림, UI 상태 변경, 텍스트 하이라이트, 커서 애니메이션 등 다양한 인터페이스 요소를 활용하여 사용자에게 정보를 전달하고 상호작용의 풍부함을 더합니다.
- **기존 소프트웨어에 음성 지능 계층 추가**: 현재 서비스 중인 웹 애플리케이션의 API 엔드포인트나 React 훅과 같은 기존 액션들을 음성 모델이 사용할 수 있는 "도구"로 정의하여, 사용자가 음성으로 소프트웨어를 제어할 수 있도록 확장합니다.
- **실시간 모델을 통한 지연 시간 최적화**: 음성-텍스트 변환 과정을 생략하고 네이티브 오디오를 직접 처리하는 실시간 모델(예: GPT-Realtime-2)을 활용하여 음성 상호작용의 지연 시간을 최소화하고, 서문(preambles) 기능을 통해 모델이 복잡한 작업을 수행할 때 사용자에게 미리 알림으로써 사용자 경험을 개선합니다.
