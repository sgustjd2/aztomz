# Agents That Write Their Own Tools at Runtime — Sandhya Subramani, AWS

🔗 https://youtu.be/33Oct2hqGnk · 📅 2026-10-04 · 🎙 AI Engineer

## 한 줄 요약
AI 에이전트가 런타임에 자체 도구와 에이전트를 생성하고 활용하며, 심지어 스스로 코드를 수정하여 문제를 해결하는 메타 툴링(meta-tooling) 개념을 시연하고 설명합니다.

## 발표자·소속
Sandhya Subramani, Senior Developer Advocate, Amazon Web Services (AWS)

## 핵심 주장
*   **런타임에 도구 생성 및 활용:** 에이전트가 사용자 요청에 따라 필요한 도구를 실시간으로 생성하고 로드하여 즉시 사용할 수 있습니다. 이는 기존에 명시적으로 프로그래밍되지 않은 기능도 에이전트가 스스로 학습하고 구현할 수 있음을 의미합니다.
*   **동적 에이전트 생성:** 메타 에이전트(meta-agent)는 복잡한 작업을 여러 개의 하위 에이전트(sub-agent)로 분해하고, 각 하위 에이전트를 동적으로 생성하여 특정 작업을 수행하도록 지시할 수 있습니다.
*   **자체 코드 업데이트 능력:** 에이전트가 자신의 소스 코드를 이해하고, 필요에 따라 스스로 수정하여 기능을 개선하거나 버그를 해결하는 자가 개선(self-improvement) 능력을 가질 수 있습니다.
*   **안전 및 신뢰를 위한 가드레일:** 에이전트의 자율성과 능력이 증가함에 따라, 환경 제약, 도구 제약, 권한 제약, 그리고 관찰 가능성(observability)을 통해 안전하고 신뢰할 수 있는 시스템을 구축하는 것이 중요합니다.

## 세부 내용
발표는 2026년 7월 2일 AI Engineer World's Fair Expo Stage에서 진행되었으며, Sandhya Subramani는 "Agents That Forge Their Own Tools"라는 주제로 발표했습니다. 그녀는 기존의 코드 편집기나 클라우드 코드 도구들이 이미 코드를 작성할 수 있지만, 에이전트가 런타임에 스스로 버그를 인지하고, 필요한 도구를 작성하여 자신을 수정하는 "메타 툴링(meta-tooling)"의 개념이 얼마나 강력한지 강조했습니다.

**데모 1: 런타임에 도구 생성**
발표자는 `strands-meta-tooling-demo`라는 VS Code 환경에서 `agent.py` 파일을 실행했습니다. 이 에이전트는 `strands` 프레임워크의 `Agent`와 `strands_tools`의 `editor`, `shell`, `load_tool`이라는 세 가지 기본 도구만 가지고 시작합니다. 시스템 프롬프트는 "당신은 런타임에 자체 사용자 지정 도구를 생성하고 사용하는 메타 툴링 에이전트입니다"라고 설정되어 있습니다.
1.  사용자가 "복잡한 수학 방정식을 계산하는 데 도움을 주세요"라고 입력하자, 에이전트는 기존 도구를 확인한 후 `editor` 도구를 사용하여 `tools` 디렉토리에 `math_calculator.py`라는 새로운 도구 파일을 생성했습니다.
2.  이후 `load_tool` 도구를 사용하여 새로 생성된 도구를 로드했습니다.
3.  에이전트는 `math_calculator`가 사칙연산, 삼각함수, 로그 함수, 복소수 등을 지원한다고 설명했습니다.
4.  사용자가 "456789의 제곱은 무엇인가요?"라고 묻자, 에이전트는 방금 생성한 `math_calculator` 도구를 호출하여 "456789의 제곱은 675861.656..."이라는 정확한 답을 제공했습니다.
5.  이어서 사용자가 "내 단어의 문자 수를 세어주세요"라고 입력하자, 에이전트는 기존 도구로는 이 작업을 수행할 수 없음을 인지하고 `editor` 도구를 사용하여 `character_counter.py`라는 새로운 도구를 생성했습니다.
6.  생성된 `character_counter` 도구를 `load_tool`로 로드한 후, 에이전트는 사용자가 입력한 임의의 문자열("sdyujkbhvftyuikembgbfyucol")의 문자 수가 28개라고 정확히 세어주었습니다. 짧은 문자열 "rty"에 대해서도 3개의 문자가 있다고 정확히 세었습니다.

**Strands Agents 프레임워크 설명**
발표자는 이 데모가 AWS에서 개발한 오픈소스 에이전트 하네스(Agent Harness) SDK인 "Strands Agents"를 사용하여 구축되었음을 설명했습니다. 이 프레임워크는 몇 줄의 코드로 에이전트를 구축할 수 있으며, 모델에 구애받지 않고(model agnostic), MCP(Model-Centric Programming) 및 AZA(Agent-Centric Programming)를 지원하며, 프로덕션 준비가 되어 있습니다. 특히 `Agent` 클래스 초기화 시 `load_tools_from_directory=True` 옵션을 통해 에이전트가 런타임에 동적으로 도구를 로드할 수 있도록 합니다.

**데모 2: 에이전트가 자체 에이전트 구축**
발표자는 에이전트가 도구를 넘어 자체 에이전트를 구축하는 시나리오를 시연했습니다.
1.  `strands-meta-agents-demo` 환경에서 메타 에이전트(meta-agent)가 실행됩니다. 이 메타 에이전트의 시스템 프롬프트는 "당신은 메타 에이전트 아키텍트입니다. 사용자가 사용 사례를 설명하면, 당신은 1. 계획: 2-4개의 하위 에이전트로 분해하여 계획을 출력합니다. 2. 구축: 각 하위 에이전트를 `./agents`에 도구 파일로 작성합니다. 'editor'를 사용하여 각 파일을 생성한 다음 'load_tool'로 로드합니다. 3. 오케스트레이션: 모든 하위 에이전트가 로드되면, 사용자 요청을 해결하기 위해 순서대로 호출합니다."라고 명시되어 있습니다.
2.  사용자가 "하와이로 비행 중입니다. 여정 계획을 도와주세요"라고 입력하자, 메타 에이전트는 이 작업을 `flight_agent`, `activities_agent`, `itinerary_agent`의 세 가지 하위 에이전트로 분해하는 계획을 제시했습니다.
3.  메타 에이전트는 `editor` 도구를 사용하여 이 세 가지 하위 에이전트 파일(`flight_agent.py`, `activities_agent.py`, `itinerary_agent.py`)을 `agents` 디렉토리에 동적으로 생성하고, `load_tool`을 사용하여 로드했습니다.
4.  이후 메타 에이전트는 `flight_agent`와 `activities_agent`를 병렬로 호출하여 비행 정보와 활동 정보를 수집한 후, `itinerary_agent`를 호출하여 3일간의 상세한 하와이 여행 일정을 종합하여 제공했습니다.

**가드레일 및 자율성 증가**
발표자는 에이전트의 자율성과 능력이 증가함에 따라 신뢰와 안전을 보장하기 위한 "가드레일(Guardrails)"의 중요성을 강조했습니다.
*   **환경 제약:** 샌드박스 환경(컨테이너/임시 작업 공간), 네트워크 송신 제어(허용 목록 도메인), 기본적으로 읽기 전용(쓰기 시 의도 필요) 등을 통해 에이전트의 실행 환경을 제한합니다.
*   **도구 제약:** 도구 허용 목록 및 스키마(유형화된 입/출력), 시간 초과, 재시도, 속도 제한, 프롬프트/로그의 민감 정보 삭제 등을 통해 도구 사용을 제어합니다.
*   **권한 제약:** 최소 권한 ID(범위 지정 IAM), 작업별 권한 부여 확인, 고위험 작업에 대한 사람의 승인 등을 통해 에이전트의 권한을 관리합니다.
*   **관찰 가능성:** 도구 호출 및 아티팩트의 감사 로그, 추적 및 메트릭(지연 시간/비용/오류율), 변경 사항에 대한 평가 스위트 및 회귀 게이트 등을 통해 에이전트의 행동을 모니터링하고 평가합니다.

발표자는 Strands Agents가 "자체 도구 구축"에서 시작하여 "동적으로 에이전트 생성"을 거쳐 "자체 소스 코드 업데이트" 단계에 이르렀다고 설명하며, 실제로 Strands Agents의 Python 버전이 TypeScript 버전을 스스로 작성했다고 언급했습니다. 이는 에이전트의 자율성과 에이전시(agency)가 지속적으로 증가하고 있음을 보여줍니다.

## 실무 적용 포인트
*   **런타임 도구 생성 활용:** 개발자는 에이전트가 특정 작업을 수행할 수 있는 도구가 없을 때, 런타임에 해당 도구를 생성하고 로드하여 사용하는 메타 툴링 패턴을 적용해 에이전트의 유연성과 적응성을 높일 수 있습니다.
*   **멀티 에이전트 시스템 설계:** 복잡한 문제를 해결하기 위해 메타 에이전트가 여러 하위 에이전트를 동적으로 생성하고, 이들 간의 협업(swarms), 데이터 흐름(graphs), 또는 순차적 작업(workflows)을 오케스트레이션하는 패턴을 활용하여 시스템을 구축할 수 있습니다.
*   **자가 개선 에이전트 개발:** 에이전트가 자신의 코드베이스를 이해하고, 오류 발생 시 스스로 코드를 수정하거나 새로운 기능을 추가하는 자가 개선 메커니즘을 구현하여 유지보수 비용을 줄이고 시스템의 복원력을 향상시킬 수 있습니다.
*   **AI 시스템의 안전성 확보:** 에이전트의 자율성이 높아질수록 샌드박싱, 도구 허용 목록, 최소 권한 원칙, 사람의 승인, 그리고 상세한 로깅 및 평가 스위트와 같은 가드레일을 반드시 적용하여 오작동이나 악의적인 행위를 방지해야 합니다.
