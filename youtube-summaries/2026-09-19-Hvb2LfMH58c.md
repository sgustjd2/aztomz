# The Frontier AI Inference Cloud for Agents — Byung-Gon (Gon) Chun, FriendliAI

🔗 https://youtu.be/Hvb2LfMH58c · 📅 2026-09-19 · 🎙 AI Engineer

## 한 줄 요약
FriendliAI는 에이전트 워크플로우의 고유한 과제(긴 컨텍스트, 반복되는 프리픽스, 비모델 작업의 인터리빙)를 해결하기 위해 특별히 설계된 프론티어 AI 추론 클라우드를 제공하여, 프로덕션 에이전트를 더 빠르고, 저렴하며, 안정적으로 만듭니다.

## 발표자·소속
Byung-Gon Chun (Gon), Founder and CEO, FriendliAI

## 핵심 주장
- **에이전트의 폭발적인 성장과 오픈웨이트 모델의 경제성:** 2026년은 에이전트가 대규모 프로덕션에 도입되는 해가 될 것이며, 오픈웨이트 모델은 프론티어 수준의 지능을 제공하면서도 비용 효율성을 크게 향상시켜 에이전트의 경제성을 확보합니다.
- **에이전트 추론은 기존 챗봇과 다른 문제:** 에이전트 작업은 여러 모델 호출과 도구 호출을 포함하며, 컨텍스트가 계속 누적되고 확장됩니다. 따라서 단일 요청의 지연 시간이 아닌 전체 작업의 완료 시간을 최적화하는 것이 중요합니다.
- **FriendliAI의 에이전트 중심 추론 스택:** FriendliAI는 프리픽스 캐싱, KV 캐시 관리, 캐시 인식 라우팅, 에이전트 인식 최적화 등 에이전트 워크플로우의 고유한 특성에 맞춰 추론 클라우드를 재구축하여 이러한 과제를 해결합니다.
- **향상된 성능과 비용 효율성:** FriendliAI의 에이전트 중심 설계는 동일한 에이전트 작업을 다른 추론 제공업체보다 훨씬 빠르게(예: 2배 이상, 특정 테스트에서는 7배 더 빠름) 완료하고, 토큰 비용을 크게 절감하여 생산 에이전트의 실질적인 배포를 가능하게 합니다.

## 세부 내용

발표자는 2026년이 에이전트가 프로덕션에 대규모로 도입되는 해가 될 것이라고 주장하며, 이는 두 가지 주요 트렌드에 의해 주도된다고 설명합니다. 첫째, 코딩, 운영, 연구 및 지식 작업 전반에서 AI 에이전트의 채택이 폭발적으로 증가하고 있습니다. 둘째, 오픈웨이트 모델이 프론티어 수준에 도달하여 에이전트를 경제적으로 만들고 있습니다. 발표자는 FriendliAI의 GLM-5.2 모델과 Anthropic의 Opus-4.8 모델을 사용하여 타워 디펜스 게임을 코딩하는 에이전트의 데모를 보여주며, 두 모델 모두 워크플로우를 성공적으로 완료하여 오픈웨이트 모델이 실제 에이전트 워크플로우에 충분히 강력하다는 것을 입증했습니다.

하지만 경제성은 크게 다릅니다. 동일한 에이전트 작업에 대해 Opus-4.8은 약 1.50달러가 드는 반면, FriendliAI의 GLM-5.2는 27센트가 들어 5.6배 더 저렴합니다. 발표자는 모델 비용 외에도 에이전트가 실제로 빠르고 안정적으로 작동하려면 추론 스택 자체가 변경되어야 한다고 강조합니다.

기존 챗봇은 짧은 입력과 출력, 1대1 응답 지연 시간에 초점을 맞췄지만, 에이전트는 여러 모델 호출과 도구 호출을 포함하며 자율적으로 실행되는 "작업"이 기본 단위입니다. 따라서 사용자는 개별 요청의 지연 시간이 아닌 전체 작업이 완료되는 시점에 관심을 가집니다. 에이전트 워크플로우는 계획(LLM 호출), 실행(도구 호출), 관찰(컨텍스트에 결과 추가)의 반복적인 루프를 통해 진행됩니다. 이 과정에서 컨텍스트는 계속 누적되고, 연속적인 에이전트 단계는 큰 프리픽스를 공유합니다. 매번 이 프리픽스를 재계산하는 것은 비효율적입니다.

이러한 에이전트 추론의 고유한 문제점(컨텍스트 누적 및 성장, 비모델 작업의 인터리빙, 입력에 따라 달라지는 호출 수, 엔드투엔드 작업 지연 시간의 중요성)을 해결하기 위해 FriendliAI는 추론 클라우드를 재구축했습니다. 핵심 엔지니어링 요소는 다음과 같습니다.
1.  **프리픽스 캐싱:** 공유 프리픽스 KV(Key Value)를 한 번 계산하고 캐싱하여 중복된 프리필을 건너뛰고, 작업이 길어질수록 이득이 커집니다.
2.  **KV 캐시 관리:** GPU 메모리, 호스트 메모리, 디스크에 걸쳐 계층적 캐싱을 사용하고, KV 캐시 양자화를 통해 메모리 사용량을 줄이며, 분산 캐싱을 통해 여러 복제본에서 프리픽스를 공유합니다.
3.  **캐시 인식 라우팅:** 분산 클러스터에서 캐시 인식 라우터를 사용하여 요청을 이미 적절한 프리픽스를 캐싱하고 있는 GPU 파드로 보내 캐시 적중률을 최대화하고 부하를 분산합니다.
4.  **에이전트 인식 최적화:** 개별 호출이 아닌 에이전트 수준 컨텍스트를 기반으로 최적화합니다. 이는 선제적 스케줄링, 추측성 프리필, 에이전트 인식 캐시 제거와 같은 기술을 통해 엔드투엔드 작업 지연 시간을 줄이는 것을 목표로 합니다.

이러한 기술들을 통합하여 FriendliAI는 Kilo Code를 사용하여 간단한 모바일 게임을 생성하는 데모에서 다른 잘 알려진 추론 제공업체보다 2배 이상 빠른 1분 47초 만에 작업을 완료했습니다. Kilo의 사용 후기에 따르면 FriendliAI는 7배 더 빠르고 훨씬 낮은 오류율을 보였습니다. FriendliAI는 모델 API, 전용 엔드포인트, BYOG(Bring Your Own GPU)의 세 가지 방식으로 배포를 지원합니다.

## 실무 적용 포인트
- **오픈웨이트 모델 활용 고려:** 프론티어급 성능을 제공하는 오픈웨이트 모델을 활용하여 에이전트 개발 비용을 절감하고 경제성을 확보할 수 있습니다.
- **엔드투엔드 작업 지연 시간 최적화:** 에이전트 시스템 설계 시 개별 LLM 호출의 지연 시간보다는 전체 에이전트 작업의 완료 시간을 핵심 지표로 삼고 최적화해야 합니다.
- **프리픽스 캐싱 및 KV 캐시 관리 도입:** 에이전트 워크플로우의 반복적인 특성을 고려하여 프리픽스 캐싱, KV 캐시 양자화, 계층적/분산 캐싱을 통해 추론 효율성을 극대화할 수 있습니다.
- **에이전트 인식 스케줄링 및 라우팅 구현:** 에이전트 프로그램의 전체 컨텍스트를 이해하고 스케줄링, 캐싱, 라우팅 결정을 내리는 시스템을 구축하여 성능을 더욱 향상시킬 수 있습니다.
