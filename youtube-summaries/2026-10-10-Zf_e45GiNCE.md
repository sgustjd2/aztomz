# Zero Cold Starts: Serverless AI Agents on Akamai Functions — Thorsten Hans

🔗 https://youtu.be/Zf_e45GiNCE · 📅 2026-10-10 · 🎙 AI Engineer

## 한 줄 요약
발표자는 Akamai Functions와 CNCF Spin을 활용하여 Edge-Native AI 애플리케이션(MCP 서버 및 AI 에이전트)을 구축하는 방법을 시연하며, 이를 통해 지연 시간, 콜드 스타트, 과도한 프로비저닝, 벤더 종속성 등의 인프라 문제를 해결하고 개발 생산성을 높일 수 있다고 강조합니다.

## 발표자·소속
Thorsten Hans, Sr. Developer Advocate, Akamai

## 핵심 주장
-   **WebAssembly 기반의 휴대성과 개방성:** WebAssembly는 코드를 한 번 컴파일하여 에지를 포함한 모든 곳에서 실행할 수 있는 휴대성을 제공하며, CNCF Spin과 WASI/WebAssembly는 개방형 표준을 기반으로 벤더 종속성을 제거합니다.
-   **Akamai Functions를 통한 속도 및 제로 콜드 스타트:** Akamai Functions는 평균 0.4ms의 콜드 스타트 시간을 제공하여 AI 도구 호출을 즉각적으로 만들고, 빠른 응답 시간과 시장 출시 기간 단축을 가능하게 합니다.
-   **NoOps 개발자 경험:** Akamai Functions는 컨테이너나 VM 관리가 필요 없는 완전 관리형 플랫폼으로, 개발자는 인프라가 아닌 비즈니스 로직에만 집중할 수 있어 개발 생산성이 극대화됩니다.

## 세부 내용

발표는 AI 엔지니어링 컨퍼런스에서 진행되었으며, Thorsten Hans는 Akamai의 Sr. Developer Advocate로서 Edge-Native AI 애플리케이션 구축에 대해 발표했습니다.

**MCPs 및 AI 에이전트 인프라 마찰**
MCP(Model Context Protocol) 서버와 AI 에이전트는 빠른 응답 시간을 요구하지만, 기존의 지역 기반 아키텍처는 다음과 같은 문제점을 야기합니다.
-   **지연 시간:** 에이전트와 오리진이 동일한 클라우드 지역에 있지 않으면 지연 시간이 극적으로 증가하여 사용자 경험이 저하됩니다. 중앙 집중식 배포는 일부 사용자에게만 빠릅니다.
-   **콜드 스타트:** 컨테이너와 VM은 부트스트랩에 몇 초에서 몇 분까지 걸리며, 예상치 못한 사용자 수요에 빠르게 대응하기 어렵습니다.
-   **과도한 프로비저닝:** 인프라를 미리 워밍업 상태로 유지하면 상당한 재정적 지출과 과도한 에너지 낭비가 발생하여 환경적으로 지속 불가능합니다.
-   **벤더 종속성:** 독점 런타임은 단일 공급업체에 묶이게 하여 워크로드 마이그레이션을 복잡하고 비용이 많이 들게 합니다.

**Edge-Native AI 스택**
이러한 문제에 대한 해결책으로 WebAssembly를 서버 측에 도입하는 것을 제안합니다. WebAssembly는 컨테이너가 가상 머신과 유사하게 바이너리 크기가 작고, 배포가 용이하며, 실행 속도가 빠르고, 휴대성이 뛰어납니다. Edge-Native AI 스택은 CNCF Spin과 Akamai Functions의 조합으로 구성됩니다.
-   **CNCF Spin:** WebAssembly 기반 서버리스 애플리케이션을 컴포넌트 모델로 구축하기 위한 개발자 도구입니다. CLI, WASI(WebAssembly System Interface) 호환 런타임, 언어별 SDK를 제공하여 개발 생산성을 높입니다. Rust, TypeScript, Python 등 WebAssembly로 컴파일 가능한 모든 언어로 앱을 코딩할 수 있습니다.
-   **Akamai Functions:** 완전 관리형 글로벌 분산 서버리스 엣지 컴퓨팅 플랫폼으로 WebAssembly 워크로드를 실행합니다. 평균 0.4ms의 제로 콜드 스타트, 글로벌 분산, 완전 관리형(클라우드 인프라 관리 불필요), WebAssembly 샌드박스 내 제로 트러스트 보안, 내장된 키-값 저장소 등의 특징을 가집니다.

**데모: wasmcp를 사용한 MCP 서버 구축**
발표자는 `wasmcp` CLI 도구를 사용하여 MCP 서버를 구축하는 과정을 시연했습니다.
1.  `wasmcp new --language typescript hello` 명령으로 TypeScript 기반의 'hello' 프로젝트를 생성합니다.
2.  `index.ts` 파일에는 `listTools` 및 `callTool` 함수를 포함한 기본 코드가 있습니다. `ExampleToolSchema`로 입력 스키마를 정의합니다.
3.  `make` 명령으로 TypeScript 코드를 WebAssembly 컴포넌트로 컴파일합니다.
4.  `wasmcp compose server dist/hello.wasm -o server.wasm` 명령으로 WebAssembly 컴포넌트를 완전한 MCP 서버로 구성합니다.
5.  `spin up -f server.wasm` 명령으로 서버를 로컬(localhost:3000)에서 실행합니다.
6.  MCP Inspector(v0.22.0) 브라우저 도구를 사용하여 로컬 서버에 연결하고 "Example Tool"을 실행하여 "foo"를 입력하면 "Received: foo"를 반환하는 것을 확인합니다.

**데모: Akamai Functions에 MCP 서버 배포**
다음으로 Rust로 구현된 `decision-log-mcp` 프로젝트를 Akamai Functions에 배포하는 과정을 시연했습니다.
1.  `decision-log-mcp` 프로젝트의 `decision.rs` 파일은 키-값 저장소를 사용합니다. 로컬에서는 Spin이 SQLite를 사용하고, Akamai Functions에서는 내장된 글로벌 분산 키-값 저장소를 사용합니다.
2.  `spin aka deploy --no-confirm --build` 명령으로 애플리케이션을 빌드하고 Akamai Functions에 배포합니다. 배포에는 약 60초가 소요됩니다.
3.  배포 완료 후 `https://b1762282-ad78-41f7-a6a5-3e050cfd832b.fwf.app`와 같은 앱 라우트 URL을 받습니다.
4.  Zed Agent(AI 기능을 갖춘 IDE)를 사용하여 원격 MCP 서버를 추가합니다.
5.  `delete_decision`, `get_decision_by_slug`, `insert_decision`, `list_decisions`, `update_decision` 등 5가지 CRUD 도구가 표시됩니다.
6.  "Track a decision to use Oauth2.0 for authn" 프롬프트를 입력하면, 에이전트가 `insert_decision` 도구를 실행할 의도를 파악하고 권한을 요청합니다.
7.  에이전트는 OAuth 2.0에 대한 세부 정보를 제공하고, "Give me all the decisions please" 프롬프트에 `list_decisions` 도구를 사용하여 응답합니다.

**데모: AI 에이전트 구축**
Vercel AI SDK를 사용하여 AI 에이전트를 구축하는 과정을 시연했습니다.
1.  `game-agent` 프로젝트의 `index.ts` 파일은 `flipCoinTool`과 `rollDiceTool`을 정의합니다.
2.  `app.post("/agent")` 핸들러는 Ollama 인스턴스(Linode에 배포된 전용 GPU 사용)를 가리키는 `ToolLoopAgent`를 생성하고 도구를 등록합니다.
3.  `spin aka deploy --no-confirm --build` 명령으로 빌드 및 배포를 진행합니다.
4.  `curl` 명령으로 `https://b1762282-ad78-41f7-a6a5-3e050cfd832b.fwf.app/agent` 엔드포인트에 "Toss a coin" 프롬프트를 보냅니다.
5.  응답으로 "The coin toss resulted in tails." 또는 "heads."를 받습니다.
6.  `x-envoy-upstream-service-time` 헤더를 통해 LLM을 통한 전체 루프에 약 820ms가 소요되었음을 확인합니다. 이는 Akamai Functions에 배포된 WebAssembly 애플리케이션이 JavaScript 런타임을 포함하더라도 네이티브 JavaScript 애플리케이션보다 콜드 스타트 및 런타임 성능 면에서 빠르다는 것을 의미합니다.

**개발자 워크플로우**
개발자 워크플로우는 다음과 같습니다.
1.  **개발(Develop):** Rust, TypeScript, Python 등 WebAssembly로 컴파일 가능한 언어를 사용하여 MCP 및 에이전트를 구현합니다.
2.  **로컬 테스트(Test Locally):** `spin` CLI를 사용하여 MCP 서버 또는 AI 에이전트를 구성하고 로컬에서 원활하게 실행합니다.
3.  **배포(Deploy):** `spin aka deploy` 단일 명령어를 사용하여 Akamai Functions에 배포합니다.
4.  **사용(Consume):** 클라이언트를 제공된 MCP 서버/AI 에이전트 엔드포인트로 연결합니다.

## 실무 적용 포인트
-   **WebAssembly 도입 고려:** 고성능, 저지연, 휴대성이 중요한 서버리스 AI 애플리케이션 개발 시 WebAssembly(Wasm) 런타임을 적극적으로 고려합니다.
-   **Akamai Functions 활용:** 제로 콜드 스타트 및 글로벌 분산이 필수적인 엣지 AI 워크로드에 Akamai Functions와 같은 엣지 컴퓨팅 플랫폼을 활용하여 사용자 경험을 최적화하고 운영 부담을 줄입니다.
-   **CNCF Spin으로 개발 생산성 향상:** `spin` CLI와 `wasmcp` 같은 도구를 사용하여 AI 에이전트 및 MCP 서버 개발 시 인프라 설정 대신 비즈니스 로직 구현에 집중하여 개발 시간을 단축합니다.
-   **다국어 개발 환경 활용:** Rust, TypeScript, Python 등 익숙한 언어로 WebAssembly 애플리케이션을 개발하고, 이를 통해 팀의 기존 기술 스택을 활용하면서 엣지 컴퓨팅의 이점을 누립니다.
