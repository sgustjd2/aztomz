## 발표 흐름

### 도입: GenAI 플랫폼 팀의 목표
발표자들은 도어대시의 중앙 GenAI 플랫폼 팀 소속으로, 회사 내 모든 제품 팀이 생성형 AI를 활용할 수 있도록 돕는 수평적 조직입니다. 이들의 핵심 목표는 제품 팀들이 **정확성(Accuracy), 지연 시간(Latency), 비용(Cost)** 이라는 세 가지 상충하는 요소를 올바르게 절충(trade-off)하여 최적의 품질을 달성하도록 지원하는 것입니다. 이 원칙은 LLM 모델뿐만 아니라 AI 에이전트에도 동일하게 적용됩니다.

### 도어대시 GenAI 플랫폼의 4가지 시스템
도어대시의 GenAI 플랫폼은 모든 AI 제품을 지원하기 위해 4가지 핵심 시스템으로 구성됩니다.
1.  **LLM 게이트웨이:** 다양한 LLM 모델(최신 모델 포함) 간에 쉽게 전환할 수 있게 하여, 비용과 성능의 균형을 맞출 수 있도록 합니다. 주당 6억 건 이상의 API 호출을 처리합니다.
2.  **에이전트 게이트웨이:** AI 에이전트가 외부 도구 및 다른 에이전트와 안전하게 연결되도록 지원합니다. 인증, 에이전트 신원 확인 등을 중앙에서 관리하여 보안팀의 승인을 용이하게 합니다. 일일 30만 건 이상의 도구 호출을 처리합니다.
3.  **슬링샷(Slingshot):** 오픈소스 경량 모델(open-weight models)을 호스팅하여 비용을 절감합니다. LLM 게이트웨이와 연동되어 수백만 달러의 비용 절감 효과를 가져왔습니다.
4.  **평가(Evals):** AI 모델과 에이전트의 품질을 추적, 주석 처리, 보정하는 시스템입니다. 이 발표의 핵심 주제입니다.

### 문제 정의: 파편화된 평가(Eval)의 필요성
플랫폼을 구축하며 다양한 제품 팀과 소통한 결과, 모든 AI 제품이 평가를 필요로 하지만 그 형태와 요구사항이 매우 다르다는 것을 발견했습니다.
- **다중 턴 대화형 AI (소비자 검색 및 쇼핑 어시스턴트):** 수백만 사용자의 전체 대화 세션(multi-turn transcripts)에 대한 품질 판단이 필요했습니다.
- **개인화 ML:** 사용자의 선호도를 학습하기 위해 인간의 판단과 일치하는, 프로덕션 등급의 자동화된 평가자(judge)가 필요했습니다.
- **에이전트 운영 시스템:** 수백만 개의 자동화된 의사결정을 처리하는 다중 에이전트 시스템을 위해, 전체 작업 궤적(trajectory) 수준의 평가와 대규모 주석 처리가 필요했습니다.

이처럼 다양한 요구사항을 하나의 공통 플랫폼에서 어떻게 지원할 것인가가 핵심 과제였습니다.

### 플랫폼의 진화: 도메인 전문가 중심의 품질 관리
이 문제를 해결하는 과정에서 중요한 깨달음을 얻었습니다. **"품질 판단은 도메인을 아는 사람들의 몫이다."** 즉, 엔지니어뿐만 아니라 제품 관리자(PM), 전략 및 운영(S&O) 팀, 외부 레이블링 파트너 등 도메인 전문가들이 품질 평가의 주체가 되어야 한다는 것입니다. 이 깨달음을 바탕으로 플랫폼은 세 단계에 걸쳐 진화했습니다.

1.  **UI-First:** 비엔지니어도 쉽게 사용할 수 있는 주석 인터페이스를 제공하여, 스프레드시트 기반의 작업을 플랫폼으로 이전했습니다.
2.  **API-First:** 안정적인 API 계약을 제공하여, 엔지니어링 팀이 중앙 플랫폼에 종속되지 않고 독립적으로 맞춤형 워크플로우를 구축할 수 있도록 했습니다.
3.  **Workflow-First:** 코딩 에이전트를 활용하여, 비엔지니어(PM, S&O)가 플랫폼 API를 기반으로 임시 워크플로우 실행 및 맞춤형 UI를 직접 생성할 수 있도록 지원했습니다.

결론적으로, 평가는 단순한 엔지니어링 테스트 하네스가 아니라, **여러 부서가 함께 품질을 운영하는 인프라**라는 것이 이들의 핵심 논지입니다.

### 평가 워크플로우: 8단계의 지속적인 루프
도어대시는 AI 품질 관리를 8단계로 구성된 하나의 지속적인 루프로 정의했습니다.
1.  **추적(Trace) → 샘플링(Sample):** 프로덕션 환경의 동작을 캡처하고, 평가할 가치가 있는 부분을 선택합니다.
2.  **주석(Annotate) → 검토(Review):** 인간 전문가가 예시에 레이블을 지정하고, 의견 불일치 지점을 검토합니다.
3.  **골든셋 생성(Create golden sets) → 보정(Calibrate):** 확정된 데이터셋을 정답(ground truth)으로 삼고, 이를 기준으로 평가자(judge)를 보정합니다.
4.  **모니터링(Monitor) → 반복(Repeat):** 드리프트를 추적하고, 새로운 예시를 루프에 다시 투입하여 지속적으로 개선합니다.

### 1. 추적 및 샘플링: API-First 플랫폼 기반
- 플랫폼의 기반은 API-First입니다. API는 안정적인 계약 역할을 하며, UI는 그 위에 구축된 클라이언트입니다.
- 추적, 점수, 데이터셋, 작업, 검토, 평가자 등 모든 요소가 하나의 플랫폼 데이터 모델을 공유합니다.
- SQL 접근 및 SDK 추적 기능을 제공하여, 팀들이 자신만의 분석을 수행할 수 있도록 지원합니다.

### 2. 주석 및 검토: 규모에 맞는 인간의 판단
- 주석 작업은 단순한 스프레드시트 작업이 아닌, 하나의 워크플로우입니다.
- 팀마다 품질을 판단하는 데 필요한 컨텍스트가 다르므로, 공유된 계약(API) 위에 전문화된 인터페이스를 구축하는 방식을 채택했습니다.
- **예시:**
    - **메모리 블록 주석:** 구조화된 다단계 검토, 레이블이 지정된 컨텍스트 창 제공.
    - **이미지 주석:** 바운딩 박스, 폴리곤 도구, 레이블 계층 구조 제공.
    - **수동 테스트(JETS):** 정답 기반의 수동 테스트, 검토자를 위한 전체 컨텍스트 제공.
- 코딩 에이전트를 활용해 비전문가도 자신에게 필요한 맞춤형 주석 UI를 직접 생성할 수 있도록 지원했습니다.

### 3. 골든셋 생성 및 보정: 자동화 보정
- 평가자(Judge)는 전문가의 판단을 재현할 수 있을 때만 유용합니다.
- 보정(Calibration) 과정은 인간의 판단과 자동화된 평가자 간의 정렬 상태를 가시화하고 검토 가능하게 만듭니다.
- **GEPA(Genetic Eval-based Prompt Augmentation)**와 같은 도구를 사용하여 프롬프트 최적화를 감사 가능한 프로세스로 전환합니다.
- **보정 프로세스:**
    1.  **시작:** 평가자 프롬프트와 주석 처리된 예시(기준선)를 준비합니다.
    2.  **기준선 설정:** 초기 평가를 실행하고 점수를 기록합니다.
    3.  **최적화:** GEPA가 후보 프롬프트를 탐색하고, 반복 과정을 추적하며 스냅샷을 남깁니다.
    4.  **수락:** 소유자가 최적화 전후 결과를 검토하고, 개선된 프롬프트를 저장합니다.
- 이 모든 과정을 비전문가도 쉽게 실행할 수 있도록 셀프서비스 UI로 제공합니다.

### 4. 모니터링 및 반복: 품질 루프의 실제 적용
- 이 지속적인 품질 루프는 측정 가능한 절감 효과로 이어졌습니다.
- **40% 비용 절감:** 스프레드시트에서 Evals UI로 전환 후, 작업당 주석 비용이 40% 감소했습니다.
- **더 빠른 루프:** 아이디어 구상부터 주석 처리된 데이터를 얻기까지의 과정이 더 적은 핸드오프로 더 빠르게 진행됩니다.
- **복리 효과(Compounding savings):** 재사용 가능한 워크플로우가 일회성 스크립트를 대체하면서 시간이 지남에 따라 비용 절감 효과가 누적됩니다.

## 구체 수치·데모·아키텍처
- **LLM 게이트웨이 처리량:** 600M+ API calls/week (주당 6억 건 이상)
- **에이전트 게이트웨이 처리량:** 300K+ daily tool calls (일일 30만 건 이상)
- **비용 절감 효과:** 주석 작업 UI 도입 후 작업당 비용 40% 감소.
- **아키텍처: 품질 트레이드오프 삼각형:** 정확성(Accuracy), 지연 시간(Latency), 비용(Cost)의 균형을 맞추는 것이 핵심 목표임을 시각화.
- **아키텍처: GenAI 플랫폼 4대 시스템:** LLM Gateway, Agent Gateway, Slingshot, Evals.
- **아키텍처: Evals 워크플로우 루프:** [Trace → Sample] → [Annotate → Review] → [Create golden sets → Calibrate] → [Monitor → Repeat]의 8단계 순환 구조.
- **아키텍처: 플랫폼 모델:** Telemetry layer(추적, 점수, 데이터셋, API 등)와 Workflow layer(주석, 검토, 평가 등)의 두 가지 연결된 기능으로 구성.
- **아키텍처: GEPA 보정 워크플로우:** Start → Baseline → Optimize → Accept의 4단계 프로세스.
- **도구/제품명:**
    - **Slingshot:** 도어대시의 오픈소스 경량 모델 호스팅 시스템.
    - **GEPA (Genetic Eval-based Prompt Augmentation):** 프롬프트 최적화를 위한 도구.
- **데모/UI 스크린샷:**
    - **주석 UI 예시:** 레스토랑 메뉴 항목에 대해 선호도(like, dislike, neutral) 태그를 지정하는 화면.
    - **보정 실행 설정 UI:** 평가자, 데이터셋, 모델, 예산, 검색 전략 등을 설정하는 셀프서비스 화면.
    - **보정 결과 UI:** 보정 전후의 점수 변화, 프롬프트 변경 내역(diff), 점수 진행 그래프를 보여주는 검토 화면.
