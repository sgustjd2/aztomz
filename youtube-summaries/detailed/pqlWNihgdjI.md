# From AI-Assisted to AI-Native: Building a Frontier Development Team — Clare Liguori, AWS

🔗 https://www.youtube.com/watch?v=pqlWNihgdjI

## 개요
*   **발표자:** 클레어 리구오리 (Clare Liguori), AWS 수석 프린시펄 엔지니어 (Senior Principal Engineer)
*   **주제:** 단순한 AI 지원(AI-Assisted) 개발을 넘어, AI를 핵심으로 활용하는 AI 네이티브(AI-Native) 개발팀으로 전환하기 위한 방법과 실제 사례를 소개합니다.

## 발표 흐름
### 서론: AI 개발의 새로운 단계
발표자는 AWS의 에이전트 기반 코딩 어시스턴트인 'Q'(영상에서는 'Kiro'로도 언급됨) 개발에 참여하며, 아마존 내부 팀들이 AI를 활용해 생산성에서 '계단 함수(step-function)'적인, 즉 비약적인 향상을 이루는 사례들을 목격했다고 밝힙니다. 이 발표에서는 이러한 성공적인 변화를 이끈 구체적인 프랙티스들을 공유합니다.

### AI 개발 지원 도구의 진화 과정
발표자는 지난 3년간 AI 코딩 어시스턴트가 4단계로 진화해왔다고 설명합니다.

1.  **인라인 코드 완성 (Inline code completion):** 다음 줄이나 함수를 자동으로 완성해주는 초기 단계.
2.  **코드에 대한 질문 (Ask questions about my code):** 채팅 인터페이스를 통해 코드에 대해 질문하고 답변을 얻는 단계.
3.  **바이브 코딩 (Vibe coding):** 대략적인 아이디어나 느낌을 전달하면 AI가 코드를 생성해주는 단계.
4.  **프론티어 개발 (Frontier development):** 개발의 패러다임 자체를 바꾸는 새로운 단계.

초기 3단계(AI-Assisted)는 발표자의 개인적인 경험상 약 10~20%의 생산성 향상을 가져왔습니다. 하지만 '프론티어 개발' 단계에 이른 팀들은 내부 파일럿 연구 결과, **중앙값(median) 4.5배, 일부 팀은 10배 이상의 생산성 향상**을 보였습니다. 이는 단순한 도구 도입을 넘어선 근본적인 변화가 일어났음을 시사합니다.

### '프론티어 개발자'의 3가지 행동 특성
발표자는 이러한 비약적 생산성 향상을 이룬 '프론티어 개발자'들의 공통적인 행동 3가지를 정의합니다.

1.  **손 떼고 코딩하기 (Hands-off coding):** 전체 코드 중 단 1~2%만 직접 작성합니다. 나머지는 모두 AI 에이전트가 생성합니다.
2.  **에이전트와 드물게 상호작용하기 (Interact with agents infrequently):** 에이전트에게 작업을 지시한 후, 사람의 개입 없이 몇 시간 동안 스스로 실행하도록 목표를 설정합니다.
3.  **에이전트 유휴 시간 최소화 (Minimize agent idle time):** 여러 에이전트를 병렬로 실행하여 끊임없이 밀려드는 작업 백로그를 처리하게 함으로써 유휴 시간을 줄입니다.

### 사례 연구 1: 선구자(Pathfinder) - Amazon Bedrock Mantle 팀
*   **과제:** Amazon Bedrock의 새로운 추론 데이터 플레인(Inference Data Plane) 구축.
*   **기존 예상:** 30명의 엔지니어가 18개월 동안 작업.
*   **실제 결과 (Kiro 에이전트 활용):** **6명의 엔지니어가 76일 만에 완료.**
    *   프로젝트 기간 86% 단축.
    *   필요 인력 80% 감축.
    *   주간 커밋 수 20배 증가 (기존 2개 → 40개).
*   **한계점:** 이 팀은 2명의 디스팅귀시드 엔지니어(Distinguished Engineers)와 4명의 프린시펄/수석 프린시펄 엔지니어로 구성된, 아마존 내 최고 수준의 '어벤져스' 팀이었습니다. 따라서 이 결과가 일반적인 팀에서도 재현될 수 있을지에 대한 의문이 남았습니다.

### 사례 연구 2: 스프린트(Sprint) - Prime Video Financial Systems 팀
*   **과제:** 일반적인 엔지니어 6명을 한 방에 모아 10일간 집중적으로 실험.
*   **목표:** '선구자' 팀의 성과를 일반 팀에서도 재현할 수 있는지 검증.
*   **실제 결과:**
    *   프로젝트 예상 기간이 90주에서 24주로 73% 단축.
    *   커밋 수가 기준선(96개) 대비 556개로 5.8배 증가.
*   **한계점:** 이 또한 이상적인 환경이었습니다. 참가자들은 온콜(on-call) 업무나 회의 없이 오직 개발에만 집중했고, 시니어 엔지니어가 3주간 사전 작업을 통해 모든 태스크를 명확하게 정의하고 세분화해두었습니다. 이는 여전히 '실제 업무 환경'과는 거리가 있었습니다.

### 사례 연구 3: 파일럿(Pilot) - Amazon Stores
*   **과제:** 50개의 '평범한' 팀을 대상으로 2025년까지 AI 도입 효과를 연구. 이 팀들은 일반적인 경력 분포를 가지며, 기존에 운영되던 브라운필드(brownfield) 시스템에서 작업했습니다.
*   **핵심 발견:** 팀들은 두 그룹으로 나뉘었습니다.
    *   **그룹 1 (50%):** 기존 작업 방식에 AI 도구를 '뿌리는(sprinkled)' 수준으로 활용. **3배 미만의 생산성 향상**에 그쳤습니다.
    *   **그룹 2 (50%):** AI 도구를 활용해 **의도적으로 새로운 작업 방식을 도입**. **중앙값 4.5배의 생산성 향상**을 달성했습니다.
*   **결론:** 도구 자체가 아니라, **'일하는 방식을 바꾸는 것'**이 생산성 비약의 핵심 요인이었습니다.

### 프론티어 팀의 5가지 습관
이러한 사례들을 통해 도출된, AI 네이티브 개발을 위한 5가지 핵심 습관은 다음과 같습니다.

1.  **에이전트 컨텍스트에 투자하라 (Invest in agent context):** 에이전트가 실수를 할 때마다 "내 스킬 파일에 무엇이 빠졌지?"라고 자문하고, 새로운 모델이 나올 때마다 "이 내용이 아직도 필요한가?"를 검토하며 컨텍스트를 지속적으로 관리해야 합니다.
2.  **속도를 내기 위해 속도를 늦춰라 (Slow down to speed up):** 에이전트 컨텍스트 구축, 기존 도구의 에러 메시지 개선, 코드베이스 리팩토링, 심지어 프로그래밍 언어 변경 등, 장기적인 생산성 향상을 위한 의도적인 엔지니어링 작업에 시간을 투자해야 합니다.
3.  **에이전트를 '돌보지' 말고 '먹여라' (Feed agents, don't babysit):** 모호한 지시 후 계속해서 수정하는 '돌보기(Babysitting)' 방식 대신, '무엇을 할지(what to do)'와 '어떻게 검증할지(how to validate)'를 명확히 제공하는 '먹이기(Feeding)' 방식으로 전환해야 합니다. 예를 들어, 단순히 "API에 인증 추가"가 아니라, "API에 인증 추가하고, 유닛 테스트를 실행하여 통과시키고, 새 코드에 대해 90% 커버리지를 달성하고, 통합 테스트를 추가하여 인증을 검증하라"고 구체적으로 지시해야 합니다.
4.  **의도를 명확하게 하라 (Make intent explicit):** 모호한 프롬프트 대신, 목표, 사용 사례, 핵심 기능, 기술 요구사항 등이 명시된 구조화된 명세서(Specification)를 작성해야 합니다. 코드 대신 명세서를 두고 AI와 반복적으로 소통하는 것이 더 효율적입니다.
5.  **테스트를 앞으로 당겨라 (Shift testing left):** 에이전트가 빠르고 국소적인 피드백 루프(fast, local feedback loop)를 가질 수 있도록 환경을 구축해야 합니다. 린터(Linters), 모의 서비스(Mock services), 유닛 테스트 등을 통해 에이전트가 외부 의존성 없이 로컬 환경에서 스스로 오류를 수정하고 검증할 수 있게 해야 합니다.

### 여전히 어려운 점들: 번아웃과 조직적 변화
프론티어 개발로의 전환은 여전히 어려운 과제들을 동반합니다.

*   **번아웃(Burnout):**
    *   **FOMAT (Fear Of Missing Agent Time):** 에이전트가 작업하는 시간을 놓칠까 봐 두려워 늦게까지 완벽한 프롬프트를 만들려는 강박.
    *   병렬로 실행하는 에이전트 수가 늘어날수록 인지 부하(cognitive load)가 증가.
    *   AI가 생성한 코드를 리뷰하는 것이 직접 작성하는 것보다 더 어려울 수 있음 (특히 주니어 개발자에게).
*   **조직적 변화(Organizational change):**
    *   '속도를 내기 위해 속도를 늦추는' 개념을 조직 전체가 받아들이기 어려움.
    *   너무 넓은 범위에 너무 빠르게 변화를 적용하려는 시도는 실패하기 쉬움.
    *   코드 작성이 더 이상 병목이 아니게 되면서, 의사결정 속도나 제품 출시 승인 절차 등 새로운 병목 지점이 드러남.

### 결론
발표자의 핵심 메시지는 명확합니다. AI 시대에 비약적인 생산성 향상을 이루기 위해서는 단순히 도구를 도입하는 것을 넘어, **의도적으로 일하는 방식을 바꾸어야 합니다.**

## 구체 수치·데모·아키텍처
*   **10-20%:** AI-Assisted 단계(인라인 완성, 챗봇 등)에서 얻는 일반적인 생산성 향상률.
*   **4.5배:** AI-Native 방식을 도입한 팀에서 나타난 생산성 향상의 중앙값.
*   **10배 이상:** 일부 AI-Native 팀에서 달성한 최대 생산성 향상률.
*   **1-2%:** 프론티어 개발자가 직접 손으로 작성하는 코드의 비율.
*   **Amazon Bedrock Mantle 프로젝트:**
    *   **예상:** 30명, 18개월
    *   **실제:** 6명, 76일 (86% 기간 단축, 80% 인력 감축)
    *   **커밋 수:** 20배 증가 (주당 2개 → 40개)
*   **Prime Video Financial Systems 스프린트:**
    *   **프로젝트 기간:** 90주 → 24주로 73% 단축 예상.
    *   **커밋 수:** 5.8배 증가 (기준 96개 → 556개)
*   **Amazon Stores 파일럿:**
    *   **연구 대상:** 50개의 "평범한" 팀.
    *   **AI-Assisted 그룹:** <3배 생산성 향상.
    *   **AI-Native 그룹:** 4.5배 생산성 향상 (중앙값).
*   **도구/제품명:**
    *   **Q / Kiro:** 발표자가 언급한 AWS의 에이전트 기반 코딩 어시스턴트.
    *   **Amazon Bedrock:** AWS의 파운데이션 모델 호스팅 서비스.
*   **피딩(Feeding) 프롬프트 예시:** "Add authorization to this API. Add unit tests. Run the unit tests; ensure they pass and achieve 90% coverage for the new code. Add integ tests to validate authorization and ensure they pass." (API에 인증을 추가하고, 유닛 테스트를 추가/실행하여 통과 및 90% 커버리지를 달성하고, 통합 테스트를 추가하여 인증을 검증하고 통과시켜라.)
*   **피드백 루프 도구 목록:** Linters, Mock services, Unit tests, Integration tests, Performance tests, Security tests.

## 핵심 인용
*   "Internal pilot study shows 4.5x median productivity improvement; some teams more than 10x." (내부 파일럿 연구 결과, 중앙값 4.5배, 일부 팀은 10배 이상의 생산성 향상을 보였습니다.)
*   "Hands-off coding: Hand-write 1-2% of the code they produce." (손 떼고 코딩하기: 그들이 생산하는 코드의 1~2%만 직접 작성합니다.)
*   "Feed agents, don't babysit." (에이전트를 돌보지 말고, 먹이를 주십시오.)
*   "My one big takeaway: Intentionally change the way you work." (저의 가장 큰 교훈은 이것입니다: 의도적으로 당신이 일하는 방식을 바꾸십시오.)

## 한 줄 결론
AI를 통한 개발 생산성의 비약적인 향상은 단순히 도구를 도입하는 것이 아니라, 에이전트가 스스로 작업하고 검증할 수 있도록 컨텍스트를 제공하고 테스트 환경을 구축하는 등, '일하는 방식'을 근본적으로 바꾸는 의도적인 노력에서 비롯됩니다.
