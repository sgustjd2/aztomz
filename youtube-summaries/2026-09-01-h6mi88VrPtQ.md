# x402 isn’t good (yet) — Jan Curn, Apify

🔗 https://youtu.be/h6mi88VrPtQ · 📅 2026-09-01 · 🎙 AI Engineer

## 한 줄 요약
Apify의 Jan Curn은 AI 에이전트 간의 자율적인 상거래를 가능하게 하는 에이전트 결제 프로토콜, 특히 x402의 현재 상태와 과제를 논하며, 이 기술이 아직 초기 단계이지만 미래 에이전트 경제의 핵심이 될 것이라고 주장합니다.

## 발표자·소속
Jan Curn, Apify 공동 창업자 겸 CEO

## 핵심 주장
-   **에이전트 결제 프로토콜의 부상:** AI 에이전트가 자율적으로 작업을 수행하기 위해 현금(예산)이 필요하게 되면서, L402, Mastercard Agent Pay, x402, Agent Payments Protocol (AP2), Agentic Commerce Protocol (ACP) 등 다양한 에이전트 결제 프로토콜이 빠르게 등장하고 있습니다.
-   **암호화폐 기반 결제의 적합성:** 기존 결제 방식(신용카드, PayPal 등)은 마이크로 트랜잭션에 비효율적이고 구매자 분쟁 문제가 있어 에이전트 간 거래에 부적합합니다. 반면, 암호화폐는 낮은 수수료와 환불 불가(no chargebacks) 특성으로 에이전트 결제에 매우 적합합니다.
-   **x402 프로토콜의 초기 과제:** x402는 HTTP 402 상태 코드를 활용하여 결제를 요구하지만, 이로 인해 이중 지불(double-spending) 문제와 가변 사용량(metered billing) 처리의 어려움이 발생합니다. 또한, 기존 MCP(Machine-to-Client Protocol)와 OAuth 표준과의 충돌로 인해 API 호스트를 복제해야 하는 비효율적인 해결책이 사용되고 있습니다.
-   **Apify의 AGI(Agent General Interface)와 미래 비전:** Apify는 에이전트가 Apify의 45,000개 이상의 웹 자동화 도구(Actors)를 쉽게 사용할 수 있도록 AGI(Agent General Interface)를 개발했습니다. 이는 에이전트가 Apify 토큰을 구매하여 다양한 결제 프로토콜을 통해 작업을 실행할 수 있게 하며, 궁극적으로 에이전트 경제가 일반 상거래를 능가할 것이라고 예측합니다.

## 세부 내용

발표자는 작년 AI Engineer World's Fair에서 Sentry의 David Cramer가 "MCP isn't good (yet)"이라는 제목으로 MCP(Machine-to-Client Protocol)의 초기 미흡함을 지적했으나, 1년 만에 Sentry MCP가 시장 최고의 MCP 서버 중 하나가 되었고, Claude와 ChatGPT 같은 주요 AI 에이전트들이 MCP 커넥터(Claude)나 앱(ChatGPT)을 제공하며 MCP가 에이전트-도구 상호작용의 표준이 되었다는 점을 언급하며 강연을 시작합니다.

이러한 흐름에 영감을 받아, 발표자는 자신의 강연 제목을 "x402 isn't good (yet)"으로 정하고, Apify가 x402 프로토콜을 통해 에이전트 결제 시장에 진출한 경험을 공유합니다. Apify는 45,000개 이상의 "Actors"라고 불리는 AI 도구 마켓플레이스를 운영하며, 소셜 미디어, 이커머스, 여행, 검색 엔진 등 다양한 분야의 데이터 추출 및 자동화 서비스를 제공합니다. Apify 커뮤니티는 이 도구들을 판매하여 월 100만 달러 이상을 벌어들이고 있습니다.

Apify는 에이전트가 이러한 도구에 쉽게 접근할 수 있도록 에이전트 결제에 큰 기대를 걸고 있습니다. 발표 2일 전, Apify는 Coinbase와 협력하여 x402 통합을 출시했으며, 이를 통해 20,000개 이상의 도구를 에이전트 시장에 추가하여 총 30,000개 이상으로 확장했습니다. 이 소식은 약 100만 조회수를 기록하며 큰 관심을 받았습니다.

발표자는 에이전트가 인간의 감독 없이 작업을 완료하려면 예산이 필요하며, 이는 에이전트 경제의 핵심이라고 강조합니다. 지난 1년간 에이전트 결제 프로토콜 분야에서 L402(Lightning Labs/Bitcoin Lightning, 2020년 중반), Mastercard Agent Pay(Mastercard, 2025년 4월), x402(Coinbase, 2025년 5월), KYAPay(Skyfire with Visa, 2025년 6월), Agent Payments Protocol (AP2, Google, 2025년 9월), Agentic Commerce Protocol (ACP, OpenAI/Stripe, 2025년 9월), Trusted Agent Protocol (TAP, Visa, 2025년 10월), Universal Commerce Protocol (UCP, Google+Shopify, 2026년 1월), Agentic Commerce Trust Protocol (ACTP, Alipay, 2026년 1월), Machine Payments Protocol (MPP, Stripe/Tempo, 2026년 3월), Agentic Mobile Protocol (AMP, Alipay, 2026년 4월), Agentic Payment Open Protocol (APOP, UnionPay, 2026년 4월), OKX Agent Payments Protocol (APP, OKX, 2026년 4월), Agent Pay for Machines (Mastercard, 2026년 6월) 등 수많은 새로운 표준이 등장했다고 언급합니다.

암호화폐는 에이전트 결제에 매우 적합하다고 주장합니다. 기존 결제 수단(신용카드, PayPal, ACH/은행 직불)은 마이크로 트랜잭션에 비효율적이고 수수료가 높으며, 구매자 분쟁(chargebacks) 문제가 있어 에이전트 간 자율 거래에 적합하지 않습니다. 반면, 암호화폐는 낮은 수수료(x402는 프로토콜 수수료 0달러)와 환불 불가 특성을 가집니다. 현재 x402는 MPP보다 20배 큰 규모(지난 30일간 100만 달러 vs 5만 달러)를 보이고 있습니다.

x402는 1997년 HTTP 1.1 RFC 2068에 도입된 HTTP 402 "Payment Required" 상태 코드를 활용합니다. 이 코드는 거의 30년간 "미래 사용을 위해 예약됨" 상태였습니다. x402의 작동 방식은 다음과 같습니다: 클라이언트가 API 요청을 보내면 서버는 HTTP 402 Payment Required로 응답합니다. 클라이언트는 지갑에서 돈을 인출하는 서명을 생성하여 서버에 보냅니다. 서버는 이를 Facilitator(예: Coinbase)와 블록체인을 통해 검증하고, 작업 수행 후 Facilitator에게 정산(settle) 요청을 보냅니다. 블록체인에서 거래가 확인되면 정산이 완료되고 서버는 200 OK Payment-Response를 보냅니다.

하지만 여기에 문제가 있습니다. 정산이 블록체인에 제출되기 전까지는 클라이언트가 동일한 지갑과 돈으로 다른 거래를 시도하는 이중 지불을 막을 수 없습니다. Apify는 이 문제를 해결하기 위해 "exact" 결제 방식(고정 금액 청구)과 환불 방식을 사용했습니다. 즉, 최대 금액을 선불로 청구하고, 작업 완료 후 남은 금액을 환불하는 방식입니다. 이 방식은 두 번의 블록체인 거래와 수수료가 발생하며, 클라이언트가 서버를 신뢰해야 한다는 단점이 있습니다.

Apify는 이 문제를 해결하기 위해 Coinbase가 2025년 12월에 발표하고 2026년 4월에 출시한 "upto" 결제 방식을 기대했으나, 이 방식 역시 이중 지불 문제를 해결하지 못했습니다. 결국 Apify는 2026년 5월에 Coinbase가 도입한 "batch-settlement" 방식을 구현 중입니다. 이 방식은 클라이언트가 ERC-20 토큰을 에스크로에 예치하여 채널을 열고, 각 결제 요청에 대해 서명된 누적 바우처를 받습니다. 서버는 바우처를 검증하고 온체인 전송을 기다리지 않고 응답을 제공합니다. 서버의 채널 관리자는 주기적으로 여러 채널의 최신 바우처를 한 번의 거래로 청구하고, 유휴 채널은 미결제 바우처가 모두 청구된 후 협력적으로 환불됩니다.

Apify는 이러한 복잡성을 해결하기 위해 "Agent General Interface (AGI)"라는 새로운 서비스를 도입했습니다(agi.apify.com). AGI는 AI 에이전트를 위한 Apify의 "정문" 역할을 합니다. 에이전트는 AGI 웹사이트를 통해 Apify 토큰을 구매하고, 이 토큰을 사용하여 Apify의 API나 MCP를 통해 작업을 실행할 수 있습니다. AGI는 에이전트가 새로운 버전의 프로토콜을 유연하게 채택할 수 있도록 설계되었으며, 인간 사용자를 위한 것이 아니므로 "못생기게" 보일 수 있습니다.

발표자는 데모를 시도했으나 기술적인 문제로 실패했습니다. 그는 x402 생태계가 아직 매우 초기 단계이며(월 약 100만 달러 거래량), 프로토콜과 도구가 빠르게 발전하고 있다고 강조합니다. 암호화폐 용어에 겁먹지 말고 직접 x402를 시도하고 무언가를 만들어 보라고 독려합니다. 토큰 보조금 시대가 끝나면 에이전트 결제가 폭발적으로 성장할 것이며, 에이전트 경제가 일반 상거래를 능가할 것이라고 예측하며 발표를 마칩니다.

## 인상적인 대목
-   "MCP isn't good (yet)"이라는 작년 발표를 인용하며, 1년 만에 MCP가 표준이 된 것을 보여준 후, 자신의 발표 제목을 "x402 isn't good (yet)"으로 정한 점이 인상적입니다. 이는 기술 발전의 빠른 속도와 현재 x402가 겪는 과제를 동시에 보여줍니다.
-   "Agents will need cash to complete jobs without supervision"이라는 문장은 에이전트 경제의 근본적인 필요성을 명확하게 제시합니다.
-   "Crypto is well-suited for agentic payments"라는 주장과 함께, 기존 결제 수단의 높은 수수료와 구매자 분쟁 문제를 지적하며 암호화폐의 장점을 부각한 점이 흥미롭습니다.
-   "Solution: duplicate x402 API hosts"라는 대목에서, 기술적 제약 때문에 비효율적인 방식으로 API 호스트를 복제해야 하는 현실을 지적하며 "It sounds like anti-pattern"이라고 말한 부분이 기억에 남습니다.
-   "Agent General Interface (AGI) ... is not what you mean it is. It actually stands for Agent General Interface. So instead of like Application Programming Interface, we have Agent General Interface that can change anytime because it's used by agents, so they're flexible, right?"라는 설명은 유머러스하면서도 에이전트 중심의 설계 철학을 잘 보여줍니다.

## 실무 적용 포인트
-   **에이전트 결제 프로토콜 학습:** 에이전트 경제가 빠르게 성장하고 있으므로, x402, MPP, ACP 등 주요 에이전트 결제 프로토콜의 작동 방식과 장단점을 이해하는 것이 중요합니다. 특히 Apify의 "batch-settlement"와 같은 새로운 방식은 마이크로 트랜잭션의 효율성을 높이는 데 기여할 수 있습니다.
-   **암호화폐 기반 결제 시스템 고려:** 에이전트 간 마이크로 트랜잭션이 필요한 서비스 개발 시, 기존 금융 시스템의 높은 수수료와 환불 위험을 피하기 위해 암호화폐 기반 결제 시스템(특히 스테이블코인)의 도입을 적극적으로 검토해야 합니다.
-   **API 설계 유연성 확보:** Apify의 AGI 사례처럼, AI 에이전트가 사용하는 API는 인간 사용자를 위한 API와는 다른 유연성을 가질 수 있습니다. 에이전트의 빠른 적응력을 활용하여 API 변경에 대한 제약을 줄이는 설계를 고려할 수 있습니다.
-   **이중 지불 및 가변 사용량 처리 방안 연구:** x402 프로토콜이 겪는 이중 지불 문제와 가변 사용량에 대한 효율적인 결제 처리(예: "batch-settlement" 방식)는 에이전트 기반 서비스의 안정성과 경제성을 확보하는 데 필수적이므로, 관련 기술 및 구현 방안을 지속적으로 연구해야 합니다.
