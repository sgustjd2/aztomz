# Paving the Road to Production: Governed Enterprise AI Agents — Harish Gaggar, Credit Karma

🔗 https://youtu.be/tZycGA_Fbfo · 📅 2026-10-14 · 🎙 AI Engineer

## 한 줄 요약
AI 에이전트를 프로덕션 환경에 배포할 때 발생하는 보안, 관리, 비용 문제를 해결하기 위해 게이트웨이 기반의 엔터프라이즈 프레임워크를 구축하는 방법을 제시한다.

## 발표자·소속
Harish Gaggar, Senior Staff Software Engineer, Credit Karma

## 핵심 주장
- AI 에이전트를 프로덕션 환경에 성공적으로 배포하려면 단순한 에이전트 개발을 넘어 포괄적인 엔터프라이즈 프레임워크 구축이 필수적이다.
- 게이트웨이 우선 보안(Gateway-first security)은 에이전트와 엔터프라이즈 서비스 간의 모든 통신을 인증하고 통제하는 데 있어 핵심 기반이다.
- MCP(Managed Control Plane)는 REST API를 에이전트가 안전하게 호출할 수 있는 유형화되고 권한 범위가 지정된 도구로 전환하여 보안과 통제를 강화한다.
- 고위험 작업에 대해서는 항상 인간의 개입(Human-in-the-Loop, HITL)을 유지하여 에이전트의 자율성으로 인한 잠재적 위험을 관리해야 한다.
- 에이전트의 신뢰성을 확보하려면 모든 작업에 대한 가시성(observability), 개인정보 보호(privacy), 영속성(persistence)이 보장되어야 한다.
- 컨텍스트 최적화는 LLM 호출 전에 불필요한 토큰 사용을 줄여 비용을 절감하고 효율성을 높이는 중요한 요소이다.

## 세부 내용

발표자는 AI 에이전트를 프로덕션 환경에 배포할 때 겪는 주요 도전 과제들을 언급하며, 이를 해결하기 위한 포괄적인 엔터프라이즈 프레임워크의 필요성을 강조했다. 주요 도전 과제로는 인증 및 라우팅을 위한 게이트웨이 부재, 에이전트 쿼리 실행을 위한 적절한 도구 부족, 쿼리 추적 및 평가 시스템 미비, 메모리 관리의 어려움, PII(개인 식별 정보) 및 민감 정보 유출 위험, 토큰 비용 최적화 부족 등이 있다.

이러한 도전 과제에 대응하기 위해 발표자는 다음 8가지 프레임워크를 제안했다:
1.  **에이전트 프레임워크**: LangChain 커뮤니티의 LangGraph 프레임워크를 활용하여 태스크별 노드를 구축하고 스킬, 프롬프트, 플러그인을 쉽게 통합한다.
2.  **모든 호출 전 OAuth**: MCP 게이트웨이를 구축하여 모든 MCP 도구 호출이 인증되도록 한다.
3.  **맞춤형 MCP**: 내부 보안 관행에 맞춰 MCP 도구를 맞춤 설정한다.
4.  **지속적인 감사**: 모든 작업은 MCP 게이트웨이에 로깅되어 감사된다.
5.  **PII/민감 정보 제거**: LLM에 도달하기 전에 민감한 데이터를 스크러빙한다.
6.  **추적 및 평가**: 쿼리당 모델, 토큰, 지연 시간, 응답 품질을 추적한다.
7.  **메모리 관리**: 스레드 및 체크포인트를 통해 워크플로우 상태를 저장하고 복원한다.
8.  **컨텍스트 최적화**: 불필요한 토큰 사용을 줄이기 위해 컨텍스트를 다듬고 요약한다.

**에이전트 인프라 구축 아키텍처**는 다음과 같다:
*   **로컬 개발**: 개발자는 에이전트를 등록하고, 개발 포털을 통해 에이전트의 사용 사례, 언어, 스킬 등을 정의한다. 개발 포털은 에이전트 프레임워크, 메모리, 추적/평가, 컨텍스트 최적화, PII 차단 기능을 포함하는 저장소를 생성한다. 개발자는 이 저장소를 클론하여 에이전트를 Docker 이미지로 빌드하고 로컬에서 테스트한다.
*   **배포 파이프라인**: PR 승인 후 CI/CD 파이프라인(예: CircleCI)이 Docker 이미지를 빌드하고 스캔하여 취약점이 없는지 확인한다. 이후 Kubernetes 클러스터에 에이전트 POD를 배포한다. 이 과정에서 에이전트 워크로드 아이덴티티, 메모리, 추적/평가 테이블, 에이전트 시크릿 등 필요한 프로덕션 리소스가 자동으로 생성 및 바인딩된다.
*   **공유 서비스**: 배포된 에이전트는 LangFuse(에이전트 추적), AI Gateway(LLM 서비스), MCP Server(도구), API Endpoint(외부 서비스)와 통신한다.

**MCP 서버**는 REST API를 에이전트가 안전하게 호출할 수 있는 유형화되고 권한 범위가 지정된 도구로 전환하는 프로토콜 계층이다. FastMCP 서버를 활용하여 다양한 도구를 노출하고, 서버는 요청 필터, 제한, 차단된 필드를 강제한다. 사용자 또는 서비스 계정 ID를 MCP 게이트웨이를 통해 지원한다.

**MCP 게이트웨이**는 코딩 지원 도구/에이전트를 엔터프라이즈 서비스에 안전하게 연결하는 중앙 집중식 인증 및 라우팅 허브이다. 클라이언트(예: VS Code, 에이전트)는 JWE(JSON Web Encryption) 토큰을 사용하여 MCP 게이트웨이에 요청을 보낸다. 게이트웨이는 사용자 세션 상태를 Redis에 저장하고, JWE를 언랩하며, 사용자 토큰을 첨부하고, 속도 제한을 확인한 후 백엔드 MCP 서버(예: Artifactory MCP, Github MCP)로 요청을 라우팅한다. MCP 서버는 Jfrog API 호출 등을 통해 사용자 범위의 응답을 받아 클라이언트에 전달한다. MCP 서버는 클라이언트에 직접 노출되지 않는다.

**MCP 게이트웨이 모니터링 및 규정 준수**는 포괄적인 텔레메트리, 분산 추적, AI 워크플로우를 위한 실시간 시각화를 제공한다. MCP 게이트웨이는 운영 로그를 Log Store(ELK, Loki, CloudWatch)에 보내고, OTLP(OpenTelemetry Protocol)를 통해 추적 및 메트릭을 OpenTelemetry Collector로 보낸다. OpenTelemetry Collector는 추적을 Tempo에, 메트릭을 Prometheus에 보내고, 이 모든 데이터는 Grafana에서 시각화 및 대시보드로 제공된다. 이를 통해 401 오류, 토큰 갱신 실패, 도구 지연 시간 등을 모니터링할 수 있다.

**에이전트 메모리 관리**는 워크플로우의 상태를 시간 경과에 따라 저장하고 복원하는 기능으로, 내구성과 원활한 복구를 보장한다. 각 쿼리는 스레드를 생성하고, 각 노드 실행 시 체크포인트가 생성되어 메모리 DB(로컬은 SQLite, 프로덕션은 Cloud Spanner)에 저장된다. 이를 통해 에이전트가 과거 대화 내용을 기억하고 복구할 수 있다.

**에이전트 추적 및 평가**는 에이전트 측 LLM 텔레메트리와 게이트웨이 운영 텔레메트리를 구분하여 각 LLM 호출에 대한 모델, 토큰, 비용, 지연 시간을 기록한다. 답변 품질 피드백을 캡처하고 요약하여 에이전트의 성능과 ROI를 평가하는 데 활용한다.

**에이전트 PII 트리머**는 LLM 쿼리 전에 민감한 데이터를 차단하거나 수정하는 프레임워크이다. 개인 키, AWS 시크릿 키, 베어러 토큰 등 심각도 90% 이상의 민감 정보는 차단하고, API 키, SSN, 신용카드, 여권 정보 등은 수정(redact)한다. 이는 민감 정보가 LLM, 메모리 DB, 추적/평가 테이블, 추적 시스템에 도달하는 것을 방지한다.

**컨텍스트 최적화 프레임워크**는 LLM에 전달되는 컨텍스트를 최적화하여 토큰 비용을 절감한다. 사용자 쿼리를 받은 후, 관련성 높은 페이로드를 선택(select)하고, 가장 관련성 높은 정보를 재순위화(rerank)하며, 중복을 제거(cluster)하고, 마지막으로 페이로드를 압축(compress)하여 LLM에 전달한다. 데모에서는 컨텍스트 최적화 기능을 활성화했을 때 동일한 쿼리에서 약 90%의 토큰 비용이 절감되는 것을 보여주었다.

## 인상적인 대목
- "Build an enterprise framework, not just an AI agent." (단순히 AI 에이전트를 만드는 것을 넘어 엔터프라이즈 프레임워크를 구축해야 한다.)
- "Gateway-first security is the foundation." (게이트웨이 우선 보안이 기반이다.)
- "Trust requires observability, privacy, and persistence." (신뢰는 관찰 가능성, 개인 정보 보호, 영속성을 필요로 한다.)
- "Optimize context before it becomes cost." (비용이 되기 전에 컨텍스트를 최적화하라.)

## 실무 적용 포인트
- **게이트웨이 도입**: AI 에이전트가 백엔드 서비스와 통신할 때 직접적인 접근을 허용하지 않고, 인증, 권한 부여, 라우팅, 로깅을 담당하는 중앙 집중식 게이트웨이를 구축하여 보안과 통제력을 강화한다.
- **PII/민감 정보 차단**: LLM으로 전달되는 모든 입력에 대해 PII 트리머 프레임워크를 적용하여 민감한 데이터를 자동으로 식별하고 차단하거나 수정함으로써 데이터 유출 위험을 최소화한다.
- **컨텍스트 최적화 구현**: LLM 호출 전에 컨텍스트를 선택, 재순위화, 클러스터링, 압축하는 컨텍스트 최적화 프레임워크를 도입하여 불필요한 토큰 사용을 줄이고 LLM 비용을 절감한다.
- **종합적인 모니터링 시스템 구축**: OpenTelemetry, Tempo, Prometheus, Grafana와 같은 도구를 활용하여 에이전트의 운영 로그, 추적, 메트릭을 실시간으로 수집, 분석, 시각화하여 에이전트의 성능, 안정성, 규정 준수를 지속적으로 모니터링한다.
