# It’s Tokens All The Way Down: How RLMs are Different — Kevin Madura, AlixPartners

## 한 줄 요약
재귀적 언어 모델(RLM)은 컨텍스트를 조작 가능한 객체로 취급하고 하위 언어 모델(sub-LLM)에 작업을 위임하여 긴 컨텍스트 및 복잡한 작업을 처리하는 데 있어 기존 LLM 및 에이전트보다 뛰어난 성능과 효율성을 제공합니다.

## 발표자·소속

## 핵심 주장
- **컨텍스트 처리 방식의 혁신:** RLM은 컨텍스트를 단순히 텍스트 입력으로 간주하는 대신, 모델이 심볼릭 환경(REPL) 내에서 직접 조작할 수 있는 객체로 취급하여 기존 LLM의 컨텍스트 창 한계를 극복합니다.
- **재귀적 문제 분해 및 위임:** RLM은 복잡한 작업을 하위 언어 모델(sub-LLM)에 기능으로 위임하여 재귀적으로 분해하고 해결합니다. 이는 모델이 스스로 작업 방식을 결정하도록 하여, 수동적인 프롬프트 엔지니어링의 필요성을 줄입니다.
- **향상된 성능 및 효율성:** LongCoT 및 BrowseComp-Plus 벤치마크에서 RLM은 기존 LLM 및 툴-콜링 에이전트보다 훨씬 높은 정확도를 보이며, 특히 긴 컨텍스트 작업에서 토큰 사용량과 처리 시간을 크게 절감합니다.
- **추상화에 집중:** RLM은 컨텍스트 엔지니어링 대신 추상화에 집중할 수 있도록 하여, 사용자가 원하는 목표(입력 및 출력)를 정의하면 모델이 실행 경로를 스스로 결정하고 코드를 작성하여 문제를 해결합니다.

## 세부 내용
발표는 RLM(Recursive Language Model)의 개념과 기존 언어 모델(LLM)과의 차이점을 설명하며 시작됩니다. RLM의 핵심 차이점은 컨텍스트를 모델이 심볼릭 환경(REPL) 내에서 조작할 수 있는 객체로 취급한다는 것입니다. 또한, RLM은 하위 언어 모델(sub-LLM)에 기능을 위임할 수 있는 능력을 가지고 있어, 모델이 스스로 작업 방식을 결정하도록 합니다.

RLM의 기원은 2023년 5월 Omar Khattab의 트윗에서 소개된, 임의로 긴 텍스트를 재귀적인 DSPy 프로그램으로 요약하는 83줄짜리 코드에서 찾아볼 수 있습니다. 이는 컨텍스트 창의 한계를 넘어서는 새로운 접근 방식의 시작을 알렸습니다.

성능 측면에서 RLM은 LongCoT 및 BrowseComp-Plus 벤치마크에서 기존 모델들을 압도하는 결과를 보여줍니다. 특히 BrowseComp-Plus에서는 RLM이 100%에 가까운 정확도를 유지하는 반면, 다른 모델들은 성능이 급격히 저하됩니다. 비용 측면에서도 RLM은 GPT-5를 사용한 툴-콜링보다 훨씬 효율적입니다. LongCoT 벤치마크에서는 RLM이 논리, CS, 화학, 체스, 수학 등 500개 질문에 대한 정확도를 2.8%에서 45.4%로 크게 향상시켰습니다.

"결정론적 셸(Deterministic Shell)" 개념은 RLM의 중요한 특징입니다. 사용자는 작업(입력 및 출력)을 정의하고, 모델은 REPL 내에서 컨텍스트를 탐색(peek, grep, chunk, recurse)하는 방법을 스스로 결정합니다. 이는 에이전트나 툴-콜링 방식이 컨텍스트 창의 제약을 받는 것과 대조적입니다. RLM은 중간 결과를 스크립트 변수에 저장하여 컨텍스트 창 오염을 방지하고, 이는 Anthropic의 워크플로우와 유사한 접근 방식입니다.

RLM을 사용해야 하는 경우는 다음과 같습니다: 매우 크거나 밀도 높은 입력 또는 출력, 분해 가능한 작업, 장기적인 세션. 반대로, 컨텍스트에 맞는 작업, 낮은 지연 시간 요구사항, 또는 기본 코더가 약한 경우에는 RLM을 건너뛸 수 있습니다.

실제 적용 사례로는 데이터프레임 탐색, 인보이스를 재고로 변환, CloudWatch 로그 분석, 코드베이스 스캔 등이 있습니다.
- **데이터프레임 탐색:** `dsp.RLM`을 사용하여 데이터 과학자가 수행할 법한 코호트 유지율 분석을 단 20줄 남짓한 코드로 수행할 수 있습니다. 모델은 REPL 내에서 데이터프레임과 직접 상호작용하며, 스스로 코드를 작성하고 결과를 분석합니다.
- **인보이스-재고 변환:** `predict-rlm`은 여러 PDF 인보이스에서 라인 아이템을 추출하여 벤더별 통합 스프레드시트를 생성하고 요약을 제공합니다. 이는 복잡하고 가변적인 인보이스 처리 작업을 추상화하여 컨텍스트 엔지니어링 없이도 효율적으로 처리할 수 있게 합니다.
- **CloudWatch 로그 분석:** AWS 엔지니어가 RLM 에이전트를 사용하여 8백만 라인의 CloudWatch 서비스 로그에서 통찰력을 추출했습니다. 53단계 후 32k "활성" 토큰만 사용하며, 모델이 전체 컨텍스트를 한 번에 처리하는 대신 페이지를 넘기며 필요한 부분만 탐색했습니다.
- **코드베이스 스캔:** OWASP의 취약한 서버리스 앱을 `dsp.RLM`으로 스캔하여 10개의 심어진 취약점 중 6개를 발견했으며, 이 모든 과정이 0.87달러의 비용으로 이루어졌습니다. 이는 프롬프트 엔지니어링이나 커스텀 스캐너 로직 없이 단지 시그니처만으로 가능했습니다.

`predict-rlm`은 하위 LLM 호출 간의 시그니처를 강제하여, 오케스트레이터가 하위 LLM에 산문을 전달하는 대신 타입이 지정된 경계를 통해 시그니처를 전달하도록 합니다. 이는 Pydantic 모델을 사용하여 응답을 파싱하고 스키마 불일치 시 재시도하여 구조를 강제합니다. REPL은 재파싱할 필요 없는 실제 Python 객체를 반환합니다.

## 실무 적용 포인트
- **긴 컨텍스트 작업 자동화:** 복잡한 문서 요약, 대규모 데이터 분석, 코드베이스 스캔 등 컨텍스트 창 한계로 어려움을 겪던 작업에 RLM을 적용하여 효율성을 극대화할 수 있습니다.
- **데이터프레임 및 지식 작업 간소화:** 데이터 과학자는 `dsp.RLM`과 같은 도구를 활용하여 데이터프레임 탐색 및 분석 작업을 위한 복잡한 스캐폴딩이나 오케스트레이션 없이, 목표 정의만으로 모델이 스스로 코드를 작성하고 실행하게 할 수 있습니다.
- **비용 효율적인 LLM 활용:** RLM은 필요한 컨텍스트만 선택적으로 처리하고 재귀적으로 작업을 분해하여, 기존 LLM 사용 시 발생하는 과도한 토큰 사용량과 비용을 절감할 수 있습니다.
- **생산성 향상 및 추상화 집중:** 엔지니어는 컨텍스트 엔지니어링의 세부 사항에 얽매이지 않고, 문제 해결을 위한 상위 수준의 추상화와 목표 정의에 집중하여 생산성을 높일 수 있습니다.
