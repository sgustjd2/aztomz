# 구조 — prompt-pack (AI 이미지 프롬프트 모음집)

검색의도: AI로 SNS·프로필용 사진을 만들고 싶은데 프롬프트를 어떻게 써야 할지 모르는 사람.
"복사해서 바로 쓴다"가 이 글의 유일한 성공 기준이다 — 읽는 글이 아니라 쓰는 글이다.

## 이 구조가 다른 카테고리와 다른 점

- **팩트체크는 없지만 조사는 있다.** 프롬프트 자체는 사실 주장이 아니라 팩트체크 대상이 아니다. 하지만
  **어떤 테마를 고를지는 조사가 결정한다** — 프롬프트 "스타일"도 유행을 탄다(지브리풍처럼 한물간다).
  Threads·인스타그램·블로그·유튜브에서 지금 화제인 스타일을 찾아 테마를 고른다(2026-07-26 정정 —
  처음엔 조사 없이 정적 목록에서 테마를 골랐는데, 그러면 이미 저문 스타일을 계속 우려먹게 된다).
- **이모지를 쓴다.** 다른 카테고리는 전부 금지지만, 이 형식 자체가 소제목·장식 표기에 이모지를 쓴다.
- **가사 저작권 같은 문제가 없다** — 대신 **실존 인물·브랜드**를 예시 대상으로 쓰지 않는 게 이 카테고리의
  저작권/초상권 규칙이다.
- **프롬프트가 실제로 말이 되는지**가 유일한 품질 기준이다(AI에게 뭘 하라는 건지 모호하면 안 된다).

## 뼈대

### 1. 제목
`[테마] + [형식 이름] + [변형 개수]종` 패턴. 예: "우리 댕댕이 인생샷 만들기 AI 잡지컷 프롬프트 6종 모음",
"챗GPT 잡지컷 프롬프트 모음 | 여행·일상·음식·육아·제품·풍경 36종".

### 2. 도입 (2~3문장)
이 팩이 뭘 만들어주는지 + 사용법 한 줄("아래 프롬프트를 복사한 뒤, 맨 아래 공통 디자인 룰북을 함께
붙여넣으세요"). 이모지 1~2개 정도는 자연스럽다.
**조사에서 "왜 지금 이 테마인지" 근거를 찾았으면 한 줄 넣는다**(예: "요즘 인스타에서 ○○ 스타일이
화제예요"). 근거가 약하면 이 줄은 빼고 바로 사용법으로 들어간다 — 지어내지 않는다.

### 3. 한눈에 보기 (목차)
변형 이름을 번호 매겨 나열. 독자가 원하는 상황으로 바로 스크롤하게.

### 4. 변형마다 (H3 또는 H2, 이모지 + 영문 라벨 + 한글 이름)

소제목 바로 아래 **한 줄 설명**(이 변형이 어떤 상황용인지) → 그 아래 **``` 코드블록 하나**에 실제
프롬프트 전체를 담는다. 독자가 코드블록 하나만 통째로 복사해서 붙여넣으면 끝나야 한다 — 코드블록
밖에 있는 정보는 "복사가 안 되는" 부가 설명일 뿐이라고 생각해라.

코드블록 안에 전부 들어간다 — 하나라도 비면 프롬프트로서 불완전하다:

- **오프너**: `[상황 사진]에 대해, ~스타일의 SNS 이미지를 생성한다.` 형식. 대괄호 안은 독자가 자기 사진으로
  바꿔 끼우는 자리라는 걸 명확히.
- **날짜/시간 자동 반영 지시**: `※ date tool 호출 → "[형식]" 자동 표기.` — AI가 실행 시점에 오늘 날짜를
  조회해서 채우게 하는 장치. **날짜를 미리 못 박지 마라** — "date tool 호출"이라고만 지시하고 실제 날짜값은
  절대 쓰지 않는다(글이 오래돼도 안 틀리게).
- **타이틀 후보 1~2개**: 영문 헤드라인 느낌으로 짧게(10~20자).
- **포인트 컬러 1색**: 색 이름으로.
- **메모 요소**: 폴라로이드·스티커·영수증 같은 소품 은유 + 들어갈 텍스트.
- **서브 코멘트 2~3개**: 해시태그나 한 줄 코멘트 예시.
- **장식 요소**: 아이콘·손그림 모티프 나열.
- 코드블록 맨 끝 줄: `※ 아래 [공통 디자인 룰북]을 반드시 함께 적용할 것.`

마크다운으로는 이렇게 쓴다(백틱 세 개로 시작·종료, 안쪽은 순수 텍스트):

    ```
    [일상·집콕 사진]에 대해, 따뜻한 펫 다이어리 매거진 스타일의 SNS 이미지를 생성한다.
    ※ date tool 호출 → "[오늘 날짜] · 함께한 ○○일째" 형식으로 자동 표기.
    - 타이틀: "MY BEST FRIEND" 또는 "OUR DAY"
    - 포인트 컬러: 머스타드 옐로우 1색
    - 메모 요소: "이름 · 나이 · 견종" 손글씨 프로필 카드
    - 서브 코멘트: "오늘도 사랑해" / "#멍스타그램" / "최고의 룸메이트"
    - 장식: 발바닥 도장, 하트, 뼈다귀 손그림
    ※ 아래 [공통 디자인 룰북]을 반드시 함께 적용할 것.
    ```

### 5. 공통 디자인 룰북 (글 전체에 딱 1번, 이것도 코드블록 하나로)
모든 변형이 공유하는 규칙 — 독자가 위에서 고른 변형 코드블록 뒤에 이어 붙일 수 있게, **이 룰북도
통째로 복사되는 코드블록 1개**에 담는다. 최소 이 항목들을 포함:

- **피사체 보호** — 주 피사체에 텍스트·장식이 겹치지 않게, 여백 확보.
- **타이틀 규칙** — 개수·크기·위치·글자수 상한.
- **메모 요소 규칙** — 개수·질감(그림자·기울기)·문장 길이.
- **레이아웃 설계** — 시선 흐름, 텍스트 분산 배치, 피사체 주변 여백 유지.
- **텍스트 스타일(손글씨 질감)** — "디지털 폰트 금지, 실제 필기구로 쓴 듯한 질감" + 구체적 질감 예시
  (드라이 브러시·분필·잉크 등).

### 6. 마무리
다른 프롬프트 팩 예고(내부링크 있으면 걸고, 없으면 URL 없이 예고만).

## 프롬프트 작성 규칙 — 여기가 품질의 전부

- **완결된 문장으로 써라.** "여행 사진 프롬프트" 같은 조각이 아니라, 그대로 복사해서 AI 채팅창에 붙이면
  작동하는 완전한 지시문이어야 한다.
- **모호한 지시를 남기지 마라.** "예쁘게", "느낌 있게" 대신 색·질감·배치를 구체적으로 지정한다(참고 예시가
  이미 그렇게 되어 있다 — 그 구체성 수준을 유지할 것).
- **변형끼리 겹치지 마라.** 포인트 컬러·타이틀 후보·서브 코멘트가 변형마다 달라야 한다. 색이나 문구를
  복사해서 상황명만 바꾸면 안 된다.
- **AI 이미지 생성 자체의 한계를 부풀리지 마라.** "이 프롬프트로 항상 똑같이 나온다"처럼 결정론적으로
  쓰지 않는다. 생성형 AI는 매번 다르게 나온다는 걸 안다는 전제로 쓴다.

## 안 써본 것을 쓰는 법

이 프롬프트로 실제 이미지를 생성해본 게 아니다. **"이렇게 나왔어요" 같은 결과 서술을 하지 마라.**
프롬프트 텍스트 자체가 콘텐츠이지, 생성 결과 리뷰가 아니다.

## 원본성 (사실 검증 대신 이 카테고리가 통과해야 하는 게이트)

- 다른 창작자의 특정 바이럴 게시물 문구를 그대로 베끼지 않는다 — 형식(잡지컷+손글씨)은 장르이지 특정
  게시물의 소유물이 아니지만, 문장 표현은 새로 쓴다.
- 실존 인물·브랜드를 프롬프트의 예시 대상으로 등장시키지 않는다(초상권·상표권).
- 테마는 이미 이 블로그에서 다룬 것과 겹치지 않게 고른다(반려동물·여행·일상·음식·육아·제품·풍경은 이미
  발행됨 — 겹치면 같은 검색어를 두고 자기잠식한다).
- **도입부의 "요즘 화제" 같은 유행 언급은 조사 단계(`backend/blog/research/<slug>.json`)의 근거와
  대조한다.** 근거가 없는데 유행이라고 썼으면 그 문장을 빼거나 "~로 보여요" 정도로 낮춘다 — 지어낸
  유행 근거는 다른 카테고리의 지어낸 인용·수치와 똑같은 문제다.
