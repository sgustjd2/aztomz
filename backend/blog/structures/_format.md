# 편집 양식 — 개발·기술 글 공통 (goddaehee·inpa 참고)

개발 블로거 **갓대희(goddaehee)·inpa** 스타일에서 가져온 공통 포맷. 단, 우리 렌더러(`backend/scripts/lib/md.mjs`)로
**실제 렌더되는 것만** 정리했다. 기술 계열 템플릿(news·listicle·howto·troubleshooting·comparison)은 이걸 같이 따른다. 말투는 **해요체**.

## 1. 섹션 흐름 (inpa 패턴)
도입(무엇을·왜 볼 만한지 2~3문장) → 배경/문제 → 방법·해결(본체) → 예시·코드 → **정리(핵심 요약)** → 참고.
큰 단락 사이엔 `---`(구분선)로 숨을 준다. 소제목은 `##`·`###`(우리 렌더러는 `#`도 h2로 내린다, h4까지).

## 2. 콜아웃 = 인용부호(`>`)에 이모지 (inpa 의 💡⚠️📌)
`md2html`은 `>`를 굵은 좌측선 박스로 렌더한다. 이걸 콜아웃으로 쓴다.
**⚠ 여러 줄 `>`는 한 줄로 합쳐지니, 콜아웃은 한두 문장으로 짧게.**
- `> 💡 **팁** — …`  (요령·단축)
- `> ⚠️ **주의** — …` (함정·자주 하는 실수)
- `> 📌 **핵심** — …` (꼭 기억할 것)
남발 금지 — 한 글에 3~4개 이내, 진짜 중요한 데만.

## 3. 코드블록 (갓대희의 파일명 명시)
- 세 backtick 펜스로 감싼다.
- **⚠ 우리 렌더러는 언어 하이라이트도, 파일명 라벨도 안 보여준다** (```` ```java ````라 써도 색 안 입음).
  그래서 파일명·언어는 **코드블록 바로 위 굵은 줄**로 밝힌다:
  ``**UserService.java**`` 다음 줄에 펜스를 연다.
- 명령어·짧은 식별자는 인라인 `` `코드` ``.
- 코드 안에 `<`, `>`는 자동 이스케이프되니 `&lt;` 같은 엔티티를 직접 쓰지 말 것(이중 이스케이프 사고).

## 4. 목차 (선택 — inpa/갓대희 상단 목차의 대체)
우리 렌더러는 제목 앵커(클릭 이동)를 못 만든다. 긴 글이면 도입 뒤에 **"이 글 순서"**를 불릿으로
나열(링크 아님)해 지도만 준다. 짧은 글은 생략.

## 5. 비교는 표로 (inpa "쿠키 vs 세션 vs 토큰")
개념 A vs B vs C, 옵션 장단점, 버전별 차이 등은 문장 나열보다 **표**가 낫다. `md2html` 표 지원(`| … |` + `|---|`).

## 6. 정리 섹션
끝에 `## 정리` + 핵심 불릿 3~5개, 또는 `> 📌 **한 줄 정리** — …`.
독자가 스크롤만 훑어도 요점이 남게 한다.

## 7. 참고 링크
끝에 `## 참고` + 원문·문서 링크 불릿(`- [원제](url)`). 본문에서 인용한 수치·주장의 출처를 여기 모은다(우리 철칙: 근거는 링크로).

## 하지 말 것
- 이모지 콜아웃 남발(3~4개 이내), 문단마다 붙이기.
- 렌더 안 되는 문법에 기대기(언어 하이라이트·중첩 목록·클릭 목차) — 위 대체법을 쓴다.
- 남의 코드·이미지·글 전재. 인용은 짧게 + 출처 명시.
- 갓대희 인사말("안녕하세요! …입니다") 흉내 — 한끗 톤은 담백하게 바로 본론.
