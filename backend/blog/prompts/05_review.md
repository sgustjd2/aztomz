# 05 자가검수

완성된 글을 독자의 관점에서 냉정하게 검수한다. 사람 작성자인 척하거나 AI 판별을 피하는 것이 목적이 아니다. 사실을 지키면서 읽기 편한 글인지 평가한다.
여기서 통과시킨 글이 그대로 공개 발행된다.

## 채점 (각 10점, 총 40점)

| 항목 | 10점의 기준 | 감점 |
|---|---|---|
| **가독성** | 답이 앞에 있고, 문장이 자연스러운 한국어이며, 소제목만 훑어도 흐름이 보임 | 번역투·빈 도입·접속사 반복 / 문단이 벽 / 소제목이 내용을 안 알려줌 |
| **독창성** | 출처를 단순 나열하지 않고 근거 있는 비교·선택 기준·확인 범위를 더함 | 어디서 본 내용의 재배열 / 일반론만 / 경험이나 수치를 지어냄 |
| **키워드** | 메인 검색 의도가 제목·첫 문단·관련 소제목에 자연스럽게 이어짐 | 억지 반복·무관 키워드 / 제목과 본문이 다른 질문에 답함 |
| **신뢰성** | 수치·버전·날짜에 근거, 추측은 추측이라 표시, 출처 링크 | **지어낸 사실** / 근거 없는 단정 |
| **카테고리 적합성** | 구조 템플릿·`mustInclude` 를 다 지킴, `banned` 표현 0개 | 필수 항목 누락 / 금지어 사용 |

**5항목이지만 총점은 40점 만점**으로 계산한다(카테고리 적합성은 다른 항목에 녹여 채점하지 말고
독립으로 매기되, 총점은 가독성+독창성+키워드+신뢰성 4항목 합으로 낸다).
카테고리 적합성이 7점 미만이면 총점과 무관하게 **불합격**이다.

## 반드시 잡아야 할 것 (하나라도 있으면 신뢰성 5점 이하)

- 확인 안 된 수치·버전·날짜를 사실처럼 쓴 곳
- 존재하지 않을 수 있는 고유명사(라이브러리·API·곡·인물)
- 가사 인용 또는 번역
- 남의 이미지 URL
- 프로파일 `banned` 표현

## 출력 (JSON만)

```json
{
  "scores": { "readability": 8, "originality": 7, "keyword": 8, "credibility": 9, "categoryFit": 9 },
  "total": 32,
  "pass": true,
  "problems": [{ "where": "어느 섹션", "what": "무엇이 문제", "why": "왜 문제" }],
  "fixInstructions": ["03단계에 넘길 구체적 수정 지시 — pass 면 빈 배열"]
}
```

`total` 은 readability + originality + keyword + credibility 의 합.
`pass` 는 `total >= 32 && categoryFit >= 7`.

문체는 실제로 걸리는 부분만 고친다. 기계적인 접속사·같은 어미 반복·영어 번역투·비어 있는 맺음말이 보이면 짧고 명료한 한국어로 다듬되, 일부러 문장 길이를 흔들거나 유행어·오탈자·이모지를 넣지 않는다. 직접 경험·독자 반응·검색량은 조사나 사용자 메모에 없으면 평가 점수를 위해 만들어내지 않는다. FAQ, 표, 인용구도 글감과 근거가 있을 때만 쓴다.
