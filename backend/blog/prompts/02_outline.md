# 02 아웃라인

리서치 결과와 구조 템플릿에 맞춰 뼈대를 짠다. **아직 본문을 쓰지 않는다.**

## 할 일

1. **제목 후보 5개** — 각 28~42자. 다섯 개가 서로 다른 패턴이어야 한다.
   - 핵심 검색어를 앞 15자 안에.
   - 숫자 / 궁금증 / 이득 중 하나는 반드시 포함.
   - 다섯 개가 같은 틀이면(전부 "~하는 법") 실패다. 다시 짠다.
   - 낚시 금지 — 본문이 뒷받침 못 할 제목은 쓰지 않는다.
2. **H2/H3 구조** — 구조 템플릿의 뼈대를 그대로 따른다. 임의로 섹션을 빼거나 순서를 바꾸지 않는다.
3. **섹션별 핵심 메시지** — 각 H2가 독자에게 남길 한 문장.
4. **프로파일 `mustInclude` 배치** — 각 항목이 어느 섹션에 들어가는지 명시. 빠진 게 있으면 실패다.

## 음악 카테고리(structureTemplate = song-guide)일 때 추가

### 위에 "실제로 존재하는 곡 목록" 이 주어진 경우 (최신곡)

- **그 목록에서만 고른다.** 다른 곡을 떠올려 넣지 마라 — 무시되고 개수만 축낸다.
- `songCandidates` 에 **반드시 `videoId` 를 그대로 옮겨 적는다.** 없으면 그 곡은 버려진다.
- 5~7곡을 고른다. 고를 때 보는 것:
  - **hiddenRatio 가 낮은 곡** — 그 아티스트 규모에 비해 안 들린 곡. 이게 '숨은 명곡'의 핵심 신호다.
    **대형 아티스트라도 상관없다.** 유명한 사람의 묻힌 곡이야말로 발굴 가치가 크다.
  - **topComments 반응이 구체적인 곡** — "좋아요"뿐인 것보다, 어느 대목이 왜 좋은지 쓰인 쪽.
  - 장르·분위기가 서로 겹치지 않게. 비슷한 곡 7개면 목록이 아니라 반복이다.
- 목록에 쓸 만한 곡이 3곡뿐이면 3곡만 고른다. 채우려고 억지로 넣지 마라.

### 목록이 없는 경우 (레트로 등 LLM 이 실제로 아는 영역)

- **곡 후보를 목표 개수의 2배로 낸다.** 뒤에서 유튜브 실재 검증을 거쳐 절반은 떨어진다.
- 곡마다 `artist`(원어 표기), `title`(원어 표기), 추정 발매연도를 낸다.
- **확실하지 않은 곡은 내지 마라.** 지어낸 곡은 검증에서 어차피 떨어진다.

## 출력 (JSON만)

```json
{
  "titles": ["...", "...", "...", "...", "..."],
  "outline": [
    { "h2": "...", "message": "...", "h3": ["...", "..."] }
  ],
  "mustIncludeMap": { "항목명": "들어갈 H2" },
  "songCandidates": [{ "videoId": "목록에서 그대로 복사", "artist": "...", "title": "...", "year": 2025, "why": "이 곡을 고른 이유 한 문장" }]
}
```

`songCandidates` 는 song-guide 가 아니면 빈 배열.
