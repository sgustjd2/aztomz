문제와 사용자

낯선 유행을 만났을 때, 검색 결과는 많지만 판단 근거는 흩어져 있다.

누가
30~50대 직장인·부모자녀·후배의 말과 SNS 피드에서 처음 보는 유행어와 메뉴를 자주 만나는 사람.
어떤 상황에서
단톡방·회의·피드에서"두쫀쿠 먹어 봤어요?" 같은 말을 듣고 그 자리에서 뜻과 맥락을 빨리 알아야 할 때.
주말 맛집을 고를 때SNS에서 본 가게가 진짜 후기로 뜬 곳인지 광고로 뜬 곳인지 가려야 할 때.
무엇 때문에 불편한가
뜻·시기·근거가 따로 논다뜻은 사전에, 유행 시기는 기사에, 후기는 블로그에 흩어져 서너 번 검색해야 한다.
이미 한물간 정보와 광고2024년 글이 지금 정보처럼 보이고, 협찬 후기가 실후기처럼 섞여 있다.
한끗이 풀 문제. 뜻 · 지금 단계 · 근거 출처를 한 화면에, 광고 의심도와 후기 신뢰도는 추정치로 따로 보여 준다.

MVP 범위 · 9주차까지

핵심 기능은 세 개로 고정한다.

기능 · 01

1분 트렌드 카드

한 화면에 뜻 한 줄, 지금 단계(발견·상승·피크·하락), 근거 출처 링크를 함께 보여 준다.

기능 · 02

광고일까 진짜일까

맛집·디저트 항목에 광고 의심도와 후기 신뢰도를 별개의 두 축으로, 근거 문장과 함께 추정치로 표시한다.

기능 · 03

검증 통과분만 게시

Hermes가 모은 후보를 자동 검증 게이트가 출처 생존·관련성·근거로 걸러 통과한 것만 사이트에 올린다.

이번에 하지 않을 것
  • 인스타·틱톡 직접 수집(약관 위반)
  • 실제 회원가입·로그인 서버
  • 점수를 확정 판정처럼 표기
  • 네이티브 앱·푸시 알림
  • 사용자 후기 작성·댓글
완료 기준 — 사용자가 낯선 트렌드 하나를 검색해 1분 안에 뜻 · 지금 단계 · 출처 한 곳을 말할 수 있으면 MVP가 동작한 것으로 본다.

에이전트와 사람의 역할

Hermes는 모으고, 스크립트는 거르고, 판단은 내가 한다.

Hermes 에게 맡길 일
매일 21:30 후보 수집요일별 분야 2~4건을 공개 검색으로 찾아 뜻·요약 초안을 쓴다.
출처 찾기와 초안본문이 실제로 읽히는 기사·리뷰 URL만 모아 넘긴다.
매일 21:15 재확인가장 오래된 분석 1건의 출처를 다시 확인한다.
결정적 스크립트가 할 일
스키마 검사분류 7개·단계 라벨·날짜 형식 위반을 막는다.
출처 게이트404·무관·못 읽는 출처만 있는 항목은 자동 보류한다.
근거 대조출처 본문에 없는 수치·확산 표현이 있으면 보류한다.
내가 판단하고 확인할 일
기준을 정한다광고 의심 신호(협찬 흔적·후기 품앗이)와 게시 기준을 설계한다.
보류 항목을 검토한다게이트가 못 잡는 유래·인물 바꿔치기, 오래된 출처로 쓴 '지금 피크'를 본다.
최종 책임을 진다단정 표현을 고치고, 잘못 올라간 항목은 사후에 수정·삭제한다.

검증 계획

동작한다고 말할 근거 네 가지와 확인 방법.

근거 · 01

데이터 규칙 통과

전체 항목이 분류 7개·단계 라벨·날짜 형식을 지키고 id 중복이 0건.

확인 방법validate-trends.mjs 실행 결과 화면을 남긴다.
근거 · 02

출처가 살아 있다

게시된 출처 URL 중 404·접속 불가 0건.

확인 방법check-links.mjs로 전체 URL을 점검하고 죽은 링크 수를 기록한다.
근거 · 03

서술이 출처에 있다

새로 게시된 항목의 근거 없는 서술 0건. 10월 8일 감사의 기준선은 182건 중 139건이다.

확인 방법check-source.mjs와 근거 대조 결과에 표본 5건을 직접 원문과 비교한다.
근거 · 04

1분 안에 이해한다

참여자 3명 중 2명 이상이 낯선 트렌드의 뜻·지금 단계·출처를 1분 안에 말한다.

확인 방법휴대폰으로 사이트를 주고 시간을 잰 뒤 답과 걸린 시간을 표로 남긴다.
추가 확인 — 제출 전 7일 동안 Hermes 자동 수집 커밋이 매일 남는지 git 기록으로 보고, 빠진 날은 원인을 적는다.
