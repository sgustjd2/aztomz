# [원문 사본] 구현 결과 슬라이드 만들기 (classroom unit 32086d72…) — 2026-10-28 Chrome get_page_text 결과를 그대로 옮김

이번 슬라이드는 내 결과물에 맞게 자유롭게 만듭니다. 디자인도, 장 순서도, 장 수도 정해 두지 않았습니다. 기획안 때처럼 모두가 같은 틀을 쓰면 서로 다른 프로젝트가 같은 이야기처럼 보입니다. 지도 앱과 업무 자동화 도구와 학습 도우미는 보여 줄 방법이 달라야 합니다.

정해진 것은 두 가지뿐입니다. 꼭 들어가야 하는 내용과 classroom 에서 제대로 열리기 위한 기술 규칙입니다.

## 1. 꼭 들어가야 하는 내용
순서와 장 배치는 자유입니다. 한 장에 몰아도 되고 여러 장에 나눠도 됩니다. 평가표의 항목과 같습니다.

| 내용 | 확인할 것 |
|---|---|
| 이름, 분반, 서비스 이름 | 첫 화면에서 누구의 무엇인지 알 수 있다 |
| 데모 | 영상 링크(1~3분), 또는 "수업 중 라이브 시연" 표시. 핵심 기능이 실제로 움직이는 장면 |
| 기획안과 달라진 점, 그 이유 | 달라진 것이 없으면 그 사실 |
| 검증 3건 이상 | 무엇을 해 봤고, 결과가 어땠고, 근거(실행 결과, 화면, 수치)가 무엇인지 |
| 에이전트 작업 기록 | Hermes 에게 시킨 주요 요청, 내가 확인하거나 고친 것, 막힌 곳과 복구한 방법 |
| 앞으로의 계획 | 기말까지 완성할 것, 어떤 형태로 어디에 공개할지, 소스 공개 여부. 이미 공개했다면 주소 |

## 2. 같은 슬라이드가 되지 않게
Hermes 에게 장 구성을 정해 주면 모두 비슷해집니다. 이야기 방식을 먼저 고르고 그 안에 위 내용을 넣으세요.
- 데모가 먼저: 첫 장에서 바로 동작 장면, 그다음 왜 만들었는지 — 눈으로 보면 바로 이해되는 앱, 웹서비스
- 사용자 하루 따라가기 — 업무 자동화, 일정, 알림 도구
- 전과 후 비교 — 시간이나 단계를 줄이는 도구
- 실패에서 배운 것 — 기획안에서 많이 달라진 프로젝트
- 숫자로 보여 주기 — 검증 결과 수치가 주인공
- 한 장짜리 긴 페이지 — 공개용 안내 페이지와 함께 쓰고 싶은 경우
이 표에 없는 방식도 좋습니다.

## 3. 디자인 시스템 고르기
디자인 시스템은 색, 글꼴, 간격, 버튼 같은 규칙을 모아 둔 문서입니다. 하나를 골라 Hermes 에게 읽히면 슬라이드가 일관돼 보입니다.
- awesome-design-md (https://github.com/VoltAgent/awesome-design-md), 미리 보기 https://getdesign.md
- classroom 의 디자인 시스템 목록 (단테랩스 공용 디자인 시스템 포함)
- 공개 디자인 시스템: Material Design 3, Carbon, Primer, Fluent 2, Polaris, Atlassian Design, Ant Design, KRDS, shadcn/ui, 더 많은 목록 https://github.com/alexpate/awesome-design-systems
주의: 디자인 규칙(색, 글꼴, 간격)만 빌려 씁니다. 그 회사의 로고나 이름을 내 서비스처럼 쓰지 않습니다.

## 4. classroom 에서 제대로 열리기 위한 기술 규칙
| 규칙 | 이유 |
|---|---|
| HTML 파일 하나, 10MB 이하 | classroom 은 파일 하나만 받습니다. 이미지는 파일 안에 넣거나(base64) 공개 주소로 겁니다 |
| 장마다 `<section>` 으로 감싸고, 한 장의 높이를 화면 높이(`100vh`) 이상으로 | classroom 보기 화면은 section, .slide, [data-slide] 요소를 한 장으로 보고 키보드 → ← 스페이스로 넘깁니다. 이 구조가 아니면 화면 높이만큼 스크롤만 됩니다 |
| 직접 넘김 기능(reveal.js, 가로 넘김, 캐러셀)을 만들어도 됩니다 | 슬라이드가 키 입력을 먼저 처리하면 classroom 은 끼어들지 않습니다. 이때는 → ← 키와 클릭 둘 다 되게 합니다 |
| 장 번호 표시 (예: 3 / 8) | 발표와 질문 때 몇 번째 장인지 말할 수 있습니다 |
| `localStorage`, 쿠키를 쓰지 않기 | classroom 은 보안을 위해 슬라이드를 격리된 창에서 엽니다. 저장소에 접근하면 오류가 날 수 있습니다 |
| 링크는 새 창으로 (target="_blank") | 데모 영상, 배포 주소가 슬라이드 창 안에서 열리지 않게 |
| 노트북 화면(1280px)과 큰 모니터 둘 다에서 글자가 잘리지 않기 | 수업 화면과 채점 화면 크기가 다릅니다 |
| API 키, 토큰, 비밀번호, 남의 개인정보 넣지 않기 | 슬라이드는 갤러리에서 다른 수강생에게도 보입니다 |

Hermes 에게 마지막으로 점검시킵니다 (점검 프롬프트):
1. 장마다 section 으로 감싸져 있고 화면 높이를 채우는지, → ← 키로 한 장씩 넘어가는지 브라우저로 확인
2. 장 번호가 보이는지
3. localStorage 나 쿠키를 쓰는 코드가 있는지
4. 링크가 모두 새 창으로 열리는지, 실제로 열리는지
5. 파일 크기가 10MB 이하인지
6. 꼭 들어가야 하는 내용(데모, 달라진 점, 검증 3건, 에이전트 작업 기록, 앞으로의 계획)이 다 있는지
문제가 있으면 목록으로 알려 주고, 내가 확인한 다음에 고쳐 줘.
